# Spark 的 Job、Stage、Task

适用版本：Spark 3.x 基础术语；不提供优化器版本细节
简介：Spark 的 Job、Stage、Task的课堂概念说明与资料边界。

本文为教学示例资料，不是官方文档。来源核对见 docs/sources.md。

## 基础概念

Spark 执行可以从三个层次观察：Job、Stage 和 Task。Job 表示由动作触发的一次并行计算工作；一个 Job 可以被划分为多个相互依赖的 Stage；Task 是交给执行器的一份工作单元。三者不是可以互换的名称。教学时先画出层级，再把学生看到的执行界面标签放回图中，比单独背诵三个英文词更容易形成理解。

Stage 用于组织一组任务及其依赖关系。理解数据依赖有助于阅读阶段之间的边界，但不要凭源代码行数推断 Stage 数量。Task 的数量与工作划分有关，也不能简单等同于机器数量。一台执行节点可以承担多个任务，而某些任务可能需要等待资源。这里讨论的是概念关系，不给出某个查询在所有版本中必然产生几个阶段的承诺。

## 课堂观察与资料边界

课堂例子可以先读取多份课程日志，再按课程名称做汇总，最后取出结果。让学生标记哪里产生结果需求、哪里可能需要重新组织数据，然后与实际执行信息对照。若没有真实运行环境，就把它明确称为纸面推演，不能把画出的任务数量当作实测数据。检索“Spark Stage Task”时应同时观察命中词与正文，确认资料确实解释了这些层次。

本资料没有包含自适应执行规则、各版本配置默认值或精确性能对比。运行计划可能受到查询、数据与配置影响。学习任务是建立阅读执行信息的词汇，而不是从术语直接预测耗时。当问题要求某个版本的基准数字时，应说明当前资料不足，并列出需要补充的实验条件。引用当前解释也应附上片段与快照信息，避免更新资料后误用旧编号。
