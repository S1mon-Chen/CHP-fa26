## 基础概念

MapReduce 可以用词频统计来介绍。输入是一组文本记录，Map 读取记录并产生中间键值对。例如把每个词与计数一配对。这个例子强调数据如何转换，并不要求学生把所有应用都改造成词频统计。Map 的输出不是通常意义上的最终答案，它为后续按键组织数据提供材料。课堂可让不同小组分别处理不同段落，再把中间结果汇总。

Shuffle 将中间结果按键分发和组织，使相同键对应的值能够交给相应的 Reduce 处理。在教学图中，可以把同一个词画成相同颜色，观察来自不同 Map 的记录如何汇聚。这个阶段可能涉及数据传输与排序，不应被理解成一次没有成本的函数调用。知道 Shuffle 的存在，才能解释为什么局部计算很快也不代表整个作业一定很快。

## 课堂观察与资料边界

Reduce 接收某个键及其对应值的集合，并按照应用逻辑生成结果。对于词频例子，它把计数求和。并非所有业务都能用简单加法解决，键的设计和聚合语义需要由应用决定。学生可以改变示例的分组键，比较“按词统计”和“按首字母统计”的输出差异。这种变化改变的是问题定义，而不是系统自动理解了自然语言需求。

这份教学示例刻意不规定任务数量、分区策略或运行时间。遇到性能问题应先收集数据规模、键分布、资源配置和执行指标。不能根据这里的三个阶段推导某个版本一定比另一个框架快。检索命中 Map 或 Reduce 时，应继续阅读完整片段，确认它谈的是输入、中间过程还是最终输出，避免把术语相似误当成同一个阶段。
