# 三个学生练习

只使用虚构教学资料；先复制项目到自己的练习目录，不修改教师原件。使用本地模型或 scripted，无付费 API。

## 练习一：新资料与新快照

1. 在练习目录运行 `python -m app.cli snapshot`，保存快照 ID。
2. 在 corpus 新建 UTF-8 Markdown，包含标题、主题、编写日期、版本范围和两段自编课程内容，明确标注教学示例。
3. 再运行 snapshot，比较快照；运行 `python -m app.cli search '你新增的关键词'`，解释命中词与分数。
4. 在网页查看旧记录 E1，确认仍是旧原文。新运行加载新快照；旧运行不会自动更新。

提交：前后快照 ID、一次搜索结果、旧证据仍保持不变的截图。不要把旧 chunk_id 当作跨快照稳定引用。

## 练习二：预算改变轨迹

1. scripted / single 默认预算运行一次，查看成功答案与证据。
2. 保持场景，工具预算设为 1，再运行；比较搜索后是否还有额度读取并回答。
3. scripted / budget 调整工具预算，记录终止状态、工具尝试和未执行提议。

提交：两个 run_id、预算表及解释。预算由后端校验；网页按钮禁用不是执行互斥机制。scripted 是固定响应，不能代表真实模型质量。

## 练习三：承认资料缺口

1. scripted / insufficient 观察 missing_information 和 COMPLETED。
2. 如果 Ollama 可用，在 live 提问“给出某具体版本 Spark 在指定硬件上的精确吞吐量”，当前资料没有这类数据。
3. 展开证据，逐条检查真实回答有无数字编造、结论偏离或引用不足。

提交：问题、答案状态、缺失信息、结论与原文对照。引用校验只验证来源合法性；即使全部 E1 合法，也要人工判断语义支持。Ollama 不可用时完成第一步并说明 live 未测。
