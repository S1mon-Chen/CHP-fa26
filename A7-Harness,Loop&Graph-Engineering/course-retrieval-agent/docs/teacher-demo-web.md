# 第三轮教师演示：看见检索 Agent 的边界（约 18 分钟）

## 课前检查

使用 Python 3.12，按 README 安装，在项目根目录运行 `python -m pytest -q`，然后 `python -m app.web`。打开 http://127.0.0.1:8770/，检查资料集和 Ollama 状态。live 默认模型来自 agent-config.json；使用 `ollama list` 确认已安装。不需要 Docker，不下载模型。

准备投屏，默认预算 8 决策轮、10 工具尝试。确认历史表已有示例记录。没有 Ollama 也能完成下列 scripted 教学；离线回放必须已有完整记录。

## 0—4 分钟：单资料成功

选择 scripted / single，问题填“解释 HDFS 文件块与副本的关系”，开始。强调顶部“预设模型响应与真实工具”。逐项观察模型提议、Harness 校验、工具实际执行。搜索命中有分数但没有证据 ID；读取成功才登记 E1。点击答案 E1 定位完整片段与行号。

提问：搜索结果为什么不能直接登记证据？引用存在是否足以证明结论？

## 4—7 分钟：跨资料与资料不足

运行 compare，比较 Spark 与 Flink 分别读取的证据。再运行 insufficient，观察 COMPLETED 与 insufficient_evidence 同时出现，缺失信息明确列出。这是正常结束，不是系统故障。

提问：真实模型如果漏掉一方资料，应如何进行语义评测？scripted 的问题输入不会改变固定场景逻辑。

## 7—10 分钟：权限决定与实际执行

运行 unauthorized，找到 DOCUMENT_NOT_ALLOWED：调用计入尝试，但卡片显示“未执行”。再运行 injection，说明使用项目虚构 fixture，展示资料中的指令不能获得工具权限。这个受控故障不能证明真实模型永远不受注入影响。

提问：动作提出、批准执行、工具返回分别由谁负责？

## 10—13 分钟：受控结束与答案修复

运行 stalled，观察重复无命中后结束。运行 budget，观察不同无进展搜索耗尽额度。运行 bad_citation，展开 answer_rejected，看到 E99 被拒绝与一次修复。没有读取证据不能直接接受答案。

提问：增加预算一定改善回答吗？为何模型重试与工具预算分开记录？

## 13—17 分钟：历史原文与轨迹

在历史表查看刚才的报告，再从头回放、单步、播放、暂停和调速。指出顶部持续显示“历史轨迹回放”，原始事件时间不变。查看保存的 E1 原文；播放不调用模型、资料工具，也不重读当前 corpus。刷新页面仍能查看相同 run_id。

运行 live 时可刷新页面观察重连；没有 Ollama 时使用 scripted 和完整历史。不要为了展示进度安排虚假动画。

## 17—18 分钟：限制与故障解释

MODEL_ERROR 是模型调用失败；TOOL_ERROR 是工具内部失败；VALIDATE_TOOL 的拒绝是 Harness 按规则拦截。资料不足单独看答案状态。INTERRUPTED 表示后端异常退出留下不完整记录，不支持恢复续跑；CORRUPT 表示完整性校验失败。

没有真实取消按钮。回放暂停不取消任务。正常关闭服务使用启动终端 Ctrl+C，等待当前有限运行结束。课后可运行 `python tests/verify_web_restart.py`，它在临时目录用独立测试进程验证异常退出，不杀当前课堂服务。
