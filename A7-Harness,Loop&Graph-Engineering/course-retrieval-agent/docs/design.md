# 资料层和受限工具的设计

## 数据流与文件分工

`config.json → app/corpus.py → 不可变 Snapshot → app/search.py / app/tools.py → app/cli.py`。
`app/schemas.py` 定义严格参数和结果。所有依赖均本地运行；唯一运行时直接依赖为 Pydantic。没有网络查询、模型、执行代码、网页或 Agent 循环。

## 加载和快照

配置路径由教师掌握，corpus 相对配置文件目录解析。只遍历此目录的 md/txt；其他后缀忽略。目录中的符号链接一律拒绝（包括不支持后缀的链接），根目录和父目录也不得是符号链接。检查真实路径与普通文件；读取错误使用固定脱敏信息。默认单文件 128 KiB、集合 1 MiB，读取单文件最多上限加 1 字节，不依赖可能过时的文件大小。

UTF-8 严格解码，空白文件、缺少元数据和重复 ID 失败，整个加载不部分成功。标题在首行；第 2–8 行包含 `主题：`、`编写日期：`、`适用版本：`，可选 `简介：`。未提供简介时确定性截取开头 100 字符。日期描述的是示例编写日期，不是原官方文档发布日期。

文档 ID 是规范化的相对文件名（去后缀、casefold）的 SHA-256 前 16 位。排序与目录位置不改变 ID，改名会改变。同名 md/txt 拒绝；截短哈希若碰撞也作为重复 ID 拒绝，不静默覆盖。

快照 ID 对固定排序的相对文件名、文档 ID、标题、元数据、实际完整文本和切分格式版本做 SHA-256。不使用绝对路径、mtime 或随机数。以 frozen Pydantic 对象和只读映射保存资料，无源文件路径字段。工具仅读此快照，不重新打开文件。重新 load 才创建新快照；每个独立 CLI 进程会显式 load 一次。在一个 Python 进程中可同时持有旧新快照。

快照是已读取内容的稳定集合，不是文件系统的原子事务。教师加载期间不应同时改写资料目录。本版没有防御恶意本机用户并发替换目录的完整操作系统沙箱；不要允许不可信调用者修改配置或 corpus。资料正文若本身写有路径，那是作者提供的内容；系统不会额外附带宿主文件路径。

## 切分与引用

Markdown 按 ATX 标题（`#` 至 `######`）划节；TXT 不解析标题标记，按段落组织。节内按空行划段，尽量拼接到 600 字符以内。不能跨标题合并，所以元数据节、短小节和末尾片段可能不足 300 字符。正文片段通常约 300–600 字符；字符按 Python Unicode 字符计数，不按 token 或 UTF-8 字节。

超长段落：在接下来的 600 字符内优先取第 300 字符后最后一个句号、问号、感叹号、分号或换行处；没有这些边界则在第 600 字符处切开。分隔符、空格、空行和 Markdown 标记全部保留。依次拼接同一文档片段应逐字重建原文本，不补写标题、不改写正文。

`char_start/char_end` 是原文零起点半开字符区间；`line_start/line_end` 是覆盖该区间的 1-based 行号。一条很长的源文件行可以出现在多个片段的行范围内，此时字符区间给出精确位置。正文保留末尾换行，行号对应有内容或分隔符的原始行。

chunk_id 是快照 ID、文档 ID 与片段序号的 SHA-256 前 24 位。同快照唯一；任何资料变化后，旧片段编号不保证沿用。引用使用 `(corpus_snapshot_id, document_id, chunk_id, content_hash)`。它是引用定位机制，不是事实真实性证明。

本版 Markdown 是简单教学文本，不解析 Setext 标题或 fenced code 的语法树；代码块中以 `# ` 开头的行也会被当作标题边界，但原文仍不丢失。

## 检索和解释

英文/数字/下划线连续串作为词，转小写；中文连续串取相邻双字组，单汉字保留。例如“多版本”产生“多版、版本”，“HDFS 副本”产生“hdfs、副本”。这不是通用中文语义分词，可能有假阳性；但无需词典下载且可逐项解释。停止词由配置给出。

检测到配置中的同义短语，加入其目标词：水位线加入水印、watermark；迟到消息加入迟到数据、late data；行键加入 rowkey。扩展是明确的单向规则。英文词频使用整词边界，中文词或同义短语使用子串次数；查询词去重。

对每个候选片段：

`score = Σ词 [正文出现次数 + 3 × 文档标题出现次数 + 2 × 小节标题出现次数]`

保留在正文中的标题会同时贡献正文分和标题权重，这是公式的明确设计。`term_scores` 展示每词贡献，`matched_terms` 展示非零词，`query_terms` 展示实际查询扩展。检索使用 OR 语义：任一词得分非零即可进入候选，不要求全部词都出现。只命中文档标题也可能返回某个片段，请读取上下文，不要把得分当正确概率。同分按 document_id、line_start、chunk_id 排序，稳定可重现。

snippet 取实际片段里首个命中位置之前最多 35 字符起的 180 字符；只命中外部标题时取开头。绝不生成摘要，也不加伪造文本。空白、纯停用词或零命中返回空结果；空字符串违反最小长度，返回参数错误。

## 权限、类型和输出

`ToolService(snapshot, allowed_document_ids=...)` 在可信构造时冻结可见集合。null 表示全体登记文档，空列表表示一个也不可见。list 只列可见项；search 默认只搜可见项，显式 ID 列表有任一不被允许则整次拒绝；read 先核对文档权限，再核对片段归属。未知文档与未授权文档统一为 DOCUMENT_NOT_ALLOWED，不暴露存在性。来自不可见文档的片段统一当作 CHUNK_NOT_FOUND；仅两个可见文档之间才报告 CHUNK_DOCUMENT_MISMATCH。

工具参数不能传 corpus、权限集合、URL、命令、行号或任意路径。文档 ID 严格匹配 `doc_` 加 16 位十六进制；片段 ID 同理为 24 位。所有参数、结果模型都 extra=forbid、strict=True。注册表固定，无 eval、exec、动态导入。语法合法的未登记 ID 不会触发文件查找。

输出上限按 `json.dumps(result, ensure_ascii=False)` 的 UTF-8 字节数计算，默认 32768。超限返回固定 OUTPUT_LIMIT_EXCEEDED 错误，不截断读取片段，不产生破损 JSON。可信配置最少 256 字节，以容纳错误信封。CLI 的 check/snapshot/schema 属于教师诊断命令，不是三项模型工具；它们不按工具正文输出上限裁剪。

权限只保护本服务的工具调用，不阻止拥有本机文件权限的用户直接读文件。本轮也不宣称解决 Prompt Injection、模型幻觉或所有语义误检问题。
