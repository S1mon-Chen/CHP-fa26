1. `update_state()` 物理覆写机制

State Patching & Node Identity Spoofing

State Overriding Spec
# 1. 获取会话最新的隔离句柄 Config
config = {"configurable": {"thread_id": "ticket_8902"}}

# 2. 人类审批人在打断恢复前，直接更新物理状态字典
app.update_state(
config,
{"refund_amount": 100, "reason": "CS Manager Approved $100 Limit"},
as_node="human_review_node" # 伪装该写操作出自指定节点
)

# 3. 传入 None 原位唤醒，图引擎将读取被人类覆写后的 State 重新计算
app.invoke(None, config=config)
  • 增量覆盖与 Reducer 应用：更新内容与现有快照合并；对于含有 `Annotated[list, add]` 的字段按照归约规则追加。
  • `as_node` 伪装作用：告知图引擎“该状态由指定节点产出”，决定后续条件边（Conditional Edges）的下级跳转分支。
物理本质：建立在持久化 Checkpoint 上的状态强行修改与指针校正

2. 生产场景：大模型生成物的人类二次纠偏

LLM Artifact Revision & Human Safeguard

Hybrid Human-AI
# 场景示例：人类审核并直接修补大模型生成的 SQL 补丁草稿
snapshot = app.get_state(config)
# 发现大模型生成的 SQL 漏掉了 WHERE 索引条件，人类人工修补：
bad_sql = snapshot.values["generated_sql"]
fixed_sql = bad_sql + " WHERE tenant_id = 'prod_01'"

# 将纠偏后的安全 SQL 覆写回 State 字典
app.update_state(config, {"generated_sql": fixed_sql})
# 放行执行物理写数据库节点
app.invoke(None, config=config)
  • 超越二元“批准/拒绝”：人类不仅能点 Approve/Reject，还能直接当编辑（Editor），修补代码、调整参数、校正提示词。
  • 版本快照自动审计：每次 `update_state` 均会生成全新的 `checkpoint_id`，留下人类干预的完整审计履历。
物理本质：人类智慧与大模型自动化推理的高效融合控制通道
