状态分支 Fork 与 What-If 假设推演

构建平行多宇宙决策演练阵地：解构基于历史 Checkpoint 的 State Forking (状态分叉) 机制，通过将已存档快照挂载至全新 thread_id 派生平行分支，实现无毒化对比方案 A/B 演算与对复杂 Task 的 What-If 假设模拟分析

1. State Forking (状态分叉) 机制

Snapshot Spawning & Thread Isolation

Forking Spec
# 1. 抓取主干历史节点的 Snapshot 快照状态
base_config = {"configurable": {"thread_id": "main_branch", "checkpoint_id": "ckpt_step_2"}}
snapshot = app.get_state(base_config)

# 2. 注入全新的 thread_id 派生独立子分支，原主干完好无损
fork_config = {"configurable": {"thread_id": "fork_branch_a"}}
app.update_state(fork_config, snapshot.values)
app.invoke(None, config=fork_config) # 从派生分支独立推演！
  • 绝对物理隔离：派生分支产生的任何工具调用或状态变更均写入全新的 `thread_id`，原主干历史路径不受丝毫不良污染。
  • 版本快照复用：继承选定快照（Snapshot）截至第 N 步的所有上下文、计算中间件与全局状态。
物理本质：建立在关系型/KV Key 索引隔离基础上的状态树分叉技术

2. What-If 假设推演与 A/B 方案比对

Parallel Scenario Testing & Strategy A/B Eval

What-If Eval
# 同时从 Step 2 分叉两条分支，注入不同的假设参数 (What-If)
# 分支 A: 假设提升重试策略与宽松 Prompt
app.update_state(cfg_a, {"strategy": "aggressive", "temperature": 0.7})
res_a = app.invoke(None, config=cfg_a)

# 分支 B: 假设采用保守安全 Prompt 与只读校验
app.update_state(cfg_b, {"strategy": "conservative", "temperature": 0.1})
res_b = app.invoke(None, config=cfg_b)

# 平行评估方案 A 和 B 的产出质量，选优合并！
  • 基准环境绝对对齐：保证方案 A 与方案 B 在分叉前的输入与中间状态 100% 完全一致，得出最客观的评测。
  • 安全无毒沙箱试错：在大规模代码重构或高风险架构决策前，先在平行 Fork 分支中预演推演，零风险选择最优方案。
物理本质：以特定快照为树根节点派生平行决策树（Decision Tree Spawning）

Architectural Core Thesis / 架构师视角

State Forking 将单线推理升维为多分支决策树！通过从指定快照点派生独立 thread_id，架构师能够实现平行的 What-If 假设推演与 A/B 策略比对，在完全隔离的安全分支中寻找最优质决策路径。

Speaker Notes / 讲师讲稿
🎯 讲授 State Forking (状态分叉) 机制： “向学员深入剖析：上一页我们学习了 Time Travel，即沿着主干往前或往后重放。但在复杂的商业决策或代码重构中，我们往往不希望把原主干数据给覆盖掉，而是希望能派生出一个平行分支进行试错——这就是 State Forking。”
💡 强调 What-If 假设推演的价值： “提示学员看右侧代码：我们可以读取第 2 步的快照，赋予一个全新的 `thread_id="fork_branch_a"`。在这个分支里，我们可以修改参数（如把策略改为激进或保守），让它独立推演后半段。原主干 `main_branch` 的快照树不会受到任何污染，最后比对两条分支的结果，择优应用即可。”
