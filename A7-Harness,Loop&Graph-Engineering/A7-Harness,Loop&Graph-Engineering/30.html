2. 生产级多 Agent 蜂群 5 大红线法则

5 Swarm Production Architecture Redlines

5 Redlines
1. 坚持微型 Agent 专有化 (Micro-Agent Specialization)

拒绝全能通用 Agent；单个 Agent 的工具注入不得超过 5 个，保持极其干净的专属 Prompt。

2. 强制状态隔离写回 (Isolated State Boundaries)

子 Agent 的思考与代码草稿禁止泄露至全局 State；仅通过 Reducer 归约写回核心产物。

3. 严禁盲目采用无中心 P2P 自由交接 (Explicit Handoff)

严肃工程系统首选 Supervisor 或 Hierarchical 拓扑；仅在受限分诊流中使用 P2P Handoff。

4. 必须挂载外层死锁熔断器 (Ping-Pong & Budget Guards)

配置 `swarm_loop_guard` 监控乒乓死锁（A-B 循环）与全局 Token 费用配额，超标强杀降级。

5. 跨语言解耦采用强类型 DTO 消息契约 (Schema Decoupling)

异构蜂群通过 JSON/Pydantic `CrossAgentMessage` 与 Redis/RabbitMQ 事件总线解耦网关。

Architectural Core Thesis / 架构师视角

多智能体蜂群的本质是分而治之，而不是混乱的群体辩论！通过严格的拓扑选择（Supervisor/Hierarchical）、专有化微型 Agent 设计、隔离状态树与硬性 swarm_loop_guard 熔断器，架构师能将复杂的协同网络控制在确定性与高吞吐的安全边界内。
