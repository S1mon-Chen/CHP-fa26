角色扮演与辩论对齐 (Role-Play & Multi-Agent Debate)

消除单 Agent 的自确认偏见 (Confirmation Bias)：解构 Coder、Tester 与 Reviewer 之间的多视角 对抗性辩论 (Adversarial Debate) 控制流，结合隐式 状态共识卡扣 (Consensus Gate) 与收敛轮次限制，将概率推演转化为确定性质量治理

1. 单 Agent 认知盲区与角色对抗

Confirmation Bias Elimination & Adversarial Personas

Role Specialization
自确认陷阱
单 Agent 既当裁判又当运动员： 大模型在审查自己刚写的代码时存在强烈盲区，难以主动发现越界边界条件或安全漏洞。
三角辩论
分工明确的三角对抗阵容： Coder (注重功能实现)、Tester (寻找边界崩溃条件)、Reviewer (OWASP 安全与规范评估)。
证据驱动
拒绝空口质问，物理证据说话： Reviewer/Tester 抛出否定必须附带反例 TestCase 或具体 Traceback，迫使 Coder 针对性修补。
物理本质：用多视角概率相互约束纠偏代替单一 LLM 的主观臆断

  • 单向否定打回机制：只要 Reviewer 评估出任何 `CRITICAL` 漏洞，流程自动回退给 Coder Agent。
  • 死锁防线熔断（Adjudicator）：当辩论超过 3 轮仍无法统一时，强行路由至 `human_adjudicator` 进行人工判定。
物理本质：把非确定性的观点质问收敛在带有轮次上限与全绿卡扣的状态环中

Architectural Core Thesis / 架构师视角

引入角色扮演与对抗性辩论 (Debate) 能够将单一 Agent 的概率性自我怀疑打造成确定性的代码质量门控！通过 Coder、Tester 与 Reviewer 的多视角碰撞与严格的共识判定卡扣 (Consensus Gate)，能在进入生产前消除 99% 以上隐蔽的逻辑与安全缺陷。
