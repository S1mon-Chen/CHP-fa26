死循环与图环死锁控制：recursion_limit 与动作指纹防线

阻断非确定性推理的无限震荡死锁：建立图运行时的双重物理防护网——通过图编译层 recursion_limit 硬性步数强杀 兜底，配合状态层 动作指纹 (Action Fingerprinting) 实时捕获重复非法调用并强行切入降级路由

1. 全局递归深度限制 (recursion_limit)

Step Budget Counter & Hard Execution Interrupt

Hard Limit
# 在 app.invoke / stream 执行层挂载硬性步数预算
config = {"recursion_limit": 10}
try:
res = app.invoke(inputs, config=config)
except GraphRecursionError:
# ❌ 触发硬强杀：停止生成并抛出死锁异常
logger.error("Recursion limit 10 reached! Trapped in loop.")
  • 账单熔断断路器：设定单次 Graph 调用的最大步数上限（如 10~25 步），硬性隔绝无限循环引发的 API 巨额账单刺客。
  • 框架级安全保底：不依赖 LLM 自觉收敛，从控制流引擎底座赋予物理强杀能力。
物理本质：图运行时的最后一道粗暴但绝对可靠的硬性止损阀门

2. 动作指纹去重 (Action Fingerprinting)

Semantic Hash Deduction & Loop Interception

Smart Intercept
# 计算当前节点与其工具入参的 SHA-256 哈希指纹
def calc_action_fingerprint(node_name: str, args: dict) -> str:
raw = f"{node_name}:{json.dumps(args, sort_keys=True)}"
return hashlib.sha256(raw.encode()).hexdigest()

# 滑动窗口检测：若连续 3 次指纹完全一致，认定为无效震荡
if state["recent_fingerprints"].count(fp) >= 3:
return "human_approval_node" # 优雅切入人工审批
  • 语义级震荡识别：当 LLM 陷入用相同错误参数反复尝试同一工具的窘境时，第一时间捕获指纹重复。
  • 优雅降级而非崩溃：相比 `recursion_limit` 的抛错中断，指纹去重能提前将状态路由至自愈或人工干预节点。
物理本质：基于计算哈希的图状态机动态自愈与降级防护切面

Architectural Core Thesis / 架构师视角

任何允许图环（Loop）存在的系统，都必须在控制流最外层挂载物理熔断器！通过 recursion_limit 绝对保底和动作指纹 (Action Fingerprinting) 语义去重，可以在第一时间截断震荡死锁，保护系统架构与企业财务安全。
