状态树管理：全局共享 State 与子 Agent 隔离 Sub-State

防范蜂群协同中的上下文污染与内存爆表：解构 Global Shared State (全局共享状态) 与 Sub-Agent Isolated State (子智能体隔离状态) 的物理分界，通过受控的归约导出（Reducer Merge）实现多 Agent 清洁协同

1. 全局状态与子状态物理边界

Global State vs Sub-Agent Scratchpad

State Boundary
Global State
单源真理 (SSOT) 共享核心： 仅保存高阶工单 ID、全局目标、最终产物（Final Patch）及当前激活 Agent 指针，保持极轻量。
Sub-State
专业子智能体私有草稿箱： Coder/Tester 内部推演产生的临时 AST、中间 Linter 调试信息及单测堆栈；执行完毕后由引擎销毁。
Benefit
彻底消除 Agent A 与 B 间的相互干扰： 防止 Coder 的大量代码草稿直接挤爆 Tester 的 Prompt 上下文。
物理本质：建立在树状作用域（Scope Scoping）基础上的增量归约机制

2. 状态树定义与映射归约代码

LangGraph / Swarm Sub-Graph State Mapping

Python Typing
# 1.1 全局 Shared State (瘦身主干)
class SwarmGlobalState(TypedDict):
ticket_id: str
user_query: str
final_patch: str | None # 仅保存子 Agent 最终落盘的核准成果

# 1.2 开发者 Coder Agent 专属私有 Sub-State
class CoderLocalState(TypedDict):
ast_tree: dict # 语法树
scratchpad_diffs: list[str]# 临时修改草稿

# 1.3 子图运行结束时只向 Global State 归约写入经过核准的 final_patch
def coder_to_global_reducer(local: CoderLocalState) -> dict:
return {"final_patch": local["scratchpad_diffs"][-1]}
  • 归约映射器 (State Mapper/Reducer)：子图结束时仅抽取受调和字段，丢弃私有 scratchpad 废弃日志。
  • 提升单测可维护性：子 Agent 可以针对自身的 `CoderLocalState` 编写独立的模拟测试。
物理本质：用局部变量与全局变量的作用域分界阻止 Context Window 级联泄漏

Multi-Agent State Tree Isolation & Reducer Pipeline / 状态树隔离与归约写回拓扑

State Tree Topology
1. Swarm Global State
Lightweight Master SSOT
2. Spawn Sub-Agent
Initialize `CoderLocalState`
3. Local Reasoning Loop
Generate AST & Run Linters
4. Reducer Merge
Write final_patch to Global

Architectural Core Thesis / 架构师视角

不要把所有子智能体的草稿都塞进同一个全局 State！通过严格限定 GlobalState 仅保存核心目标与结果，并将子智能体的推演约束在私有的 SubState 中，能够在极度繁复的多智能体协同中实现上下文 Slimming 与数据的绝对清洁。

Speaker Notes / 讲师讲稿
🎯 剖析多智能体状态隔离的核心痛点： “向学员深入剖析：在使用 Multi-Agent 架构时，最容易踩坑的就是让所有 Agent 共享同一个长 Message 数组或大型字典。如果 Coder Agent 生成了 500 行中间 AST 代码，而后端 Reviewer 不需要看这个 AST，如果直接传过去，就会导致 Reviewer 的上下文爆表，甚至干扰其判断。”
💡 强调归约映射（State Reducer Mapper）： “提示学员看右侧代码：我们定义了 `SwarmGlobalState`（只存 `ticket_id` 和 `final_patch`）以及 `CoderLocalState`（存 `ast_tree` 和 `scratchpad_diffs`）。通过 `coder_to_global_reducer` 函数，在子图推演结束时，仅提取最新的 `final_patch` 写入全局状态。这在软件工程里就是标准的‘局部变量与全局变量的作用域分界’。”
