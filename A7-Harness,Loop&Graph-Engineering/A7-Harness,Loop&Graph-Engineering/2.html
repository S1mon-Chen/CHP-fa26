为什么 DAG 无法满足 Agent？从无环图向有向有环图 (DCG) 的演进

突破单向数据管道的限制：剖析传统 DAG (有向无环图) 在非确定性任务中的脆断风险，以及行业为何全面转向以 LangGraph 为代表的 DCG (有向有环图) 来构建具备回溯、修正与反射 (Reflexion) 能力的自愈 Agent

DAG (有向无环图) 的脆性瓶颈

Directed Acyclic Graph (Airflow / Prefect)

No Retries
// 传统 Pipeline：单向流水线执行
Step 1: Write Code
Step 2: Run Tests ──► Error: SyntaxError!
// ❌ 管道崩溃退出，无法退回 Step 1 重新生成
Pipeline Failed.
  • 单向执行假定：DAG 假定上游任务永远成功并向下游传递数据，不支持节点指针逆向返回。
  • 无法支持自我修正 (Reflexion)：Agent 往往需要“生成代码 $\to$ 运行报错 $\to$ 分析错误 $\to$ 重新生成”，这在拓扑上是一个明显的闭环 (Loop)。
物理事实：DAG 适合确定性的 ETL 管道，但不适合充满试错的非确定性大模型推理

DCG (有向有环图) 与自愈系统

Directed Cyclic Graph (LangGraph)

Loops Allowed
// DCG：允许条件边指回历史节点
Node A: Write Code
Node B: Run Tests ──► Error!
Edge Logic: If Error -> Route back to Node A
// ✅ Node A 根据报错日志重新生成
Node B: Run Tests ──► Success! ──► Route to END
  • 原生状态循环 (State Loops)：允许图中的边 (Edges) 指向已经执行过的节点，从而在逻辑上形成图环。
  • 错误即反馈 (Error as Feedback)：测试失败不再导致系统崩退，而是作为 `Observation` 注入状态字典 (State)，循环回大脑重试。
定位：有向有环图是实现 ReAct 循环、多 Agent 辩论与自我纠偏的结构基石

Architectural Core Thesis / 架构师视角

有向有环图（DCG）是实现 Agent 自动化重试、试错与自我进化（Reflexion）的物理数学基础。大语言模型的输出在本质上是非确定性的（Non-deterministic），如果用确定性的单向 DAG 去承载非确定性的推理，系统注定会极其脆弱。引入图环（Cycles），才能让错误变成反馈，让系统走向韧性。

Speaker Notes / 讲师讲稿
🎯 剖析 DAG 在 Agent 场景下的失效： “向学员深入解释：在传统的数据工程中（比如 ETL 或者是早期的 LangChain Chains），我们习惯了用 DAG（有向无环图）来建模。任务 A 做完给任务 B，B 做完给 C。但在 AI Agent 的真实世界里，模型生成代码是有概率出错的。一旦出错，DAG 就会直接崩溃退出，无法满足自愈需求。”
💡 DCG 图环的物理意义： “引导学员看下方的拓扑图对比：右侧的 DCG 允许一个向回指的箭头。这就意味着，当我们在 Eval 节点发现测试不通过时，我们可以将报错信息塞进 State，然后让状态流环回溯到 Write 节点。这就是 ReAct 循环和 Reflexion 自我修正机制在数学层面上的底层表达。”
