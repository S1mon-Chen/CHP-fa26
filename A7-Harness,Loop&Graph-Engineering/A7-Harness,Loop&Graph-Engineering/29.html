主流多 Agent 框架对比：LangGraph Swarm vs AutoGen vs CrewAI

建立企业级多智能体系统的技术选型坐标系：横向剖析 LangGraph (图状态机与强控制)、AutoGen (事件驱动与 Actor 模拟) 与 CrewAI (角色扮演与流水线) 在状态持久化、控制粒度与生产可控性上的物理权衡

1. LangGraph / Swarm

Explicit State-Machine Swarm

Production Ready
# 显式状态图 + Handoff 工具模式
builder = StateGraph(SwarmState)
builder.add_node("coder", coder_agent)
builder.add_conditional_edges(...)
app = builder.compile(checkpointer)
  • 强确定性控制与持久化：基于离散 State Graph 编排，原生支持 Checkpointer 状态存盘与时光旅行。
  • 极高工程门槛与灵活性：代码级掌控每一个 Edge 与 Reducer，没有任何黑盒隐藏逻辑。
定位：严肃企业级工程、需要强合规审计与打断恢复的生产系统

2. Microsoft AutoGen

Actor-Based Conversational Agents

Actor / Chat
# 基于 Actor 模型的多 Agent 对话组网
user_proxy = UserProxyAgent(...)
assistant = AssistantAgent(...)
group_chat = GroupChat(agents=[...])
manager = GroupChatManager(group_chat)
  • 强大的多角色自由对话：基于事件驱动与 Actor 消息传递，极度适合复杂辩论与自由协商。
  • 控制流较难预测：在多轮 GroupChat 中控制流容易漂移，不容易限制绝对路径收敛。
定位：多角色自由辩论演练、复杂仿真与研究型多智能体系统

3. CrewAI

Role-Playing & Task Pipeline

Role & Process
# 声明 Role、Goal、Task 与 Process
researcher = Agent(role='Senior Researcher')
task1 = Task(description='...', agent=researcher)
crew = Crew(agents=[...], tasks=[...], process=Process.sequential)
crew.kickoff()
  • 极快的 POC 开发速度：拟人化 Role/Goal/Backstory 建模，几行代码快速搭建流水线。
  • 缺乏复杂的图环控制：主要依赖 Sequential / Hierarchical 线性任务链，处理复杂的图环自愈较为吃力。
定位：快速业务原型 POC、固定的角色协作团队与内容生成工作流

Architectural Core Thesis / 架构师视角

根据业务严肃性与状态可控性决定框架选型！对于需要强事务管理、中断恢复与可追溯性的严肃工程系统，首选 LangGraph / Swarm；对于多角色自由碰撞与辩论模拟，选择 AutoGen；对于快速搭建特定角色的团队敏捷 POC，选择 CrewAI。
