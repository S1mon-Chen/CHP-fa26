解决代码执行物理破坏风险与非确定性推理的评估难题：解构如何通过 MicroVM 安全隔离沙箱 (E2B / Modal) 与 确定性测试 Harness 构建安全运行与自动化 Pass@k 质量度量 演进管道

1. 未隔离代码执行的破坏性物理风险

Arbitrary Code Execution Hazards & Isolation Need

Execution Risk
# ❌ 试图在宿主机直接运行 AI 生成的代码：
code = llm_response.extract_code()
exec(code) # 危险至极！可能触发 rm -rf / 或读取宿主环境变量

# 💥 物理悲剧威胁：
1. 删库与文件系统清空 (Data Destruction)
2. 泄漏物理服务器 AWS_KEY / 环境变量 (AK/SK Leak)
3. 无限循环死锁榨干物理 CPU/RAM (Resource Exhaustion)
  • 完全零信任假设：在 Coding Agent 场景中，生成的任意代码均必须假设存在语法缺陷、恶意注入或死循环。
  • 需要秒级用后即焚：测试完成后环境必须瞬间物理销毁，防范脏状态残留与跨任务污染。
物理事实：离开隔离沙箱运行生成的代码在企业级生产环境属于绝度禁止的裸奔

2. Agent 测试 Harness 三大核心支柱

3 Pillars of Deterministic Agent Test Harness

Harness Pillars
1. 沙箱隔离
安全物理执行沙箱 (MicroVM Sandboxes)： 依托 E2B、Modal 或 Firecracker MicroVM 提供毫秒级启动、用后即焚的全新 Linux 运行环境。
2. 副作用 Mock
外部副作用 Mock 拦截器 (Side-Effect Mocking)： 拦截写 DB/扣费等外部调用，替换为录制好的稳定回放响应，确保测试过程 100% 可重复。
3. Pass@k 评测
确定性评估指标 (Deterministic Eval Metrics)： 结合 `pytest` 单测通过率输出 Pass@k、轨迹步数与 Token 成本，量化 Agent 性能演进。
物理本质：把非确定性的推理转化为可重现、可量化的标准化软件工程测试管道

Architectural Core Thesis / 架构师视角

沙箱解决物理安全问题，测试 Harness 解决非确定性评估与质量退化难题！通过将 Agent 生成的代码置于 MicroVM 沙箱（E2B/Firecracker）中运行，并用固定的 Mock 响应与 Pass@k 指标搭建测试 Harness，架构师能为智能体系统建立高确定性的工程演进底座。
