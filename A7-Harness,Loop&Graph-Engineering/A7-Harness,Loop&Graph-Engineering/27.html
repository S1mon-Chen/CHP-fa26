1. 蜂群死锁风险与三重物理防线

Swarm Oscillation, Cost Storms & 3 Safeguards

Swarm Safeguards
Max Turns
全局 Swarm Turns 硬性上限： 限制整网 Agent 间交接总步数（如最多 15 次 Handoffs），防止跨角色无限递归触发。
Ping-Pong Guard
乒乓死锁交接检测 (Ping-Pong Detection)： 若检测到 Agent A 与 Agent B 连续交接超过 3 次（如 `Coder -> Reviewer -> Coder -> Reviewer`），判定为无效震荡。
Token Budget
硬性 Token 费用配额强杀： 全网累计消耗超过指定配额（如 50,000 Tokens）时，直接切断 LLM 调用，原位触发 `human_adjudicator`。
物理本质：多 Agent 系统非线性爆炸风险下的确定性安全熔断器

def swarm_loop_guard(state: SwarmGlobalState) -> str:
tokens_used = state["total_tokens"]
swarm_turns = state["swarm_turns"]
handoff_history = state["handoff_history"]

# 1. Token 硬性配额配额拦截
if
tokens_used >= 50000:
return "human_adjudicator" # 触发 Token 预算物理强杀！

# 2. Ping-Pong 死锁交接检测
if
handoff_history[-6:] == ["coder", "reviewer"] * 3:
return "human_adjudicator" # 捕获 A-B 乒乓死锁循环！

return "next_swarm_agent"
  • 前置防线保护：在分发给下一个 Agent 前触发 `swarm_loop_guard` 评估，消除无感知的持续扣费。
  • 降级至人工裁决：触发死锁后不抛抛错崩溃，而是优雅降级路由至 `human_adjudicator` 进行介入。
物理本质：用计算哈希与配额统计建立的多智能体死锁防线

Architectural Core Thesis / 架构师视角

多 Agent 蜂群系统的死锁风险与资源消耗远高于单 Agent！架构师必须在蜂群控制流的最外层挂载物理熔断器（swarm_loop_guard），结合乒乓交接死锁检测 (Ping-Pong Detection) 与 Token 费用配额硬锁，方能防止系统陷入无休止盲目辩论带来的财务暴雷。
