离散节点设计模式：LLM 节点、Tool 节点、Data 节点与 Guard 节点

遵循单一职责原理 (SRP) 解耦图计算：将大杂乱函数解构为只读推理的 LLM Node、知识检索的 Data Node、物理改变系统的 Tool/Action Node 与合规风控拦截的 Guard Node

Reasoning

1. LLM Node (推理节点)

Pure Reasoning / Prompt Assembly

// 仅做概率推理与 JSON 输出
def reasoning_node(state):
prompt = build_prompt(state)
res = llm.invoke(prompt)
return {"intent": res.intent}
  • 单一职责：仅做文本生成、意图分类与 ReAct 计划推演。
  • 零副作用：绝不直接发起写 DB、网络请求或执行代码。
物理本质：纯推理计算单元
Read-Only

2. Data Node (数据检索)

RAG / AST / Vector Store

// 只读知识库与 AST 提取
def rag_search_node(state):
query = state["email"]
docs = vector_db.search(query)
return {"chunks": docs}
  • 只读隔离：负责向量库检索、代码 AST 结构抽取与数据库查表。
  • 开销隔离：把耗时的向量匹配独立开来，便于独立挂载缓存 Cache。
物理本质：无副作用数据抽回器
Side-Effect

3. Action Node (动作节点)

DB Write / API / E2B Sandbox

// 物理写操作与外部改变
def apply_patch_node(state):
patch = state["patch"]
res = sandbox.exec(patch)
return {"executed": True}
  • 物理副作用：专门管辖写 DB、提 PR、发邮件或在沙箱跑代码。
  • 卡扣审计：所有的系统状态修改动作均收敛在此类节点进行严格监控。
物理本质：物理状态变更执行器
Safety Gate

4. Guard Node (风控节点)

PII Redact / RBAC / Rate Limit

// 合规校验与物理拦截
def guard_check_node(state):
if state["amount"] > 1000:
raise PolicyViolationError()
return {"safe": True}
  • 物理拦截闸门：执行 PII 脱敏、RBAC 越权拦截与高危操作限额校验。
  • 安全解耦：由安全/风控团队统一维护，独立于业务 LLM 代码之外。
物理本质：确定性物理安全防火墙

Architectural Core Thesis / 架构师视角

严格区分只读节点（Data/LLM）与副作用节点（Tool/Guard），是构建高鲁棒性状态图的第一步！单一职责解耦不仅大幅降低单测门槛，还能让安全团队专门对 Guard 节点施加物理硬拦截，彻底隔绝越权风险。

Speaker Notes / 讲师讲稿
🎯 剖析离散节点拆解的核心痛点： “向学员深入剖析：在早期的代码写法中，大家习惯把写 Prompt、调大模型、查数据库、调工具全部塞在一个巨大的 `run_agent()` 函数里。这种大混杂导致代码根本无法编写单元测试，一旦工具报错整块崩溃。”
💡 强调 4 类离散节点与只读/写分离： “提示学员注意 4 类节点的职责：Data 节点只读查向量库，LLM 节点只读算推理，Guard 节点只读跑校验，Tool 节点才真正产生系统修改（副作用）。这种读写分离让安全团队可以把防护重点集中在 Guard 与 Action 节点上。”
