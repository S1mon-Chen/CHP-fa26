会话隔离与句柄设计：thread_id、checkpoint_id 与 Config 注入

建立多租户高并发场景的强隔离防御句柄：解构基于 thread_id 长生命周期会话逻辑隔离、checkpoint_id 点对点版本快照定位 与运行时 Config 配置字典物理注入 的状态管理体系

1. 三级句柄标识隔离体系

Multi-Tenant Handle Identification Architecture

Handle Spec
thread_id
长生命周期会话句柄 (Session Key)： 唯一标识特定用户或工单主线（如 "ticket_8901"），隔离物理多租户状态。
checkpoint_id
步骤版本快照句柄 (Step Snapshot ID)： 标识当前 `thread_id` 内某一确定节点完成后的快照 UUID，用于回溯与时光旅行。
checkpoint_ns
子图嵌套命名空间 (Namespace Isolation)： 用于在嵌套子图（Sub-graph）中隔离父图与子图私有 Checkpoint 存储路径。
物理本质：防止高并发租户间 State 相互穿透与写冲撞的核心元数据强契约

2. Runtime Config 句柄注入代码规范

RunnableConfig & Point-in-time Reading

Python Injection
# 1. 构造三级隔离 RunnableConfig 运行时配置
config = {
"configurable": {
"thread_id": "usr_session_9021", # 会话组隔离
"checkpoint_id": "1ef5a8b2-3c81-...", # 指定版本
"checkpoint_ns": "subgraph_billing" # 子图命名空间
}
}

# 2. 携带 Config 注入发向图推演或读取历史状态
state_snapshot = app.get_state(config)
app.invoke(inputs, config=config)
  • 复合主键检索（Composite PK）：Checkpointer 底层以 `(thread_id, checkpoint_ns, checkpoint_id)` 复合主键强校验数据。
  • 无缝挂钩 HTTP Header：在 Web 接口层直接将请求头的 `X-Thread-ID` 转化为 Config 字典透传给图引擎。
物理本质：把无状态的通用计算图与特定用户的特定历史快照绑定的控制中枢
