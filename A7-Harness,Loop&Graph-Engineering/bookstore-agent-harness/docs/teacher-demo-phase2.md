# 第二阶段教师演示：18 分钟

## 课前检查

1. 启动 Docker Desktop 和 Ollama。项目虚拟环境中执行 `python -m pip install -e ".[test]"`。
2. 确保镜像存在。若需构建：`docker build --build-arg BASE_IMAGE=public.ecr.aws/docker/library/python:3.12-slim -t bookstore-harness:py312 .`。
3. 执行 `python -m pytest -q`；启动 `python -m harness.web`，打开 http://127.0.0.1:8765。
4. 网页选择 scripted 并点击“检查依赖”；选择 live，确认模型名称与 `ollama list` 一致，再检查依赖。
5. 课前各运行一次四种 scripted 场景，留好历史记录。准备展示时选择 replay，避免依赖临场模型生成速度。
6. 建议投屏使用 1440×900 或更大分辨率；可适当放大浏览器。网页只有本地资源，无 CDN。

## 0–3 分钟：业务规则与执行边界

打开“实际任务说明”。让学生计算 100 元购物车、使用 SAVE10 的 100 元购物车，以及空购物车的结果。解释 Decimal 和“先折扣、舍入，再计算运费”。展示“初始代码”中的 `>`。

提问：模型能修改测试，把失败变成通过吗？页面上谁负责校验目标文件？指出允许的 `bookstore.py` 和禁止修改的测试/Harness。

## 3–7 分钟：成功修复

选择 scripted → 成功修复，预算 3，**不勾选模拟结果**，开始运行。当前模式应为“预设响应演示”；TEST 观察是本次真实 Docker 测试。

运行完成后“从头开始”，选择慢速自动播放，或者逐步点击。注意：这时标签会改为历史轨迹回放。依次观察 GENERATE → VALIDATE → APPLY → TEST，第 1 轮 3 个边界失败；反馈后第 2 轮代码 diff 将 `>` 改为 `>=`，29 项通过。展开测试输出和事件详情，查看每轮候选编号及哈希。

提问：语法校验通过为什么不能直接 SUCCESS？哪条观察使 Harness 决定进入下一轮？

## 7–10 分钟：重复失败和预算结束

切回 scripted → 重复错误，预算 3。观察相同哈希与相同失败摘要，第 2 轮 STALLED，仍有 1 次候选预算。

再运行预算耗尽场景，预算 3。每轮候选的运费阈值都不同，哈希不同但仍错，最终 FAILED，剩余预算为 0。

提问：STALLED 和 FAILED 有什么区别？为什么只有失败摘要相同还不够判定重复补丁？

## 10–12 分钟：Harness 拦截

选择违规修改。查看候选请求路径为测试文件、标记“已拒绝”、拦截原因。轨迹没有 APPLY 或 TEST，最终预算耗尽。

提问：这是业务测试失败吗？应定位模型提出的动作，还是 Docker？被拒建议只是保存为 JSON，不会执行。

## 12–15 分钟：真实模型与可靠记录

切换 live，配置本地已安装模型，点击检查依赖后开始。观察 GENERATE 等待真实模型调用，状态不是定时动画。可刷新页面确认活动 run_id 和 SSE 事件仍能恢复。

模型结果不保证每次相同。以 TEST 观察和 summary 为准；模型调用重试耗尽是 MODEL_ERROR，容器超时、输出上限和基础设施问题是 EXECUTION_ERROR，非法动作是 VALIDATE/rejected，业务断言失败是 TEST/test_result 后的反馈。

不展示或要求模型内部思维链，只展示建议、控制规则和工具反馈。

## 15–18 分钟：历史轨迹回放

选择历史成功记录，查看报告，再“从头开始”。演示下一步、自动播放、暂停、速度切换和滑动进度。核对事件时间：播放变慢不会改动原始时间。

从列表选择第一阶段旧记录。缺失的退出码、测试计数和耗时显示“未提供”，不能用猜测补齐。记录来自模拟执行时，页面应同时标明历史记录和模拟来源。

提问：回放看到 29 passed 能否证明本次重新测试通过？为什么关闭网页不会取消后端运行？

## Ollama 或 Docker 不可用时

先用历史区选择课前录制，或模式 replay → 选择历史 → 开始。该路径不调用模型、不执行 Docker、不做依赖探测。

也可以显式勾选 scripted 的“模拟工具结果”，展示控制流。必须说明模型响应和工具结果均为预设；不要将它当成真实测试证据。Docker 不可用但未勾模拟时，启动会明确被拒，不会在宿主机执行代码。

本阶段没有可靠取消机制，因此不提供停止按钮。结束课堂前等待活动运行完成，再在服务终端 Ctrl+C。
