第 4 讲课程总结与核心架构心法

gRPC IPC Performance, GraphQL Declarative Query, WebSocket Full-Duplex & SSE AI Streaming Summary

1. gRPC & Protobuf IPC Benchmark

底层采用 HTTP/2 多路复用 解决队头阻塞；上层结合 Protobuf TLV 二进制压缩，消除了文本 Key 冗余，是数据中心内部微服务高频互调的极致吞吐底座。

核心关键点：
• 4 种 RPC 模式 (Unary / Stream)
• `.proto` 强类型接口契约
• Spring gRPC Starter 容器化
定位：内网微服务超级管道
2. GraphQL 声明式 API Client-Driven

打破传统 REST 端点约束，颠覆为 “提问即结构 (Ask what you need)”。前端在单次 1 RTT 网络往返中精准索取复杂嵌套数据，彻底消除了 Over/Under-fetching 缺陷。

核心关键点：
• Schema SDL 类型驱动
• Queries, Mutations, Fragments
• Spring `@BatchMapping` 降维 N+1
定位：多端聚合极速交付
3. WebSocket & STOMP Full-Duplex TCP

借道 HTTP 101 Switching Protocols 建立持久全双工 TCP 管道。结合上层 STOMP 消息子协议 与 Kafka/Redis Pub/Sub 广播总线，实现高并发即时长连接。

核心关键点：
• JSR 356 注解与消息 Encoder
• SockJS 跨浏览器透明降级
• Kafka 跨节点 Session 广播
定位：全双工高频即时交互
4. SSE & AI LLM Stream TTFT < 200ms

基于标准 HTTP `text/event-stream` 单向流。在大模型生成式 AI 时代，以 Token-by-Token 增量推流将用户感知首字延迟 (TTFT) 从 10s+ 瞬间降低至 200ms 以内。

核心关键点：
• 原生断线自动重连 (`Last-Event-ID`)
• Spring AI `Flux`
• JS `ReadableStream` 打字机 UI
定位：AI 时代流式推送标准
现代服务端通信架构四大金律 (4 Architecture Golden Rules) Architectural Philosophy
律一：边界分明 (Boundary Isolation)

数据中心**内部微服务间 IPC 高频通信，坚定选用 gRPC**，享用 Protobuf 极速序列化；**面向外网及三方开发者，保留标准 RESTful/OpenAPI 契约**。

律二：图按需取 (Ask What You Need)

多端（Web/App/MiniProgram）复杂聚合视图场景下，**引入 GraphQL 统一网关**解耦前端UI变更，后端务必**挂载 DataLoader (`@BatchMapping`)** 压平数据库查询开销。

律三：长联按需 (Full-Duplex for Interactive)

只有在**高频双向实时数据交错**（IM 聊天、协同画布、竞技游戏）时才引入 WebSocket，并在分布式集群中引入 **Kafka / Redis Pub/Sub 广播总线**解耦 Session 记忆。

律四：单向选 SSE (Keep Streaming Simple)

凡是**服务端单向推流场景（如大模型 AI 流式输出、控制台日志、任务进度条）**，绝不盲目使用 WebSocket，**优先选择轻量级 SSE**，充分享受 HTTP/2 多路复用与零 Session 治理红利。

第 4 讲总结展望 (Lecture 04 Wrap-up)

从 REST 的单一请求-响应模式，演进为 **gRPC、GraphQL、WebSocket 与 SSE 构成的四维高阶通信体系**。掌握每种协议背后的底层原理与工程落地，是构建现代高并发、低延迟服务端系统的必备功底。
