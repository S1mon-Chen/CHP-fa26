1. SockJS 传输协议平滑降级与客户端生命周期 SockJS & STOMP.js

在复杂真实网络（旧版浏览器、受限公司防火墙、拦截 101 Upgrade 响应的代理）中，原生 WebSocket 可能握手失败。**SockJS** 提供了透明的传输协议**平滑降级链 (Fallback Chain)**，确保长连接的高可用性。

① SockJS 传输降级三阶梯 (Transport Priority) Graceful Degradation
1. WebSocket
原生全双工
2. HTTP Stream
XHR / EventSource
3. Long Polling
XHR Polling 兜底
② STOMP.js 客户端订阅与心跳侦测 (Heartbeats) Subscriptions

客户端握手成功后调用 stompClient.subscribe('/topic/...') 向 Broker 注册订阅标记。STOMP 客户端会定期发送空 Ping/Pong 字符帧检测 TCP 死链，发生网络拥堵时可自动触发重连机制。

③ 用户私聊队列订阅规范 (`/user/queue/...`) P2P Routing

接收点对点私信时，前端只需订阅固定前缀 /user/queue/messages。Spring 底层会自动将其与握手身份关联，转换为用户独享的 Session 隔离通道（如 `/user/session123/queue/messages`）。

前端最佳实践：SockJS 封装抹平了网络环境差异，前端 API 保持绝对统一
2. STOMP 客户端 JavaScript 代码实现 (`app.js`) SockJS + STOMP.js
① 连接挂载、全局订阅与断线重连 (`app.js`) Stomp.over(socket)
let stompClient = null;
function connect() {
// 1. 使用 SockJS 初始化降级端点（匹配后端 addEndpoint("/ws-stomp")）
const socket = new SockJS('/ws-stomp');
stompClient = Stomp.over(socket);
// 2. 配置心跳间隔与连接回调
stompClient.heartbeat.outgoing = 10000; // 10s 发出心跳
stompClient.connect({}, function (frame) {
console.log('Connected: ' + frame);
// A. 订阅广播 Topic (/topic/public)
stompClient.subscribe('/topic/public', function (msg) {
const body = JSON.parse(msg.body);
showBroadcastMessage(body);
});
// B. 订阅个人专属私聊 Queue (/user/queue/messages)
stompClient.subscribe('/user/queue/messages', function (msg) {
const privateMsg = JSON.parse(msg.body);
showPrivateMessage(privateMsg);
});
}, function (error) {
console.error('STOMP error, reconnecting in 5s...', error);
setTimeout(connect, 5000); // 自动指数退避重连
});
}
// 3. 发送消息到服务端入口 /app/chat.sendMessage
function sendMessage(text) {
stompClient.send("/app/chat.sendMessage", {}, JSON.stringify({content: text}));
}

核心架构启发 (SockJS & STOMP Client Protocol Insight)

SockJS 抹平了复杂异构网络的通信壁垒，而 STOMP.js 为前端提供了结构化的发布/订阅 (Pub/Sub) 语义。两者结合使得网页端能够像使用专业 MQ 客户端一样，无缝接收广播与私信通知。
