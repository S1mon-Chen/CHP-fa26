企业级案例 1：金融级高频 ETF 实时行情推送架构

High-Frequency Market Ingestion, Server-Side Batching & Throttling, RingBuffer, STOMP `/topic/etf-quotes`

1. 高频行情推送挑战与服务端环形防爆缓冲区 FinTech High-Freq

在金融 ETF/股票行情系统中，交易所每秒会触发上千次毫秒级 Tick 报价变动。**若不加限制直接透传，极度密集的 WebSocket 帧将冲垮前端浏览器 UI 渲染主线程，造成页面死锁与堆内存爆炸。**

① 100ms 窗口动态聚合与数据压缩 (Batch Window) Disruptor / RingBuffer

后端使用无锁 **LMAX Disruptor 环形缓冲区** 接收毫秒级行情。系统定时器每隔 **100ms（人眼视觉极限）** 抓取最新切片，将多个 ETF 变动归并打成单条 JSON 数组帧一次性广播，帧数量降低 90%+。

② 增量增量切片 (Delta Quotes Only) Payload Optimization

仅推送发生价格/成交量变更的 ETF 代码（如 `{"510300": 3.825, "510500": 5.920}`），避免发送未变动的冗余字段，极大降低带宽占用。

③ 网页端防抖渲染与红绿涨跌高亮 (UI Flashing) Canvas & CSS Delta

前端收到数组后，通过 requestAnimationFrame 批量更新 Canvas 图表，同时对价格上涨添加绿色闪烁样式、下跌添加红色闪烁样式，兼顾极速与流畅度。

金融高并发经验：服务端 100ms 聚合 + 增量切片是高频行情系统的必修课
2. 100ms 行情窗口聚合与前端高亮实现 Java & JS Code
① 后端 100ms 批量聚合推送 (`EtfTickerBroadcaster.java`) SimpMessagingTemplate
@Service
public class EtfTickerBroadcaster {
@Autowired private SimpMessagingTemplate messagingTemplate;
private final ConcurrentHashMap<String, Double> deltaBuffer = new ConcurrentHashMap<>();
// 交易所行情 Tick 回调，高频写入并发 Buffer
public void onMarketTick(String symbol, Double price) { deltaBuffer.put(symbol, price); }
@Scheduled(fixedRate = 100) // 每 100ms 定时冲刷一次增量变动
public void flushBatchToWebSockets() {
if (deltaBuffer.isEmpty()) return;
Map<String, Double> snapshot = new HashMap<>(deltaBuffer);
deltaBuffer.clear(); // 快速清空
messagingTemplate.convertAndSend("/topic/etf-quotes", snapshot);
}
}

核心架构启发 (High-Frequency Real-Time Architecture Insight)

处理高频实时行情时，绝对不能将网卡接收到的每一个字节盲目推给网页端。**“服务端 100ms 批处理窗口 + 无锁 RingBuffer 缓冲 + 增量 Delta 字典”**，是构建金融级千万并发实时系统的核心防爆壁垒。
