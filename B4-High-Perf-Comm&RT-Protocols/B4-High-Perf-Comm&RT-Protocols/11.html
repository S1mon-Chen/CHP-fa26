Spring Boot gRPC 服务端业务实现与响应观测器

Service Implementation (`GrpcServerService.java`), `SimpleImplBase`, `StreamObserver` Callback & Error Handling

1. gRPC 服务端继承基类与响应回调逻辑 ImplBase & Observer

在 Spring Boot 中实现 gRPC 服务端非常直观：只需编写一个标注 @Service 的 Java 类，继承由 `protoc` 插件自动派生的抽象基类 SimpleGrpc.SimpleImplBase，并重写对应的 RPC 方法。

① 容器自动感知与 Netty 路由注册 @Service Auto-Bind

`spring-grpc-spring-boot-starter` 会在启动时自动扫描所有继承自 `*ImplBase` 且被 Spring 容器托管的 Bean，无缝注册到嵌入式 Netty gRPC 监听 Server。

② `StreamObserver` 响应观察者三方法 Stream Callback
onNext(response): 将一个响应 Payload 推送给网络 Stream 管道。
onCompleted(): 告知客户端本次 RPC 调用流响应已圆满结束。
onError(throwable): 发生异常时将错误状态沿 HTTP/2 Stream 抛给客户端。
③ 无返回值 (`void`) 与异步管道架构 Void Return

重写的方法返回类型均为 void。服务端不必同步阻塞等待结果返回，而是通过 `responseObserver` 句柄在任意工作线程或异步完成时推送数据。

核心解耦：业务逻辑不必操心底层 HTTP/2 Frame 的封包与发送细节
2. 简单一问一答业务实现 (`GrpcServerService.java`) GrpcServerService.java
package org.sjtu.se.se3353_22_grpc;
import io.grpc.stub.StreamObserver;
import org.springframework.stereotype.Service;
@Service
public class GrpcServerService extends SimpleGrpc.SimpleImplBase {
private static final Log log = LogFactory.getLog(GrpcServerService.class);
@Override
public void sayHello(HelloRequest req, StreamObserver<HelloReply> responseObserver) {
// 1. 读取 Protobuf 强类型请求字段
log.info("Hello " + req.getName());
// 2. 参数校验与业务异常拦截
if (req.getName().startsWith("error")) {
throw new IllegalArgumentException("Bad name: " + req.getName());
}
// 3. 利用 Builder 模式构建 Protobuf 响应对象
HelloReply reply = HelloReply.newBuilder()
.setMessage("Hello ==> " + req.getName())
.build();
// 4. 将响应推送至观察者，并标记通道完成
responseObserver.onNext(reply);
responseObserver.onCompleted();
}
}
StreamObserver 关键流控制要领
1. onNext(reply) 发送数据包。在一问一答 Unary 模式中仅调用 1 次；在流式模式中可重复调用多次。
2. onCompleted() 发送 EOS (End of Stream) 状态包，通知网络管道关闭该 Stream 流。
下一个核心：服务端流式 RPC (`streamHello`) 持续推送实现 (Slide 12)

核心架构启发 (StreamObserver Pattern Insight)

gRPC 采用 **`StreamObserver` 观察者模式** 代替传统 Java 的 `return` 关键字。**这种异步流式句柄设计使得同一个接口不仅能处理简单的 Unary 调用，还能无缝拓展为全双工流式推送**。
