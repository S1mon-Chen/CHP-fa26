企业级案例 2：WebSocket 集群扩容与 Kafka 消息总线异步推送

Multi-Node Cluster Scaling, Session Memory Isolation, Kafka / Redis Event Bus & `convertAndSendToUser`

1. WebSocket 多节点集群扩容与分布式 Session 隔离痛点 Cluster Scaling

在微服务分布式集群（Node 1、Node 2、Node 3）中，WebSocket 句柄 Session 必须保存在特定节点的内存中。**若用户 A 连接到 Node 1，而后台转账成功事件被 Node 2 的消费线程处理，Node 2 无法直接向 User A 推送数据！**

① 内存 Session 节点盲区 (Node Session Isolation) Session Trap

负载均衡器（Nginx / ALB）按 Hash 将 TCP 长连接分发至特定服务器。其他服务器节点无法跨 JVM 访问别人的 WebSocket `Session` 实例。

② Kafka / Redis 消息总线全网扇出 (Broadcast Fanout) Redis / Kafka Bus

业务计算完成后向 Kafka 发送转账完成事件。所有 WebSocket 网关节点同时订阅此 Topic，**只有持有 User A 长连接的 Node 1 命中内存 Key，并执行最终的 Socket 写入**。

③ 耗时业务与长连接推送彻底解耦 (Async Event Drive) Event-Driven EDA

银行转账、风控审核等耗时异步管道（数秒至数分钟）无需挂起 HTTP 请求。任务完成后由 Kafka Listener 触发轻量级 WebSocket 通知，极致提升吞吐。

集群法则：Kafka / Redis Pub/Sub 是粘合多节点 WebSocket 长连接的通信血脉
2. Kafka 消费者驱动 WebSocket 私聊推送代码 Kafka + STOMP Listener
① Kafka 转账异步回调监听器 (`TransferResultKafkaListener.java`) @KafkaListener & Push
@Component
public class TransferResultKafkaListener {
@Autowired private SimpMessagingTemplate messagingTemplate;
@KafkaListener(topics = "transfer-result-topic", groupId = "ws-cluster-group")
public void onTransferCompleted(TransferEvent event) {
// 集群所有节点均会收到 Kafka 广播消息
String targetUserId = event.getUserId();
NotificationDTO notification = new NotificationDTO(
"TRANSFER_SUCCESS",
"Your transfer of $" + event.getAmount() + " was successful!"
);
// 寻址本节点的内部 Session；若用户不在此节点，Spring 底层安全忽略
messagingTemplate.convertAndSendToUser(
targetUserId, "/queue/notifications", notification
);
}
}
② 集群全节点广播寻址数据流 (Cluster Routing Topology) Kafka Fanout Routing
Kafka Topic === Event Fanout ===> Node 1 (User A Socket), Node 2, Node 3

Node 1 在本地持有 User A 的 Session 句柄，成功将通知推入 User A 的网页窗口；Node 2 和 Node 3 找不到目标 Session 自动忽略。

核心架构启发 (Kafka + WebSocket Cluster Insight)

单机内存 Session 无法跨服务器访问。借助 Kafka / Redis Pub/Sub 广播总线 + SimpMessagingTemplate.convertAndSendToUser()，系统优雅解耦了后端异步计算与前端长连接推送，为微服务集群扩容奠定了无缝接入基础。
