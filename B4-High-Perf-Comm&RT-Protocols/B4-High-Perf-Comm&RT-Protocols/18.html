Part 02 · GraphQL 声明式查询语言与按需索取数据

GraphQL 声明式查询：可复用片段与多态内联片段

Named Fragments (`fragment ... on Type`), Spread Operators (`...`), Inline Fragments & Polymorphic Selection

1. 片段 (Fragments) 与多态查询解耦机制 Fragments & Inline

在大型前端应用（如 React 组件树）中，复杂的页面往往需要多次复用相同的字段组合。GraphQL 提供了 **命名片段 (Named Fragments)** 实现字段选择集的声明式复用，并支持 **内联片段 (Inline Fragments)** 处理多态接口（Interface）与联合类型（Union）。

① 命名片段复用 (Named Fragments) DRY Principle

使用 fragment name on Type 构造可复用的字段集合，并在 Query 中使用展开运算符 ...fragmentName 展开。遵循 DRY (Don't Repeat Yourself) 原则，极大地净化了复杂 AST 表达。

② UI 组件驱动数据依赖解耦 (Component Colocation) Relay / Apollo Pattern

每一个前端 UI 子组件（如 `Avatar` 或 `UserCard`）可自行声明专属的 Fragment 契约，顶层页面只需将所有子组件 Fragment 组合成单次 Query，实现了视图组件与其数据依赖的完美同置 (Colocation)。

③ 接口与联合类型的多态内联片段 (Inline Fragments) Polymorphism

当字段返回类型为抽象 `Interface` 或 `Union` 类型（如 `Character` 可能是 `Droid` 或 `Human`）时，通过内联片段 ... on Droid { primaryFunction } 条件式提取具体子类的特有属性。

架构收益：组件级数据依赖同置，消除重复表达与强类型多态图遍历
2. 命名片段与内联片段查询代码示例 (Code & Response) Fragments & Inline
示例 1：命名片段 (`fragment` & `...`) 字段复用 Named Fragment
// GraphQL Query (使用片段展开)
{
leftComparison: hero(episode: EMPIRE) {
...comparisonFields
}
rightComparison: hero(episode: JEDI) {
...comparisonFields
}
}
// 声明片段套件
fragment comparisonFields on Character {
name
appearsIn
friends { name }
}
// JSON Response (展开后精确平铺)
{ "data": {
"leftComparison": {
"name": "Luke Skywalker",
"appearsIn": ["NEWHOPE", "EMPIRE"],
"friends": [{"name": "Han Solo"}]
},
"rightComparison": {
"name": "R2-D2",
"appearsIn": ["JEDI"],
"friends": [{"name": "Luke Skywalker"}]
}
} }
示例 2：内联片段 (`... on ConcreteType`) 多态条件查询 Inline Fragments
// 多态类型抽象查询
query HeroForEpisode($ep: Episode!) {
hero(episode: $ep) {
name
... on Droid {
primaryFunction
}
... on Human {
height
}
}
}
// 具象类型 (Droid) 自动匹配
{ "data": {
"hero": {
"name": "R2-D2",
"primaryFunction": "Astromech"
}
} }

核心架构启发 (GraphQL Fragment Abstraction Insight)

GraphQL 通过**命名片段**实现了组件级字段依赖同置，消除重复定义；同时利用**内联片段**解决了面向对象领域模型中接口与继承子类的多态类型条件检索，优雅地融合了强类型约束与图遍历灵活性。
