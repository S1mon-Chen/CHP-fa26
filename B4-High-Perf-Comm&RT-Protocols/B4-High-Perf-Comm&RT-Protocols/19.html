Part 02 · GraphQL 声明式查询语言与按需索取数据

GraphQL 声明式查询：变量参数化与 Mutation 写变更操作

Dynamic Query Variables (`$var`), Operational Mutations (`mutation`), Input Types & Payload Selection

1. 变量动态提取 (Variables) 与 Mutation 写变更机制 Variables & Mutations

在实际应用中，查询参数通常是动态变化的（如用户选中的下拉项或表单输入）。GraphQL 将**变量 (Variables)** 从查询语句中抽离成独立的 JSON 字典，同时通过 **Mutation (写变更)** 操作规范化处理数据写入与视图更新。

① 变量动态解耦 (GraphQL Variables) Query Parameterization

在操作签名处声明以 $ 开头的变量（如 $episode: Episode），变量真实值在独立的 JSON 对象中传输。彻底避免了硬编码字符串拼接导致的 SQL/GQL 注入风险与 AST 缓存失效。

② 声明式写变更操作 (Mutations) Side-Effect Writes

任何会修改底层数据存储的操作（新增、更新、删除）在 GraphQL 中必须显式声明为 mutation。按规范，Query 允许并行执行，而 Mutation 中的多个顶层写字段按顺序**串行保证原子执行**。

③ 写后即时返回表述 (Atomic Write & Read) Instant Read-back

Mutation 字段本身也是一个返回对象的普通字段。客户端可以在提交写变更的同时追加选择集（如获取刚创建评论的 `stars` 与 `commentary`），在 **单次 1 RTT 网路往返中** 完成写入并刷新 UI 视图。

架构收益：消除字符串拼接风险，实现多写串行原子性与变更即时视图同步
2. 变量解耦与 Mutation 语法示例 (Code & Response) Variables & Mutation
示例 1：查询变量参数化 (`query` + `$variable`) Dynamic Variables
// GraphQL Query (带 $episode 变量)
query HeroNameAndFriends($episode: Episode) {
hero(episode: $episode) {
name
friends { name }
}
}
// VARIABLES (独立 JSON 字典)
{ "episode": "JEDI" }
// JSON Response
{ "data": {
"hero": {
"name": "R2-D2",
"friends": [
{ "name": "Luke Skywalker" },
{ "name": "Han Solo" }
]
}
} }
示例 2：Mutation 提交写变更并即时拉取新表述 Mutation Payload
// GraphQL Mutation
mutation CreateReview($ep: Episode, $review: ReviewInput) {
createReview(episode: $ep, review: $review) {
stars
commentary
}
}
// VARIABLES
{ "ep": "JEDI", "review": { "stars": 5, "commentary": "This is a great movie!" } }
// JSON Response (包含写后结果)
{ "data": {
"createReview": {
"stars": 5,
"commentary": "This is a great movie!"
}
} }

核心架构启发 (Variables & Mutation Architecture Insight)

GraphQL 通过**变量字典参数化**将 AST 查询语句变成强类型的安全模板，彻底消除了 SQL/GQL 字符串拼接注入漏洞；同时利用 **Mutation 语义**保证了写变更的串行原子性，并在同一个网络请求中同步回收更新后的最新实体表述。
