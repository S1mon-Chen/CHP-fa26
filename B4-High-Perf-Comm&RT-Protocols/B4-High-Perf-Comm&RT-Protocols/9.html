Client-Side Stubs Architecture, BlockingStub vs. AsyncStub vs. FutureStub & StreamObserver

1. gRPC Stub (存根) 架构原理与封包解包机制 Stub Architecture

**Stub（存根）** 是客户端通过 `.proto` 动态派生的**本地代理对象**。客户端调用 Stub 方法时，Stub 负责将 Java 对象序列化为 Protobuf 字节流（Marshal），并通过 HTTP/2 通道发送给服务端；收到响应后再自动反序列化（Unmarshal）为本地对象。

**透明寻址**：屏蔽底层的网络连接、序列化与 HTTP/2 Frame 切片细节。
**强类型绑定**：方法签名、入参与返回值受 Protobuf 强校验，避免运行时类型不匹配。
核心抽象：用本地方法调用的感官屏蔽复杂的分布式 IPC 细节
2. Java gRPC 派生的 3 种 Stub 变体对比 Stub Flavors
1. BlockingStub 同步阻塞式，适合 Unary 和 Server Streaming；简便直观。
2. AsyncStub 异步非阻塞，全类型可用；基于 `StreamObserver` 回调。
3. FutureStub Future 异步式，返回 `ListenableFuture`；仅适用于 Unary。
// 1. BlockingStub 同步调用范例 (阻塞直到获取结果)
SimpleGrpc.SimpleBlockingStub blockingStub = SimpleGrpc.newBlockingStub(channel);
HelloReply reply = blockingStub.sayHello(HelloRequest.newBuilder().setName("Alien").build());
// 2. AsyncStub 异步流式回调范例 (StreamObserver 非阻塞)
SimpleGrpc.SimpleAsyncStub asyncStub = SimpleGrpc.newStub(channel);
asyncStub.sayHello(request, new StreamObserver<HelloReply>() {
@Override public void onNext(HelloReply value) { System.out.println(value.getMessage()); }
@Override public void onError(Throwable t) { t.printStackTrace(); }
@Override public void onCompleted() { System.out.println("Stream Finished"); }
});
选型决策提示 (Sync vs. Async Trade-off)

传统微服务或简单 CRUD 优先推荐 **`BlockingStub`**（代码线性直观）；而对于海量高并发推拉流、长连接网络通信或虚拟线程 (Java 21 Loom) 环境，建议结合 **`AsyncStub`** 发挥最大吞吐优势。
