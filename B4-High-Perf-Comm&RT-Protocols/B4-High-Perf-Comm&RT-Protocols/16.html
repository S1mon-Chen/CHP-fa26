Part 02 · GraphQL 声明式查询语言与按需索取数据

GraphQL 声明式查询：字段拣选与对象图关联遍历

Declarative Field Selection, Nested Graph Traversal & Single-RTT Data Aggregation

1. 字段选择 (Field Selection) 与对象图遍历机制 Query Mechanics

**GraphQL 查询的核心是“提问即结构”**。客户端在 Query 中精确写明所需的标量字段 (Scalar Fields) 和嵌套对象 (Nested Objects)。GraphQL 运行时会严格按照 Query 声明的树状形状返回精准 JSON，不多也不少。

① 标量字段精确裁剪 (Scalar Field Selection) Zero Bloat

即使底层 `User` 对象包含 50 个数据库列（密码哈希、详细地址、历史记录等），若客户端只声明 name，响应 JSON 便只包含 name，彻底消除移动端网络流量浪费。

② 对象图关联递归遍历 (Nested Graph Traversal) Single Roundtrip

客户端可以在单个 Query 中从根对象（如 `hero`）沿着关系边深入索取关联集合（如 `friends { name }`）。传统 REST 需要发起多轮 HTTP 往返，而 GraphQL 一次请求即可聚合整树数据。

③ 1:1 契约结构映射 (Predictable Shape) Predictable JSON

响应 JSON 的 data 对象的树状层级与 key 命名，与请求 Query 文本保持绝对 1:1 结构镜像，前端无需繁琐的清洗转码逻辑。

核心解耦：UI 视图字段变动完全由前端自主修改 Query 控制，无需后端修改代码
2. 字段查询语法与精准 JSON 响应对比 (Query vs Response) Declarative Mapping
示例 1：简单标量字段查询 (Basic Field Query) Scalar Selection
// GraphQL Query
{
hero {
name
}
}
// JSON Response
{
"data": {
"hero": { "name": "R2-D2" }
}
}
示例 2：对象图关联遍历查询 (Nested Relation Graph Traversal) Graph Traversal
// 客户端发送嵌套 Query
{
hero {
name
# 支持内联注释！
friends {
name
}
}
}
// 服务端 1 RTT 返回聚合 JSON
{ "data": { "hero": {
"name": "R2-D2",
"friends": [
{ "name": "Luke Skywalker" },
{ "name": "Han Solo" },
{ "name": "Leia Organa" }
]
} } }

核心架构启发 (Declarative Field Selection Insight)

GraphQL 通过声明式语法赋予了前端 UI 组件**自由拣选字段与展开关联树的能力**。服务端无需关心具体的页面展示层视图结构，仅需维护好图节点的 Resolver 解析函数，真正实现了“所问即所得”。

Speaker Notes / 讲师讲稿
🎯 引导学生透视 GraphQL 的“所问即所得”： “向学员做语法演示：最简单的 GraphQL 查询就是指定对象上的具体字段。对比示例 1 与示例 2：客户端只在 Query 中写入 `hero { name friends { name } }`，服务端返回的 JSON 便精确地包含英雄名字以及朋友列表，结构与 Query 保持 1:1 映射。”
💡 强调与 REST 传统多轮请求的对比： “提示学员注意：如果在 REST 架构中，要获取一个英雄以及其所有好友的名字，前端必须先发起 `GET /hero` 获取好友 ID 数组，再针对每个 ID 发起 `GET /friends/{id}`，产生多次 RTT 往返；而 GraphQL 在单次 Query 中即可展开图节点遍历。”
