Java JSR 356 WebSocket 消息编解码器 (`Encoder` & `Decoder`)

`Encoder.Text`, `Decoder.Text`, `willDecode()`, Jackson JSON Binding & Clean Architecture

1. 编解码器架构规范与生命周期 (Encoder & Decoder Spec) JSR 356 Pipeline

Java JSR 356 规范通过引入 **`Encoder`** 与 **`Decoder`** 接口，将 WebSocket 底层网络帧（文本 String / 二进制 byte[]）与强类型 Java 业务对象（POJO）之间的转换下沉至容器层，实现了端点处理逻辑与序列化的完全解耦。

① 编解码器接口分类 (Encoder & Decoder Types) Text & Binary
Encoder.Text<T>: Java 对象 $\to$ 文本帧 (JSON)
Decoder.Text<T>: 文本帧 (JSON) $\to$ Java 对象
Encoder.Binary<T>: Java 对象 $\to$ 二进制 (Protobuf)
Decoder.Binary<T>: 二进制帧 $\to$ Java 对象
② 生命勾子与 `willDecode()` 防御机制 Pre-validation

• willDecode(String s)：在解码前先行嗅探文本格式。若返回 `false`，容器跳过该解码器，防止脏数据引发反序列化崩塌。
• init(EndpointConfig) & destroy()：用于在对象分配和销毁时绑定 JSON 工具单例或释放资源。

③ 极简 `@OnMessage` 方法签名 (Clean Code) No Hand-written JSON

注册 Encoder/Decoder 后，服务端只需在回调中直接写 public void onMessage(ChatMessage msg)，并通过 session.getBasicRemote().sendObject(reply) 发送，容器管道会自动拦截并做极速序列化。

架构精髓：将 JSON 序列化模版代码剥离出 Endpoint，遵循单一职责原则 (SRP)
2. Jackson 编解码器与 Endpoint 整合实现代码 Encoder & Decoder
① 自定义 JSON 编码器 (`MessageEncoder.java`) Encoder.Text<T>
public class MessageEncoder implements Encoder.Text<ChatMessage> {
private static final ObjectMapper MAPPER = new ObjectMapper();
@Override
public String encode(ChatMessage message) throws EncodeException {
try { return MAPPER.writeValueAsString(message); }
catch (Exception e) { throw new EncodeException(message, "JSON error", e); }
}
@Override public void init(EndpointConfig c) {}
@Override public void destroy() {}
}
② 自定义 JSON 解码器 (`MessageDecoder.java`) Decoder.Text<T>
public class MessageDecoder implements Decoder.Text<ChatMessage> {
private static final ObjectMapper MAPPER = new ObjectMapper();
@Override
public ChatMessage decode(String s) throws DecodeException {
try { return MAPPER.readValue(s, ChatMessage.class); }
catch (Exception e) { throw new DecodeException(s, "Invalid JSON", e); }
}
@Override // 嗅探校验
public boolean willDecode(String s) {
return s != null && s.trim().startsWith("{");
}
}
③ 绑定 Endpoint 并享受强类型消息处理 @OnMessage POJO
@OnMessage
public void onMessage(ChatMessage message, Session session) throws Exception {
// message 已经是反序列化好的强类型 ChatMessage POJO
session.getBasicRemote().sendObject(new ChatMessage("Echo: " + message.getContent()));
}

核心架构启发 (Encoder & Decoder Pipeline Insight)

JSR 356 的编解码器机制将底层帧解析与上层业务处理划清界限。willDecode() 提供了防御性预检屏障，结合 Jackson/Gson 库，让 `@OnMessage` 回调可以直接处理强类型 Java 领域模型，奠定了可扩展长连接应用的基础。
