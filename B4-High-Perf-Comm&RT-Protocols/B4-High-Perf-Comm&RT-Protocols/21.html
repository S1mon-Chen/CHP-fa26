1. Spring Controller 与 Java 17 Record 实体模型 Controller & Records
① 强类型不可变数据模型 (`Book.java` & `Author.java`)
public record Book(String id, String name, int pageCount, String authorId) {
// 模拟静态数据存储与过滤 query
public static Book getById(String id) { ... }
}
public record Author(String id, String firstName, String lastName) {
public static Author getById(String id) { ... }
}
② 节点映射控制器 (`BookController.java`)
@Controller
public class BookController {
@QueryMapping // 自动映射 Schema 根节点 Query.bookById(id)
public Book bookById(@Argument String id) {
return Book.getById(id);
}
@SchemaMapping // 客户端索取 author 字段时延迟触发
public Author author(Book book) {
return Author.getById(book.authorId());
}
}
架构精髓：`@SchemaMapping` 将嵌套关联关系的解析剥离为独立的延时函数

核心架构启发 (Spring GraphQL Implementation Insight)

Spring for GraphQL 将底层的 DataFetcher 转化为极为直观的注解驱动模型。通过 **`@QueryMapping` 定位顶层节点、`@SchemaMapping` 定位嵌套节点，结合 GraphiQL 与 Postman 交互调试**，极大地提升了服务端图 API 的敏捷交付速度。

Speaker Notes / 讲师讲稿
🎯 引导学生透视 `@QueryMapping` 与 `@SchemaMapping`： “向学员深入解释：在 `BookController.java` 中，`@QueryMapping` 用于绑定 Schema 根节点 Query；而 `@SchemaMapping` 用于绑定嵌套字段解析。注意 `author(Book book)` 方法：它接收当前的 `Book` 对象，仅当客户端查询 `book { author { ... } }` 带有 `author` 属性时才会被延时触发。”
💡 演示 GraphiQL 与 Postman 工具链： “请学员关注右侧的在线调试工具：开发阶段只需在浏览器访问 `/graphiql`，即可使用自带的图形化 IDE 进行自动补全和测试；在 Postman 中建立 GraphQL 类型请求，也可直接设定 Query 与 VARIABLES JSON 进行接口自动化测试。”
