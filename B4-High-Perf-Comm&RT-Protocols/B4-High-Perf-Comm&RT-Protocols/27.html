Java 原生 WebSocket 生命周期注解与 Session 管理

JSR 356 Standard Annotations (`@ServerEndpoint`, `@OnOpen`, `@OnMessage`, `@OnClose`, `@OnError`) & Thread-Safe Session Store

1. JSR 356 生命规范与 5 大核心注解 JSR 356 API

Java EE / Jakarta EE 提供了官方规范 **JSR 356 (Java API for WebSocket)**。开发者只需在 Java 类上标注 @ServerEndpoint，并为方法挂载生命周期回调注解，容器就会自动接管 TCP 握手与长连接消息事件。

① 生命周期事件回调机制 (Lifecycle Handlers) Event Driven
@OnOpen: TCP 升轨建立后触发
@OnMessage: 接收文本/二进制数据包
@OnClose: 客户端挂断/超时触发
@OnError: 传输层或业务异常抛出
② `Session` 消息发送模式 (Sync vs Async Remote) getRemote()

每个长连接对应唯一一个 Session 实例。
• session.getBasicRemote().sendText(...)：**同步阻塞式**推送。
• session.getAsyncRemote().sendText(...)：**非阻塞异步**推送。

③ 线程安全的 Session 连接池与全局广播 ConcurrentHashMap

注意：**WebSocket 端点默认是多实例的**（每个 Connection 创建新对象）！必须使用类级别的静态 ConcurrentHashMap<String, Session> 容器统一管理全局在线连接，防止多线程死锁与读写竞态。

并发警告：容器会为每个客户端连接新建 Endpoint 实例，Session Map 必须声明为 static
2. 原生 WebSocket 端点实现 (`ChatWebSocketEndpoint.java`) JSR 356 Impl
聊天室点对点与群发广播端点 @ServerEndpoint
@ServerEndpoint("/chat/{username}")
@Component // 注册为 Spring Bean
public class ChatWebSocketEndpoint {
// 静态并发 Map 维护全局在线 Session
private static final Map<String, Session> ONLINE_SESSIONS = new ConcurrentHashMap<>();
@OnOpen // 连接建立事件
public void onOpen(Session session, @PathParam("username") String username) {
ONLINE_SESSIONS.put(username, session);
broadcast("System: " + username + " joined the chat!");
}
@OnMessage // 消息接收事件
public void onMessage(String message, Session session, @PathParam("username") String username) {
broadcast(username + ": " + message);
}
@OnClose // 断开事件
public void onClose(Session session, @PathParam("username") String username) {
ONLINE_SESSIONS.remove(username);
broadcast("System: " + username + " left.");
}
// 全局广播辅助函数
private void broadcast(String msg) {
ONLINE_SESSIONS.values().forEach(s -> s.getAsyncRemote().sendText(msg));
}
}

核心架构启发 (Java WebSocket Session Store Insight)

JSR 356 通过生命周期注解实现了极简的事件响应模型。然而原生 WebSocket 只定义了底层帧传输，**若要实现复杂的点对点私聊、群组订阅与集群节点间的广播，必须引入上层高阶子协议（如 STOMP）与分布式消息队列（如 Redis / Kafka）**。

Speaker Notes / 讲师讲稿
🎯 引导学员透视 JSR 356 注解与多实例问题： “向学员强调：在使用原生的 `@ServerEndpoint` 时，一定要注意**多实例陷阱**！底层容器（如 Tomcat）会为每一个连入的客户端连接新建一个 Endpoint 对象。因此，用来存储全局 Session 的 `ONLINE_SESSIONS` Map **必须声明为 `static`**，否则各连接之间无法共享连接句柄导致广播失败。”
💡 剖析同步与异步消息推送 API： “请学员关注右侧广播函数：`session.getAsyncRemote().sendText(msg)` 是非阻塞的，适合并发高频推送。而在生产单节点上，也要注意对失效 Session 及时从 Map 中清理，避免往已关闭的 Session 发送数据引发异常。”
