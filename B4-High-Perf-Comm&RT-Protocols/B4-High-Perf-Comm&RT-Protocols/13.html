1. 客户端 Stub 装配与通道配置 Client Integration

Spring Boot 客户端借助 GrpcChannelFactory 管理到 gRPC 服务端的长连接 Netty Channel。通过在 Spring 容器中注册 SimpleBlockingStub，业务 Bean 即可直接注入存根发起透明远程调用。

// Se335322GrpcclientApplication.java: 注入 Channel 并注册 Stub Bean
@SpringBootApplication
public class Se335322GrpcclientApplication {
@Bean
SimpleGrpc.SimpleBlockingStub stub(GrpcChannelFactory channels) {
// 从通道工厂创建指向命名为 "local" 的 gRPC 服务的 Channel
return SimpleGrpc.newBlockingStub(channels.createChannel("local"));
}
@Bean
public CommandLineRunner runner(SimpleGrpc.SimpleBlockingStub stub) {
return args -> {
HelloReply reply = stub.sayHello(HelloRequest.newBuilder().setName("Alien").build());
System.out.println(reply.getMessage()); // 输出: "Hello ==> Alien"
};
}
}
// application.properties: 声明默认 Channel 的目标监听端口
spring.application.name=grpc-client
spring.grpc.client.default-channel.address=static://0.0.0.0:${launched.grpc.port:9090}
长连接抽象：Channel 工厂底层自动维护网络连接池与无锁重连
2. 多维联调测试工具流 (`grpcurl` & Postman) gRPC Testing
① `grpcurl` 命令行免代码联调 (gRPC CLI Tool) Terminal CLI
// 1. 明文模式直接触发 Unary 方法 SayHello
$ grpcurl -d '{"name":"Tom"}' -plaintext localhost:9090 Simple.SayHello
{ "message": "Hello ==> Tom" }
// 2. 调用服务端流式推送方法 StreamHello
$ grpcurl -d '{"name":"Jerry"}' -plaintext localhost:9090 Simple.StreamHello
{ "message": "Hello(0) ==> Jerry" }
{ "message": "Hello(1) ==> Jerry" }
② Postman 原生 gRPC 界面可视化调试 GUI Client
**原生协议支持**：Postman 支持新建 `gRPC` 请求类型（替代传统 HTTP）。
**Proto 导入与 Server Reflection**：自动载入 `.proto` 文件或开启服务端反射解析服务定义。
**多模式调试**：实时展现 Unary 响应与 Streaming 消息流推送时间线。

基于 **Protobuf 二进制极速序列化** 与 **HTTP/2 多路复用传输**，gRPC 配合 Spring Boot starter 实现了代码解耦、高性能与工程化联调的完备闭环。
