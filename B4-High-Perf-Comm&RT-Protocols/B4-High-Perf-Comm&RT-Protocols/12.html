Spring Boot gRPC 服务端流式推送代码实现

Server Streaming Implementation (`streamHello`), Loop Pushing, Early Cancellation & Stream Context Guard

1. 服务端流式 RPC (Server Streaming) 机制原理 Stream Push

在 **Server Streaming** 模式下，服务端接收单个 HelloRequest 请求后，可以通过句柄多次调用 responseObserver.onNext(reply) 持续推送数据分块，最后显式调用 onCompleted() 关闭通道。

① 连续触发 `onNext()` 极速推送 Multiple onNext

在循环或响应式事件驱动下，每调用一次 `onNext(reply)`，底层 Netty 便会将 Protobuf 对象编码为 HTTP/2 DATA Frame 顺着现有的网络管道发送出去，无需等全部数据生成完毕。

② 客户端早期取消检测 (`Context.current().isCancelled()`) Cancellation Guard

若客户端在接收过程中超时或主动断开连接，服务端长循环必须通过 Context.current().isCancelled() 定期嗅探流状态，避免死循环与内存泄漏。

③ 堆内存零积压与渐进式分发 Zero Memory Load

面对数 G 级别的大文件导出或高频实时日志，流式分块推送保证 JVM 堆内存只保留当前单个分块对象，极大降低 GC 压力。

工业防爆：长流推送务必配合 Context 取消检测与超时控制
2. 服务端流式推送代码 (`GrpcServerService.java` 续) streamHello()
@Override
public void streamHello(HelloRequest req, StreamObserver<HelloReply> responseObserver) {
// 1. 记录日志与请求参数
log.info("Starting stream for " + req.getName());
// 2. 模拟长数据流持续推送到客户端
for (int i = 1; i <= 5; i++) {
// 3. 防御性编程：检测客户端是否中途断开
if (Context.current().isCancelled()) {
log.warn("Client cancelled stream early, stop pushing.");
return;
}
// 4. 构建分块响应对象并多次调用 onNext()
HelloReply reply = HelloReply.newBuilder()
.setMessage("Chunk #" + i + " for " + req.getName())
.build();
responseObserver.onNext(reply);
// 5. 模拟实时推送间隔延时
try { Thread.sleep(500); } catch (InterruptedException e) { Thread.currentThread().interrupt(); }
}
// 6. 全部数据包发送完成，关闭流
responseObserver.onCompleted();
}
Server Streaming 内部流转要领
多包 onNext(reply) 每触发一次 `onNext`，底层打包一个 DATA Frame 沿 HTTP/2 流即时推送。
显式 onCompleted() 只有调用 `onCompleted()`，客户端才能感知服务端长流推送完毕并触发结束回调。
