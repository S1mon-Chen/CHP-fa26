1. GraphiQL 在线 IDE 与 Schema 内省机制 GraphiQL & Introspection

Spring for GraphQL 引入了内置的 **GraphiQL 浏览器图形化 IDE**。开发者无需手动编写 Swagger，借助 GraphQL 自带的**内省机制 (Introspection)**，即可在浏览器中获得实时代码提示与类型树搜索。

① 自动挂载入口 (`/graphiql`) Dev Mode Enabled

在本地开发环境，访问 http://localhost:8080/graphiql 即可激活界面。内部将网络请求统一路由至服务端单一入口 /graphql。

② Schema 内省查询 (`__schema` & `__type`) Self-Describing API

GraphQL 允许客户端通过元查询（如 query { __schema { types { name } } }）自我探索服务能力，因此 IDE 能在按下 Ctrl+Space 时精准弹出字段与参数补全。

③ 动态文档侧边栏 (Docs Explorer) Zero Doc Maintenance

GraphiQL 侧边栏会自动将底层 `.graphqls` 契约转换为交互式树状文档，点击类型节点即可层层展开查看属性类型与注释，完全避免了代码与文档不一致问题。

生产提示：生产环境需通过 `spring.graphql.graphiql.enabled=false` 禁用 GraphiQL 探针
2. Postman 原生 GraphQL 自动化测试套件 Postman Suite
① Postman 原生 GraphQL Body 结构 POST /graphql
// 1. Header 必须设置 Content-Type
Content-Type: application/json
// 2. Postman 原生将 Query 文本与 Variables JSON 分离打包
{
"query": "query bookDetails($bookid: ID!) { bookById(id: $bookid) { name pageCount author { lastName } } }",
"variables": { "bookid": "book-2" }
}
② 编写 JavaScript 脚本进行自动化回归断言 Postman Test Script
pm.test
("Status code is 200 and data returned", function() {
pm.response.to.have.status(200);
var jsonData = pm.response.json();
pm.expect(jsonData.data.bookById.name).to.eql("Hitchhiker's Guide to the Galaxy");
pm.expect(jsonData.data.bookById.pageCount).to.eql(208);
});
