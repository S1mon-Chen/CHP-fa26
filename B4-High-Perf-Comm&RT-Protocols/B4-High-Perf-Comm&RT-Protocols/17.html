Part 02 · GraphQL 声明式查询语言与按需索取数据

GraphQL 声明式查询：字段参数与别名冲突解决

Field Arguments (Filtering & Formatting), Field Aliases & Single-RTT Parallel Query Execution

1. 字段级实参 (Field Arguments) 与别名 (Aliases) 机制 Arguments & Aliases

传统 REST API 只能将参数附加在全局 URI 尾部（如 /users?id=1000）。而在 GraphQL 中，**每一个字段（标量或嵌套对象）均可接收独有的形参**，且支持通过**别名 (Aliases)** 解决单次请求中的同名字段冲突。

① 字段级实参传入 (Field-level Arguments) Flexible Filtering

根字段（如 `human(id: "1000")`）或标量属性字段（如 `height(unit: FOOT)`）均可独立传参。服务端 Resolver 接收实参后可自动完成数据库过滤或单位换算，减少前端数据二次清洗开销。

② 别名消除同名节点冲突 (Field Aliases) Collision Resolution

当需要在单次 Query 中以不同参数两次查询同一个根节点（例如分别获取 `EMPIRE` 剧集与 `JEDI` 剧集的英雄 `hero`）时，通过给字段加别名 empireHero: hero(...) 可完美避免 JSON Key 冲突。

③ 单次 HTTP 往返并行聚合 (Single RTT Aggregation) Parallel Execution

结合别名，前端可以在 1 次网络往返（1 RTT）中并行批量索取不同参数下的图数据，完全取代多轮串行 HTTP 请求。

架构收益：消除同名冲突，将数据过滤与格式化逻辑下沉至服务端 Resolver
2. 字段参数与别名查询代码示例 (Queries & Response) Arguments & Aliases
示例 1：字段级参数与单位格式化 (Field Arguments) Field-level Args
// GraphQL Query (带参数)
{
human(id: "1000") {
name
height(unit: FOOT)
}
}
// JSON Response (单位换算后)
{ "data": {
"human": {
"name": "Luke Skywalker",
"height": 5.6430448
}
} }
示例 2：别名解决同名节点冲突 (Field Aliases) Aliases Resolution
// GraphQL Query (使用别名)
{
empireHero: hero(episode: EMPIRE) {
name
}
jediHero: hero(episode: JEDI) {
name
}
}
// JSON Response (自动使用别名 Key)
{ "data": {
"empireHero": {
"name": "Luke Skywalker"
},
"jediHero": {
"name": "R2-D2"
}
} }

核心架构启发 (Arguments & Aliases Design Insight)

GraphQL 的**字段级参数**与**别名机制**彻底突破了传统 REST 接口只能对全局 URI 进行整体传参的局限。前端可以在单个网络请求中并行获取不同条件下的同名数据节点，服务端响应格式会自动与别名匹配，真正实现了“零冲突、极速并行索取”。
