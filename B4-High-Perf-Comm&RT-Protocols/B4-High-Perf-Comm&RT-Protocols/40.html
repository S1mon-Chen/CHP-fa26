思考与研讨题 (Thought-Provoking Discussion Topics) 4 Q&A Topics
Q1: 大模型 (LLM) 流式输出为何普遍弃用 WebSocket 转而选用 SSE？ AI Streaming

**提示**：对比 AI 交互的单向不对称性（单次 HTTP POST 请求触发连续 Response 吐 Token），分析 SSE 基于标准 HTTP 的高穿透性、HTTP/2 多路复用支持，以及无需在网关层维护长连接 Session 状态的巨大优势。

Q2: 如何防御 GraphQL 的恶意深度嵌套 DoS 攻击与 N+1 查询？ GraphQL Defense

**提示**：考虑在网关/解析引擎层引入 AST 查询深度限制 (Query Depth Limiting)、复杂度评分 (Query Complexity Analysis)，以及在后端数据层强制挂载 `@BatchMapping` / DataLoader 批处理。

Q3: 多节点微服务集群中，gRPC 与 WebSocket 如何实现 Session 广播？ Cluster Session

**提示**：剖析单机内存 Session 的物理隔离局限；阐述利用 Kafka / Redis Pub/Sub 全网广播总线解耦节点 Session 存储，以及使用 `convertAndSendToUser` 动态寻址的工程机制。

Q4: “对外 REST/GraphQL，对内 gRPC” 模式有何架构优越性？ Hybrid Architecture

**提示**：分析外网网关对于通用性、强类型 Schema 与防攻击的需求，与数据中心内网微服务之间对于极致吞吐、Protobuf TLV 压缩与低延迟 TCP 复用的需求差异。

研讨要领：结合业务场景与网络传输层原理进行架构利弊权衡分析
