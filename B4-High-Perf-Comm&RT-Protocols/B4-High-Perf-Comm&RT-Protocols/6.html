Protobuf `.proto` 语法解构与 RPC 服务契约定义

Proto3 Syntax Rules, Language Options, Field Tag Optimization & Service Declarations

1. Proto3 核心语法规范与字段 Tag 规则 Proto3 Standard
① 语法版本与代码生成 Option 声明 Syntax & Options

首行强制声明 syntax = "proto3";；通过 option java_package = "..." 与 option java_multiple_files = true; 控制生成的 Java 类包名与多文件分离结构。

② Field Tag（1~15 黄金区间）优化 Tag 1-15 Optimization

**Tag 1 至 15** 在二进制流中仅占用 **1 个字节** 编码 Tag Header。最频繁传输的字段（如 ID、高频状态）应优先分配给 Tag 1~15；Tag 16~2047 需占用 2 个字节。

③ 标量数据类型与 `repeated` 数组 Types & Collection

原生支持 string、int32/int64、bool、enum 及嵌套 message。列表或集合统一使用前缀关键词 repeated 修饰。

Proto3 特性：所有字段默认为可选，默认值不占用任何网络传输字节！
2. 完整 RPC 契约定义范例 (`helloworld.proto`) helloworld.proto
// 1. 声明语法版本
syntax = "proto3";
// 2. 代码派生生成配置
option java_multiple_files = true;
option java_package = "org.sjtu.se.se3353_22_grpc";
option java_outer_classname = "HelloWorldProto";
// 3. 定义 RPC 服务契约接口
service Greeter {
// 一问一答 Unary RPC
rpc SayHello (HelloRequest) returns (HelloReply) {}
}
// 4. 定义请求与响应 Payload 结构
message HelloRequest {
string name = 1; // Field Tag 1
}
message HelloReply {
string message = 1; // Field Tag 1
}
Java Interface vs Protobuf Service 契约映射
Java 原生接口定义 HelloReply sayHello(HelloRequest req);
Protobuf 语言中立契约 rpc SayHello (HelloRequest) returns (HelloReply);
下一个核心：利用 `.proto` 文件定义 gRPC 的 4 种通信服务模式 (Slide 7)

核心架构启发 (Schema-First Contract Principle)

`.proto` 文件是跨团队、跨语言协作的**绝对权威契约 (Single Source of Truth)**。通过提前定义清晰的 `message` 与 `service`，客户端与服务端可以平行开发与 Mock 测试，彻底告别沟通壁垒。
