Server-Sent Events (SSE) 架构原理与单向 HTTP 流式推送

W3C EventSource Standard, `text/event-stream` MIME Type, `Last-Event-ID` Reconnection & Spring Boot `SseEmitter`

1. W3C SSE 标准规范与 HTTP `text/event-stream` 格式 W3C EventSource

**Server-Sent Events (SSE)** 是 W3C 预定义的轻量级单向流式通信标准。与 WebSocket 需升级为 TCP 长连接不同，**SSE 完全基于标准 HTTP 协议**，由服务端维持一个持久的 HTTP 连接并以 text/event-stream MIME 类型持续分块推流。

① HTTP 响应头与 UTF-8 事件流文本格式 Header & Framing

客户端发送普通 `GET` 请求，服务端响应头设为 Content-Type: text/event-stream 与 Cache-Control: no-cache。推送数据使用换行符分隔（`\n\n`）：

id: 1001\nevent: message\ndata: Hello World\n\n
② 原生断线自动重连与 `Last-Event-ID` 状态追溯 Auto Reconnect

浏览器内置 `EventSource` API 会在连接意外断开时**自动尝试重新连接**，并自动在 HTTP 请求头中携带 Last-Event-ID，帮助服务端补发断连期间错过的事件流。

③ 企业网络友好性 (HTTP/1.1 & HTTP/2 Multiplexing) Proxy Friendly

纯 HTTP 语义使其能天然穿透防火墙与反向代理（如 Nginx），在 **HTTP/2** 模式下可复用同一 TCP 连接发起多个 SSE 管道，且相比 WebSocket 占用极低的系统资源。

架构定性：SSE 是服务端单向高频/长流推送的最优选，无需引入复杂的双向 Socket 握手
2. Spring Boot `SseEmitter` 与前端 `EventSource` 代码实现 Java & JS Implementation
① Spring Boot 控制器端点 (`SseController.java`) SseEmitter API
@RestController
@RequestMapping("/api/sse")
public class SseController {
@GetMapping(path = "/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public SseEmitter streamEvents() {
SseEmitter emitter = new SseEmitter(180000L); // 3分钟超时
// 在异步后台线程中推流数据
Executors.newSingleThreadExecutor().execute(() -> {
try {
for (int i = 1; i <= 5; i++) {
SseEmitter.SseEventBuilder event = SseEmitter.event()
.id(String.valueOf(i))
.name("message")
.data("Chunk #" + i + ": Event stream active.");
emitter.send(event);
Thread.sleep(1000);
}
emitter.complete(); // 正常完成关闭流
} catch (Exception e) { emitter.completeWithError(e); }
});
return emitter;
}
}
② 前端原生 `EventSource` 订阅处理脚本 (`client.js`) EventSource API
const eventSource = new EventSource('/api/sse/stream');
// 1. 监听普通消息
eventSource.onmessage = function(event) {
console.log('Received chunk:', event.data, 'ID:', event.lastEventId);
};
// 2. 捕获错误与连接断开
eventSource.onerror = function(err) {
console.error('SSE connection closed/errored.', err);
eventSource.close();
};

核心架构启发 (Server-Sent Events Architecture Insight)

并非所有实时推送都需要复杂的全双工 WebSocket。在**服务端单向推送数据**（如大模型 AI 流式输出、实时系统监控告警、状态进度条）场景下，SSE 以其极简的 HTTP 机制、内置自动重连与低资源开销，展现出无与伦比的优雅性。
