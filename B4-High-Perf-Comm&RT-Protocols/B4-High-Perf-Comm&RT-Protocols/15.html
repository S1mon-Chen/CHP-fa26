GraphQL 核心架构与 Schema 类型系统

Schema-First Principle, Type System (Query, Mutation, Object Types), Field Resolvers & Execution Pipeline

1. Schema-First 模式与强类型系统 (Type System) SDL Specification

**GraphQL 服务的核心是 Schema**。GraphQL 不依赖具体的数据库或存储引擎，而是通过强类型的 **Schema 定义语言 (SDL)** 声明 API 支持的数据类型及字段，作为客户端与服务端之间的强校验契约。

① 根入口类型 (Root Operation Types) Query & Mutation

Query（读操作入口）与 Mutation（写变更入口）是 GraphQL 请求图遍历的根节点。

② 对象类型 (Object Types) 与标量 (Scalars) Type & Field

内置标量类型：String、Int、Float、Boolean 和 ID；感叹号 ! 表示非空字段 (Non-Null)。

③ 字段解析器 (Field Resolver Functions) Data Resolvers

Schema 中的每一个字段都对应一个服务端 Resolver 函数。解析引擎按照 Query 结构层层递归调用函数填充 JSON 属性。

核心解耦：GraphQL Schema 将底层数据存储细节与客户端查询完全隔离
2. Schema 定义与 Resolver 函数映射模式 Schema & Resolvers
// schema.graphqls: 声明类型与字段契约
type Query {
me: User
}
type User {
id: ID!
name: String
}
// 服务端绑定字段解析函数 (Resolver Functions)
function Query_me(request) {
return request.auth.user; // 返回 User 对象实例
}
function User_name(user) {
return user.getName(); // 延迟取属性字段
}
GraphQL 查询服务端解析执行流水线 (Execution Pipeline) AST Execution
1. 接收 Query POST Payload
2. 语法校验 AST & Type Check
3. 逐层 Resolver Graph Traversal
4. 精准 JSON { "data": { ... } }

核心架构启发 (GraphQL Schema-First Architecture)

GraphQL 的本质是**基于 Schema 类型树的图调度引擎**。服务端不关心客户端的展示视图逻辑，只需为类型字段绑定相应的 Resolver 函数，剩下的字段拣选与图遍历交由引擎自动完成。
