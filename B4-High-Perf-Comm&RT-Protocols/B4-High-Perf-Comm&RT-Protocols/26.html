WebSocket 寻址 Endpoint 与传输层安全 (`ws://` vs `wss://`)

Unencrypted WebSocket (`ws://`), Encrypted TLS Tunnel (`wss://`), Nginx Reverse Proxy & SSL Offloading

1. `ws://` 与 `wss://` 协议 Schema 对比 URI Schemas

WebSocket 定义了两种专属 URL Schema：ws://（明文）和 wss://（TLS 加密）。在生产环境，必须强制开启 wss:// 以规避网络代理拦截与混合内容 (Mixed Content) 阻断。

① 明文传输协议 (`ws://` - WebSocket Unencrypted) Port 80 (HTTP)

借道默认 **HTTP 80 端口**。由于传输层数据未加密，中间透明代理服务器（Proxy/Middlebox）经常无法识别 101 Upgrade 升轨报文，导致长连接被强行切断；且极易受到窃听与篡改。

② TLS/SSL 加密协议 (`wss://` - WebSocket Secure) Port 443 (HTTPS)

借道 **HTTPS 443 端口**。TCP 三次握手后建立 TLS 安全加密隧道，所有 101 握手与后续二进制数据帧均受到强加密保护。中间代理仅能看到密文，**完美穿透防火墙与中间件**。

③ 浏览器混合内容 (Mixed Content) 限制规则 HTTPS Constraint

现代浏览器严格执行安全同源策略：若前端页面运行在 https:// 安全域下，尝试发起 ws:// 连接将被浏览器视为**混合内容错误直接拦截**，必须统一使用 wss://。

生产准则：线上环境一律采用 `wss://` + Nginx SSL 卸载组合拳
2. Nginx 反向代理配置与 WSS 代理穿透 (Nginx Setup) Nginx Config
① Nginx 反向代理 `Upgrade` 标头转换 (`nginx.conf`) SSL Offloading
server
{
listen 443 ssl;
server_name ws.example.com;
// SSL 证书部署
ssl_certificate /etc/nginx/certs/server.crt;
ssl_certificate_key /etc/nginx/certs/server.key;
location /ws/ {
proxy_pass http://127.0.0.1:8080; // 后端 Spring Boot 端口
proxy_http_version 1.1; // 必须使用 HTTP/1.1
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection "Upgrade";
proxy_set_header Host $host;
proxy_read_timeout 3600s; // 长连接空闲超时保护
}
}
② Nginx SSL 卸载与后端交互管道 (SSL Termination Pipeline) Proxy Topology
Client ====== wss:// (TLS 443 加密) ======> Nginx Gateway
Nginx Gateway ------ ws:// (101 Upgrade 明文) ------> Spring Boot (:8080)

外网通过 wss:// 保障数据安全性；网关统一解密（SSL 卸载）后通过内网高带宽转交 Java WebSocket 容器，兼顾安全与高性能。

核心架构启发 (WebSocket Transport Security Insight)

WebSocket 的网络穿透力依赖于传输层安全。wss:// 通过 TLS 强加密彻底解决了中间透明代理误切连接与浏览器混合内容阻断问题；配合 **Nginx 边缘 SSL 卸载与 `proxy_read_timeout` 调优**，构建了兼具高并发与安全性的生产级推送防线。

Speaker Notes / 讲师讲稿
🎯 引导学员理解 `ws://` 与 `wss://` 的本质区别： “向学员强调：在工业界生产环境，绝不要在 HTTPS 网站中使用 `ws://`！浏览器会直接报 Mixed Content 错误并拦截连接。使用 `wss://` (Port 443) 通过 TLS 强加密，能够避开绝大多数中间代理（Middlebox）对 101 Upgrade 响应的误切。”
💡 剖析 Nginx 反向代理配置要素： “请学员关注右侧的 Nginx 配置：实现 WebSocket 代理的核心在于必须显式设置 `proxy_http_version 1.1;`、`proxy_set_header Upgrade $http_upgrade;` 与 `proxy_set_header Connection "Upgrade";`。此外，`proxy_read_timeout 3600s;` 能够防止默认 60s 空闲导致的长连接超时断开。”
