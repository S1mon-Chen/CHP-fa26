Java 原生 WebSocket 端点实战与 Encoder/Decoder 消息编解码

`EchoEndpoint.java`, Custom `Encoder.Text` / `Decoder.Text`, `ServerEndpointConfig.Configurator` & Spring `ServerEndpointExporter`

1. 消息编解码器 (Encoders/Decoders) 与上下文配置 JSR 356 Advanced

原生 Java WebSocket 不仅支持发送原生 String / byte[]，还允许通过注册 **Encoder (编码器)** 与 **Decoder (解码器)** 实现 Java 对象与 WebSocket 数据包的透明转换，并借助 `Configurator` 拦截 HTTP 握手请求头。

① 声明式编解码器 (`Encoder.Text` & `Decoder.Text`) Auto JSON Parsing

在 @ServerEndpoint 中通过 encoders 和 decoders 属性指定转换类。`@OnMessage` 可直接接收强类型 POJO 对象，避免在方法体内手写 Jackson 序列化。

② HTTP 握手拦截器 (`ServerEndpointConfig.Configurator`) Handshake Context

重写 modifyHandshake(...) 方法，可将 HTTP `HttpSession` 或 Request Headers (如 JWT Token) 注入到 `ServerEndpointConfig` 的 UserProperties 中，传递给 WebSocket `Session`。

③ Spring Boot `ServerEndpointExporter` 注册 Bean Spring Container

在嵌入式 Tomcat / Jetty 环境下，必须显式注册一个 ServerEndpointExporter 的 `@Bean`，由 Spring 容器自动扫描并挂载所有带有 `@ServerEndpoint` 的组件。

提示：Spring 托管的 @ServerEndpoint 实例默认受 Java JSR 356 规范控制（非标准 Spring Singletons）
2. 消息响应端点与 Spring 挂载实现 (`EchoEndpoint.java`) Echo & Config
① Echo 端点实现与对象编解码 EchoEndpoint.java
@ServerEndpoint(value = "/echo", encoders = {MessageEncoder.class}, decoders = {MessageDecoder.class})
@Component
public class EchoEndpoint {
@OnOpen // 连接触发
public void onOpen(Session session) {
System.out.println("Connected: " + session.getId());
}
@OnMessage // 接收自动解出的 ChatMessage POJO 对象
public void onMessage(ChatMessage msg, Session session) throws Exception {
ChatMessage reply = new ChatMessage("Server Echo: " + msg.getContent());
// 自动触发 MessageEncoder 编码写回
session.getBasicRemote().sendObject(reply);
}
@OnError // 异常捕获
public void onError(Session session, Throwable error) {
error.printStackTrace();
}
}
② Spring Boot 工厂导出配置 (`WebSocketConfig.java`) ServerEndpointExporter
@Configuration
public class WebSocketConfig {
@Bean // 导出内嵌 Servlet 容器中的 WebSocket 端点
public ServerEndpointExporter serverEndpointExporter() {
return new ServerEndpointExporter();
}
}

原生 JSR 356 的 **Encoder/Decoder** 机制将报文与强类型 Java 对象的转换下沉至容器层，保持了 `@OnMessage` 处理函数的极简语义；结合 **`ServerEndpointExporter`** 实现了原生 Java API 与 Spring Boot 依赖注入容器的无缝工程化融合。

🎯 引导学员理解 Encoders / Decoders 解耦优势： “向学员做原理解析：在 JSR 356 规范中，如果你不希望在 `@OnMessage` 中手动反序列化 JSON 文本，可以通过 `encoders` 与 `decoders` 声明转换器。底层 WebSocket 容器会在收到消息时自动触发 `Decoder.Text` 将文本转为强类型 Java 对象（如 `ChatMessage`），并在发送时自动通过 `Encoder.Text` 打成 JSON。”
