第 3 讲课程总结与 4 大核心架构启发

Core Architectural Principles: Contracts, Resource Abstractions, CORS Security & Gateway Governance

启发 1：契约驱策与异构解耦 (Contract & Decoupling) WSDL & OpenAPI 3.0

契约是消除分布式系统耦合的第一护城河

**契约优先 (Schema-First)**：不管是 SOAP 的 XSD/WSDL 还是 REST 的 OpenAPI 3.0，契约定义了强类型的输入输出边界。
**代码即契约**：使用 `springdoc-openapi` 在运行期自动提取元数据，保持接口文档与后端代码绝对同步，自动派生 SDK。
核心原理：以不可变的 API 契约隔离两端技术栈细节 Loose Coupling
启发 2：面向资源抽象与状态机 (Resource Modeling) REST & HATEOAS

将复杂业务建模为标准资源状态机

**纯名词 URI 与动词解耦**：用 URL 定位客观实体，用 HTTP 动词修饰操作，用状态码（201/409/404）精准传达结果。
**星巴克状态机与超媒体**：利用 HATEOAS 超链接引导客户端进行交易状态转换，享受标准 Web 缓存红利。
核心原理：摒弃 RPC 方法思维，以统一接口表达资源 Uniform Interface
启发 3：边缘同源防御与 CORS 治理 (CORS Security) OPTIONS Preflight

同源策略 (SOP) 契约与预检缓存优化

**OPTIONS 预检流程**：非简单请求（如包含自定义 Header 或非 GET/POST 动词）必须先通过 `OPTIONS` 嗅探获得许可。
**生产治理技巧**：使用 `allowedOriginPatterns` 防范 Cookie 通配符漏洞，配合 `maxAge(1800)` 消除重复预检的延时。
核心原理：前端 Web 容器与后端 API 服务间的信任授权 Boundary Security
启发 4：API 网关流量治理与选型决策 (Gateway Governance) Token Bucket & Transcoding

收拢切面关注点，保护后端微服务集群

**网关四大核心职责**：动态路由、统一鉴权、无锁分布式限流（Redis 令牌桶）与 SSL 卸载。
**工业混合范式**：网关边缘“对外暴露通用 RESTful，对内转码为高性能二进制 gRPC”。
核心原理：将安全、限流、路由等切面下沉，实现业务高内聚 Gateway Governance

第二单元 第 3 讲终极架构视角 (Full Lecture Architecture Takeaway)

好的服务端架构从来不是盲目追新。通过**在边缘使用 API 网关统筹安全与限流，在外网使用 RESTful/OpenAPI 保证最大化通用性与解耦，在内网局域网使用二进制 gRPC 保证极致吞吐**，是现代化企业级分布式系统的黄金法则。
