Part 02 · RESTful 架构风格与资源设计 (RESTful Architecture & Resource Design)

REST 架构 4 大核心要素：资源、URI、表述与状态转移

Core Elements: Resource, Unique Identifier (URI), Representation & State Transfer

1. REST 架构的 4 大核心概念定义 The 4 REST Pillars
① 资源 (Resource) Domain Entity

网络上任何可被命名的客观抽象实体（如用户 `users`、订单 `orders`、图片或数据库表记录）。资源是抽象概念，不局限于某行具体的数据库记录。

② 唯一资源标识符 (URI) Noun-Based Addressing

每个资源在网络中都有唯一的 URI。URI 应当**只包含名词（代表资源实体）**，绝不应该包含操作动词。

③ 表述 (Representation) Data Manifestation

资源在特定时刻的具体呈现形式。同一个资源可拥有多种表述（如 JSON、XML、Protocol Buffers 或 HTML）。

④ 状态转移 (State Transfer) State Machine Flow

客户端通过传输资源的“表述”，驱动服务端业务应用在不同的逻辑状态之间平滑过渡与流转（如星巴克购餐状态机）。

核心解耦：URI 定位资源，HTTP 动词执行动作，Header 内容协商选择表述
2. 内容协商机制与 URI 命名反范式对比 Content Negotiation & Naming
URI 寻址原则：RPC 过程思维 vs REST 资源视角
RPC / 动词破坏范式 GET /getOrderDetails?id=123 POST /api/createUser URI 混入了动作谓词与过程参数
RESTful 名词规范 GET /v1/orders/123 POST /v1/users URI 仅包含纯名词，用 HTTP 动词修饰动作
HTTP 内容协商 (Content Negotiation Flow)
客户端请求期望： Accept: application/json
JSON 表述
服务端响应返回： Content-Type: application/json
JSON Payload
下一个关键点：HTTP 动词 (GET/POST/PUT/DELETE) 与幂等性 (Idempotency) 映射

核心架构启示 (REST 4 Pillars Key Insight)

REST 架构的最高境界在于**用同一套标准的统一接口（HTTP 方法）操作由 URL 唯一标示的名词资源**。同一资源通过 HTTP 内容协商暴露多种表述（JSON/XML），并引导客户端在资源状态树中优雅跳转。

🎯 引导学生掌握 REST 的四要素： “向学员深入剖析：REST 四要素即资源 (Resource)、URI 标识、表述 (Representation) 与状态转移 (State Transfer)。重点强调：URI 只能是纯名词，绝对不能在 URI 中嵌入方法动作名词（如 /getUser 或 /createOrder）！”
