SOAP 协议架构与 Envelope 消息信封结构

SOAP Protocol Architecture, XML Schema Namespaces & Message Envelope Anatomy

1. SOAP 消息信封 Anatomy (Envelope Structure) XML Protocol Standard

SOAP（Simple Object Access Protocol）是一种基于 XML 的轻量级消息交换协议，高度依赖 XML Namespace 消除同名节点歧义，包含三大核心结构节点：

<env:Envelope> (根元素 / Root Element) Mandatory

SOAP 消息的顶层根节点，定义了 XML 命名空间（`xmlns:env`）与协议边界，告知接收方此 XML 为合法 SOAP 报文。

<env:Header> (消息头 / Metadata) Optional

存储上下文元数据，例如 WS-Security 身份认证凭证、分布式事务 ID、路由路由指示（Routing）等非业务 Payload。

<env:Body> 与 <env:Fault> (载荷/异常) Mandatory

承载实际远程调用的 RPC 方法名、参数及返回数据 payload。若发生异常，`Body` 内部将包含 `` 节点输出错误码。

关键理念：用 XML Namespaces 解耦异构系统调用的同名标签
2. SOAP 客户端请求报文范例 (SOAP Request XML) Titan Reservation XML
<?xml version='1.0' encoding='UTF-8' ?>
<env:Envelope
xmlns:env="http://schemas.xmlsoap.org/soap/envelope/">
<!-- 消息头 Header：保存安全令牌或路由（可选） -->
<env:Header />
<!-- 消息体 Body：具体的 RPC 方法与参数 payload -->
<env:Body>
<reservation xmlns="http://www.titan.com/Reservation">
<customer>
<id>1001</id>
<name>John Doe</name>
</customer>
</reservation>
</env:Body>
</env:Envelope>
强类型契约 (Typed Payload)

入参 id（1001）与 name 需严格符合 XML Schema 中定义的数据类型。

命名空间隔离

`http://www.titan.com/Reservation` 精确防止不同微服务间 `reservation` 节点重名。

传输载体：普遍借由 HTTP POST 协议包装 SOAP XML 文本传输

核心架构启示 (SOAP Envelope Key Insight)

SOAP 将请求调用的所有信息（元数据 + 数据载荷）完整打包封装在标准的 **XML Envelope** 信封中，使得 SOAP 报文具备了与底层传输协议（HTTP, SMTP, JMS）无关的自包含性。

Speaker Notes / 讲师讲稿
🎯 引导学生透视 SOAP 信封三结构： “向学员剖析：SOAP 报文最外层是 `env:Envelope`；`env:Header` 用来传递如 WS-Security 身份 Token 或路由元数据；而 `env:Body` 保存具体的业务远程方法和入参。强调与后续 RESTful JSON 直接发数据体相比，SOAP 的包装非常严密但也导致 Payload 较大。”
💡 强调 XML Namespaces 的作用： “请学员特别关注代码中的 `xmlns:env` 和 `xmlns="http://www.titan.com/Reservation"`。在分布式系统跨机构集成时，不同公司可能定义了同名的 `` 或 `` 节点，XML 命名空间是保障分布式解析无歧义的关键约束。”
