WSDL Contract Anatomy: Concrete Layer Mapping (<binding>, <service> & <port>)

1. WSDL 具体实现组件解析 (WSDL Concrete Layer) Implementation Binding

如果说抽象层（`` 与 ``）定义了服务**“能做什么”**，那么具体实现层（`` 与 ``）则指定了服务**“如何传输”**以及**“在何处访问”**。

<binding> 节点 (协议与编码绑定) Protocol & Style

将抽象接口 `` 绑定到具体传输协议（如 SOAP over HTTP），并规定消息的编码样式（如 `rpc` 或 `document`，以及 `literal` 或 `encoded`）。

<service> 与 <port> (终节点与访问地址) Endpoint Address

汇总一组关联的网络端口（``）。子节点 `` 指定客户端发起远程调用的物理网络 URL（例如 `http://www.titan.com/webservices/TravelAgent`）。

WSDL 抽象层 vs 具体实现层 对比
抽象层 (Abstract) ``, ``
仅描述 Java 接口、方法及强类型参数
具体层 (Concrete) ``, ``
指定 HTTP 传输、SOAP 编码及物理 URL
高度灵活：同一个 <portType> 可以绑定多种不同的传输协议或网络终节点
2. WSDL 具体绑定 XML 范例 (WSDL Concrete Snippet) TravelAgent.wsdl
<!-- 1. 传输协议与消息编码绑定 -->
<binding name="TravelAgentBinding" type="titan:TravelAgent">
<soap:binding style="rpc" transport="http://schemas.xmlsoap.org/soap/http"/>
<operation name="makeReservation">
<soap:operation soapAction="" />
<input>
<soap:body use="literal" namespace="http://www.titan.com/TravelAgent"/>
</input>
<output>
<soap:body use="literal" namespace="http://www.titan.com/TravelAgent"/>
</output>
</operation>
</binding>
<!-- 2. 服务访问终节点与物理 URL -->
<service name="TravelAgentService">
<port name="TravelAgentPort" binding="titan:TravelAgentBinding">
<soap:address location="http://www.titan.com/webservices/TravelAgent" />
</port>
</service>
传输协议与编码样式

`style="rpc"` 指明 RPC 方式调用，`use="literal"` 承诺 XML 消息严格遵循 Schema。

网络 Endpoint 寻址

`` 为 JAX-RPC / JAX-WS 客户端 Stub 代理生成网络调用的真实 Target URL。

自动化契约：客户端可通过 WSDL 自动生成 JAX-WS 访问 Stub 代理类

核心架构启示 (WSDL Concrete Binding Insight)

将 `` 与 `` 独立定义，是 WSDL 实现**面向服务架构 (SOA)** 灵活性的关键：同一个业务逻辑接口，可以在测试环境、生产环境绑定不同的 URL，或者同时暴露 SOAP/HTTP 和 JMS/AMQP 两种传输通道，而无需修改任何上层业务代码。
