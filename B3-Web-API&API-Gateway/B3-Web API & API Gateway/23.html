1. 前后端分离架构与 React 数据消费准则 SPA Architecture
前后端解耦 (Decoupled SPA & REST) JSON Data Contract

前端 React 应用作为纯静态资源（部署在独立 Web 容器，如 Nginx 或 Node.js，端口 3000），通过 AJAX / Fetch 异步请求与 Spring Boot RESTful 后端（端口 8080）传输 JSON Payload。

React Hooks 声明式生命周期管理 useState + useEffect

使用 useState 管理三态（data 数据、loading 加载状态与 error 异常）；使用 useEffect 挂载组件初始化时的异步副作用请求。

`response.ok` 状态码校验与 Promise 异常捕获 Robust Fetch

原生 fetch() 在收到 404 或 500 时**不会**自动 Reject！必须显式判断 if (!response.ok) 并抛出 Error，确保客户端防护健全。

跨域挑战引出：Origin (端口 3000 $\rightarrow$ 8080) 阻断 CORS Preview

当 React (3000) 直接调用 Spring (8080) 时，浏览器同源策略会触发跨域拦截！这引出了下一页核心：CORS 安全机制与 OPTIONS 预检请求。

架构原则：前端通过标准的 HTTP Accept 标头驱动后端的 Content Negotiation
2. React 消费端组件代码 (`App.jsx`) App.jsx
import React, { useState, useEffect } from 'react';
function OrderInfo({ orderId }) {
const [order, setOrder] = useState(null);
const [loading, setLoading] = useState(true);
const [error, setError] = useState(null);
useEffect(() => {
fetch(`http://localhost:8080/v1/orders/${orderId}`, {
headers: { 'Accept': 'application/json' }
})
.then(res => {
if (!res.ok) throw new Error(`HTTP error! status: ${res.status}`);
return res.json();
})
.then(data => { setOrder(data); setLoading(false); })
.catch(err => { setError(err.message); setLoading(false); });
}, [orderId]);
if (loading) return <div>Loading order...</div>;
if (error) return <div className="text-rose-400">Error: {error}</div>;
return (
<div className="card">
<h3>Order #{order.id}</h3>
<p>Drink: {order.drink} | Price: ${order.cost}</p>
</div>
);
}

核心架构启发 (Frontend-Backend Decoupling Insight)

单页应用 (SPA) 消费 RESTful 服务体现了**现代 Web 极佳的契约隔离**。前端只需要按照 API 规范通过异步通道请求 JSON，就能与 Java / Spring Boot 后端无缝协作，甚至可以独立于后端实现模版化与 Mock 测试。
