Spring REST 统一全局异常处理与 RFC 7807 规范

Global Exception Interception with @RestControllerAdvice, @ExceptionHandler & Standard Problem Details

1. REST 统一异常处理设计原则与注解体系 Exception Strategy
`@RestControllerAdvice` 全局切面切入 Global Aspect

组合了 @ControllerAdvice 与 @ResponseBody，以 AOP 方式拦截所有 `@RestController` 抛出的未捕获业务异常，并将其统一转换为 JSON 错误响应。

`@ExceptionHandler` 异常类型精确映射 Type Mapping

将指定的 Exception 类（如 `ResourceNotFoundException.class`）绑定到具体处理方法，配合 @ResponseStatus(HttpStatus.NOT_FOUND) 映射准确的 HTTP 状态码。

杜绝 500 异常堆栈泄漏 (Information Leak) Security Best Practice

避免在生产环境直接向客户端返回包含数据库表名、内部代码行号的 500 StackTrace 堆栈。通过全局捕获后包装为结构化 `ErrorResponse` 格式输出。

规范标准：符合 RFC 7807 (Problem Details for HTTP APIs) 标准错误定义
2. 全局异常处理器代码实现 GlobalExceptionHandler.java
package com.example.restservice.exception;
import java.time.LocalDateTime;
import org.springframework.http.HttpStatus;
import org.springframework.web.bind.annotation.*;
@RestControllerAdvice
public class GlobalExceptionHandler {
// 1. DTO: 定义符合 RFC 7807 标准的错误结构体
public record ErrorResponse(
int status, String error, String message, LocalDateTime timestamp) { }
@ExceptionHandler(ResourceNotFoundException.class)
@ResponseStatus(HttpStatus.NOT_FOUND)
public ErrorResponse handleNotFound(ResourceNotFoundException ex) {
return new ErrorResponse(
HttpStatus.NOT_FOUND.value(),
"Resource Not Found",
ex.getMessage(),
LocalDateTime.now()
);
}
@ExceptionHandler(IllegalArgumentException.class)
@ResponseStatus(HttpStatus.BAD_REQUEST)
public ErrorResponse handleBadRequest(IllegalArgumentException ex) {
return new ErrorResponse(400, "Bad Request", ex.getMessage(), LocalDateTime.now());
}
}
客户端收到的 HTTP 响应 Payload (404 Not Found) HTTP/1.1 404 Not Found
{"status": 404, "error": "Resource Not Found", "message": "Order #1234 not exist", "timestamp": "2026-08-19T21:30:00"}

核心架构启发 (REST Exception Architecture Insight)

全局异常处理不仅是**代码整洁度**的要求，更是**API 契约安全性与稳定性**的护城河。通过 `@RestControllerAdvice` 统一捕获异常并映射为 RFC 7807 格式，可以实现前端提示友好化、监控系统自动化以及敏感堆栈防泄漏。
