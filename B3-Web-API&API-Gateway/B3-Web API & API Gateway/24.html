Same-Origin Policy (SOP), Preflight Request (OPTIONS), Header Contracts & Browser Security Guard

1. 浏览器同源策略 (SOP) 与 CORS 契约解防 SOP & CORS Contract
同源策略 (Same-Origin Policy - SOP) 铁律 Browser Defense

浏览器安全基石：当请求的 协议 (Scheme)、域名 (Host)、端口 (Port) 任意一项不一致时（如 React :3000 $\rightarrow$ Spring :8080），即属于**跨域**。默认拦截脚本读取跨域响应！

简单请求 vs. 预检请求 (Preflighted Request) Request Classifier

若请求使用非简单动词（PUT/DELETE）、自定义标头（Authorization）或 application/json 类型，浏览器**必须先自动发起 `OPTIONS` 预检嗅探**，获准后才真正发送业务请求！

核心 CORS 响应标头契约 (Headers Contract) W3C Standard
Access-Control-Allow-Origin: 允许的客户端源地址
Access-Control-Allow-Methods: 允许调用的 HTTP 动词
Access-Control-Max-Age: 预检结果在浏览器的缓存时长（秒）
关键认知：跨域拦截行为发生在【浏览器端】而非服务端（请求已送达服务端）
2. OPTIONS 预检请求与真实请求双向交互时序 Preflight Sequence
Browser (port 3000) Spring REST (port 8080)
阶段 1：自动预检请求 (Browser $\rightarrow$ Server) OPTIONS
OPTIONS /v1/orders/1234 HTTP/1.1
Origin: http://localhost:3000
Access-Control-Request-Method: PUT
Access-Control-Request-Headers: Content-Type, Authorization
阶段 2：服务端批准放行 (Server $\rightarrow$ Browser) 200 OK / 204
HTTP/1.1 200 OK
Access-Control-Allow-Origin: http://localhost:3000
Access-Control-Allow-Methods: GET, POST, PUT, DELETE, OPTIONS
Access-Control-Allow-Headers: Content-Type, Authorization
Access-Control-Max-Age: 1800
阶段 3：发送真正业务 Payload (PUT /v1/orders/1234) Actual Request
PUT /v1/orders/1234  ⇒  HTTP/1.1 200 OK
Payload: {"id": 1234, "drink": "Latte", "status": "PAID"}
Access-Control-Max-Age 缓存预检结果，避免后续每次请求都重复触发 OPTIONS 损耗性能
Credentials 支持 允许跨域传递 Cookie 时，`Allow-Origin` 严禁写泛域名通配符 `*`
下一个核心：Spring Boot 中的三种 CORS 全局与局部配置实现

核心架构启发 (CORS Security & Performance Insight)

CORS 是**前端 Web 容器与后端 API 服务之间达成信任的安全机制**。合理配置 Access-Control-Max-Age 能有效降低 OPTIONS 预检产生的双倍 HTTP 延迟，而精确限定 Allow-Origin 则是防止 CSRF 攻击与数据泄露的第一道防线。
