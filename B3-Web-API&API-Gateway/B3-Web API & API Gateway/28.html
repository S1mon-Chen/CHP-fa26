1. 客户端直连微服务 (Direct Access) 的 4 大架构痛点 Direct Route Pain Points
① 客户端强耦合后端内部微服务网络拓扑 Network Coupling

前端 iOS、Android 或 Web 必须记忆与配置上百个后端微服务的 IP 和端口号（如 :8081, :8082）。一旦后端服务发生重构或拆分，前端被迫大面积发布更新。

② CORS 跨域配置散落与重复维护危机 Scattered CORS

每一个独立微服务都必须单独配置跨域策略（CorsWebFilter），不同研发团队配置标准不一，极易产生漏洞或预检 OPTIONS 阻断问题。

③ 认证鉴权与流量限流逻辑严重重复编写 Duplicated Logic

JWT 验签、OAuth2 Token 校验、IP 黑白名单与防刷限流代码散落在每个业务服务中。非业务通用逻辑污染了核心业务代码。

④ 缺乏统一全局入口可观测性与审计监控 No Global View

无法在全局网络入口处收集统一的访问日志、RTT 延迟和请求成功率，给全局链路追踪与 DDOS 攻击抵御带来极大困难。

下一个核心：API 网关的 4 大核心职责深度解构 (Part 04 续)

核心架构启发 (API Gateway Pattern Insight)

API 网关是现代云原生微服务架构的**门面 (Facade Pattern)**。它将散落的跨域 (CORS)、身份鉴权 (Auth)、流量限流 (Rate Limiting) 与日志审计完全从业务微服务中剥离，使得后端团队能专注于核心业务逻辑。
