Part 02 · RESTful 架构风格与资源设计 (RESTful Architecture & Resource Design)

星巴克 RESTful 订单生命周期：订单创建与状态更新

Step 1: Order Creation (POST /order) & Step 2: Order Modification with Conflict Validation (PUT /order/1234)

阶段 1：创建订单资源 (Place Order - POST /order) 201 Created
客户端 HTTP 请求 (POST /order) Request Payload
POST /order HTTP/1.1
Host: starbucks.example.org
Content-Type: application/xml
<order xmlns="http://starbucks.example.org/">
<drink>latte</drink>
</order>
服务端 HTTP 响应 (201 Created + 超媒体超链接) Location Header
HTTP/1.1 201 Created
Location: http://starbucks.example.org/order/1234
Content-Type: application/xml
<order xmlns="http://starbucks.example.org/">
<drink>latte</drink>
<cost>3.00</cost>
<!-- 超媒体驱动：直接注入下一步支付链接 -->
<next rel="http://starbucks.example.org/payment"
uri="http://starbucks.example.com/payment/order/1234" />
</order>
Location 标头作用 指向新增资源派生的唯一 URI 地址 (`/order/1234`)
rel & uri 超媒体 告知客户端下一步允许调用的支付接口 URI
关键特点：服务端在响应体中包含未来允许跳转的状态迁移超链接
阶段 2：修改订单与状态守卫校验 (PUT /order/1234) Order Modification
场景 A：未开始制作前修单成功 (200 OK) State: Placed

若咖啡师尚未接单制作，顾客可以通过 PUT /order/1234 增加配料（加浓缩 Shot）：

PUT /order/1234 HTTP/1.1   ⇒   HTTP/1.1 200 OK
<order xmlns="http://starbucks.example.org/">
<drink>latte</drink>
<additions>shot</additions>
<cost>4.00</cost>
</order>
场景 B：已开始制作时修改失败 (409 Conflict) State: Chosen

若咖啡师已经通过 Atom Feed 锁定接单开始做咖啡，服务端将拦截并发修改并回绝请求：

HTTP/1.1 409 Conflict
<!-- 状态机校验锁定：告知顾客订单已被咖啡师锁定，无法修改 -->
<order xmlns="http://starbucks.example.org/">
<status>PREPARING</status>
<cost>3.00</cost>
</order>
OPTIONS 端点嗅探：预检资源支持的动作

客户端可在更新前发起 OPTIONS /order/1234 查询，服务端在响应头返回 Allow: GET, PUT, DELETE，指明当前状态可接受的操作。

下一个阶段：订单支付处理 (PUT /payment/order/1234) 与咖啡师订单列表

核心架构启发 (State Machine Transition Insight)

资源状态机的转换规则**由服务端契约严格保护**。通过对不同状态请求返回 201 Created、200 OK 或 409 Conflict，RESTful 接口能够以自描述且安全的方式指导客户端完成复杂的交易生命周期。

🎯 引导学生剖析订单创建阶段的响应特征： “向学员深入强调：当客户端通过 `POST /order` 创建新资源时，规范的服务端应当回传 `201 Created` 状态码，并在 `Location` 头中附带派生的新 URI（如 `/order/1234`）。响应 Payload 中的 `` 超链接体现了 HATEOAS 核心机制，引导客户端发起下一个支付请求。”
💡 分析状态冲突 409 Conflict 的业务防重意义： “请学员关注右侧的场景 B：如果咖啡师已经在后台接单并处于准备状态 (`Preparing`)，顾客此时试图修改订单将触发状态机的守卫逻辑，服务端通过返回 `409 Conflict` 防范并发竞争与非法状态转移。”
