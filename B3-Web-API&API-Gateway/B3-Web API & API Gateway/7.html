Part 01 · SOAP 协议与 XML 契约机制 (SOAP & XML Schema)

Spring WS 服务端开发：模式优先 (Schema-First) 架构

Contract-First SOAP Service Development with XML Schema (.xsd) & JAXB2 Maven Plugin

1. 模式优先 (Schema-First) 开发哲学 Contract-First vs Code-First

在现代企业级 SOAP 服务开发中，Spring 框架强烈主张 **契约优先 (Contract-First / Schema-First)**：即先编写不可变的数据契约（`` 文件），再通过自动化编译插件推导出 Java 实体类（DTOs），而非从 Java 代码反向生成 WSDL。

彻底避免“类-契约 (Java-to-XML)”耦合噩梦 Stability

如果从 Java 类反向生成 XML，一旦 Java 属性或包路径重构，将破坏线上已有异构客户端（如 .NET 或 C++ Client）的 XML 序列化兼容性。

精确的数据校验 (XSD Strong Typing) Strict Schema

XSD 原生支持字符串枚举限制（`xs:enumeration`）、正则模式匹配与强类型数值范围校验，将不合规报文挡在 Spring Endpoint 业务逻辑之外。

Spring Boot SOAP 核心起步依赖
spring-boot-starter-web-services 引入 Spring WS 框架与 SAAJ 消息处理库
wsdl4j / wsdl4j 用于在运行时根据 XSD 动态生成 WSDL 契约
架构准则：契约一旦发布，只能向前兼容扩展，严禁破坏性修改
2. Maven 依赖与 JAXB2 编译插件配置 (pom.xml) pom.xml
<!-- 1. Spring Web Services 核心依赖 -->
<dependency>
<groupId>org.springframework.boot</groupId>
<artifactId>spring-boot-starter-web-services</artifactId>
</dependency>
<dependency>
<groupId>wsdl4j</groupId>
<artifactId>wsdl4j</artifactId>
</dependency>
<!-- 2. JAXB2 Maven 插件：根据 XSD 自动编译产生 Java 实体类 -->
<plugin>
<groupId>org.codehaus.mojo</groupId>
<artifactId>jaxb2-maven-plugin</artifactId>
<version>3.1.0</version>
<executions>
<execution>
<id>xjc</id>
<goals><goal>xjc</goal></goals>
</execution>
</executions>
<configuration>
<sources>
<source>${project.basedir}/src/main/resources/countries.xsd</source>
</sources>
</configuration>
</plugin>
XJC 编译目标 (xjc Goal)

在 `mvn compile` 阶段自动执行 XJC，把 `.xsd` 转换为带 JAXB 注解的 DTO 类。

动态契约适配

`wsdl4j` 使得服务端在运行时能将内存 Schema 实时发布为 `.wsdl` URL。

自动化工作流：修改 XSD 文件后执行 mvn compile 即可完成代码同步

核心架构启示 (Schema-First Principle)

采用 **Schema-First** 模式，将 XML 契约定义与 Java 代码的编写彻底解耦。这种以契约为核心（Contract-Centric）的架构思想，也是现代化 RESTful (OpenAPI/Swagger) 以及 gRPC (Protobuf) 模式优先开发的鼻祖。
