2. 核心架构问题与课堂研讨 (Q&A Topics) Classroom Discussion
Q1 RESTful 规范中 PUT 和 PATCH 的本质区别是什么？

**讨论点**：`PUT` 要求全量替换（未提交字段清空且具幂等性），`PATCH` 为局部增量更新。若更新提交的数据违反业务规则或字段类型不匹配，服务端应当分别返回哪些 HTTP 状态码（如 400 vs 422）？

Q2 为什么云原生微服务架构普遍采用“对外 REST，对内 gRPC”？

**讨论点**：对外暴露 RESTful/JSON 保证了前端与多端消费的通用性与零门槛；对内使用二进制 gRPC/Protobuf+HTTP/2 多路复用提升了高并发 IPC 吞吐。API 网关是如何高效完成这两种协议转码 (Transcoding) 的？

Q3 开启 `allowCredentials(true)` 时为什么禁止 `allowedOrigins("*")`？

**讨论点**：W3C CORS 规范出于防止 CSRF 跨站请求伪造与 Cookie 泄漏的考虑，禁止泛通配符。若生产环境必须支持特定泛子域名（如 `https://*.example.com`），Spring Boot 的 `allowedOriginPatterns` 内部机制是如何安全的？
