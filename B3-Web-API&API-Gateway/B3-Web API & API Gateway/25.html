Part 03 · Spring Boot REST 开发与 CORS 安全 (Spring Boot REST & CORS)

Spring Boot CORS 跨域治理实现策略

Granular @CrossOrigin, Global WebMvcConfigurer & Filter-Level CorsFilter for Spring Security

1. Spring Boot 中的 3 种 CORS 配置粒度 Configuration Levels
① `@CrossOrigin` 细粒度注解 (局部级别) Controller / Method

直接标注在 Controller 类或具体 Handler 方法上：@CrossOrigin(origins = "http://localhost:3000")。适合局部端点快速定制，但不推荐大规模项目零散维护。

② `WebMvcConfigurer` 全局配置 (推荐方式) Global Web MVC

重写 addCorsMappings(CorsRegistry registry) 方法。统一对路由通配符（如 /**）设置 Origins、Methods、Headers 与 maxAge 预检缓存时长。

③ `CorsFilter` 过滤器级别 (Spring Security 必备) Filter Chain

结合 Spring Security 时，MVC 拦截器生效时间晚于 Security 过滤器，会导致 `OPTIONS` 预检被 401 拦截。必须通过注册最高优先级的 CorsFilter Bean 来保证预检顺利放行！

凭证允许陷阱：`allowCredentials(true)` 与通配符 `*` W3C Strict Guard

当允许跨域传递 Cookie 凭证（allowCredentials(true)）时，allowedOrigins 绝对不允许配置为泛通配符 *！必须改用 allowedOriginPatterns 支持正则匹配。

架构提示：结合微服务 API 网关时，建议将 CORS 配置统一收拢在网关层执行
2. 全局跨域配置类实现 (`CorsConfig.java`) CorsConfig.java
package com.example.restservice.config;
import org.springframework.context.annotation.*;
import org.springframework.http.HttpHeaders;
import org.springframework.web.servlet.config.annotation.*;
@Configuration
public class CorsConfig implements WebMvcConfigurer {
@Override
public void addCorsMappings(CorsRegistry registry) {
registry.addMapping("/**") // 1. 映射所有 REST 端点路径
.allowedOriginPatterns("http://localhost:3000", "https://*.example.com")
.allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
.allowedHeaders("*") // 允许携带 Authorization 等自定义 Header
.exposedHeaders(HttpHeaders.SET_COOKIE, "X-Total-Count") // 暴露自定义 Header
.allowCredentials(true) // 允许客户端跨域携带 Cookie
.maxAge(1800); // OPTIONS 预检结果在浏览器缓存 30 分钟
}
}
maxAge(1800) 性能优化 告知浏览器在 30 分钟内复用 preflight 批准，避免后续业务请求产生双倍 RTT 延迟
exposedHeaders 字段暴露 默认情况下，JavaScript 仅能读取 6 个基本响应标头，暴露属性后才可读取分页或 Token

核心架构启发 (Spring Boot CORS Configuration Insight)

CORS 是 Web 容器在客户端与服务端之间达成的信任契约。在 Spring Boot 项目中，正确使用 allowedOriginPatterns 与 maxAge，既能保障携带 Credential Cookie 时的安全防御，又能避免 OPTIONS 预检请求造成的性能损耗。
