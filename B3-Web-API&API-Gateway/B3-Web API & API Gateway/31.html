网关流量控制实战：Redis 分布式令牌桶限流

Gateway Rate Limiting in Practice: Distributed Token Bucket Algorithm with Spring Cloud Gateway & Redis

1. 分布式令牌桶 (Token Bucket) 算法原理 Token Bucket Mechanism
① 速率填充与突发容量 (Replenish Rate & Capacity) Burst Tolerant

**机制**：系统以固定速率（replenishRate，如 100/s）往桶中添加令牌，桶的最大容量为 burstCapacity。当并发请求到来时，从桶中取走 1 个令牌；若桶空，则直接触发降级响应（HTTP 429 Too Many Requests）。
**优势**：相较于漏桶 (Leaky Bucket) 的绝对匀速限制，令牌桶**天然支持应对瞬间突发流量 (Burst Traffic)**。

② Redis + Lua 脚本原子的无锁高并发计数 Atomic Redis Lua

**无锁架构**：集群模式下多个 Spring Cloud Gateway 节点共享集中式 Redis。RequestRateLimiter 利用底层原子的 Lua 脚本在 Redis 内部计算令牌填补充扣减，避免多网关节点并发竞态，且延迟低于 1ms。

限流状态码：被限流请求返回 `HTTP 429 Too Many Requests`
2. 网关限流配置 (`application.yml` & `KeyResolver.java`) SCG RequestRateLimiter
# application.yml: 激活分布式 RequestRateLimiter 限流过滤器
spring:
cloud:
gateway:
routes:
- id: order_service_route
uri: lb://order-service
predicates:
- Path=/api/v1/orders/**
filters:
- name: RequestRateLimiter
args:
redis-rate-limiter.replenishRate: 100 # 令牌生成速率 (100/s)
redis-rate-limiter.burstCapacity: 200 # 令牌桶最大容量上限
key-resolver: "#{@userKeyResolver}" # 引用限流维度 Bean
// RateLimiterConfig.java: 自定义基于 User ID 或 Client IP 的限流解析器
@Configuration
public class RateLimiterConfig {
@Bean
public KeyResolver userKeyResolver() {
return exchange -> {
String userId = exchange.getRequest().getHeaders().getFirst("X-User-Id");
if (userId != null) return Mono.just(userId); // 1. 按登录用户维度
return Mono.just(exchange.getRequest().getRemoteAddress().getAddress().getHostAddress()); // 2. 备选 IP 维度
};
}
}
