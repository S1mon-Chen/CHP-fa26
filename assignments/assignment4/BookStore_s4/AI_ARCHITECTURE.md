# 智能在线书店架构设计

## 1. 架构概述

### 1.1 架构演进
- **现状**：传统响应式网页应用，分层架构（Controller -> Service -> Repository）
- **目标**：感知型智能体架构，引入AI能力实现"懂业务、能查数、会下单"的完整闭环

### 1.2 技术栈增强

| 类别 | 现有技术 | 新增技术 |
|------|---------|----------|
| 前端 | React/AntD/Vite | 保持不变，增强AI交互界面 |
| 后端 | SpringBoot/Spring Data JPA/Spring Security | Spring AI, MCP Server |
| 数据库 | MySQL | Vector DB (ChromaDB) |
| AI能力 | 无 | RAG, 大语言模型集成 |

## 2. 智能后端架构设计

### 2.1 核心架构层次

```
┌─────────────────────────────────────────────────────────────┐
│                       前端层                                │
├─────────────────────────────────────────────────────────────┤
│                  API Gateway / Controller                  │
├─────────────────────────────────────────────────────────────┤
│   ┌───────────────┐ ┌───────────────┐ ┌───────────────┐    │
│   │  业务服务层   │ │  智能服务层   │ │  MCP执行层    │    │
│   └───────────────┘ └───────────────┘ └───────────────┘    │
├─────────────────────────────────────────────────────────────┤
│                  数据访问层 (Repository)                  │
├─────────────────────────────────────────────────────────────┤
│         ┌───────────────┐ ┌───────────────┐               │
│         │  关系数据库   │ │  向量数据库   │               │
│         └───────────────┘ └───────────────┘               │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 智能服务层设计

#### 2.2.1 核心组件
- **AI Assistant Service**：智能助手核心服务，处理用户自然语言请求
- **RAG Service**：检索增强生成服务，从向量数据库获取相关领域知识
- **Intent Recognition**：意图识别，理解用户请求的具体意图
- **Action Executor**：动作执行器，执行具体的业务操作

#### 2.2.2 数据流
1. 用户通过前端发送自然语言请求
2. Controller接收请求并转发给AI Assistant Service
3. AI Assistant Service进行意图识别
4. 根据意图，RAG Service从向量数据库检索相关知识
5. 大语言模型生成响应
6. 如需执行具体操作，通过MCP Server执行
7. 将结果返回给用户

### 2.3 MCP执行层

#### 2.3.1 功能
- 提供AI与后端系统的交互接口
- 执行具体的业务操作，如查询书籍、下单等
- 确保操作的安全性和可靠性

#### 2.3.2 核心API
- `executeAction(actionType, params)`：执行指定类型的动作
- `validateAction(actionType, params)`：验证动作的合法性
- `monitorActionExecution()`：监控动作执行状态

### 2.4 向量数据库

#### 2.4.1 数据存储
- 书籍信息：标题、作者、描述、分类等
- 用户行为数据：购买历史、浏览历史等
- 业务规则：促销规则、库存管理规则等

#### 2.4.2 检索策略
- 语义搜索：根据用户查询的语义相关性检索
- 多模态检索：支持文本、图像等多种输入方式
- 个性化检索：根据用户历史行为优化检索结果

## 3. 智能助手功能设计

### 3.1 核心能力

#### 3.1.1 懂业务
- 理解书籍相关知识（作者、分类、内容简介等）
- 掌握书店业务规则（促销活动、会员政策等）
- 了解用户偏好和历史行为

#### 3.1.2 能查数
- 查询书籍库存
- 统计销售数据
- 分析用户行为
- 生成报表

#### 3.1.3 会下单
- 处理用户订单
- 管理购物车
- 处理支付流程
- 跟踪订单状态

### 3.2 典型场景

#### 3.2.1 书籍推荐
- 用户："推荐几本关于人工智能的书籍"
- 助手：分析用户历史偏好，检索相关书籍，生成推荐列表

#### 3.2.2 订单管理
- 用户："我想查看我的订单"
- 助手：识别用户身份，检索订单信息，展示订单列表

#### 3.2.3 智能查询
- 用户："最近有什么促销活动"
- 助手：检索促销规则，生成促销信息

#### 4.1.1 依赖添加
- Spring AI
- MCP Server
- ChromaDB Client

#### 4.1.2 核心类设计

- `RAGService`：检索增强生成服务

### 4.2 前端增强

#### 4.2.1 AI交互界面
- 聊天界面：支持自然语言交互
- 智能推荐区域：展示个性化推荐
- 语音输入：支持语音交互

#### 4.2.2 数据流
- 前端发送用户请求到后端
- 后端处理并返回AI响应
- 前端展示响应结果
- 支持多轮对话

## 5. 部署与集成

### 5.1 部署架构
- 主应用：Spring Boot应用
- MCP Server：独立部署
- 向量数据库：独立部署
- 大语言模型：可选择云服务或本地部署

### 5.2 集成方案
- REST API：前后端通信
- MCP API：AI与后端系统通信
- 向量数据库API：RAG服务与向量数据库通信

## 6. 安全与监控

### 6.1 安全措施
- 身份认证：确保用户身份合法性
- 权限控制：限制AI执行的操作范围
- 数据加密：保护敏感数据
- 审计日志：记录AI操作

### 6.2 监控与运维
- 性能监控：监控AI响应时间和资源使用
- 错误监控：捕获和处理AI执行错误
- 日志管理：记录系统运行状态
- 告警机制：及时发现和处理异常
