1. 服务端 Message Selectors 消息过滤器 SQL-92 Expression

Broker 侧零网络损耗拦截 (Server-Side Filtering)

Consumer 在创建时传入 SQL-92 选择器字符串，**JMS Provider 直接在 Broker 侧进行匹配与丢弃**，不合要求的消息不会占用 TCP 网络带宽推送给客户端。

// 1. Producer 标记属性 (Properties)
TextMessage msg = context.createTextMessage("VIP Order");
msg.setStringProperty("Region", "EAST");
msg.setIntProperty("Priority", 5);
// 2. Consumer 声明 SQL-92 选择器表达式
String selector = "Region = 'EAST' AND Priority >= 4";
JMSConsumer consumer = context.createConsumer(queue, selector);

QueueBrowser 只读非破坏性探测 Non-Destructive Read

允许系统监控工具窥探 Queue 中的消息标头与载荷，**不会改变消息状态，也不会导致消息被弹出或 Ack 移除**。

QueueBrowser browser = context.createBrowser(queue);
关键优势：精准路由匹配 + 可视化无损运维探测

// 持久订阅物理生命周期：离线期间消息存盘，重连后补发
1. Active Sub Receives Msg M1, M2 synchronously
2. Disconnected Broker retains M3, M4, M5 in persistent storage
3. Reconnected Delivers retained M3, M4, M5 to subscriber

JMS 2.0 持久订阅与共享消费 API JMS 2.0 API

// 1. 创建普通持久订阅 Consumer (独占实例)
JMSConsumer consumer = context.createDurableConsumer(topic, "SubName");
// 2. JMS 2.0 共享持久订阅 (支持集群负载均衡平摊 Topic 离线积压)
JMSConsumer sharedConsumer = context.createSharedDurableConsumer(topic, "GroupSub");
JMS 异常管理体系 (`JMSException`)

JMS 规范所有受检异常派生自 `JMSException`（如 `InvalidSelectorException`, `TransactionRolledBackException`），提供链式网络错误定位信息。

Message Selectors 让数据过滤前置在 Broker 侧，节约网络带宽；而 Durable Subscription 让广播 Topic 具备了不丢失离线消息的坚固特性。这两大机制是构建高可靠分布式事件驱动系统的基石。

Speaker Notes / 讲师讲稿
🎯 引导学生透视 Message Selectors 的优化机制： “向学员做解构说明：Message Selectors 的强大之处在于它是在 Broker 服务端拦截并过滤消息的。这就好比在数据库层面做 WHERE 过滤，极大地降低了客户端网络 I/O 开销。”
💡 强调 JMS 2.0 共享持久订阅的突破： “提示学员：在 JMS 1.1 中，持久订阅是单 Consumer 独占的；而在 JMS 2.0 中引入了 `createSharedDurableConsumer`，允许同一个持久订阅名字下挂载多个 Consumer 实例，从而可以在 Topic 上实现‘持久积压 + 负载均衡平摊’的双重优势。”
