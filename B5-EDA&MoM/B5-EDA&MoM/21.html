Kafka 常用运维命令行交互链 (Kafka Operational CLI Pipeline) KRaft Native: `--bootstrap-server localhost:9092`
1. Topic 创建
kafka-topics.sh --create
声明 Partition 与 Replication Factor
2. 交互式 Producer
kafka-console-producer.sh
支持指定 Key 分隔符与 Headers
3. 消费与历史重放
kafka-console-consumer.sh
支持 `--from-beginning` 与格式打印
4. 消费组 Lag 监控
kafka-consumer-groups.sh
排查积压与重置 Offset 指针
1. Topic 生命周期管理与 Consumer Group 积压排查 Topics & Groups
// A. 创建 3 分区 2 副本的 Topic (`kafka-topics.sh`)
kafka-topics.sh --bootstrap-server localhost:9092 \
  --create --topic order-events \
  --partitions 3 --replication-factor 2
// B. 查看 Topic 详细元数据分布（Leader & ISR 列表）
kafka-topics.sh --bootstrap-server localhost:9092 \
  --describe --topic order-events
// C. 排查 Consumer Group 积压情况 (LAG = LOG-END - CURRENT)
kafka-consumer-groups.sh --bootstrap-server localhost:9092 \
  --describe --group order-group
// D. 紧急事故：重置消费组 Offset 到最最早时间点进行重放
kafka-consumer-groups.sh --bootstrap-server localhost:9092 \
  --group order-group --topic order-events \
  --reset-offsets --to-earliest --execute
运维要领：不再依赖 `--zookeeper` 标志，统一使用 `--bootstrap-server`
2. 交互式 Console Producer 与格式化 Console Consumer Producer & Consumer
// A. 发送包含 Key 的事件（解析 Key-Value 冒号分隔符）
kafka-console-producer.sh --bootstrap-server localhost:9092 \
  --topic order-events \
  --property parse.key=true \
  --property key.separator=":"
> order_1001:{"status":"CREATED","amount":299.00}
> order_1002:{"status":"PAID","amount":150.00}
// B. 消费消息并打印 Key、Timestamp、Partition 信息
kafka-console-consumer.sh --bootstrap-server localhost:9092 \
  --topic order-events --from-beginning \
  --group order-group \
  --property print.key=true \
  --property print.timestamp=true \
  --property print.partition=true

🎯 引导学生掌握 Kafka 现代化 CLI 参数： “向学员做解构：在过去的 Kafka 教程中，许多命令使用 `--zookeeper` 参数。自 KIP-500 移除 ZooKeeper 后，在 Kafka 3.x/4.x 中统一改用 `--bootstrap-server localhost:9092`。提示学员特别关注带 Key 发送与消费打印格式的命令标志。”
💡 剖析 `kafka-consumer-groups.sh` 线上故障排查： “请学员重点关注 `kafka-consumer-groups.sh`：在生产线上发生消费者卡死或消息积压时，通过 `--describe --group` 能一眼看出哪一个 Partition 发生了 LAG 积压；若由于代码 Bug 导致坏消息阻塞，可使用 `--reset-offsets --to-earliest` 或跳过问题 Offset 进行恢复。”
