CQRS 读写责任分离架构：原理、模型与事件双写控制

Command Query Responsibility Segregation, Normalized Write DB vs. Denormalized Read Views & Async Event Projection

CQRS 命令与查询数据流解耦管线 (CQRS Architecture & Event Projection Pipeline) Command (ACID) $\to$ Domain Event $\to$ Event Bus $\to$ Projection $\to$ Query Store
1. 命令模型 (Command Model) Write Side
命令 (Command): CreateOrderCommand
写数据库 (Write DB): MySQL (规范化范式表)
校验领域约束与业务规则，保障 ACID 强一致性落盘。
2. 领域事件总线 (Event Bus)
OrderCreatedEvent
Kafka / Pulsar 异步广播，触发下游写模型投影 (Projection)。
3. 查询模型 (Query Model) Read Side
读存储 (Read Store): Elasticsearch / Redis / MongoDB
视图形态: 反规范化 (Denormalized Views, 零 JOIN)
按 UI 展示需求定制平铺视图，极致提升高并发读吞吐与响应延迟。
1. CQRS 核心原理与模型分离三大价值 Command/Query Segregation

读写模型完全独立（高内聚领域模型 vs. 平铺 UI 视图） Model Independence

传统单模型架构下，写模型需满足 3NF 范式约束，而读模型需要复杂多表 `JOIN` 甚至大字段聚合。CQRS 允许写侧使用高一致性关系型 DB，读侧使用 Elasticsearch 或 Redis 存储平铺 JSON 视图，彻底解决读写模式冲突。

读写性能非对称扩展（Asymmetric Scaling） Independent Scaling

互联网应用中，读流量通常是写流量的 10 倍乃至 100 倍（Read-Heavy）。CQRS 允许独立扩容读存储副本与缓存，而无需扩容高成本的写主库，极大节省硬件资源开销。

架构权衡：接受最终一致性 (Eventual Consistency) Lag Handling

读模型通过事件异步投影更新，存在毫秒级的同步延时（Eventual Consistency）。前端可通过客户端 UI 优化（如预渲染本地状态）避免“刚提交写操作却查不到”的体验问题。

黄金准则：不要盲目全量引入！仅在读写吞吐非对称或领域模型极度复杂时使用 CQRS
2. CQRS 命令写处理与读视图投影代码实战 Spring Boot 3
// A. 命令写服务：保存写 DB 并广播领域事件 (`OrderCommandService.java`)
@Service
public class OrderCommandService {
@Autowired private OrderRepository orderRepo; // MySQL 写库
@Autowired private KafkaTemplate<String, Object> kafkaTemplate;
@Transactional
public String handleCreateOrder(CreateOrderCommand cmd) {
Order order = new Order(cmd.getUserId(), cmd.getItems());
orderRepo.save(order); // 1. 规范化数据库落盘
OrderCreatedEvent event = new OrderCreatedEvent(order.getId(), order.getUserId(), order.getAmount());
kafkaTemplate.send("order-events", order.getId(), event); // 2. 发送广播事件
return order.getId();
}
}
// B. 读视图投影监听器：异步消费事件并更新 ES 读视图 (`OrderProjectionListener.java`)
@Component
public class OrderProjectionListener {
@Autowired private OrderViewElasticRepository orderSearchRepo; // ES 读库
@KafkaListener(topics = "order-events", groupId = "cqrs-projection-group")
public void onOrderCreated(OrderCreatedEvent event, Acknowledgment ack) {
OrderReadView view = new OrderReadView(event.getOrderId(), event.getUserId(), event.getAmount());
orderSearchRepo.save(view); // 构造平铺 JSON 并更新 Elasticsearch 读模型
ack.acknowledge();
}
}

核心架构启发 (CQRS Architecture Insight)

CQRS 的核心精髓在于**“放弃单模型幻想”**。通过将命令（Command）与查询（Query）从数据结构到物理存储层彻底剥离，配合 Kafka 异步事件投影，让写入模型保持业务规则的纯粹一致性，让查询模型享受毫秒级平铺检索的极致性能。
