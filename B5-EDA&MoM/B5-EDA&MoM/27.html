1. 毒丸消息 (Poison Pill) 死锁机制与容错三原则 Poison Pill Defense

毒丸消息 (Poison Pill) 引起的 Partition 卡死死锁 Infinite Loop

如果 Producer 发送了不合法的 JSON 字节，原始 `JsonDeserializer` 会在 `poll()` 阶段直接抛出 `DeserializationException`。若未经特殊包装，容器捕获异常后重新拉取该消息，导致 **无限死循环卡死当前 Partition**。

使用 `ErrorHandlingDeserializer` 委派包装 Delegating Wrapper

生产环境必须使用 Spring Kafka 的 ErrorHandlingDeserializer 包装实际的反序列化器。解包失败时它会捕获异常并返回 `null`，同时把原始字节与异常存入 Record Header，使消息能顺畅传给 Listener 容器。

`DeadLetterPublishingRecoverer` 自动推入 `.DLT` DLQ Forwarding

结合 DefaultErrorHandler，在重试次数耗尽或遭遇反序列化等非重试异常时，通过 Recoverer 自动将损坏消息转发至 {topic}.DLT 死信主题，安全推进主 Partition 的 Offset。

核心原则：坏消息绝不阻塞主流量，死信进入 DLT，主 Offset 必须前发
2. 生产级 ErrorHandler 与 YAML 序列化配置 Java & YAML Config
// A. 挂载 CommonErrorHandler 配置文件 (`KafkaErrorConfig.java`)
@Configuration
public class KafkaErrorConfig {
@Bean
public CommonErrorHandler errorHandler(KafkaTemplate<Object, Object> template) {
// 1. 自动将重试失败或毒丸消息发往 {topic}.DLT
DeadLetterPublishingRecoverer recoverer = new DeadLetterPublishingRecoverer(template);
// 2. 最多重试 3 次，每次退避 1000ms
DefaultErrorHandler handler = new DefaultErrorHandler(recoverer, new FixedBackOff(1000L, 2L));
// 3. 设定反序列化异常为不可重试异常，直接推入 DLT
handler.addNotRetryableExceptions(DeserializationException.class);
return handler;
}
}
# B. application.yml 配置 ErrorHandlingDeserializer
spring.kafka.consumer:
value-deserializer: org.springframework.kafka.support.serializer.ErrorHandlingDeserializer
properties:
spring.deserializer.value.delegate.class: org.springframework.kafka.support.serializer.JsonDeserializer
spring.json.trusted.packages: "com.example.domain"

核心架构启发 (Poison Pill Resilience Insight)

消费端健壮性的关键在于**隔离损坏报文**。通过 ErrorHandlingDeserializer 包装加上 DeadLetterPublishingRecoverer，可以在发生坏数据或反序列化失败时无缝将该记录压入死信队列 .DLT，主 Partition 顺利前推 Offset，实现线上主管线 100% 零卡死。

🎯 引导学生理解“毒丸消息”与反序列化死锁： “向学员强调：如果在生产环境中突然有一个格式损坏的字节流传入，普通的 `JsonDeserializer` 会直接在拉取时抛出异常。因为 Offset 没有推进，下一轮 `poll()` 会继续拉取同一个坏字节，导致消费线程陷入无限死循环卡死当前分区。这就是‘毒丸消息 (Poison Pill)’。”
