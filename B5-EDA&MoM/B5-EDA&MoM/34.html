1. “双写不一致”硬伤与 Transactional Outbox 解法 Outbox & CDC Core

直接“写数据库 + 发 Kafka”的双写不一致死穴 Dual-Write Vulnerability

传统代码先执行 db.save() 再执行 kafka.send()。若数据库成功但网络抖动导致发送失败，或者 Kafka 发送成功但事务提交时数据库崩溃，都会导致**数据库状态与消息事件永久不一致**。

利用 RDBMS 本地事务打通 Outbox 数据表 Local ACID Integration

放弃直接在主业务逻辑中调用 Kafka 发送。将准备抛出的事件对象转化为 JSON 记录，与业务实体在**同一个 RDBMS 本地 ACID 事务中**写入独立的 outbox 临时数据表中，保证落盘绝对原子化。

Change Data Capture (CDC / Debezium) 无侵入提速 Log Tailing Engine

替代传统的轮询线程（`SELECT ... FOR UPDATE`，容易造成数据库高 CPU 与行锁竞争），使用 Debezium 监听 MySQL Binlog 或 PostgreSQL WAL，毫秒级将 `outbox` 变更捕获并投递到 Kafka。

黄金法则：将分布式跨系统双写，降维转化为同数据库的本地 ACID 事务写
2. 本地事务 Outbox 写入与事件结构 (`OrderService.java`) Spring Boot & JPA
// 1. 本地事务原子写入 Outbox 表 (`OrderService.java`)
@Service
public class OrderService {
@Autowired private OrderRepository orderRepo;
@Autowired private OutboxRepository outboxRepo;
@Transactional // 开启单数据库本地 ACID 事务
public String createOrderInTransaction(CreateOrderReq req) {
// A. 保存业务实体记录
Order order = new Order(req.getUserId(), req.getAmount());
orderRepo.save(order);
// B. 在同一个本地事务中插入 Outbox 事件结构
OutboxEvent event = new OutboxEvent(
"Order", order.getId(), "OrderCreated",
toJsonPayload(order)
);
outboxRepo.save(event); // 原子落盘！
return order.getId();
}
}
// 2. Debezium Outbox 扩展配置参考 (`application.properties`)
debezium.transforms=outbox
debezium.transforms.outbox.type=io.debezium.transforms.outbox.EventRouter
debezium.transforms.outbox.table.fields.additional.placement=type:header

核心架构启发 (Transactional Outbox & CDC Insight)

Transactional Outbox + CDC 是分布式微服务解决“双写不一致”最优雅的黄金范式。它巧妙地将跨网络的不确定写操作降低为单数据库本地 ACID 事务落盘，并借助 DB Binlog 异步提取技术，实现了高吞吐、强一致与零业务侵入。

Speaker Notes / 讲师讲稿
🎯 引导学生透视“双写不一致”的根本原因： “向学员做解构说明：在很多系统中，开发者喜欢写 `orderRepo.save(order)` 接着写 `kafkaTemplate.send(event)`。一旦中间出现网络超时或数据库回滚，就会导致 DB 成功但 MQ 失败，或者 MQ 成功但 DB 回滚，造成永久不一致。Transactional Outbox 模式将这两个写操作同时放在单数据库本地事务里，写入 `outbox` 临时表，利用 ACID 事务彻底解决不一致。”
💡 剖析 CDC Engine (Debezium) 的无侵入提速优势： “请学员关注右侧代码与中间图解：早期人们使用定时线程轮询 `outbox` 表，但这会给数据库带来行锁竞争与 CPU 飙升。现代解法是配合 Debezium 或 Canal，直接读取数据库底层的 Binlog / WAL 事务日志，零业务线程占用，毫秒级抛给 Kafka。”
