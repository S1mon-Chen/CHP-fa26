1. 不可变追加日志 (Append-Only Commit Log) 原理 Sequential Write

消除磁盘随机寻道 (Eliminate Random I/O) Sequential I/O

Kafka 放弃了 B-Tree 等复杂的随机读写数据结构，采用最纯粹的顺序追加日志（Append-Only）。物理磁盘顺序写入的吞吐量可与内存随机读写相媲美。

事件不可变性 (Event Immutability) Immutable Data

写入 Log 的事件是客观发生的事实，**不可修改也不可原地删除**。即使发生数据更新，也是以发布新的“更新事件”的形式追加到 Log 尾部。

与消费状态解耦的保留策略 (Retention Policy) Time/Size Retention

日志保留时间（如 7 天或 1 个月）由配置项 log.retention.hours 决定，**与消息是否被消费完全无关**。

存储基石：顺序追加写赋能了千万级 QPS 吞吐与物理落盘安全
2. 单调递增 Offset 与游标式无损重放 (Replayability) Offset Cursor

分区内单调递增 Offset 序号 64-bit Int ID

每个写入 Partition 的事件均获取一个全局唯一的 64 位单调递增整数 **Offset**。消息在分区内的物理位置可以通过 Offset 进行精确的随机定位。

多 Consumer Group 独立游标指针 Group Independence

Consumer 仅需提交自己已消费到的 Offset。不同业务的 Consumer Group（如订单处理组与实时推荐计算组）拥有各自独立的消费游标，互不影响。

任意历史数据重放 (Log Replayability) Offset Rewind

当上线新算法、修复代码 Bug 或进行数据审计时，Consumer 可以调用 seek(offset) **将游标任意回退到历史时间点**，实现数据的无损重新消费。

核心架构启发 (Log & Offset Paradigm Shift)

打破 JMS “消费即摧毁” 的宿命，转向 不可变追加日志 + 独立 Offset 游标 的存算分离思维，是 Apache Kafka 获得**无限数据重放 (Replayability)** 与 **百倍吞吐扩展** 的最决定性创新。
