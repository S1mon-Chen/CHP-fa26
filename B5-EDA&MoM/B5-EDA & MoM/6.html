JMS Message 物理结构与 5 大载荷类型

JMS Message Headers, Application/JMSX Properties, Message Selectors & Body Payload Variants

JMS 消息物理物理三层分图 (JMS Message Physical Anatomy) Header (Required) + Properties (Optional) + Body (Optional)
1. Message Headers (消息头) Fixed System Fields

系统预定义标准元数据：`JMSMessageID`, `JMSDestination`, `JMSReplyTo`, `JMSCorrelationID`, `JMSDeliveryMode` ...

2. Message Properties (扩展属性) App / JMSX Props

自定义 Key-Value 属性（支持 SQL-92 Message Selectors 过滤）：`JMSXUserID`, `AppRegion`, `Priority` ...

3. Message Body (消息载荷) 5 Payload Types

灵活业务载荷：`TextMessage`, `MapMessage`, `BytesMessage`, `StreamMessage`, `ObjectMessage`.

1. 标准 Headers 元数据与 Message Selectors 过滤 SQL-92 Filtering

核心预定义 Header 标头 System Modifiable

JMSDestination 目标 Queue/Topic
JMSDeliveryMode PERSISTENT / NON
JMSReplyTo RPC 回复 Destination
JMSCorrelationID 关联请求链路 ID

Message Selectors 消息服务端过滤 SQL-92 Expression

Consumer 可在创建时指定 SQL-92 条件（基于 Properties），**Broker 会在服务端直接拦截过滤**，只推送符合条件的消息，极大地节省网络带宽。

// Producer 设置扩展属性
message.setStringProperty("Region", "CN_EAST");
message.setDoubleProperty("Amount", 1200.50);
// Consumer 使用 SQL-92 选择器表达式过滤
String selector = "Region = 'CN_EAST' AND Amount > 1000";
JMSConsumer consumer = context.createConsumer(queue, selector);
过滤性能：服务端路由拦截，避免无关消息灌满客户端网络
2. JMS Message Body 5 大核心载荷类型 JMS Payload Variants
TextMessage
文本消息（最常用）

包含一个 `java.lang.String` 对象。完美承载 **JSON, XML 或 HTML** 等结构化纯文本文本。

MapMessage
键值对字典消息

包含一系列 Name-Value 键值对。键为 `String`，值为 Java 基础类型。无序排列，支持随机检索。

BytesMessage
未解释二进制字节流

包含连续的原始 `byte[]` 字节数组。常用于对接已有二进制私有协议报文或音频/图片文件。

StreamMessage
顺序基础数据流

按写入顺序依次读取的 Java 原始类型数据流（Sequential Primitive Stream）。

ObjectMessage
Java 序列化对象

包含实现了 `Serializable` 接口的 Java 对象（注：跨语言兼容性较差，现代开发更推荐 `TextMessage` + JSON）。

开启下一个核心：Slide 7 · P2P (Queue) 与 Pub/Sub (Topic) 传递范式

核心架构启发 (Message Payload Best Practices)

在现代高并发微服务架构中，尽可能**避免使用依赖 JVM 强绑定的 `ObjectMessage`**，优先采用 TextMessage（搭配 JSON 文本）或 BytesMessage（搭配 Protobuf 二进制），以保障极高的跨语言互操作性与极致解析性能。
