1. 资源配置管理 (Admin / JNDI)

管理员创建 `ConnectionFactory` 与 `Destination` (Queue/Topic) 并绑定到 JNDI / Spring 容器。

2. 依赖注入与逻辑连接 (JMS Client)

应用通过 `@Resource` 或 Spring `@Autowired` 注入 CF 与 Destination，创建 `JMSContext` 实例。

3. 厂商独立服务 (JMS Provider)

底层的 ActiveMQ / Artemis 等消息代理处理真正的 TCP 网络传输、落盘持久化与事务协调。

1. JMS API 核心能力与平台契约特征 JSR 343 Spec

厂商无关性 (Provider Independence)

应用仅面向 `javax.jms` / `jakarta.jms` 标准接口编程。无论底层的 Provider 切换为 **ActiveMQ, Artemis, RabbitMQ JMS 插件, 还是 IBM MQ**，业务代码无需修改。

JTA 分布式事务集成 (Transaction Participation)

JMS 消息收发可无缝参与 **JTA (Java Transaction API)** 全局事务。允许在同一个 XA 事务中原子地完成数据库写操作与消息发送（要么全部提交，要么全部回滚）。

Message-Driven Beans (MDB) 容器并发池化

Java EE 容器（或 Spring Boot `@JmsListener`）通过线程池自动管理多实例并发拉取消息，提供高性能的高并发事件消费环境。

规范保证：标准 API + 灵活路由 + XA 强事务支持
2. JMS 1.1 冗长代码 vs JMS 2.0 `JMSContext` 流式 API JMS 2.0 Simplification
// ❌ 传统 JMS 1.1：极其冗长的嵌套建立与显式关闭
Connection connection = connectionFactory.createConnection();
Session session = connection.createSession(false, Session.AUTO_ACKNOWLEDGE);
MessageProducer producer = session.createProducer(queue);
TextMessage message = session.createTextMessage("Hello World");
producer.send(message);
// 繁琐的 try-finally connection.close() ...
// ✅ 现代 JMS 2.0：结合 JMSContext 与 AutoCloseable
try (JMSContext context = connectionFactory.createContext()) {
context.createProducer().send(queue, "Hello World (JMS 2.0)");
}
// 1 行链式调用完成 Producer 创建与消息投递，自动释放连接！
JMS 消息确认模式 (Acknowledge Modes)
AUTO_ACK 成功返回自动 Ack
CLIENT_ACK 客户端显式调用 `msg.acknowledge()`
DUPS_OK 允许重复，性能更高

核心架构启发 (JMS Standard Insight)

JMS 规范的最大功劳在于定义了 **Java EE 消息抽象统一语言**。无论是通过 JNDI 寻址还是 Spring 的依赖注入，JMSContext 彻底抹平了各种消息代理底层的套接字细节，实现了生产级的厂商无缝切换能力。

Speaker Notes / 讲师讲稿
🎯 引导学生透视 JMS 2.0 API 的重大简化： “向学员对比解析：在传统的 JMS 1.1 中，开发者需要依次手动创建 ConnectionFactory、Connection、Session，并在 `finally` 块中繁琐关闭。而 JMS 2.0 (JSR 343) 引入了 `JMSContext` 接口，它实现了 `AutoCloseable`，可以用单行代码 `context.createProducer().send(queue, body)` 极速发送消息。”
💡 强调 JTA 分布式事务支持： “提示学员注意：JMS 的一大杀手锏是原生支持 JTA 事务。在 Enterprise Java 中，这意味着对数据库的更新与对 JMS 队列的消息发送可以放入同一个全局 XA 事务中，保障强一致性。”
