1. 声明式监听器与并发容器核心机制 Spring Listener

`@KafkaListener` 声明式无侵入方法监听 Declarative Consumption

隐去底层的复杂的 `poll()` 无限循环，只需在 Spring Bean 方法上标注 @KafkaListener(topics = "...", groupId = "...")，框架会自动管理线程生命周期与异常唤醒。

灵活参数解构与 JSON 类型映射 Argument Resolvers

方法参数支持直接声明强类型 Java POJO、@Header(KafkaHeaders.RECEIVED_PARTITION) 标头、底层 ConsumerRecord 以及 Acknowledgment 提交对象。

手动提交模式 (`AckMode.MANUAL_IMMEDIATE`) Manual Ack

生产推荐关闭 `enable.auto.commit`，将容器 `ack-mode` 设为 `MANUAL_IMMEDIATE`。仅当业务代码成功无误后调用 ack.acknowledge()，实现真正的“At-Least-Once”防丢保证。

安全要点：配置 `spring.json.trusted.packages` 避免 JSON 注入安全漏洞
2. 生产级 `@KafkaListener` 与手动 Ack 实现 Java & YAML Config
// A. 消费者服务类 (`OrderConsumerService.java`)
@Component
@Slf4j
public class OrderConsumerService {
@KafkaListener(topics = "order-events", groupId = "order-service-group", concurrency = "3")
public void onOrderEvent(
@Payload OrderEvent event,
@Header(KafkaHeaders.RECEIVED_PARTITION) int partition,
@Header(KafkaHeaders.OFFSET) long offset,
Acknowledgment ack) {
// 执行幂等业务逻辑
log.info("Processing order [{}] from partition [{}] offset [{}]",
event.getOrderId(), partition, offset);
processOrder(event);
// 业务无异常后手动提交 Offset
ack.acknowledge();
}
}
# B. application.yml 反序列化与手动 Ack 配置
spring.kafka:
listener:
ack-mode: MANUAL_IMMEDIATE # 开启显式手动 Ack
consumer:
enable-auto-commit: false
value-deserializer: org.springframework.kafka.support.serializer.JsonDeserializer
properties:
spring.json.trusted.packages: "com.example.domain"
