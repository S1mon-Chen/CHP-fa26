事件驱动架构四大核心金律 (4 Golden Rules for Event-Driven Systems) Architectural Philosophy
金律一：假定重复必然发生，消费端逻辑强制幂等 (Idempotent Consumers)

网络抖动与集群 Rebalance 决定了“至少一次 (At-Least-Once)”传递是物理现实。借助 Redis SETNX 状态锁 与 数据库唯一约束 / 本地事务去重表，构建防重防线。

金律二：双写必有死穴，用 Outbox + CDC 将分布式写降维为本地 ACID (Outbox + CDC)

弃用脆弱的“写 DB + 发 MQ”双写调用。把事件以 JSON 存入单数据库本地事务 `outbox` 临时表，交由 Debezium / Binlog 异步无侵入提取投递。

金律三：放弃单模型幻想，用 CQRS 解耦高并发读写冲突 (CQRS Model Split)

写模型满足 3NF 范式进行校验写落盘；读模型存储在 Elasticsearch / Redis 中作为平铺 JSON 视图。借助 Kafka 领域事件异步投影，获得极限读写吞吐。

金律四：放弃 2PC 强锁枷锁，用 Saga 幂等补偿实现 BASE 最终一致 (Saga BASE)

微服务跨库长事务弃用 2PC / XA 全局锁。降维拆解为单服务本地事务链，配合 Kafka 事件驱动的正向执行 ($T_i$) 与逆向幂等补偿 ($C_i$) 恢复。

第 5 讲总结结语 (Lecture 05 Graduation)

掌握从 JMS 规范 到 Apache Kafka 追加日志 与 EDA 设计模式，标志着你已成功突破同步 RPC 的时空枷锁，具备了构建云原生时代高吞吐、高可用、柔性最终一致性分布式事件流系统的能力。
