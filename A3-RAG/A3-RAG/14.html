检索前置优化：查询改写 (Query Rewriting)

The Core Pain Point

用户提问极度简短（如带有错字、省略语或方言），与向量数据库中由专业严谨词汇构建的底层切片之间，存在无法直接对齐的物理语义距离。

Engineering Paradigm Shift
  • 1. 治水先治源：在 Query 送入 Embedder 之前，使用低时延模型对用户的原始提问进行对齐和词义扩充。
  • 2. 多维度对齐：将单点口语转换为 3 个适合检索的多角度精准、高保真关键词或短句。
query_rewriter.py 
def rewrite_query(user_query: str) -> list[str]:
    system_prompt = (
        "你是一个搜索专家。请将用户输入的模糊口语转换为"
        "3个不同角度的标准的、适合向量检索的关键词或短句，"
        "以标准的 Python 列表格式输出，无需额外解释。"
    )
    
    # 核心逻辑：驱动大模型，返回列表格式的改写关键词
    llm_output = call_llm(system_prompt, user_query)
    
    # 预期输出: ["HNSW 原理", "向量数据库索引优化", "ANN 算法时间复杂度"]
    return eval(llm_output)
系统架构师的延迟权衡 (Latency Trade-off)： 查询改写能在检索前解决约 40% 的相关性丢失问题，但会平白引入一轮额外的 LLM 推理开销。在实际的敏捷软件开发中，通常只对长度极短或含有冷门错别字的提问启用此改写模块，以严格守护首字响应时间（TTFT）。
