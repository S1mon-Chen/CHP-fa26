什么是 Agentic RAG (智能体化检索)

The Rigidity of Static RAG Pipelines

传统 RAG 的机械死板：不管三七二十一，哪怕用户只是打招呼（如 *“你好！”*）或提问常识，静态管道都会死板僵硬地强制运行一次耗时的向量索引和重排序流程，再被动地将一堆垃圾废话喂给大模型，造成巨大的**延迟浪费与算力损耗**。

The Autonomy of Agentic Retrieval
  • ● 交出系统“控制权”：大模型不再是流水线末端的被动总结者，而是手握多维工具库、控制整个检索生命周期的 **决策大脑 (Agent)**。
  • ● 意图按需分流 (Dynamic Intent)：大模型能够首先自审：要不要启动检索？查哪一个子数据库？还是直接调用工具或直接响应？
  • ● 主动反思与重试补救：检索出来的资料若判定相关度太低，大模型可自主舍弃，改写关键词进行二阶检索，甚至直接求助于全网搜索。

def agentic_rag_loop(user_query: str) -> str:
    # 1. 意图自审：大模型自主决定是否需要检索，抑或直接用参数内化知识作答
    intent = route_intent(user_query)
    if intent == "DIRECT_REPLY":
        return call_llm(user_query)
        
    # 2. 动态多路工具选择：根据意图路由选择特定的外部知识库
    kb_source = "tech_kb" if intent == "TECH" else "hr_kb"
    context = db.query(user_query, source=kb_source)
    
    # 3. 自反思纠偏补救：若召回结果质量低，自主重试并调用搜索引擎补救
    if not evaluate_relevance(context, user_query):
        context = google_search_api(user_query)
        
    return generate_answer(user_query, context)
工程思维飞跃 (Passive Retrieval to Active Reasoning)： 从静态 RAG 向 Agentic RAG 演进，是系统从**单纯的物理搬运数据**向**具有主动反思、工具链调配能力的自主智能体**发生的范式蜕变。大模型重新拿回了管道各阶段的审判决策权。动态路由能够从物理源头上砍掉 40% 的不必要检索，而自反思（Self-RAG）机制则通过自适应的重试补救确保了生产系统在高并发、长尾刁钻提问下的极致召回确定性。
