检索前置优化：假设性文档嵌入 (HyDE)

The Core Pain Point

提问与回答的几何异构性：用户提问往往很短且带口语，而知识库中的正确答案是详尽的标准长文。两者在向量表征空间中的投影特征可能极其不接近，导致相似性匹配首轮失效。

Mathematical Core Premise

利用 LLM 自主发散的“直觉”，先“瞎编”一个非绝对真实、但符合期望长相的技术草稿（假设性文档 $H$）。

💡 几何公理：在高维空间中，“假设文档 H ➔ 真实回答 D” 的语义特征距离，远远小于 “简短提问 Q ➔ 真实回答 D” 的距离。

def hyde_retriever(query: str, top_k: int = 2) -> list[dict]:
    system_prompt = (
        "请针对用户的技术提问，撰写一段契合专业学术"
        "文档规范的假设性回答草稿，无需保证事实绝对准确。"
    )
    
    # 1. 引导大模型编造符合真实答案“骨架特征”的假设性长文
    fake_doc = call_llm(system_prompt, query)
    
    # 2. 将“假答案”转为高维特征向量，替代原始简短提问进行检索
    fake_vector = get_ollama_embedding(fake_doc)
    return db.query(fake_vector, top_k=top_k)
工程落地警示 (以时间换精度)： HyDE 算法能够有效克服冷启动检索的相关度遗漏问题，但因为在首轮引入了额外的大模型推理开销（生成假文档），系统响应的首字延迟（TTFT）会增加 0.5s~1.5s。此方案更适合对精准度要求极严、但对耗时相对宽容的财务、法律及内部专业知识检索业务。
