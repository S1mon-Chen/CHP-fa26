检索中优化：混合检索 (Hybrid Search) 与两路召回

Vector Search Bottleneck

单语义向量检索的致命弱点：对精确匹配（如特定产品型号 v2.4.1、唯一股票代码、序列号）极其不敏感。向量化往往会因语义泛化，错误召回“相似但不精确”的噪点段落。

The Double-Edged Sword Solution
  • ● 1. 语义召回 (Dense Retrieval)：依靠向量神经网络，深度理解字面背后的抽象意图、多同义词和逻辑关联。
  • ● 2. 关键词召回 (Sparse Retrieval)：依靠经典的 BM25 算法，硬字面精确统计，百分百无偏差锁定专有名词。
Hybrid Search Pipeline Workflow

def hybrid_retriever(query: str, top_k: int = 5) -> list[dict]:
    # 1. 语义召回 (Dense Path) -> 捕获同义词与长语义抽象意图
    dense_res = db.dense_vector_search(get_embedding(query), limit=20)
    
    # 2. 精确召回 (Sparse Path) -> 锁定具体版本、型号、产品 ID
    sparse_res = db.sparse_bm25_search(query, limit=20)
    
    # 3. 倒数排名融合 (RRF) -> 将不同量纲的多路评分进行科学无偏归并
    ranked_docs = reciprocal_rank_fusion(dense_res, sparse_res)
    return ranked_docs[:top_k]
业界共识 (多路召回是生产落地的基石)： 混合检索是解决 RAG 系统面临特定专业专有名词失效的唯一工业标准解法。单纯基于语义向量的召回率（Recall）在面对版本号、特定产品代号时经常不尽人意。将 BM25 与 Dense 双管齐下，能完美兼顾系统的“深度语义理解”与“刚性字面拦截”。
