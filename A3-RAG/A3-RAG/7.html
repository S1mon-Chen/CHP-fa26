固定长度切分的弊端

强行按字符数切割会将核心句子“腰斩”，破坏自然语义。检索出的分块往往支离破碎，导致 LLM 理解困难。

✓

语义切分思路

  • • 利用文档原生的 # 层级结构。
  • • 保证物理段落完整，使块具有独立的话题。
  • • 建立“标题-正文”的强关联索引。
semantic_splitter.py 
def markdown_heading_chunker(md_text: str) -> dict[str, str]:
    lines = md_text.split("\n")
    current_section = "Introduction"
    chunks = {}
    
    for line in lines:
        if line.startswith("#"):
            current_section = line.lstrip("#").strip()
            chunks[current_section] = ""
        else:
            if current_section not in chunks:
                chunks[current_section] = ""
            chunks[current_section] += line + "\n"
            
    return chunks
软件工程进阶： 这种“结构化切分”不仅保留了语义，更重要的是提供了溯源标签。在生产中，我们将标题存为元数据，使检索结果能明确告知 LLM：“这段话出自第三章第一节”，从而大幅降低幻觉。
