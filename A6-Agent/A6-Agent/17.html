1. 构建 RAG 知识检索节点 (RAG Node)

agent_server.py (Part 3: RAG Node)

RAG Step
# 3.1 定义 RAG 知识库检索节点 (Pure Function)
def doc_search_node(state: EmailAgentState):
# 从 State 获取原始邮件内容作为检索 Query
query = state["email_content"]

# 调用 VectorStore Retriever 查询领域运维/产品文档
docs = vector_store.similarity_search(query, k=2)
raw_chunks = [d.page_content for d in docs]

# 仅仅返回 Raw Chunks 列表作为 Partial State 更新
return {"search_results": raw_chunks}
  • 纯原始块存留：检索出的 `search_results` 仅保留字符串数组，绝不直接拼装为 Prompt，符合 Raw State 原则。
  • 事实归因拦截：为下游的 `draft_response_node` 节点提供精准的物理参考依据，根治幻觉。
核心：把 RAG 检索封装为单一职责节点，通过 Shared State 传递知识

2. 构建 MCP 协议远程节点 (MCP Node)

agent_server.py (Part 4: MCP Client Node)

MCP Client
# 3.2 定义 MCP 协议远程工具调用节点 (Async Function)
async def mcp_crm_node(state: EmailAgentState):
# 从 State 提取发件人邮箱地址
sender = state["sender_email"]

# 通过 MCP Client 协议异步会话调用远端 CRM MCP Server
async with mcp_client_session as session:
crm_info = await session.call_tool(
"get_customer_crm_history",
{"email": sender}
)

# 将抓取到的客户层级与历史工单写入 State
return {"customer_history": crm_info}
  • 标准化神经触角：在 Node 内部透明拉起 MCP Client 协议，动态访问远端 Jira / GitHub / CRM 工具。
  • 支持原生 Async：LangGraph 原生支持 `async def` 异步节点，方便在高并发下平滑调度 MCP 协议。
核心：把 MCP Client 协议暴露的通用工具解耦封装为标准的 LangGraph 图节点

Architectural Core Thesis / 架构师视角

MCP 是远程管道，RAG 是知识记忆，节点是解耦容器！把 MCP Client 协议与 RAG 检索分别打包进 LangGraph 独立纯函数节点，使得整个 Agent 在运行时能够像调用本地 Ordinary Python 函数一样无缝吞吐全网实体与企业私有知识库。
