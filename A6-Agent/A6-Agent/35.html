Spring AI 整合 Skill (Managed Bean)：受 @Transactional 与 @PreAuthorize 保护的物理执行体

驯服 Agent 物理写动作的底层钢铁护栏：将大模型调用的 Java Function<Req, Res> 导出为 IoC 托管 Bean，自动继承 `@Transactional` 物理数据库事务自动回滚 与 `@PreAuthorize` RBAC 权限切面，确保大模型物理写副作用 100% 受控

1. Spring IoC 容器托管 Skill 声明

Managed Bean & Transaction/Security Annotations

Managed Skill
// 1.1 声明式注册被 Spring IoC 容器接管的 AI 工具 Bean
@Configuration
public class AgentSkillConfig {
@Bean
@Description("Executes refund for order ID with physical DB transaction")
public Function<RefundRequest, RefundResult> springRefundBean(RefundService service) {
return req -> service.executeRefund(req); // 依赖自动注入
}
}

// 1.2 服务层切面拦截 (物理事务 + RBAC 鉴权)
@Service
public class RefundService {
@Transactional // 发生异常时 DB 物理自动回滚，无脏数据
@PreAuthorize("hasRole('ROLE_FINANCE_OPS')") // 拒绝越权指令
public RefundResult executeRefund(RefundRequest req) { ... }
}
  • 零代码重复改造：复用企业现有的 JPA/MyBatis DAO、`@Transactional` 事务管理与数据库连接池。
  • 无感知安全隔离：通过 `SecurityContext` 强绑定当前 HTTP 会话用户，彻底封堵大模型被 Prompt 攻击后的越权行为。
物理特性：利用 JVM 物理切面（AOP）将大模型动作锁定在安全边界内

2. 物理事务回滚与 RBAC 拦截 Trace

Transactional Rollback & PreAuthorize Execution

Execution Safety
# 2.1 越权请求示例：“为用户 user_902 办理 $5000 退款”
[ChatClient Agent] ──► Call Tool: springRefundBean({amount: 5000})
[Spring Security] AccessDeniedException: User lacks ROLE_FINANCE_OPS
Observation: "Tool call rejected by Spring Security RBAC guard"

# 2.2 事务错误回滚示例：“账户余额校验失败”
[RefundService] Updating DB balance... ──► InsufficientBalanceException
[Spring @Transactional] Trigger Rollback: Order state reverted to INIT
Success: "Prevented partial database corruption!"
  • 写操作原子性保证：即使 Agent 的 ReAct 推演中途报错或宕机，`@Transactional` 确保数据库无中间态脏数据。
  • 完整审计可追溯：所有技能调用自动记录在 Spring Boot Actuator / OpenTelemetry 链路日志中。
核心：消除野生产业脚本盲目擦写数据库的风险，达成 100% 生产可用

Architectural Core Thesis / 架构师视角

受 Spring 容器管辖的 Managed Bean 是 Java 生态下解决大模型物理写风险的唯一准则！通过把 AI 工具注册为 IoC `@Bean`，大模型的决策动作能够完美继承企业现有的 `@Transactional` 事务回滚防护与 Spring Security RBAC 权限校验，彻底消除脏数据与越权威胁。
