1. 定义 TypedDict State 与 Ollama 实例

agent_server.py (Part 1: State & LLM)

Python Code
# agent_server.py
from typing import TypedDict, Literal
from langchain_ollama import ChatOllama
from langchain_core.prompts import ChatPromptTemplate

# 1.1 分类结构体定义
class EmailClassification(TypedDict):
intent: Literal["question", "bug", "billing"]
urgency: Literal["low", "medium", "high", "critical"]

# 1.2 共享状态 Shared State 定义
class EmailAgentState(TypedDict):
email_content: str
classification: EmailClassification | None
draft_response: str | None

# 1.3 初始化本地 Ollama Qwen2.5 模型
llm = ChatOllama(model="qwen2.5", temperature=0)
  • 纯数据类型定义：遵从 Raw State 设计原则，状态库中完全不混杂 Prompt 文本。
物理特性：完全基于 Ollama 本地部署，数据零上传，离线可用

# 2.1 定义分类 LLM 推理节点 (Pure Function)
def classify_intent_node(state: EmailAgentState):
# 现场现场装配 Prompt 文本
prompt = ChatPromptTemplate.from_messages([
("system", "Classify the customer email intent and urgency."),
("human", "Email Content: {email_content}")
])

# 绑定结构化输出 (Structured Output)
structured_llm = llm.with_structured_output(EmailClassification)
chain = prompt | structured_llm

# 运行本地 Qwen2.5 模型并返回局部 State 更新
res = chain.invoke({"email_content": state["email_content"]})
return {"classification": res}
  • 纯函数输入输出：节点接收 `state: EmailAgentState`，仅返回更新字典 `{"classification": res}`，完全由框架全自动 Merge。
  • 结构化输出保证：使用 `with_structured_output` 强制 Qwen2.5 输出符合 Python 类型的字典。
核心：把 LLM 转化为状态图中的单一职责纯函数节点
