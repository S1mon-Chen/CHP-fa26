1. 异构全栈 Agent 三层分工与契约交汇

Heterogeneous Stack Division & Protocol Contracts

Stack Division
# 1.1 网关层 (n8n Visual Gateway - Port 5678)
├── Chat / Webhook Event Ingestion
├── Node JS Schema Normalization
└── Third-Party Output (Slack / Email / Webhook)

# 1.2 业务层 (Spring AI Java Microservice - Port 8080)
├── Spring Security RBAC Auth Check
├── Managed `@Bean` Skill (@Transactional DB)
└── VectorStore RAG & MCP Client Provider

# 1.3 推理层 (LangGraph Python Engine - Port 8000)
├── Complex ReAct / Plan-and-Execute StateGraph
└── Local Ollama (Qwen2.5 7B) Offline Inference
  • 各司其职解耦：n8n 解决敏捷接入与通知，Spring AI 管辖数据库写事务与安全授权，LangGraph 驾驭复杂状态图推演。
  • 标准 HTTP/MCP 通信：三层架构之间通过 REST API 和 MCP 协议完成轻量级 JSON 结构化交互。
物理特性：打破单一语言框架局限，达成企业级生产系统的最高吞吐与安全性

2. 端到端物理数据流与 Trace 剖析

End-to-End Execution Flow & Side-Effect Trace

Execution Trace
# Step 1: 外部触发事件请求入网
[User / Slack] ──► n8n Webhook: POST /v1/support-ticket

# Step 2: 网关反向代理至 Spring AI 业务微服务
[n8n HTTP Request] ──► Spring AI Service: POST /api/v1/orchestrate
[Spring Security] Authenticated: ROLE_SUPPORT_OPS

# Step 3: Spring AI 呼叫 LangGraph 展开状态图推演
[Spring AI] ──► LangGraph (Port 8000): ainvoke(init_state)
[LangGraph + Ollama] ReAct Loop -> Decision: "Refund $50"

# Step 4: 结果返回 Spring AI 触发物理事务，最后经 n8n 吐出
[Spring AI] Executing `@Transactional` DB Refund Skill
[n8n Respond Node] HTTP 200 OK + Send Slack Notification
  • 写操作绝对受控：复杂的推理交给 Python 状态图，而最终的物理数据库修改严格限制在 Java `@Transactional` 切面内。
  • 完整链路审计：全流程带唯一的 `trace_id`，同步记录于 Spring Boot Actuator 与 n8n Executions DB。
验证结论：实现了零幻觉脏数据、细粒度鉴权与可视化网关结合的完美工业解
