第 6 课：智能体架构与自主决策引擎 · 模块一

智能体三大核心要素：Perception（感知）、Reasoning（思考）与 Action（行动）

解构自主 Agent 的闭环控制拓扑：通过 感知 (Perception) 接收多模态输入与环境 Observation 反馈，基于 思考 (Reasoning) 开展拓扑规划，并通过 行动 (Action) 触发改变，形成具身自治闭环 (Feedback Loop)

1. Perception (感知)

Environment Input Sensing

Sensors
// 感知源输入向量采集
User Query: "API 504"
Webhook: Alert_504_Triggered
RAG Feedback: "Check DB Pool"
  • 多源触发接收：接收自然语言指令、第三方 API Webhook 告警或定时 Cron。
  • 物理反馈观察 (Observation)：读取上一步物理工具或环境变动返回的日志。
定位：决定 Agent 对环境现状的认知准确度

2. Reasoning (思考)

Cognitive & Planning Core

Brain Engine
// 大脑决策逻辑推演
Goal: "Resolve 504 Timeout"
Analyze: "DB connections full"
Next Step: "Invoke DB_Skill"
  • 意图理解与目标对齐：评估当前状态与目标的距离（Distance to Goal）。
  • 任务拓扑拆解：将终局目标生成下一个具体行动决策（Next Action）。
定位：决定 Agent 的智能逻辑与收敛能力

3. Action (行动)

Physical Execution Hands

Execution
// 物理能力触发与状态改变
1. MCP Tool: Jira.create_issue()
2. Skill: DbPatch.execute()
3. Output: Send Slack Alert
  • 触发物理修改 (Side Effects)：执行受控工具、发送 HTTP 响应或改变数据库。
  • 生成新 Observation：物理行动的执行结果将作为新感知输入再次喂回大脑。
定位：决定 Agent 的物理触达边界与安全底线

Architectural Core Thesis / 架构师视角

闭环反馈 (Feedback Loop) 是 Agent 区别于传统静态工作流的核心机制！传统工作流单向顺发，而 Agent 能将 Action 产生的 Observation 重新转化为 Perception 感知输入，驱动大脑在推演偏离时动态矫正，实现真正的自治收敛。

Speaker Notes / 讲师讲稿
🎯 讲授智能体闭环三要素： “向学员深入剖析：Agent 的运行机制可以精准抽象为 Perception（感知）、Reasoning（思考）与 Action（行动）三大要素。感知捕获环境状态与 RAG 文档，思考负责规划下一步决策，行动通过工具触发环境改变。”
💡 强调 Observation 反馈闭环（Feedback Loop）： “提示学员注意：静态脚本或线性工作流最大问题是‘一发不可收拾’——不管执行成功与否都不掉头。而 Agent 的精髓在于 Action 产生新的 Observation，重新作为 Perception 喂回 Brain 展开二次 Reasoning，这就是自我修正能力。”
