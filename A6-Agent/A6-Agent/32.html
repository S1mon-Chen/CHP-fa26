1. Spring AI `AroundAdvisor` 拦截链范式

ChatClient Fluent API & Interceptor Pipeline

Advisor Chain
// Spring AI 2.0+ 声明式 ChatClient 拦截链
ChatClient chatClient = ChatClient.builder(chatModel)
.defaultAdvisors(
new MessageChatMemoryAdvisor(memory), // 1. 上下文记忆
new QuestionAnswerAdvisor(vectorStore), // 2. RAG 知识硬注入
new ReActAgentAdvisor() // 3. ReAct 推理循环
)
.defaultFunctions("mcpOrderTool", "springRefundBean")
.build();
  • AOP 切面增强：`AroundAdvisor` 在 Prompt 发送前自动拼接记忆与 RAG，在模型返回后拦截 Observation 并控制重试。
  • 解耦无侵入：大模型推演算法与企业业务逻辑彻底解耦，Advisor 可任意插拔配置。
核心：利用 Spring AOP 思想将记忆、RAG 与 ReAct 推理抽象为链式拦截器

2. Spring State Machine 刚性状态机编排

Deterministic State Transitions & Guard Security

State Machine
// Spring State Machine 声明长生命周期状态图
transitions.withExternal()
.source(States.INIT).target(States.RAG_SEARCH)
.event(Events.QUERY_RECEIVED)
.and().withExternal()
.source(States.RAG_SEARCH).target(States.HUMAN_APPROVAL)
.guard(hasHighRefundAmountGuard()) // 物理安全 Guard 拦截
.and().withExternal()
.source(States.HUMAN_APPROVAL).target(States.EXECUTE_REFUND)
.action(executeTransactionalRefundAction());
  • Guard 条件硬保护：Java 编写的物理 `Guard` 条件判定失败时，直接阻断大模型越权跳过审批步骤。
  • 完全事务性 Action：每一个 State 转换节点的 Action 都被 `@Transactional` 物理事务保护。
物理特性：把大模型的概率性选择收敛在 Spring State Machine 的确定性轨道上

Architectural Core Thesis / 架构师视角

Advisor 拦截链与状态机 Guard 是 Java 生态下驯服大模型非确定性的双重护栏！通过 `AroundAdvisor` 将对话记忆与 RAG 转化为透明切片，结合 Spring State Machine 的物理 `Guard` 与 `@Transactional` 事务，企业能够在不丧失模型推演能力的同时获得 100% 可控的服务端安全性。

Speaker Notes / 讲师讲稿
🎯 讲授 Spring AI Advisor 拦截链： “向学员深入剖析：在 Python/LangGraph 中我们通过状态图实现节点拦截，而在 Spring AI 中，框架引入了基于 AOP 思想的 `AroundAdvisor` 拦截链。`MessageChatMemoryAdvisor` 负责把多轮历史存取透明化；`QuestionAnswerAdvisor` 负责在前置拦截阶段把 RAG 文档压入 Prompt，这使得代码极其优雅和声明式。”
💡 剖析 Spring State Machine 的硬核守护： “提示学员注意右侧代码：对于企业级长生命周期复杂业务，我们可以结合 `Spring State Machine`。通过给状态转换配置 Java 物理 `Guard`，即使大模型试图伪造事件调过审批，`Guard` 也会在 JVM 物理层面直接拒绝状态跳变，彻底消除 Agent 越权风险。”
