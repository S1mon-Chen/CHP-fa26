模块二导论：为什么复杂 Agent 需要状态图 (State Graph) 编排控制流

从线性 Sequential Chain 向有向有环图 (Directed Cyclic Graph) 的控制流工程跨越：克服传统 Pipeline 无法处理 状态回溯与图环（Loops） 的缺陷，利用 LangGraph 状态图 (State Graph) 将离散节点与共享 State 建立在刚性物理控制网之上

传统线性 Pipeline / Chain 的物理困境

Linear / Sequential DAG Limitations

Fragile Flow
// 传统线性 Chain: 假定单向无环
chain = prompt | llm | output_parser
// 困境 1: 遇到错误无法环回（No Loops）
// 困境 2: 缺乏跨节点共享 Memory 状态存储
  • 无法表达环路 (Cycles)：真实工单（如“草拟 $\to$ 人类驳回 $\to$ 重新修改”）需要图环，线性链直接崩退。
  • 状态丢失与断点失失效：长生命周期中无 Checkpoint 持久化，中途服务器重启导致推演状态全盘清零。
痛点：线性 Chain 适用于简单的 FAQ 问答，但在复杂工单排查中极易死锁爆发

LangGraph 状态图 (State Graph) 控制力

Directed Cyclic Graph & Shared State

Stateful Agent
// LangGraph 核心哲学: Nodes + Edges + Shared State
builder = StateGraph(EmailAgentState)
builder.add_conditional_edges("draft", route_func)
app = builder.compile(checkpointer=MemorySaver())
  • 显式离散节点 (Discrete Nodes)：把 Agent 拆解为 LLM/Data/Action/Human 单一职责节点。
  • 图环控制 (Cycles & Conditions)：用代码定义的条件边收敛模型的自由跳转，支持无限次自愈与纠偏。
工程突破：平衡自主权 (Agency) 与控制力 (Control)，防止模型陷入无限死循环

Architectural Core Thesis / 架构师视角

状态图 (State Graph) 是驯服大模型非确定性决策的刚性容器！单纯将任务硬编码为单向 Chain 极其脆弱；通过将 Agent 抽象为离散节点（Nodes）、共享状态（State）与条件图环（Cyclic Edges），既赋予了大模型足够自主的排查空间，又在工程侧筑牢了不崩溃的安全围栏。
