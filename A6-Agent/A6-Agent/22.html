掌握多形态物理拉起与私有化防护：从极速单机调试的 npx / npm 开发者拉起，到生产级企业局域网物理隔离的 Docker Compose 容器化部署，确保工作流数据与秘钥 100% 不离内网

1. 本地极速开发部署 (npm / npx)

Dev / Prototype Mode (Port 5678)

Fast Dev
# 方式 1.1：免安装临时拉起 n8n 实例
npx n8n

# 方式 1.2：全局安装并启动 n8n 服务
npm install n8n -g
n8n start

# 环境变量覆盖启动 (指定端口与基础鉴权)
N8N_PORT=5678 N8N_BASIC_AUTH_ACTIVE=true n8n start
  • 秒级验证：适合本地开发、验证 Webhook 接收逻辑与调试底层 Python/Node 算法服务。
  • 数据落盘路径：本地工作流与凭证默认保存在 `~/.n8n/`SQLite 数据库文件。
定位：个人 PoC 快速验证，电子桌面版（Desktop）开箱即用

2. 企业级 Docker Compose 容器化编排

On-Premise Production Deployment

On-Prem Production
# docker-compose.yml 生产编排示例
version: '3.8'
services:
n8n:
image: docker.n8n.io/n8nio/n8n
ports: ["5678:5678"]
environment:
- N8N_HOST=n8n.internal.company
- WEBHOOK_URL=http://n8n.internal.company:5678/
volumes:
- n8n_data:/home/node/.n8n
  • 工业级持久化：结合外部 PostgreSQL 存储凭证与工作流版本，支持镜像快速水平扩容。
  • 物理脱网合规：运行在内网 VPC 中，阻断非授权数据流出，满足金融/医疗级审查。
核心：容器持久化卷挂载与内网域名绑定，构建可信控制网关

Speaker Notes / 讲师讲稿
🎯 讲授 n8n 部署路径的选择技巧： “向学员深入剖析：在进行 PoC 试错与个人开发时，直接敲 `npx n8n` 是最快的方式，端口默认开在 5678。而到了企业级生产环境，我们强烈推荐使用 Docker Compose，挂载外部 PostgreSQL 保存凭证加密密钥。”
💡 强调物理隔离与 WEBHOOK_URL 配置： “提示学员注意右侧的 `docker-compose.yml`：在 Docker 中部署 n8n 时，必须正确设置 `WEBHOOK_URL` 环境变量，否则后续生成的 Webhook 回调地址可能会因为协议或主机名不匹配导致无法被外部第三方服务（如 GitHub / Slack）正常请求回调。”
