LangGraph 核心设计哲学 (2/3)：共享状态 (Shared State Design) 与原始数据存留原则

Thinking in LangGraph 核心原则（Step 3）：构建可推演状态图的共享记忆体——明确界定 Include in State（跨节点持久化字段） 与 Don't Store（现场派生数据），并恪守 Raw Data Principle（存留原始数据），严禁在 State 中存储格式化 Prompt

State 设计边界：存什么 vs 不存什么

Include in State vs Don't Store Principles

State Boundary
Include
需要跨节点持久化的数据： 原始邮件数据、意图分类结果、开销巨大的 RAG 文档 Chunk、CRM 客户信息与草稿。
Don't Store
随时可现场计算/推导的数据： 节点内部的临时计算结果、中间渲染的长度计数与单次工具临时参数，按需现场计算。
Raw Data
原始数据存留原则 (Keep State Raw)： 仅存结构化 JSON/Dict，绝不存预拼接的 Prompt 模版或提示词字符串，Prompt 渲染放在 Node 内部。
核心：干净的 Raw State 保证了图节点的独立单测性与 Prompt 渲染的现场确定性

EmailAgentState 代码规范实现

TypedDict State Implementation

Python TypedDict
// 客服邮件 Agent 强类型共享 State 定义
class EmailClassification(TypedDict):
intent: Literal["question", "bug", "billing", "feature"]
urgency: Literal["low", "medium", "high", "critical"]
summary: str

class EmailAgentState(TypedDict):
# 1. 原始邮件 Raw Data (不可逆数据)
email_content: str
sender_email: str
# 2. 结构化分类与开销巨大的外部检索产物
classification: EmailClassification | None
search_results: list[str] | None # Raw Doc Chunks
customer_history: dict | None # Raw CRM Data
# 3. 生成内容与消息链
draft_response: str | None
  • 完全静态可推导：TypeScript 或 Python `TypedDict` 提供完美的编译期类型补全与提示。
  • 零字符串污染：State 中绝对看不到 `f"System: Hello {name}"`，所有格式化统统留在 Node 内。
架构原则：状态库仅仅充当“结构化事实数据库”，而非“格式化文本文档”

Architectural Core Thesis / 架构师视角

干净的共享状态 (Shared State) 是保证 LangGraph 节点幂等与独立可测试的关键！绝对不要将格式化好的 Prompt 文本注入 State 存留。在 State 中仅保留纯粹的结构化原始数据 (Raw Data)，并在节点触发时现场装配 Prompt，能极大减少上下文污染与状态膨胀。
