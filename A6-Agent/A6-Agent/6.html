自主推理范式 (3/3)：Reflexion / Self-Reflection 自我反思与失败进化机制

突破试错死循环的反思演化架构：通过将 物理环境报错日志、测试失败 Stacktrace 与历史轨迹 压入 Self-Reflection 反思节点，生成自然语言形式的 反思记忆 (Reflective Memory)，驱动 Agent 实现免微调 (Training-Free) 的运行时自我修正

Reflexion 架构三核联动

Actor + Evaluator + Self-Reflection

Shinn et al., 2023

单纯重试（Naive Retry）容易让 Agent 在同一报错点反复僵死。Reflexion（NIPS 2023）引入非参数化强化学习思路，将失败转化为文字记忆：

1. Actor
行动者 (Actor/LLM)： 结合用户 Goal、环境反馈以及上一轮生成的 Reflective Memory，发起工具调用与文本生成。
2. Evaluator
评估者 (Evaluator/Reward)： 检验环境结果（如运行 pytest 单测状态或算法断言），判定是否命中终止条件（Success/Fail）。
3. Self-Reflection
自我反思模型 (Self-Reflection Model)： 当 Evaluator 判定失败时，剖析原因，总结“为什么错”与“下次怎么做”，写入反思记忆缓冲池。
工程突破：无需微调（Training-Free），仅靠 Prompt 闭环实现跨试错迭代进化

pytest 单测失败自愈 Trace 剖析

Reflexion Memory Self-Correction

Execution Trace
// Task: "Generate robust user_parser.py"
[Trial 1 - Actor] Code Generated -> Run `pytest`
└─ Evaluator: FAIL (TypeError: 'NoneType' object is not subscriptable)
[Trial 1 - Self-Reflection] Diagnosing failure:
└─ Reflective Memory: "In Trial 1, I forgot to check if `user_json` is None before indexing. Next attempt: Add `if not user_json: return None` guard."
[Trial 2 - Actor] Re-generate code using Reflective Memory...
└─ Evaluator: PASS (12/12 unit tests green!)
  • 避免盲重试：由于 Reflective Memory 明确指出了 `NoneType` 的原因，Trial 2 一击即中。
实测数据：在 HumanEval 代码生成基准测试上，Reflexion 将 Pass@1 提升了 11%~20%

Architectural Core Thesis / 架构师视角

反思记忆 (Reflective Memory) 是免微调实现 Agent 运行时进化的核心工程抓手！单纯将错误日志喂回模型（Naive Retry）容易引发上下文污染与无意义僵死；而 Reflexion 强迫模型提取文字反思教训，使 Agent 具备了跨试错学习的收敛能力。

Speaker Notes / 讲师讲稿
🎯 讲授 Reflexion 范式的动机与突破： “向学员深入剖析：在实际让 Agent 生成复杂代码时，单靠一次生成很难做到 100% 完美。如果简单的重复盲重试（Naive Retry），LLM 往往会在同一行语法错或空指针错误上死循环。Reflexion 架构引入了第三者节点——Self-Reflection，将失败 Traceback 转化为总结性的文字教训。”
