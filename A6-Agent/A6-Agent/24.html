1. n8n AI Agent 插槽化 (Sub-socket) 架构

Sub-Node Socket Binding Topology

Canvas Sockets
# [n8n AI Agent Node] - 插槽绑定伪代码
AgentNode: "Tools Agent" {
socket_model: GroqChatModel("llama-3.3-70b"),
socket_memory: WindowBufferMemory(k=10),
socket_tools: [
MCPClientTool("jira-mcp-server"),
VectorStoreTool("qdrant-rag"),
CustomHttpRequestTool("fastapi-agent-8000")
]
}
  • 极简拖拽拼装：Model/Memory/Tools 节点不是独立工作流步骤，而是通过底部专用 Socket 物理“插”入 Agent 主节点。
  • 灵活切换模型：无需修改任何下游 Tool 代码，直接将 Model Socket 从 Groq 切换为本地 Ollama 即刻生效。
物理特性：利用子插槽组网，解耦推演大脑、上下文记忆与物理工具

2. ReAct 思考循环与参数表达式

Agentic Execution Loop & $fromAI()

Execution Mechanics
# 2.1 Agent 节点自动 ReAct 思考循环
Prompt ──► LLM Model Socket ──► Decide Tool Call
Tool Socket Execution ──► Return Observation ──► Repeat

# 2.2 n8n 魔法表达式：动态获取 AI 提取参数
{{ $fromAI("issue_id", "The BUG ticket ID to query") }}
# 自动生成工具入参 Schema 并充当运行时取值注入器
  • `$fromAI()` 魔法表达式：自动向 LLM 描述入参语义，并在模型生成 JSON 时反向抽取绑定至 HTTP Request 节点。
  • 零代码 ReAct 闭环：Tool 运行日志无需手写解析，n8n 自动将返回值包装为 Observation 喂给 Model 插槽。
核心：使用 `$fromAI()` 实现无缝的 AI 参数自动对齐与结构化提纯

n8n 的插槽组网模式将复杂 Agent 的物理构成打散为标准可插拔模块！通过在 AI Agent 节点下方插接 LLM Model、Memory 与 Tools 插槽，配合 `$fromAI()` 表达式提取参数，开发者可以用极致的拖拽效率搭建出兼具大模型推演与微服务调用的可视化 Agent。
