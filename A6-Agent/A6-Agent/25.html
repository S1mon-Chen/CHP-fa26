n8n 与 MCP 深度集成：挂载 MCP Client 节点直连跨系统 Server 资源

在 n8n 可视化画布中实现 Anthropic Model Context Protocol (MCP) 标准接入：通过挂载 MCP Client Tool 节点 无缝握手远程 Jira / GitHub / PostgreSQL MCP Servers，解锁零硬编码的动态工具感知（`tools/list`）与跨系统安全调度

1. n8n MCP Client 子节点挂载机制

Dynamic Tool Discovery & Transports

MCP Sub-Node
# [n8n MCP Client Tool Socket] 配置范例
MCPClientToolNode: "mcp-jira-bridge" {
transport: "sse", # 支持 SSE 或 Stdio 模式
url: "http://mcp-jira-server:3000/sse",
headers: { "Authorization": "Bearer {{ $credentials.mcp_key }}" }
}

# 动态握手过程：向 AI Agent 暴露工具集
1. Client 触发 tools/list ──► 拉取 Jira API 描述
2. 自动格式化为大模型熟悉的 Function Schema 放入 Tools 插槽
  • 零硬编码 API 适配：只要远程服务实现了 MCP Server 协议，n8n AI Agent 节点即可自动识别其所有函数。
  • 多传输管道支持：同时支持本地 Docker 进程的 `Stdio` 管道与跨网络微服务的 `SSE (Server-Sent Events)` 协议。
物理特性：把离散的第三方工具调用归一化为标准的 MCP 协议神经触角

2. 跨系统 MCP 物理调度与执行 Trace

Cross-System Handshake & Side-Effect Guard

Distributed Trace
# 2.1 用户请求：“检查 GitHub PR #102 并创建 Jira Bug”
[n8n Agent] ──► MCP Client (GitHub SSE): call_tool("get_pr_diff", {id: 102})
Observation: "NullPointerException at OrderController.java:42"

# 2.2 ReAct 推理后跨系统调度第二个 MCP Server
[n8n Agent] ──► MCP Client (Jira SSE): call_tool("create_issue", {...})
Success: "Created Ticket BUG-8901 in Jira"
  • 协议级身份隔离：n8n 托管 MCP 凭证密钥，LLM 大脑仅能接触工具结构而无法直接触碰环境变量中的原始 Token。
  • 异构系统打通：一个低代码 Agent 节点可插接无限个 MCP Client，瞬间打通 GitHub、Jira、GitLab 与物理数据库。
核心：消除 OAuth 与 REST API 适配冗余，实现可视化 Agent 的分布式工具互联
