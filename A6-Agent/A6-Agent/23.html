n8n 工作流核心概念：Trigger 触发器 (Schedule/Webhook/Chat) 与 Execution 引擎

驱动事件驱动架构 (EDA) 的可视化起点：掌握 Schedule (Cron 定时)、Webhook (POST 回调) 与 Chat Trigger (对话窗口)，剖析 n8n Execution 执行引擎 如何将物理事件转化为结构化数据流

1. 多形态 Trigger 触发器分类

Event Entry Points & Payload Normalization

Event Ingestion
# 方式 1.1: Webhook Trigger (HTTP POST 入口)
{ "headers": {...}, "body": { "issue_id": "BUG-902" } }

# 方式 1.2: Schedule Trigger (Cron 定时触发)
{ "timestamp": "2026-08-17T09:00:00Z", "cron": "0 9 * * 1" }

# 方式 1.3: Chat / Form Trigger (交互式触发)
{ "chatInput": "Please analyze API 504 logs", "sessionId": "sess_882" }
  • 标准化入参化：不论事件源来自 GitHub Webhook 还是 Cron 定时器，Trigger 统一将载荷转换为 JSON 数组。
  • 支持两重响应模式：Webhook 节点可选择“立即返回 200 OK”或“等待工作流结束返回最终 JSON”。
定位：事件驱动架构 (EDA) 业务网关的物理第一站

核心：把复杂的异步事件转化成可被可视化节点平滑管道传输的 JSON 数据包

Architectural Core Thesis / 架构师视角

Trigger 节点是低代码 Agent 接入事件驱动架构（EDA）的网关入口！不管是定时任务（Cron）、外部回调（Webhook）还是交互对话（Chat），n8n 执行引擎都能将其标准化为强类型 JSON 载荷，为下游 AI 节点的推演提供纯萃的数据源。

🎯 讲授 Trigger 触发器在 EDA 架构中的角色： “向学员深入剖析：在低代码工作流引擎中，一切执行都始于 Trigger 节点。无论是每周一上午 9 点运行的 Schedule Cron，还是响应第三方 GitHub / Slack 回调的 Webhook，或者是前端嵌入的 Chat 窗口，Trigger 的核心使命就是将异构物理事件归一化为标准的 `$input.first().json` 载荷。”
