智能体记忆系统 (Memory Architecture)：Short-term Context vs Long-term Episodic Memory

解构 Agent 的双层记忆分层机制：结合由 Context Window & 运行 State 构成的短期工作记忆 (Working Memory)，与基于 Vector DB / 知识图谱构成的长期情境记忆 (Episodic Memory)，实现跨会话的经验累积与个性化对齐

短期工作记忆 (Short-Term Working Memory)

Context Window · In-Session Active State

In-Memory
// 短期 Context State 缓冲池 (受窗口大小限制)
Active Thread: "thread_8902_refactor"
├─ Messages: [UserPrompt, Thought_1, Action_1, Obs_1]
├─ Graph State: {current_node: "BugTrack", retry_cnt: 1}
└─ Pruning Policy: Sliding Window (TTL = Session End)
  • 即时情境锁定：保存当前会话的多轮对话 Message 列表、工具中间 Observation 以及 LangGraph 节点状态。
  • 易失性与容量门限：受 Transformer Context Window 限制，随会话结束销毁，需靠剪枝中间件压缩。
定位：保障当前单一工单推演的局部逻辑一致性与上下文连贯

长期情境记忆 (Long-Term Episodic Memory)

Vector DB / Knowledge Graph · Cross-Session Base

Persistent
// 跨会话向量召回历史成功经验 (Episodic Store)
Query: "How to fix 504 Gateway Timeout in Billing?"
Recall Score: 0.94 (From session_2025_11)
└─ Injected Experience: "In past, scaling DB pool to 300 resolved 504."
└─ User Preference: "Prefers Python fixes over Shell scripts"
  • 经验与成功模式持久化：将历史任务中的 Reflexion 反思记忆、重构经验与用户偏好存入向量库。
  • 免微调 (Training-Free) 进化：在发起新推演前，通过 RAG 语义检索注入历史最佳实践，实现运行时成长。
定位：给予 Agent 跨会话学习能力，避免相同错误在不同工单里重复发生

Architectural Core Thesis / 架构师视角

长期情境记忆 (Episodic Memory) 是赋予 Agent 跨会话进化的唯一通道！短期记忆（Context Window）保证单个工单处理不走样，而长期记忆通过向量库储存历史犯错与修复教训，使得 Agent 无需频繁微调即可越用越聪明。

Speaker Notes / 讲师讲稿
🎯 讲授智能体双层记忆系统： “向学员深入剖析：Agent 的记忆系统可以精准划分为 Working Memory（短期工作记忆）与 Episodic Memory（长期情境记忆）。短期记忆是当前的上下文窗口与 LangGraph 状态图，负责当前任务的推演；而长期记忆依托向量数据库与知识图谱，跨会话保存历史成功方案。”
💡 结合右侧 504 故障召回案例： “提示学员看右侧的终端 Trace：当用户抛出一个新的 504 报错时，Agent 在推理前先向长期记忆向量库发起召回，发现了上个月处理同类故障时‘将数据库连接池扩容到 300 即可修复’的成功经验，直接避免了二次走弯路。”
