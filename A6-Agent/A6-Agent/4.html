自主推理范式 (1/3)：ReAct (Reason + Act) 循环思考与观察闭环

解构经典 ReAct 自主推理与行动范式（Yao et al.）：交织 Thought (显式思考)、Action (工具调用) 与 Observation (物理环境反馈)，赋予 Agent 根据观察结果动态纠偏的能力

ReAct 循环工作机理

Thought → Action → Observation Loop

Paradigm Core

传统 Chain-of-Thought (CoT) 仅在内部“空想”而无法干预外部世界，而单纯的 Act 模式盲目发命令。ReAct 范式将两者深度缝合，建立交替推演闭环：

1. Thought
显式推理思考： 大模型分析当前 Prompt 状态与物理目标差距，明确下一个行动意图与必要参数。
2. Action
工具与物理行动： 生成 JSON Schema 工具指令，由宿主系统触发物理 API、数据库查询或终端命令。
3. Observation
观察结果反馈： 将工具返回的运行日志、错误堆栈或物理数据包装为反馈，喂回大模型开启下一轮 Thought。
特点：推理引导行动，行动产生感知，感知矫正下一次推理

ReAct 网络故障诊断 Trace 剖析

Real-world Troubleshooting Cycle

Execution Trace
// Task: "API 504 Gateway Timeout in billing service"
[Turn 1] Thought: Need to ping_check internal billing gateway first.
└─ Action: ping_tool(host="billing.internal")
└─ Observation: 100% packet loss, host unreachable.
[Turn 2] Thought: Ping failed. Let's check DNS resolution and DB connection pool.
└─ Action: check_db_pool(cluster="billing_db")
└─ Observation: Active connections: 200/200 (POOL_EXHAUSTED).
[Turn 3] Thought: DB pool exhausted is causing 504. Trigger DB pool scale-up skill.
└─ Final Answer: Root cause found & Auto-scale patch generated!
  • 自适应矫正：Turn 1 连通失败后，Agent 并没有在失败点“僵死”，而是自动切换假说，转向数据库连接池排查。
相比固定脚本：ReAct 具备非线性分支排查与不确定性环境适应力

Architectural Core Thesis / 架构师视角

ReAct 将推理与行动交织，赋予了 Agent 在真实物理世界中“掉头与自愈”的能力！传统线性 Pipeline 在遇到未知阻碍时直接崩溃，而 ReAct 能将失败的 Observation 转化为 Thought 的二次营养，驱动模型动态调整排查路线。
