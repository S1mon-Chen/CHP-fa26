状态持久化与 Checkpointer 机制：使用 SQLite/Redis 实现多轮会话恢复

给有向图状态机加上永不丢失记忆的硬盘中枢：利用 SqliteSaver / RedisSaver 持久化 Checkpointer，基于唯一 thread_id 识别会话线程，实现多轮对话上下文无缝关联、服务器重启后秒级断点续传与 interrupt() 人工卡扣唤醒恢复

1. 配置持久化 Checkpointer

SqliteSaver & RedisSaver Integration

Persistence
# 1.1 导入 SQLite Checkpointer 依赖
import sqlite3
from langgraph.checkpoint.sqlite import SqliteSaver

# 建立数据库物理连接
conn = sqlite3.connect("agent_checkpoints.db", check_same_thread=False)
memory = SqliteSaver(conn)

# 1.2 编译图对象时挂载 Checkpointer 中枢
graph_executor = builder.compile(
checkpointer=memory,
interrupt_before=["human_review"] # 在审批前自动暂停
)
  • 每一个节点全自动快照：图形转换的每一步，State 字典均被序列化存盘，即使服务器物理宕机也绝不丢失数据。
  • 生产无缝切换：开发期用 SQLite，生产环境可替换为 `RedisSaver` 或 `PostgresSaver`。
核心：将易失的内存逻辑升维为可追溯、可审计的硬盘持久化图状态机

2. 多轮会话与中断恢复调用

Thread ID Config & Interrupt Resume

Multi-Turn Session
# 2.1 绑定唯一 thread_id 发起第一轮推演
config = {"configurable": {"thread_id": "user_session_902"}}
res1 = await graph_executor.ainvoke(init_state, config)
# 如果命中 human_review 节点，系统抛出 Interrupt 并停止

# 2.2 恢复挂起的会话（更新 State 并复传）
graph_executor.update_state(config, {"approved": True})
# 传入 None 表示从上次打断的位置直接接着跑
final_res = await graph_executor.ainvoke(None, config)
  • 句柄强锁定：`thread_id` 是索引数据库多轮状态的唯一 Key，不同用户的会话数据完全隔离。
  • 支持长生命周期中断：无论是 5 秒后还是 3 天后，人类修改状态后传入 `None` 即可瞬间唤醒图引擎。
核心：将零散的 HTTP 请求通过 thread_id 聚合成长生命周期的连续推演流

Architectural Core Thesis / 架构师视角

持久化 Checkpointer 是 LangGraph 打造高可用长生命周期 Agent 的硬核基石！通过把图状态转换过程自动写入 SQLite 或 Redis，不仅完美支持基于 `thread_id` 的多轮会话关退恢复，更使得人机审批 (`interrupt()`) 与突发事故断点续传成为现实。

Speaker Notes / 讲师讲稿
🎯 讲授 Checkpointer 机制的要点： “向学员深入剖析：在单次 HTTP 请求中，Agent 的状态是在内存里的；但是真实业务需要多轮对话与断点续传。通过给 `compile(checkpointer=SqliteSaver(conn))` 传入持久化实例，LangGraph 会在图节点转换的每一步都将 State 自动存盘。”
💡 剖析 `thread_id` 与恢复机制： “提示学员看右侧代码：在传入 `config={"configurable": {"thread_id": "..."}}` 时，框架会以此作为 Key 去数据库存取快照。当触发 `interrupt()` 中断或服务器发生故障重启后，我们只需将入参设为 `None`（`ainvoke(None, config)`），LangGraph 就能从数据库自动反序列化状态并继续推演！”
