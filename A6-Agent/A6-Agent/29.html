n8n 生产落地踩坑避坑指南：localhost vs 127.0.0.1 跨容器通信、Test URL 与 Active Production URL

排查生产环境四大物理杀手：规避 Docker 容器内 `localhost` 环回网络死锁（改用 `host.docker.internal` 或容器服务名），区分 Test Webhook（UI 单次监听） 与 Production Webhook（Active 常驻后台），并正确配置 `WEBHOOK_URL` 环境变量

1. 跨容器与宿主机通信陷阱 (localhost)

Docker Network Isolation & Host Domain Resolution

Network Pitfall
# ❌ 错误示范：在 n8n 容器的 HTTP Request 节点填入
URL: http://localhost:8000/query
# 报错: ECONNREFUSED 127.0.0.1:8000 (因为指向了 n8n 容器内部!)

# ✅ 正确修补方案 1：访问宿主机微服务 (FastAPI / Ollama)
URL: http://host.docker.internal:8000/query

# ✅ 正确修补方案 2：在同一 docker-compose 网段下用服务名
URL: http://agent-server:8000/query
  • `localhost` 环回盲区：Docker 容器内部的 `localhost` 仅代表容器自身，无法直连宿主机 8000 端口。
  • 服务名直连：推荐在 `docker-compose.yml` 中将微服务与 n8n 置于同一 network 网段，直接通过容器服务名寻址。
物理事实：`host.docker.internal` 是解决桌面容器直连宿主机接口的核心通道

2. Webhook 生命周期与 Production 开关陷阱

Test URL vs Production URL & Active Switch

Lifecycle Pitfall
# ⚠️ 踩坑场景：将 Test Webhook 地址部署到 GitHub/Slack 回调
Test URL: http://n8n.co/webhook-test/agent-v1
# 结果: 只有当鼠标点击 n8n "Test step" 时才响应一次，关闭 UI 立即 404!

# ✅ 生产标准上线步骤：
1. 将右上角切换开关设为 Active = TRUE
2. 使用常驻地址: http://n8n.co/webhook/agent-v1
3. 配置环境变量: WEBHOOK_URL=http://n8n.internal:5678/
  • `webhook-test` 单次性：测试 URL 仅用于画布单步 Trace 抓包，切勿填入第三方生产回调。
  • `WEBHOOK_URL` 必填项：必须在环境变量中明确主机名或域名，避免系统自动生成不可达的内网私有 IP。
核心：开启 Active 开关后，工作流交由后台多线程 Worker 队列常驻监听

n8n Production Pitfalls & Hardening Solutions / 生产落地四大硬核防御规则

Production Hardening Checklist
No `localhost`
Use host.docker.internal
No `webhook-test`
Use Production /webhook/
Active = TRUE
Enable Background Worker
`WEBHOOK_URL` Env
Explicit External Domain

Architectural Core Thesis / 架构师视角

恪守生产环境部署规约是保证低代码网关高可用性的底线！跨容器通信切忌盲目填写 `localhost`；上线第三方 Webhook 回调前，必须开启工作流 `Active` 常驻开关，并在 Docker 环境变量中显式配置 `WEBHOOK_URL` 域名，防止回调失效死锁。
