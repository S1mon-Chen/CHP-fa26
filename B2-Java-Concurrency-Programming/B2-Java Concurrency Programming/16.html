头部与尾部双端操作，极大减少主线程与窃取线程之间的 CAS 锁冲突。

1. LIFO 局部优先 (Head Access)

工作线程自身从双端队列（WorkQueue）头部 (Head) 以 LIFO 方式压入与弹出任务。由于最新拆分的子任务大概率保留在 CPU L1/L2 缓存中，具有极高的缓存局部性 (Cache Locality)。

2. FIFO 窃取优先 (Tail Steal)

当空闲线程没有任务可做时，会随机偷取其他繁忙线程队列尾部 (Tail) 的最老任务 (FIFO)。最老任务通常规模较大，窃取后可继续二次 Fork 拆分，最大化利用多核 CPU。

核心抽象：RecursiveTask<V> (有返回值) vs RecursiveAction (无返回值)
RecursiveTask 递归分治代码范式 Parallel Sum Example
// 经典分治累加任务：继承 RecursiveTask<Long>
public class SumTask extends RecursiveTask<Long> {
private static final int THRESHOLD = 10000; // 阈值
private long[] array; private int start, end;
@Override
protected Long compute() {
if ((end - start) <= THRESHOLD) {
// 1. 达到阈值，直接进行小规模顺序计算
return computeDirectly();
}
// 2. 未达到阈值，一分为二递归派生 (Fork)
int mid = (start + end) / 2;
SumTask left = new SumTask(array, start, mid);
SumTask right = new SumTask(array, mid, end);
left.fork(); // 异步推入当前 Worker 队列
long rightResult = right.compute(); // 当前线程同步计算右半部分
long leftResult = left.join(); // 等待左半部分并合并 (Join)
return leftResult + rightResult;
}
}
⚠️ 避坑：严禁在 ForkJoin 中阻塞

ForkJoinPool 线程数默认为 CPU 核心数。如果在任务中发起阻塞 I/O（如 DB / HTTP），会导致整个线程池快速卡死饥饿！

💡 最佳实践：Common Pool

Java 8 的 parallelStream() 和 CompletableFuture 默认共享全局 ForkJoinPool.commonPool()。

基准要求：分治阈值 (Threshold) 需多次压测，防止过度拆分引发任务创建开销

Fork/Join 适用场景思考 (Divide-and-Conquer Paradigm)

Fork/Join 框架专为 **CPU 密集型、可递归拆分的巨型计算** 而生（如大数组排序、图像处理、树形结构遍历）。对于传统服务端 I/O 密集型 Web 请求，应优先选用 ThreadPoolExecutor 或 Java 21 **虚拟线程 (Virtual Threads)**！
