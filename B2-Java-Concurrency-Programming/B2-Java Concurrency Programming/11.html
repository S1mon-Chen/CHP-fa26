J.U.C 基石：AbstractQueuedSynchronizer (AQS) 机制

探究 volatile state 状态管理、CLH 双向变体队列入队与 LockSupport 线程挂起/唤醒机制

AQS 核心三要素 (Core Pillars) AbstractQueuedSynchronizer
1. State 状态变量 private volatile int state

使用 CAS 进行原子更新。在 Lock 中代表重入次数，在 Semaphore 中代表可用许可数，在 CountDownLatch 中代表剩余倒计数。

2. CLH 双向 FIFO 队列 Head & Tail Node

抢锁失败的线程被封装为 Node 节点插入尾部，形成虚拟双向链表。节点自旋检查前驱状态或挂起。

3. LockSupport 挂起/唤醒 park() / unpark()

底层使用 POSIX pthread_mutex / condition 挂起与恢复线程，避免低效自旋浪费 CPU 资源。

CLH Node 关键状态标志 (waitStatus)
SIGNAL (-1): 后继节点处于挂起状态，当前节点释放锁时必须唤醒后继。
CANCELLED (1): 线程因超时或中断放弃抢锁，需从队列中剔除。
CONDITION (-2): 节点处于 Condition 条件等待队列中。
PROPAGATE (-3): 共享模式下无条件向后传播释放通知。
AQS 驱动的顶级组件： ReentrantLock Semaphore CountDownLatch ReentrantReadWriteLock
设计精髓：模板方法模式 (Template Method Pattern) 优雅解耦

架构抽象之美 (Architectural Elegance)

AQS 将复杂的“线程排队、阻塞唤醒、中断处理”统一封装在基类中，具体的同步组件（如 ReentrantLock、Semaphore）只需重写 tryAcquire / tryRelease 定义具体的 state 改变规则——这是软件设计高内聚低耦合的经典范本！

Speaker Notes / 讲师讲稿
🎯 引导学生理解 AQS 状态与排队机制： “向学生强调：AQS 解决的核心问题是‘在竞争资源时，没抢到锁的线程去哪里、怎么安全地挂起和被唤醒’。它通过 CAS 原子修改 volatile state，结合双向 CLH 队列变体，避免了无意义的 CPU 死循环自旋。”
💡 剖析 Node 节点 state=SIGNAL 的妙用： “提示学生：为什么 Node 需要 `SIGNAL (-1)` 状态？因为前驱节点在释放锁（unpark）时，必须知道后面有没有节点在挂起等待。后继节点挂起前，会显式将前驱节点的状态设置为 SIGNAL，表示‘哥们你释放时记得唤醒我’。”
