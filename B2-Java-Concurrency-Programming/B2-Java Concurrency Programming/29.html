Part 05 · 现代服务端并发架构选型 (Architecture Choices & Practice)

结构化并发 (Structured Concurrency)：掌控并发子任务的生命周期

消除孤儿线程与资源泄漏，探究 StructuredTaskScope (JEP 453) 作用域聚合与“同生共死”控制契约

1. 传统“非结构化并发”的 3 大致命隐患 Unstructured Hazards
① 孤儿线程泄漏 (Orphan Thread Leakage) Resource Waste

使用 `ExecutorService` 或 `CompletableFuture` 启动多个并发子任务时，若主线程取消或其中一个子任务报错，其余子任务依然会在后台继续浪费 CPU / 内存盲目执行。

② 级联取消丢失 (No Automatic Cancellation) Manual Cleanup

遇到网络超时或部分节点崩溃，开发者必须手动手写繁琐的 `cancel()` 逻辑传播取消信号，极其容易出现漏洞引发挂起。

③ 异常栈断裂与上下文丢失 (Broken Observability) Lost StackTrace

子线程内部抛出的真实异常往往被封装包裹在 `ExecutionException` 深度深处，导致日志告警无法精准追踪原始引发点。

🚀 结构化并发哲学 (Structured Concurrency) Single Unit of Work

借鉴结构化编程（如 `if-else` / `try-catch` 作用域闭包）的思想：**把在不同线程中并发派生的子任务，明确绑定到同一个代码作用域中**。确保子任务的生命周期严密闭环，实现“同生共死”！

工程准则：任何子线程的派生与销毁，绝不超越当前代码块的层次边界
Java 21+ StructuredTaskScope 代码范式 JEP 453 Preview API
// 声明结构化作用域：任一子任务失败，自动触发全量短路取消 (ShutdownOnFailure)
Response fetchDataStructurally(String userId) throws Exception {
try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
// 1. 结构化派生多个并发子线程任务 (以虚拟线程运行)
Subtask<UserInfo> userTask = scope.fork(() -> userService.getUser(userId));
Subtask<Orders> ordersTask = scope.fork(() -> orderService.getOrders(userId));
// 2. 阻塞等待所有任务完成；若任一子任务报错，自动取消其他残留任务
scope.join();
scope.throwIfFailed(); // 立刻传播抛出原始子任务异常
// 3. 聚合子任务结果 (确定已安全完成)
return new Response(userTask.get(), ordersTask.get());
} // 4. 退出 try 闭包时，确保所有子线程全部退出归队，无任何遗留！
}
1. ShutdownOnFailure

**一败全败 (All-or-Nothing)**：并行请求多个子服务，当任意一个子服务抛出异常时，自动取消其他所有进行中的子任务，防止资源空转。

2. ShutdownOnSuccess

**一胜即收 (First Winner)**：同时向多个冗余节点/镜像发起请求，当率先收到首个成功响应时，立刻自动取消其余竞速请求。

底层协同：与 Java 21 虚拟线程 (Virtual Threads) 天然完美结合

结构化并发设计哲学 (Structured Concurrency Philosophy)

结构化并发带来了并发控制维度的根本变革：**将散乱的“线程控制”转变为受控的“作用域控制 (Scope Control)”**。通过 StructuredTaskScope 与虚拟线程组合，开发者可以用最清晰的单线程代码语法，构建出具备级联取消与自动清理能力的顶级弹性高吞吐后端！

Speaker Notes / 讲师讲稿
🎯 引导学生透视结构化并发的核心价值： “向学生强调：传统的 `CompletableFuture` 或 `ExecutorService` 是‘非结构化’的，父线程启动子线程后，两者在语法和作用域上毫无关联。如果父线程异常终止，子线程仍会在后台默默运行（孤儿线程）。结构化并发通过 `StructuredTaskScope` 建立了代码层次与线程生命周期的严格契约，实现了‘同生共死’。”
💡 剖析 ShutdownOnFailure 与 ShutdownOnSuccess 的场景应用： “提示学生关注两种核心策略：`ShutdownOnFailure` 用于多个子任务全量并发聚合场景，只要有一个失败立刻取消其余任务；而 `ShutdownOnSuccess` 适用于镜像节点竞速（First Winner），率先返回结果后自动取消其他冗余请求。配合 `try-with-resources`，保证作用域结束时零残留线程！”
