虚拟线程底层原理：Continuation 与 Mount/Unmount 机制

探究 jdk.internal.vm.Continuation 状态机、堆栈帧序列化卸载与 OS epoll/kqueue 事件驱动解耦过程

虚拟线程 I/O 阻塞 4 步调度生命周期 Continuation State Lifecycle
Mount Freeze / Unmount Epoll Wait Remount
STEP 1 Mount (挂载)
VT 绑至 Carrier Thread 执行 Java 字节码
执行到同步阻塞点 (如 socket.read / Thread.sleep)
STEP 2 Unmount (卸载/Yield)
栈帧冻结至 Heap Continuation，释放 Carrier
Carrier Thread 释放处理其他 VT；向 OS 注册 epoll
STEP 3 Poller Event (就绪)
OS 触发 epoll/kqueue 数据可读事件
JVM Poller 唤醒，将 VT 重新推入 ForkJoinPool 队列
STEP 4 Remount (重新挂载)
任意空闲 Carrier 加载 Continuation 恢复栈帧
核心性能红利：零 Carrier 阻塞 (Zero Carrier Stall) CPU Max Utilization

在整个 I/O 阻塞挂起期间，底层 OS 平台线程完全没有被卡住，而是被释放去运行其他虚拟线程。硬件 CPU 核心时刻保持满载运算！

本质：将原本由 OS 内核承担的调度阻塞工作，转移到了 JVM 用户态控制
Continuation 机制与 Java 运行时改进 jdk.internal.vm.Continuation
1. jdk.internal.vm.Continuation 概念 JVM Core Secret

Continuation 是 JVM 内部实现“可暂停/可恢复计算”的底层抽象。它保存了计算执行时的局部变量表、操作数栈与程序计数器 (PC)。

2. 堆栈帧按需切片 (Stack Chunk on Heap) Lazy Allocation

传统平台线程预分配 1MB 固定的连续内存；而虚拟线程的调用栈以 Chunk 形式保存在 Java 堆中，按需动态分配与回收，极大省内存！

3. JDK 基础类库重构 (Rewritten I/O Libraries) Transparent Integration

JDK 21 重构了底层网络（java.net.Socket）、并发锁（ReentrantLock）与 Thread.sleep。当被虚拟线程调用时，自动转换为 Yield/Unmount 指令，开发者零感知！

// 当虚拟线程调用 sleep 时，底层并非发起物理 OS 线程挂起：
public static void sleep(long millis) throws InterruptedException {
if (Thread.currentThread() instanceof VirtualThread vthread) {
vthread.sleepNanos(TimeUnit.MILLISECONDS.toNanos(millis));
// 内部调用 VirtualThread.yield() 将 Continuation 冻结卸载！
} else {
sleep0(millis); // 传统平台线程发起 OS Syscall
}
}
架构收益：以最简单的同步代码形式，享受高并发响应式 Netty 级别的极端吞吐

调度机制总结 (Continuation Mechanism Key Insight)

虚拟线程能够支撑百万并发的魔力在于：**把真正的阻塞挂起操作拦截在 JVM 用户态**。通过将调用栈保存到堆内存的 Continuation 对象中，解放物理平台线程去处理其他任务，从而在底层实现了与 Netty / epoll 异步事件驱动完全等价的无损吞吐！

🎯 引导学生透视 Continuation 的工作图景： “向学生强调：为什么 Java 21 的虚拟线程能做到零阻塞？关键在于 JVM 内部的 `jdk.internal.vm.Continuation` 对象。当虚拟线程遇到 Blocking I/O 时，JVM 会将当前函数的调用栈帧（Stack Frame）冻结打包存储在 Java 堆内存中，随后从底层载体线程（Carrier Thread）上卸载（Unmount）下来。此时载体线程被完全释放，可以立刻去调度其他虚拟线程，从而彻底榨干 CPU 的每一分算力！”
💡 剖析 JDK 基础类库重构的深远意义： “提示学生：为了让虚拟线程真正生效，OpenJDK 团队对 JDK 基础类库（如 `Socket`、`ReentrantLock`、`Thread.sleep`）进行了深度重构。当它们检测到调用者是 `VirtualThread` 时，会放弃引发操作系统 Syscall 的内核挂起，改为触发 `Continuation.yield()`。这也是为什么开发者**不需要改动原有的同步阻塞逻辑代码**，就能直接享受百倍吞吐提升的原因！”
