Part 01 · 并发基础 (Concurrency Fundamentals)

进程 vs. 线程 (Processes vs. Threads)

操作系统资源调度的两种基本单位及其在内存模型与通信开销上的本质差异

内存空间与运行环境示意图 Memory Topology
进程 A (Process A) 独立虚拟地址空间
共享资源: 堆 (Heap) + 方法区/代码段 + 文件描述符
线程 1 (Thread 1)
├── 私有程序计数器 (PC)
└── 私有栈 (Stack 1MB)
线程 2 (Thread 2)
├── 私有程序计数器 (PC)
└── 私有栈 (Stack 1MB)
进程 B (Process B) 内存相互物理隔离 (IPC 通信)
Java 语言中：并发编程的核心基本单位是 **Thread**

关键维度特征对比表 (Comparison Matrix) Process vs OS Platform Thread

维度 进程 (Process) 平台线程 (OS Thread)
定义与定位 操作系统**资源分配**的基本单位 CPU **独立调度/执行**的基本单位
资源隔离性 完全隔离，拥有私有虚拟地址空间 共享所属进程的堆 (Heap) 与方法区
创建/销毁开销 极大 (需分配页表、文件句柄等) 较大 (预分配 ~1MB 栈，内核态切换)
通信成本 (IPC) 高 (需通过管道、Socket、共享内存) 极低 (直接共享内存，但需同步机制)
崩溃容错性 单进程崩溃不影响其他进程 异常未捕获或内存污染可致整个进程宕机
核心结论

线程的高效通信建立在**共享内存**的基础之上，但这也是引发数据竞态 (Data Race) 与内存一致性错误的根源。

服务端并发设计的两面性 (Architectural Trade-off)

线程共享进程资源极大地提升了吞吐效率与响应速度；但同时也引入了并发同步控制、锁竞争以及线程安全问题的复杂性。

Speaker Notes / 讲师讲稿
🎯 引导学生理解内存模型差异： “向学生强调，在 Java 服务端程序中，JVM 进程对应操作系统的一个独立进程，而 JVM 内的每一个 Java 线程（传统平台线程）本质上映射为 OS 的轻量级进程。进程间内存相互独立，而线程共享堆和方法区。”
💡 强调并发安全的根本原因： “提示学生：正因为线程共享堆内存，两个线程同时修改同一个对象的 Field 才会产生数据覆盖或可见性问题。这为我们下一部分引入 JMM（Java 内存模型）与 synchronized 锁埋下了伏笔。”
