速度鸿沟： CPU 寄存器访问耗时 $<1\text{ns}$，而访问主内存需 $\approx 100\text{ns}$。CPU 引入缓存机制避免执行单元饥饿。

MESI 协议与写缓冲区： 硬件通过 MESI 协议保证 Cache 一致性，但写缓冲区与乱序执行破坏了顺序可见性。

底层矛盾：硬件追求极致性能 vs 多核内存一致性

JMM 的核心职责 (Core Purpose)

隔离不同操作系统与硬件 CPU 体系结构的差异，通过统一定义变量的访问规则，为上层 Java 开发者提供跨平台的**内存一致性保障**。

内存可见性陷阱 (Visibility Gap)

线程 A 修改了本地工作内存的变量副本后，若未及时刷回主内存，线程 B 将持续读取旧值，导致极难排查的逻辑 Bug！

关键理解：工作内存是 JVM 的规范抽象，非物理实体

并发哲学思考 (Architectural Takeaway)

物理硬件通过缓存极大地提升了单核计算效率，但也彻底破灭了多核下“天然可见性”的幻象。JMM 是 Java 语言在“运行性能”与“可编程性”之间达成的严密契约。
