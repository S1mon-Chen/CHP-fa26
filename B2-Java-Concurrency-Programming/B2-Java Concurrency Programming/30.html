并发模型全景总结与现代 Java 选型决策树

融会贯通 JMM、J.U.C、平台线程物理瓶颈与 Java 21+ 虚拟线程 / 结构化并发体系，构建工程化高吞吐决策模型

1. Java 20 年并发技术演化里程碑 Evolutionary Paradigm Shift
JDK 1.0+
内置锁时代 (Monitored Thread Era)

依赖原生 `synchronized` 与 `Object.wait/notify`，基于重度 OS Mutex 锁，无法解决复杂的非阻塞排队与细粒度同步。

JDK 5/7
J.U.C 与 AQS 无锁时代 (Explicit Locks & Pools)

Doug Lea 引入 J.U.C 工具包、AQS 双向队列、CAS 原语与 `ThreadPoolExecutor`。解耦了锁机制，奠定了高性能服务端基础。

JDK 8/17
声明式异步与响应式流 (Async Pipeline & WebFlux)

`CompletableFuture` 与 Netty / Project Reactor 解决非阻塞高吞吐，但牺牲了单线程直进直出语法与 StackTrace 调试体验。

JDK 21+
虚拟线程与结构化并发 (Project Loom & Structured)

**回归最简单线程 Blocking 语法**，利用 M:N Continuation 卸载极致释放 CPU，彻底消除 1:1 平台线程瓶颈与复杂异步回调！

核心演进准则：用最简单的代码语法，换取极致的云原生硬件吞吐
2. 现代 Java 服务端并发选型决策树 Production Decision Tree
生产环境业务负载类型 (Workload Profile)
分支 A：CPU 密集型 (如加密/图像处理/巨型计算) CPU-Bound Workload

决策：采用经典 ThreadPoolExecutor 或 ForkJoinPool。 线程池大小设为 $N_{\text{cpu}} + 1$，切勿开辟超量虚拟线程避免无效切换！

分支 B：I/O 密集型微服务 (JDBC/RPC/Rest/Redis) ★ 黄金场景首选

决策：**全面升级 Java 21+ 虚拟线程** (`spring.threads.virtual.enabled=true`)！ 一任务一虚拟线程，使用 Semaphore 进行 DB 限流，用 ReentrantLock 替代 `synchronized`。

分支 C：大模型流式推送 (SSE) / 长连接反压 (WebSocket) Reactive & Streaming

决策：结合 **Netty / WebFlux / Project Reactor** 处理网络底层的事件流与反压 (Backpressure)，业务聚合层依然可无缝衔接虚拟线程。

限制池化思想

不要池化虚拟线程！虚拟线程随用随建、用完即毁。

上下文传递演进

全面放弃 ThreadLocal，改用只读结构化 `ScopedValue`。

黄金法则：简单性大于复杂性，优先选择可读性最高的单线程 Blocking 代码

现代并发终极抉择哲学 (Ultimate Concurrency Philosophy)

现代 Java 并发革新的终化目标是：**将高并发的复杂性屏蔽在 JVM 内部**。面对绝大多数 I/O 密集型 Web 微服务，无需牺牲代码可读性去写响应式流。开启 Java 21 虚拟线程，配合 `StructuredTaskScope` 结构化管控与 `Semaphore` 资源防护，就是最优雅、最高性价比的现代后端选型！
