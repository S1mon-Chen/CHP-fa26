无锁并发与 CAS (Compare-And-Swap) 原理

探究 CPU 硬件级原子指令 cmpxchg、AtomicInteger 自旋更新机制与 ABA 问题版本号解决方案

CPU 硬件级 CAS 核心三要素 cmpxchg Assembly Instruction
原子指令格式：CAS(V, Expected, NewValue)
内存位置 V (Variable) 需要更新的物理内存地址
旧的预期值 A (Expected) 线程读取到的旧变量状态
准备写入的新值 B (NewValue) 计算后拟写入的全新数值
底层保障： x86 架构下通过 lock cmpxchg 指令加锁 CPU 总线或锁定 Cache Line (MESI 协议)，在硬件层面保障“读-改-写”的绝对原子性。
// AtomicInteger.getAndAddInt 底层自旋 CAS
public final int getAndAddInt(Object o, long offset, int delta) {
int v;
do {
v = getIntVolatile(o, offset); // 1. 读主存最新值
} while (!weakCompareAndSetInt(o, offset, v, v + delta)); // 2. CAS 自旋试错
return v;
}
优点：无用户态/内核态切换，低竞争场景下吞吐量极高
ABA 问题剖析与版本号解决方案 AtomicStampedReference
ABA 逻辑隐患演进时序 (ABA Timeline) 隐蔽的“偷天换日”
T1: 线程 1 读取变量初始值为 A，准备改写为 C (被打断挂起)
T2: 线程 2 将变量修改：A → B，随后又将其改回 B → A
T3: 线程 1 恢复，比对发现变量仍为 A，CAS 成功！但状态已被污染！
// 解决方案：增加 Stamp 版本号 (加标记元组 Pair<V, Integer>)
AtomicStampedReference<String> asr =
new AtomicStampedReference<>("A", 1); // 初始值 "A", 版本号 1
int stamp = asr.getStamp(); // 读取旧版本号
boolean success = asr.compareAndSet(
"A", "C", // 期望旧值 vs 拟更新新值
stamp, stamp + 1 // 期望旧版本号 vs 拟更新新版本号
);
高并发下 CAS 的局限性：CPU 空转浪费 JDK 8 LongAdder 优化方案

当多线程极高竞争时，CAS 将频繁失败并陷入死循环自旋，大幅浪费 CPU 资源。JDK 8 引入 LongAdder，通过**热点分散 (Cells 数组)** 将多线程单点 CAS 竞争拆分，极大提升极致并发性能！

应用延伸：AtomicReference, AtomicIntegerFieldUpdater, LongAdder

无锁架构思维 (Lock-Free Takeaway)

CAS 无锁并发是现代高并发框架（如 Netty、Disruptor、J.U.C 并发容器）实现极低延迟的核心原语。但需谨记：CAS 适用于**写低中度竞争、短平快计算**；重度写竞争场景下应选用分散热点的 LongAdder 或分段锁！

Speaker Notes / 讲师讲稿
🎯 引导学生透视 CPU cmpxchg 原理： “向学生强调：CAS 的核心在于利用 CPU 硬件级的 cmpxchg 指令。在单核时它天生原子；在多核 CPU 下，则需加上 lock 前缀锁定总线或 Cache Line。Java 语言层面的 AtomicInteger 正是封装了对 Unsafe / VarHandle 的调用。”
💡 强调 ABA 问题与 AtomicStampedReference： “提示学生：在链表或栈结构无锁出入栈时，ABA 问题可能引发严重内存泄漏或节点丢失。解决 ABA 的经典思想就是**版本号 (Version Stamp)**，例如 `AtomicStampedReference` 内部通过维护 (reference, stamp) 的 Pair 元组来消除误判。”
