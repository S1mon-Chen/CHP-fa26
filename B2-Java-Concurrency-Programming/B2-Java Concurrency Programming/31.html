2. 生产工程落地核心研讨课题 (Q&A Discussions) Architectural Debates
Q1 遗留项目开启 `spring.threads.virtual.enabled=true` 是否会有隐患？

**答**：需要全量扫描三方 Jar 包中的 `synchronized` 耗时 I/O 模块，防止 Pinning 锁住 Carrier 线程。开启 JVM 诊断标志 `-Djdk.tracePinnedThreads=full` 并压测验证！

Q2 虚拟线程下数据库连接池 (HikariCP) 为什么会爆满？如何防护？

**答**：虚拟线程极其廉价且无上限，会瞬间并发抢夺连接。必须切断“线程数 = 限流上限”的旧思维，改用 Semaphore(30) 显式限制访问 DB 的并发许可数。

Q3 大模型 AI (LLM) SSE 流式响应场景下，Netty 是否被淘汰？

**答**：没有淘汰！Netty/Reactive 在处理网络最底层的事件驱动、数据流变换与反压 (Backpressure) 时依然拥有不可替代的性能优势，业务层可结合虚拟线程互补！
