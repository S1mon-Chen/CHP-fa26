Part 03 · 传统并发架构瓶颈 (Limitations of Platform Threads)

并发扩展性定律：Amdahl 定律与 Gunther USL 模型

量化分析串行占比 (Serial Fraction) 对理论加速比的天花板限制，与多核 Cache 冲突 (Crosstalk) 引起的倒退瓶颈

1. 阿姆达尔定律 (Amdahl's Law) Theoretical Parallel Speedup
阿姆达尔并发加速比计算公式
$$S(s) = \frac{1}{(1 - p) + \frac{p}{s}}$$
$p$: 可并行计算比例 $1-p$: 强制串行比例 $s$: CPU 处理器核数
极限结论 ($s \to \infty$)： 当 CPU 核心数增加至无穷大时，系统的理论最大加速比上限仅仅取决于串行部分：$S_{\text{max}} = \frac{1}{1-p}$！
串行占比 (1-p) 对最大加速比的绝对封顶
若串行占比 10%
S ≤ 10 倍
哪怕给 10,000 核
若串行占比 5%
S ≤ 20 倍
哪怕给 10,000 核
若串行占比 1%
S ≤ 100 倍
硬件扩展边际递减
瓶颈来源：锁竞争 (Lock Contention)、上下文切换、I/O 阻塞串行化
2. 真实物理世界：Gunther 通用扩展性定律 (USL) Universal Law of Scalability
考虑锁排队与多核 Cache 协调通信损耗 (Crosstalk)
$$X(N) = \frac{\gamma \cdot N}{1 + \sigma(N - 1) + \kappa N(N - 1)}$$
$\sigma$ (Sigma): 排队延迟

线程等待抢锁或进排队队列造成的串行阻塞开销。

$\kappa$ (Kappa): 节点通信开销

多 CPU 核心间 L1/L2 缓存一致性 (MESI) 状态刷新与总线冲突。

扩展性倒退现象 (Retrograde Scalability) The Negative Return

当并发线程数/核心数过大时，$\kappa N(N-1)$ 二次项损耗爆发，吞吐量不仅不再增加，反而**急剧下降甚至引发系统卡死崩塌**！

破局之道：减小锁粒度、消除上下文切换、全面使用非阻塞轻量协程

并发模型演进总结 (The End of Part 03 & Bridge to Part 04)

阿姆达尔定律与 Gunther USL 表明：**单纯堆砌平台线程与硬件核心无法突破物理吞吐上限**。高并发架构的解法是——彻底消除操作系统线程上下文切换损耗与 I/O 阻塞锁定！这直接引出了下一章的革命性方案：**Java 21 虚拟线程 (Project Loom)**！
