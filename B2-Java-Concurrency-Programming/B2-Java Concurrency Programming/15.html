任务队列选型与 4 大拒绝策略深度实战

深入剖析 BlockingQueue 阻塞特性、四大内置拒绝策略及生产级动态降级与监控预警机制

常用 BlockingQueue 任务队列选型对比 java.util.concurrent
1. ArrayBlockingQueue 推荐生产选用

基于数组的有界阻塞队列，内部使用单一 ReentrantLock。强制要求指定容量，能有效防止并发大流量突发时引发内存 OOM 宕机。

2. LinkedBlockingQueue ⚠️ OOM 风险点

基于单向链表的分离锁 (takeLock / putLock) 队列。若构造时不显式传入 capacity，默认上限为 Integer.MAX_VALUE，易引发内存积压暴雷！

3. SynchronousQueue 零容量直接配对

不存储任何元素的直接传递队列。生产者 submit 必须直接挂接消费者获取，常用于 CachedThreadPool 或低延迟实时响应场景。

4. PriorityBlockingQueue 按优先级排序

支持优先级的无界阻塞队列（基于最小二叉堆实现）。任务实现 Comparable 接口，注意防止低优先级任务饥饿。

开发规约：绝不使用默认无界容量构造 BlockingQueue
4 大内置拒绝策略 (RejectedExecutionHandler) Policy Matrix & Custom Handler
1. AbortPolicy (默认)

直接抛出 RejectedExecutionException，中断调用方后续流程。

2. CallerRunsPolicy

退回提交任务的调用方线程自行同步执行，形成天然反压 (Backpressure)。

3. DiscardPolicy

静默丢弃最新提交的任务，无任何日志或异常抛出，极易丢失重要业务。

4. DiscardOldestPolicy

丢弃阻塞队列中最古老（等待最久）的任务，并重新尝试执行当前任务。

// 生产级自定义拒绝策略：打印堆栈 + 上报 Prometheus Metrics + 降级落盘/MQ
public class MetricsFallbackPolicy implements RejectedExecutionHandler {
@Override
public void rejectedExecution(Runnable r, ThreadPoolExecutor executor) {
// 1. 记录监控 Counter 与报警告警
Metrics.counter("threadpool.rejected.count").increment();
// 2. 打印线程池当前关键状态（队列余量、活跃线程数）
log.warn("Task rejected! Active: {}, QueueSize: {}",
executor.getActiveCount(), executor.getQueue().size());
// 3. 业务兜底降级：将无法处理的任务暂存至 Kafka 或本地磁盘
fallbackKafkaTemplate.send("biz-fallback-topic", r);
}
}
生产实践：核心关键业务强烈推荐 CallerRunsPolicy 或自定义落盘降级

线程池容量与拒绝策略防御思考 (Capacity & Backpressure Design)

高并发系统绝不能依赖“无界队列”来逃避拒绝策略。无界队列只是将危机延后并最终转化为致命的 **OOM 宕机**。正确的架构设计是：**结合有界队列 + 明确的拒绝策略**（如 CallerRunsPolicy 产生的自然反压），配合 Prometheus / Grafana 实现线程池饱和度监控！

Speaker Notes / 讲师讲稿
🎯 引导学生理解 CallerRunsPolicy 的反压 (Backpressure) 特性： “向学生强调：当线程池满载时，`CallerRunsPolicy` 让提交任务的上游线程（如 Web 容器 Tomcat 线程）去同步执行任务。这会立刻阻塞上游线程，从而降低向线程池继续提交任务的速度，形成一种优雅的**自适应反馈调节**，防止整个系统崩溃。”
💡 强调生产自定义拒绝策略与监控预警： “提示学生：在实际微服务开发中，简单的抛出异常（AbortPolicy）会导致前端收到大量 500 报错；而丢弃任务（DiscardPolicy）可能造成关键订单丢失。最佳实践是实现自定义 `RejectedExecutionHandler`，在触发拒绝时上报 Prometheus 指标、打印当前活跃线程数堆栈，并将无法处理的任务异步写入 Kafka 或本地 DB 兜底！”
