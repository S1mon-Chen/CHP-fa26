100,000+ 个微型线程，保存在 JVM 堆内存，无 OS 句柄限制

100 万级

N 个载体平台线程 (Carrier Threads)

即传统的 `java.lang.Thread`，数量 $N \approx \text{CPU 核心数}$

N 核相近
<==== 1 : 1 内核绑定 ====> OS Kernel Threads & CPU Cores
传统平台线程 (Platform)
  • • 内存：预分配 ~1MB 固定栈
  • • 数量限制：受限于 OS (~10k max)
  • • 上下文切换：昂贵的 OS 内核态切换
  • • 创建耗时：~1,000 微秒 (Syscall)
Java 21 虚拟线程 (Virtual)
  • • 内存：初始仅 ~200-300 字节
  • • 数量限制：堆内存容量 (~1,000,000+)
  • • 上下文切换：轻量级 JVM 用户态卸载
  • • 创建耗时：~1 微秒 (Heap Alloc)
本质演进：将线程管理的控制权从“操作系统内核”收回到“JVM 用户态”
虚拟线程三大核心特性与范式革新 Zero Paradigm Shift
1. 极度轻量，随用随建 (Disposable & Cheap) No Thread Pool Needed!

虚拟线程极其便宜且数量几乎无限，创建成本等同于实例化一个普通 Java 对象。彻底摒弃“线程池复用/池化”思维！

2. 零范式转移 (Zero Paradigm Shift) java.lang.Thread Subclass

虚拟线程依然是 java.lang.Thread 的实例！无缝继承已有的断点调试、`ThreadLocal`、`Thread.currentThread()` 与全部标准异常堆栈结构。

3. 保留同步阻塞代码编写体验 (Synchronous Coding) Write Sync, Run Async

开发者无需再写复杂难懂的响应式流回调（Flux/Mono）。像写单线程逻辑一样写 jdbc.query() 或 http.send()，底层自动转换为非阻塞挂起！

// Java 21 启动虚拟线程的两种标准方式
Thread.ofVirtual().name("vt-worker").start(() -> {
// 执行同步阻塞 I/O (底层自动非阻塞出栈)
var response = httpClient.send(req, HttpResponse.BodyHandlers.ofString());
});
// 生产级：为每个 incoming 任务派生独立虚拟线程
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
executor.submit(() -> processUserOrder(orderId));
} // AutoCloseable 自动等待所有虚拟线程归队
目标场景：高并发 I/O 密集型微服务与 Serverless 网关

高并发架构哲学革化 (Project Loom Philosophy)

虚拟线程让 Java 重新兼具了**“最简单易懂的同步串行编程模型”**与**“支撑 C1000K 百万并发的极端非阻塞吞吐”**。高并发不再需要牺牲代码可读性去硬写复杂的 Reactive 响应式流，Java 开发者终于迎来了云原生时代的协程红利！

Speaker Notes / 讲师讲稿
🎯 引导学生理解虚拟线程与 Go 语言 Goroutine 的异同： “向学生说明：虚拟线程本质上就是 Java 官方实现的协程（Coroutine）。它与 Go 语言 Goroutine 的核心思想高度相似，即利用 M:N 调度让海量用户态线程共享极少数操作系统平台线程，从而解决传统 1:1 平台线程创建成本昂贵和内核态上下文切换损耗。”
💡 强调思维转变：不要去‘池化’虚拟线程！ “提醒学生注意：过去我们在 Java 中使用 `ThreadPoolExecutor` 是因为操作系统平台线程太贵（1MB 栈 + Syscall）。但虚拟线程初始仅占 200 多字节，创建极为廉价，用完即丢即可。池化虚拟线程不仅没有任何性能收益，反倒增加了锁竞争与内存泄漏风险！”
