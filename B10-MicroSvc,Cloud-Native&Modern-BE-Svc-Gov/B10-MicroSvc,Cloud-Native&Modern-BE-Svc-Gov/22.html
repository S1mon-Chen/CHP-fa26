Part 03 · 网关路由与容错熔断

Gateway Global CORS & Security Filter (`globalcors` 与 JWT Filter)

Centralized Preflight Options, Custom Reactive GatewayFilter & Header Mutation

1. 网关全局 CORS 跨域配置 (`application.yaml`)

globalcors

在网关层统一统一响应浏览器的 OPTIONS 预检请求，无需在各个后端的微服务方法中重复声明 `@CrossOrigin`：

# src/main/resources/application.yaml
spring:
cloud:
gateway:
globalcors:
cors-configurations:
'[/**]':
allowedOrigins: "*"
allowedMethods:
- GET
- POST
- PUT
- DELETE
- OPTIONS
allowedHeaders: "*"
预检请求收口优势 Preflight Handshake

跨域 OPTIONS 请求直接在网关边缘层快速响应，避免无效流量透传至内部业务集群。

提示：允许配置 `allowCredentials` 与自定义跨域请求头映射

2. 自定义 JWT 安全校验网关过滤器 (`JwtCheckFilter.java`)

GatewayFilter
// JwtCheckFilter.java 响应式安全拦截器
@Component
public class JwtCheckFilter implements GatewayFilter {
@Autowired private JwtUtils jwt;
@Override
public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
String jwtToken = exchange.getRequest().getHeaders().getFirst("token");
UserInfo userInfo = jwt.parseToken(jwtToken);
if (userInfo != null && userInfo.getUsername() != null) {
// 1. 解包 JWT 校验成功，突变 (Mutate) Header 注入解密后的用户名称
ServerHttpRequest request = exchange.getRequest().mutate()
.header("userName", userInfo.getUsername())
.build();
return chain.filter(exchange.mutate().request(request).build());
}
// 2. Token 无效或过期，拦截并抛出 502 响应
throw new ResponseStatusException(HttpStatus.BAD_GATEWAY, "Jwt decode error");
}
}
Header 突变（Mutate）与身份传递物理原理 Header Injection

因为 Reactive `ServerHttpRequest` 在网关中是不可变的（Immutable），必须通过 `mutate().header()` 复制构建新 Request。下游服务无需关心 Token 解密，直接通过 `@RequestHeader("userName")` 即可获取用户身份！

安全卸载与跨域治理启发 (Security Offloading Insight)

将 **CORS 跨域握手** 与 **JWT Token 验签逻辑** 卸载至网关层，实现了“一次验签，全网信任”。所有未授权的非法请求均在网关边缘被直接阻断，极大地保障了内网微服务的安全与高性能。
