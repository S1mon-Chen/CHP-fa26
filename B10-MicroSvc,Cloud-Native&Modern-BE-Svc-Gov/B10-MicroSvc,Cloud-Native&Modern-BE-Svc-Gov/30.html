Spring Cloud Function Web 端点与 FaaS 部署 (HTTP Endpoint & Adapters)

`spring-cloud-function-web`, Auto HTTP Endpoint Mapping & Multi-Cloud FaaS Target Packaging

1. 自动 Web HTTP 端点映射 (`spring-cloud-function-web`)

Auto Web Route
// 1. pom.xml 引入 spring-cloud-function-web 依赖
<dependencies>
<dependency>
<groupId>org.springframework.cloud</groupId>
<artifactId>spring-cloud-function-web</artifactId>
</dependency>
</dependencies>
零 Controller 代码，自动暴露 HTTP 路由 Bean Mapping

引入 `spring-cloud-function-web` 后，Spring 自动扫描所有的 `@Bean` 函数，并将其方法名直接映射为 HTTP 端点（如 `/uppercase`、`/compose`），无需编写任何 `@RestController` 或 `@RequestMapping`。

关键：业务方法名即为 REST 路径，真正实现了业务逻辑与接入层的物理解耦

2. HTTP 端点测试与多云打包部署 (HTTP Test & Deploy)

Postman & Deploy
// HTTP POST 测试演练 (`POST /uppercase`)
POST http://localhost:8080/uppercase Content-Type: text/plain
Body (raw): "Hello World"
Response (200 OK): Content-Type: application/json
["HELLO WORLD"]
AWS Lambda / Azure 打包流 Maven Shade Plugin

在生产环境中部署到公有云 FaaS 时，只需更换 `pom.xml` 中的适配器为 `spring-cloud-function-adapter-aws`，并使用 `maven-shade-plugin` 打成 Fat JAR 上传即可瞬间生效！

结束 Part 04，开启 Part 05：Slide 31 · 演进至云原生 Service Mesh 与 Sidecar 模式

Serverless 函数部署终局启发 (FaaS Mapping Insight)

引入 `spring-cloud-function-web` 抹平了本地测试与公有云部署的鸿沟：本地调试时作为标准的 HTTP REST 接口运行，上传云端时作为标准的云原生 FaaS 函数运行，帮助企业无痛拥抱事件驱动无服务器架构。
