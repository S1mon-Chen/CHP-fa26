Spring Cloud Function 统一函数模型 (Spring Cloud Function Overview)

Standard Java Functional Programming (`Function`, `Consumer`, `Supplier`) & Multi-Cloud FaaS Adapters

1. 统一标准 Java 8 函数接口抽象 (Functional Model)

java.util.function

**Spring Cloud Function** 倡导通过标准的 Java 8 函数编程模型实现业务逻辑，将“业务逻辑开发”与“特定物理部署环境”完全解耦：

`Function` (有输入有输出) Input $\to$ Output

接收输入参数并返回计算结果。映射为 HTTP POST 接口、流处理器转换节点或标准 FaaS 函数。

`Consumer` (只接收输入无输出) Sink / Void

仅接收输入参数无返回值。映射为 MQ 消息订阅消费（Sink）或事件日志收集落盘。

`Supplier` (无输入纯输出) Source / Supplier

无输入参数，周期性产生或供应数据。映射为定时轮询事件源（Source）或数据生成器。

优势：同一段代码，既可作为 Web 接口，也可作为 MQ 消费者或 FaaS 函数无缝运行

Cloud Adapters

Amazon Lambda

打包为 `aws-lambda` 适配器包，映射 `RequestHandler`。

Microsoft Azure

无缝挂载至 Azure Functions 响应式触发句柄。

Apache OpenWhisk

兼容开放开源 FaaS 平台的 JSON Action 契约。

Project Riff / Knative

结合 Kubernetes 云原生网关自动拉取 Pod 扩缩容。

完整保留 Spring Boot 核心能力 Auto-Config & DI

在 FaaS 平台部署时，依然可以享受自动配置（Auto-Configuration）、依赖注入（`@Autowired`）以及 Prometheus 指标暴露等完整 Spring 生态收益。

统一函数抽象启发 (Spring Cloud Function Insight)

Spring Cloud Function 实现了**“一次编写，处处运行 (Write Once, Run Anywhere)”** 的云原生承诺：开发者只需基于标准 Java `Function` 编写纯粹的业务逻辑，同一段代码既能在本地作为 HTTP 端点调试，也能打包部署至 AWS Lambda 或 Knative 上。
