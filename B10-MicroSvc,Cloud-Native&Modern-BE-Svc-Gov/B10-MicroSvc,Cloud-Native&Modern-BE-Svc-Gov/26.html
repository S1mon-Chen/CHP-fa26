Part 04 · Serverless、FaaS 与事件函数

What is Serverless & FaaS? (Serverless 与 FaaS 物理概念)

Cloud Computing Abstraction Levels, Infrastructure Offloading & Pay-per-Execution Mechanics

1. 云计算抽象层级的演进 (Cloud Computing Abstractions)

Abstraction Levels

**Serverless (无服务器架构)** 代表了云计算抽象的最高阶段。开发者只需关注业务逻辑编写，将服务器连接、容量规划、操作系统运维与安全补丁等“服务器细节”完全交由云平台处理：

// 云计算抽象演进三部曲
IaaS (Infrastructure as a Service) VMs / ECS

开发者需要手动维护 OS 安装、网络配置、负载均衡器及虚拟机伸缩。

PaaS (Platform as a Service) Kubernetes / App Engine

云平台托管容器与应用运行时，但开发者仍需管理容器镜像、Pod 副本数与 HTTP 服务端口。

FaaS / Serverless (Function as a Service) Pure Business Function

开发者只需上传一个函数。服务器、安全、事务管理、调度器及资源分配全部托管！

核心理念：“专注于代码逻辑，不关心底层服务器基础设施”

2. FaaS (Function as a Service) 物理分工与计费模型

FaaS vs Legacy
// FaaS 与传统基础设施物理责任边界 (Responsibility Boundary)
开发者职责 (FaaS Function)
• 编写单功能处理函数 (Function)
• 声明事件触发源 (Triggers)
• 定义输入输出转换逻辑
云平台托管 (Platform Managed)
• Server 实例准备与 OS 补丁
• 运行时环境与容器分配
• 动态任务调度器与高可用
• 毫秒级按需自动弹性扩缩容
精准按次与毫秒级执行计费 (Pay-per-Execution) 1ms Billing

传统服务器需为全天 24 小时空闲等待付费。FaaS 仅在函数被触发调用的物理毫秒数内计费，真正实现了“无调用不计费”。

开启下一个核心：Slide 27 · Serverless 核心特征：事件驱动、Scale-to-Zero 与无状态性

Serverless 架构思维启发 (Serverless Abstraction Insight)

Serverless 的物理本质并不是“没有服务器”，而是**“开发者无需感知服务器”**。通过将业务逻辑精简为独立运行的函数（FaaS），使团队能够以零运维开销打造高弹性事件驱动应用。
