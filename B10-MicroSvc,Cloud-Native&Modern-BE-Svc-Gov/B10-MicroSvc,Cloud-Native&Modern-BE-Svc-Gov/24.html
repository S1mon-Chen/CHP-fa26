网关熔断与降级处理 (Gateway Fallback Controller & Circuit Breaker Code)

Resilience4j Route Integration, `setFallbackUri("forward:/fallback")` & Reactive `Mono` Response

1. 网关路由挂载 Resilience4j 断路器 (`RouteLocator`)

Route & Fallback URI
// 网关路由注册并挂载 Resilience4j 断路器
@Bean
public RouteLocator myRoutes(RouteLocatorBuilder builder,
UriConfiguration uriConfiguration) {
String httpUri = uriConfiguration.getHttpbin();
return builder.routes()
.route(p -> p
.host("*.circuitbreaker.com") // 1. 匹配 Host 头
.filters(f -> f.circuitBreaker(config -> config
.setName("mycmd") // 2. 断路器名称
.setFallbackUri("forward:/fallback"))) // 3. 熔断降级重定向
.uri(httpUri)) // 4. 后端真实目标地址
.build();
}
`forward:/fallback` 转发流程 Internal Forward

当后端 `httpbin` 出现超时或异常率过高时，Resilience4j 断路器打开并拦截请求，通过 `forward:/fallback` 将请求内部转发给网关自身的本地降级 Controller 处理。

关键：`forward:` 在网关内部进行响应式重定向，不暴露内部降级细节

2. 响应式降级端点实现 (`/fallback`)

Mono<String>
// 响应式 Fallback Controller 处理逻辑
@RestController
public class FallbackController {
@RequestMapping("/fallback")
public Mono<String> fallback() {
return Mono.just(
"fallback: Service is temporarily unavailable. Please try again later."
);
}
}
// 触发降级响应全链路测试
HTTP Request: GET /get (Host: www.circuitbreaker.com)

后端的 `httpbin.org` 响应超时或抛出错误状态码。

HTTP Response: 200 OK (Fallback Active)
