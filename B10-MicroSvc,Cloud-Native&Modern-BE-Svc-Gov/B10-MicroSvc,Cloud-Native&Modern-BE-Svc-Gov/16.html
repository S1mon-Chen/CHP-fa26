客户端负载均衡：从 Ribbon 演进到 Spring Cloud LoadBalancer

Client-side vs Server-side Load Balancing, Reactive Load Balancing & `@LoadBalanced` RestTemplate

1. 负载均衡拓扑对比：服务端 LB vs 客户端 LB

Topology Contrast
// 1. 服务端负载均衡 (Server-Side LB: Nginx / F5)
Client ──► [ Central Proxy (Nginx / F5) ] ──► Target Instance 1 / 2 / 3
缺点：多一次网络 Hop，集中式代理成为网络流量单点瓶颈
// 2. 客户端负载均衡 (Client-Side LB: Spring Cloud LoadBalancer)
Client (拉取服务列表并本地计算 Target IP) ──► 点对点直连 Target Instance 1 / 2
优点：无需中心代理，消除集中网络瓶颈，支持灵活的本地路由算法
// Spring Boot 注入具备负载均衡能力的 RestTemplate
@Bean
@LoadBalanced // 拦截逻辑服务名请求，转为目标 IP
public RestTemplate restTemplate() {
return new RestTemplate();
}
关键：`@LoadBalanced` 拦截器会将 `http://a-bootiful-client/` 自动转换为 `http://192.168.1.6:8080/`

2. 技术演进与三大核心负载均衡算法

Ribbon $\to$ LoadBalancer
Netflix Ribbon (停更/淘汰) Blocking Servlet

传统阻塞式组件，基于 Servlet 模型设计，无法适应 Spring 5+ 响应式 WebFlux 非阻塞架构，进入维护模式。

Spring Cloud LoadBalancer (现代标准) Reactive Non-blocking

官方推荐的无依赖轻量级组件，原生支持 Project Reactor 响应式流，完美兼容 `WebClient` 与 `RestTemplate`。

三大核心负载均衡算法 (Load Balancing Strategies) Algorithms
Round Robin (轮询) 默认策略，按顺序循环分发
Random (随机) 随机挑选目标有效实例
Weighted (加权) 依据响应时间/硬件配置赋权

客户端负载均衡启发 (Client-Side LB Insight)

客户端负载均衡（Client-side Load Balancing）的核心优势在于**“去中心化”**：每个微服务自行从注册中心拉取候选实例列表，并依靠本地负载均衡算法选择目标节点直接发起 RPC，彻底消除了集中式代理网关的单点性能瓶颈。
