2. 双层架构职能明细解构 (Plane Responsibilities)

Istiod & Envoy
控制面：Istiod (Control Plane) xDS Config Push

• **CRD 翻译**：解析 K8s 的 `VirtualService`、`DestinationRule` 等对象，将其翻译为 Envoy 理解的 xDS 配置。
• **安全与身份认证**：作为内置 CA，颁发并定期轮换 SPIFFE/SPIRE 格式的 mTLS 工作负载证书。
• **不介入数据流**：控制面宕机不会影响已建立连接的 Envoy 间 RPC 数据传输。

数据面：Envoy 边车代理 (Data Plane) C++ L4/L7 Proxy

• **流量物理拦截**：基于 `iptables` / `eBPF` 强行拦截 Pod 进出网络流量。
• **治理逻辑执行**：在应用感知不到的情况下完成动态负载均衡、灰度切流、超时重试与 mTLS 加解密。
• **可观测性报文**：实时采集并向 Prometheus / OpenTelemetry 暴露请求 Metrics 与 Traces。

开启下一个核心：Slide 33 · 多语言分布式运行时：Dapr 边车与中间件能力解耦

控制面与数据面分离启发 (Istio & Envoy Architecture Insight)

Istio 展现了真正的云原生解耦设计：**控制面 (Istiod)** 专注于声明式策略管理与规则下发，**数据面 (Envoy)** 专注于极致性能的流量拦截与数据包处理。这种“控制与数据物理分离”的架构极大地保障了整个网格系统的稳定性与横向扩展能力。

Speaker Notes / 讲师讲稿
🎯 引导学员理解 Istio 双层架构： “向学员做解构说明：Istio 服务网格划分为控制面和数据面：
1. **控制面 (Istiod)**：负责策略解析、证书颁发与配置下发。它不处理任何业务数据包，即使控制面临时挂掉，已运行的数据面依然能正常转发请求；
2. **数据面 (Envoy Proxy)**：高性能 C++ 代理，注入在每个 Pod 中，利用 xDS 协议从控制面接收最新路由与安全规则，并执行真正的流量拦截、mTLS 加密和指标收集。”
