Part 04 · Serverless、FaaS 与事件函数

Serverless 核心特征：事件驱动与 Scale-to-Zero

4 Primary Serverless Characteristics: Event Triggers, Zero-Idle Cost, Automated Elasticity & Statelessness

1. 事件驱动代码执行 (Event-Driven Triggers)

Event Triggers

函数的生命周期由外部事件（Event Triggers）驱动。函数无需像传统守护进程那样 7x24 小时死循环等待，无事件触发时代码静止不占用任何 CPU/内存资源：

HTTP / REST Event: API Gateway 路由请求
Object Storage Event: S3 上传图片触发自动缩略图函数
MQ Message Event: Kafka / SQS 产生消息被拉起消费
特点：由明确的物理事件源触发唤醒，处理完即刻休眠

2. 缩容至零 (Scale-to-Zero) 与空闲零成本

Zero-Idle Cost

打破传统服务器“即便零流量也必须常驻付月费”的成本模式。在无流量接入的空闲时段，FaaS 平台自动将物理容器和实例彻底销毁：

// 传统服务器 vs Serverless 成本对比
Legacy Server: 24/7 常驻 100% 物理租用费
Serverless: 流量为零 $\implies$ 费用为 0 元！
特点：将云资源闲置成本降至绝对物理零点，适合长尾/低频接口

3. 毫秒级极速自动扩缩容 (Automated Elasticity)

Milliseconds Scaling

当突发流量冲入时（如突发新闻或大促秒杀），FaaS 平台调度器根据并发请求数，在毫秒级内自动创建数百上千个函数实例分担压力：

Traffic Peak: 10 QPS $\to$ 100,000 QPS Auto Scale in <100ms

无需工程师提前设置复杂的多指标 HPA (Horizontal Pod Autoscaler) 规则，扩容动作完全对开发者透明。

特点：应对极致突发峰值流量，免去预先容量规划风险

4. 函数物理无状态性 (Statelessness)

State Externalized

为了保障任意实例可被随时销毁或弹性拉起，Serverless 函数本身**严格物理无状态 (Stateless)**：

• **禁止内存局保存 Session/State**：函数内部变量生命周期随着单次执行完成而结束。
• **持久状态外置 (Externalized State)**：用户的登录 Token、订单临时状态必须外置沉淀至 Redis Cluster、DynamoDB 或对象存储中。

Serverless 核心特征启发 (Serverless Characteristics Insight)

**事件驱动 + Scale-to-Zero + 自动扩缩容 + 无状态性** 构成了 Serverless 架构的四维支柱。它们共同锁定了无缝弹性与极致成本控制，将后端工程师从繁重的容量规划与节点维护中彻底解脱出来。
