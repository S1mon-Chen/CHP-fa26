2. 实例元数据字段解构与心跳契约 (Metadata Breakdown)

Metadata Attributes
`serviceId` & `uri` (逻辑标识与物理 Endpoint) Address Pair

• **`serviceId`**：全大写逻辑服务名称，供消费端 RestTemplate / WebClient 声明式引用。
• **`uri`**：解析后的真实物理 Socket 地址（IP + Port），负载均衡器直接用该地址发起 TCP/HTTP 通信。

`status` (健康状态：UP / DOWN / OUT_OF_SERVICE) Health Status

只有 `status == "UP"` 的节点才会参与客户端负载均衡。若节点需要无感下线，可切为 `OUT_OF_SERVICE` 拒绝新流量入站。

`leaseInfo` (心跳续约：30s 周期 / 90s 超时剔除) Heartbeat Lease

• **`renewalIntervalInSecs: 30`**：客户端每 30 秒向注册中心发送 `PUT` 续约请求。
• **`durationInSecs: 90`**：若连续 90 秒未收到心跳，注册中心判定该节点超时并予以物理剔除。

服务发现抽象启发 (Discovery API Abstraction Insight)

Spring Cloud 统一的 `DiscoveryClient` 抽象掩盖了底层的注册中心实现细节。无论是 Eureka、Nacos 还是 K8s Native DNS，消费端均可通过同一套 API 拉取包含真实物理 `uri` 与健康 `status` 的 JSON 元数据，支撑起上层柔性路由。
