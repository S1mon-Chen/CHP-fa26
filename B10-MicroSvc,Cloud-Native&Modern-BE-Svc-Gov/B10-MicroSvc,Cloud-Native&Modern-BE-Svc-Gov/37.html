集中式日志收集与分析栈：EFK / ELK (Centralized Log Aggregation)

Filebeat Log Shipper, Kafka Buffer, Elasticsearch Inverted Index & Kibana Trace ID Filtering

1. EFK / ELK 物理日志收集流管线 (EFK Architecture Pipeline)

Logging Pipeline
// 集中式日志收集四大核心环节 (Data Pipeline)
1. Pod Container (`/var/log/pods/*.log`) Filebeat Agent
Pod 内部容器写日志文件，轻量级 Filebeat 实时流式读取
2. 缓冲与清洗 (Kafka Buffer / Logstash Filter) JSON Parsing
Kafka 削峰填谷，Logstash 解析结构化 JSON 字段（如 `timestamp`, `level`, `traceId`）
3. 存储与检索 (Elasticsearch + Kibana UI) Full-Text Search
倒排索引极速全文检索，Kibana 提供基于 `traceId` 的多节点日志过滤
优点：告别逐台服务器 `tail -f`，实现海量分布式日志毫秒级全文检索

2. MDC `traceId` 注入与结构化 JSON 日志 (Logging Best Practices)

MDC & JSON
// logback-spring.xml 结构化 JSON Pattern
<encoder class="net.logstash.logback.encoder.LoggingEventCompositeJsonEncoder">
<providers>
<timestamp/>
<logLevel/>
<threadName/>
<mdc/> <!-- 自动打印包含在 MDC 中的 traceId -->
<message/>
<stackTrace/>
</providers>
</encoder>
MDC (Mapped Diagnostic Context) 贯穿 SLF4J MDC

在网关拦截器或拦截 Filter 中，通过 `MDC.put("traceId", traceId)` 将链路标识注入 ThreadLocal。日志系统会自动将 `traceId` 打入每行日志文本，实现日志与 Traces 的绑定。

集中式日志治理启发 (Centralized Logging Insight)

集中式日志收集（EFK / ELK）完成了可观测性闭环的“临门一脚”。通过规范微服务输出 **结构化 JSON 格式日志** 并注入 **MDC `traceId`**，运维人员在 Kibana 中输入特定 `traceId` 即可直接拉出全网所有相关微服务的异常堆栈。
