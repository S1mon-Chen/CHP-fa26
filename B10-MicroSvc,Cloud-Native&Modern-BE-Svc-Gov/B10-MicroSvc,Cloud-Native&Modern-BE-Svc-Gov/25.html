Part 03 · 网关路由与容错熔断

全链路 JWT 网关路由测试与鉴权流程 (End-to-End Gateway Test & JWT Flow)

Client Token Request, Gateway Filter Decoding, Header Mutation & Downstream Microservice Dispatch

1. 全链路 JWT 授权与路由演练序列 (JWT Routing Sequence)

Flow Sequence
// 1. 登录获取 JWT 令牌 (Login Request)
POST /user/Login (username=reins, password=123) Port 8080
网关剥离 `/user` 转发至 `USER-AUTH` 服务 (11230)，签发 JWT `token` 返回客户端
// 2. 带 Token 访问受保护接口 (Protected Request)
POST /book/buyBook (Header: token) Port 8080
网关 `JwtCheckFilter` 拦截解包，校验合法后重写 Request Header 注入 `userName: reins`
// 3. 动态寻址路由与最终响应 (Target Dispatch)
LB Route: `lb://BOOK-SERVICE` Port 11130
送达 `BOOK-SERVICE` 获取注入的 `userName`，返回 `{ "code": 20000, "data": "userName: reins..." }`
成就：客户端仅需感知网关 8080 单一端口，内部鉴权与路由完全透明解耦

2. 接口测试三步校验与拦截结果 (Postman Verification)

API Test Suite
① 步骤 1：获取 JWT 令牌 HTTP 200 OK

向 `http://localhost:8080/user/Login` 提交登录数据，获取响应 JSON 中的 `token`（形如 `eyJhbGciOiJIUzI1NiJ9...`）。

② 步骤 2：无 Token 访问被网关阻断 (502 Error) HTTP 502 BAD GATEWAY

不传 `token` 请求 `http://localhost:8080/book/buyBook`，网关 `JwtCheckFilter` 抛出异常，拦截并返回 `{"status": 502, "message": "Jwt decode error"}`。

③ 步骤 3：合法 Token 成功透传 (200 OK) HTTP 200 OK

带着 Header `token` 重新访问，网关解包校验通过并注入 `userName` Header，`BOOK-SERVICE` 成功处理并返回业务 JSON。

网关路由与安全终局启发 (Gateway Security Insight)

全链路演练完美展示了网关作为**边缘安全防护罩与动态路由枢纽**的威力：它将认证、鉴权、路由重写与负载均衡统一收口，让内网后端微服务能够专注于纯粹的业务逻辑。
