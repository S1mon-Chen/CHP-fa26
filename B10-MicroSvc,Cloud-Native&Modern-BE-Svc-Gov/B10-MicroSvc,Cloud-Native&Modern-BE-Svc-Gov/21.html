1. 边缘网关路径重写规则 (`GatewayApplication.java`)

rewritePath Filter
// 边缘网关服务配置
@SpringBootApplication
public class GatewayApplication {
public static void main(String[] args) {
SpringApplication.run(GatewayApplication.class, args);
}
@Bean
public RouteLocator myRoutes(RouteLocatorBuilder builder) {
return builder.routes()
.route(p -> p
.path("/books/**") // 1. 匹配对外 URL 路径
.filters(f -> f.rewritePath("/books", "")) // 2. 去除前缀 /books
.uri("http://localhost:8090/")) // 3. 路由送给后端 8090
.build();
}
}
// src/main/resources/application.properties
server.port=8080 # 统一对外网关端口
提示：正则语法 `f.rewritePath("/books/(?.*)", "/${segment}")` 可灵活替换匹配段

2. 请求路由物理管线与测试校验 (Routing Execution)

Path Mapping
// 客户端请求重写与分发链路
客户端请求入站 (Client Inbound) GET http://localhost:8080/books/available

命中断言 Predicate: `Path=/books/**`。

过滤器重写路径 (Filter Transformation) rewritePath("/books", "")

将 URL 路径头部的前缀 `/books` 替换为空白，变为 `/available`。

转发后端目标微服务 (Target Forwarding) GET http://localhost:8090/available

后端 `book-service` (`port: 8090`) 收到处理，返回响应文本: `"Spring in Action"`。

测试对比验证 (Endpoints Verification) 200 OK
  • • 直连访问后端服务: http://localhost:8090/available $\rightarrow$ "Spring in Action"
  • • 网关统一端口访问: http://localhost:8080/books/available $\rightarrow$ "Spring in Action"

路径重写解耦启发 (Path Rewrite Insight)

利用网关的 **`rewritePath`** 过滤器，可以将外部对外的 API 规范命名（如 `/api/v1/books/**`）与内部微服务的简单 REST 端点（如 `/available`）完美解耦，在对外暴露优雅统一层次结构的同时，无需改动后端已有控制器。

因此利用 `f.rewritePath("/books", "")` 过滤器，网关在转发给 `http://localhost:8090/` 之前，会自动将前缀 `/books` 替换为空，完成透明的代理重写。”
