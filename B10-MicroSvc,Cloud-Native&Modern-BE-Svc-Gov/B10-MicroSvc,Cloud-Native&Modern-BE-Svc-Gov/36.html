W3C TraceContext Propagation (`traceparent`), Span DAG Hierarchy & Zipkin / Jaeger Collector

1. W3C `traceparent` Header 全链路透传拓扑 (Trace Propagation)

Trace Context
// 客户端请求跨服务上下文透传 (W3C TraceContext: traceparent)
Client ──► API Gateway Span 1 (Gateway)
生成全局唯一 traceId: `4bf92f3577b34da6a3ce929d0e0e4736`
Gateway ──► USER-AUTH Service Span 2 (Auth)
Header: `traceparent: 00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01`
USER-AUTH ──► BOOK-SERVICE Span 3 (Book)
Header: `traceparent: 00-4bf92f3577b34da6a3ce929d0e0e4736-5e83f2a7e78110b4-01`
▲ 异步向 OpenTelemetry Collector / Zipkin / Jaeger 上报 Span 数组 ▼
核心：相同请求的 traceId 在全局跨服务网络透传中保持恒定不变

2. `traceId`、`spanId` 物理结构与 OTel 集成 (Span Mechanics)

OTel Specs
`traceId` (128-bit 全局事务唯一 ID) Global Transaction ID

标记一条端到端的完整用户请求链。不论该请求在底层跨越了 5 个还是 50 个微服务节点，`traceId` 在整个调用树中完全相同。

`spanId` & `parentSpanId` (64-bit 独立工作单元) Span DAG Node

标记单个微服务内部或单次 RPC/数据库调用的时间跨度片段。`parentSpanId` 用于建立父子调用因果关节点，组合成完整的有向无环图 (DAG)。

W3C `traceparent` 标准 Header 格式 W3C Standard
version-traceId-parentSpanId-traceFlags

格式例：`00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01`，实现跨不同语言探针的标准化透传。

链路追踪架构启发 (Tracing Architecture Insight)

OpenTelemetry 为分布式微服务系统提供了“导航地图”。通过在 HTTP / gRPC 标头中透传 W3C **`traceparent`**，将孤立的微服务日志用全局 **`traceId`** 串联，使长达数秒的慢 RPC 或瓶颈节点在 Gantt 图中一目了然。

🎯 引导学员透视 OpenTelemetry 分布式链路追踪透传原理： “向学员做解构说明：在一个包含数十个微服务的网络中，一个请求卡住了，如果不靠链路追踪是无法定位的。
OpenTelemetry（以及之前的 Sleuth）通过在 HTTP Header 中注入 W3C 标准的 `traceparent`：
1. **`traceId`**：全局唯一 128 位 ID，贯穿整条请求链保持不变；
2. **`spanId`**：每个微服务节点或者单次 RPC 的片段 ID；
3. 通过父子关系 (`parentSpanId`) 组合成完整甘特图，精确定位慢调用。”
