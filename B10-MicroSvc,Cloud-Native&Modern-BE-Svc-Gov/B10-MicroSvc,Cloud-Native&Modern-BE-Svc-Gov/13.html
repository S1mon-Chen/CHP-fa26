拓扑优势：无主从中心节点瓶颈，任何单个 Zone 宕机不影响整体可用性

2. Eureka 复制集群三大物理特性 (3 Core Principles)

Eureka Features
① 无主从平等对等复制 (Peer-to-Peer Replication) No Master Node

不同于 ZooKeeper/Consul 的 Leader-Follower 强一致性选举，Eureka 各 Server 节点平权对等。节点间通过 HTTP 异步互相同步注册变更，哪怕短暂不同步也能保证 AP 高可用。

② 机房区域就近路由 (Zone / Region Affinity) Zone First

Eureka Client 优先连接并调用同属于同一个可用区（Zone）的 Eureka Server 与实例，避免跨机房网络延时；当同 Zone 节点全部挂掉时，才跨 Zone 降级。

③ 自我保护机制 (Self-Preservation Mode) 85% Threshold

当 15 分钟内低于 85% 的心跳续约率时（通常是机房网络突发抖动/断网），Eureka 进入自我保护模式：**冻结注册表，强行不清空未发心跳的实例**，宁可保留旧数据也绝不误杀健康节点。

Eureka 架构设计启发 (AP Resilience Insight)

Eureka 的设计体现了云原生高可用（AP 模式）的精髓：**“无单点故障、就近路由与自我保护”**。它接受数据短暂的最终一致性，换取了在分布式网络分区失联时注册中心永远不会全局瘫痪的坚韧性。
