并行并发控制 (Parallel Execution Guard)：Race Condition 防范与死锁解除

守护共享物理解析与高并发调度的防冲突铁壁：当大模型在单 Turn 吐出 Parallel Tool Calls 涉及共享资源（如同一文件写/删、同一库表更新）时，通过 资源路径锁 (Resource Mutex Lock)、依赖冲突检测 (Path Collision Detector) 与 动态串行化降级队列 (Serial Fallback Queue)，杜绝 Race Condition 竞态条件与死锁溃败

ParallelExecutionGuard 实现

Resource Lock & Collision Guard

Parallel Guard 
import asyncio

class ParallelExecutionGuard:
    def __init__(self):
        self.resource_locks = {}  # 映射资源路径与读写排他锁 ★

    def detect_collisions(self, parallel_calls: list[ToolCall]) -> tuple:
        # 1. 提取所有并发 Tool Calls 的物理资源路径 (如 file_path) ★
        resource_map = {}
        for call in parallel_calls:
            res_key = call.args.get("file_path") or call.args.get("table_name")
            if res_key:
                resource_map.setdefault(res_key, []).append(call)

        # 2. 判断是否存在同一资源的写-写/写-读重叠冲突 ★
        conflicts = [calls for calls in resource_map.values() if len(calls) > 1]
        return conflicts, resource_map

    async def schedule_safe_execution(self, parallel_calls: list[ToolCall]) -> list:
        conflicts, res_map = self.detect_collisions(parallel_calls)
        if not conflicts:
            # 无冲突直接全并发并发执行
            return await asyncio.gather(*[self._exec(c) for c in parallel_calls])

        # 3. 存在竞态冲突：冲突组降级为顺序串行队列，其余放行并发 ★
        return await self._execute_serialized_queue(parallel_calls, res_map)
  • 防写冲突与覆盖：当 LLM 同时吐出 `write_file("app.py")` 与 `delete_file("app.py")` 时，前置识别并强制降级串行化。
核心：用确定性的资源路径检测锁住非确定性的 Parallel Tool Calls

并行并发控制的三大工程支柱

3 Core Pillars of Concurrency Guard

Parallel Pillars
1. 共享资源路径冲突检测 (Path Collision Detector) Conflict Scanning

在并发工具派发前，预先解析入参中的 `file_path` 或 `table_name`；若发现多个并发 Tool 作用于同一物理解析目标，标注为冲突组。

2. 动态串行化排队降级 (Serial Queue Fallback) Sequential Execution

对无依赖冲突的工具保持高并发 `asyncio.gather`；对重叠资源冲突组自动降级为串行队列（FIFO Queue），消除 Race Condition。

3. 读写互斥锁与死锁超时解锁 (RW Lock & Timeout) Mutex & Deadlock Release

为共享资源施加读写锁（Read-Write Lock）；设定强制锁获取超时（如 $T \le 5.0\text{s}$），若发生循环等待则主动释放并丢给 LLM 重新排队。

Architectural Core Thesis / 架构师视角

并行调用不等于乱序竞态！通过 资源冲突检测与读写锁 (RW Mutex Lock) 在控制流层阻止并发写冲突与死锁，是保障 Agent 开启 Parallel Tool Calling 依然保持状态一致性的必由之路。
