封堵大模型上下文的凭证泄露漏洞：在工具返回值压入 Context 之前，构建 Observation 清洗管道 (Sanitizer Pipeline)，利用正则与 NER 语义识别自动抹除 AK/SK 密钥、密码、JWT Token 与 PII 个人隐私数据

ObservationSanitizer 管道实现

Regex & PII Masking Pipeline

Sanitizer Engine 
import re

class ObservationSanitizerPipeline:
    def __init__(self):
        self.rules = [
            (r"AKIA[0-9A-Z]{16}", "[REDACTED_AWS_AK]"),            # 1. 云密钥 AK/SK 抹除 ★
            (r"eyJ[A-Za-z0-9-_=]+\.[A-Za-z0-9-_=]+\.?[A-Za-z0-9-_.+/=]*", "[REDACTED_JWT]"), # 2. JWT 鉴权 Token ★
            (r"(?i)password\s*=\s*['\"][^'\"]+['\"]", "password='[REDACTED]'"), # 3. 数据库明文密码
            (r"1[3-9]\d{9}", "[REDACTED_PHONE]"),             # 4. PII 手机号码 ★
            (r"\d{17}[\dXx]", "[REDACTED_ID_CARD]")            # 5. PII 身份证件
        ]

    def sanitize(self, raw_observation: str) -> str:
        cleaned = raw_observation
        for pattern, replacement in self.rules:
            cleaned = re.sub(pattern, replacement, cleaned)
            
        # 物理防止脱敏失败数据污染大模型 Context Window ★
        return cleaned

# 6. 工具分发钩子：在将 Observation 压入 Message 历史前强制洗言
def on_tool_execution_complete(raw_output: str) -> str:
    return ObservationSanitizerPipeline().sanitize(raw_output)

核心：把任何写回 Context 的 Observation 视为不可信数据源，强制执行正则/NER 脱敏

观察日志清洗脱敏的三大工程支柱

3 Core Pillars of Observation Sanitizer

Sanitizer Pillars
1. 凭证与密钥正则抹除 (Secret & Key Redaction) Regex Secret Eraser

匹配 AWS AK/SK、GitHub Personal Token、数据库连接串明文密码与 JWT 鉴权头，将其替换为 `[REDACTED_*]` 占位符。

2. PII 个人隐私遮蔽管道 (PII Scrubbing Pipeline) NER & PII Masking

结合轻量级命名实体识别（NER）算法过滤手机号、身份证号、银行卡号与真实姓名，确保系统符合 GDPR/数据安全法强合规需求。

3. 审计日志与拦截阻断 (Compliance Audit Guard) Egress Gate & Audit

若捕获到无法安全脱敏的高危凭证泄漏（如完整的 RSA 私钥），清洗管道前置抛出告警并阻断数据提交给云端大模型 API。

Architectural Core Thesis / 架构师视角

绝对不要盲目信任工具的返回内容！构建 观察日志清洗管道 (Observation Sanitizer Pipeline) 在写回 Message Context 前抹除密钥与 PII 隐私，是企业级 Agent 满足数据合规与防凭证外泄漏的铁底线。
