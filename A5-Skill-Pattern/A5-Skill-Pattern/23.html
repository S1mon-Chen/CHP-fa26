守护财务底线与算力安全的双重物理拦截网：建立基于 Token 预算滑动窗口 (Token Budget Guard)、单任务 Tool 深度卡扣 (Max Step Limits) 与 多租户令牌桶/漏桶限流阀，防止失控 Agent 刷爆 API 账单与穿透下游微服务

TokenBudgetAndRateLimitGuard 实现

Quota, Rate Limit & Cost Guard Engine

Cost Guard 
class TokenBudgetAndRateLimitGuard:
    def __init__(self, max_tokens: int = 50000, max_steps: int = 12):
        self.max_tokens = max_tokens
        self.max_steps = max_steps
        self.consumed_tokens = 0
        self.current_step = 0

    def check_and_consume(self, step_tokens: int) -> GuardCheckResult:
        self.current_step += 1
        self.consumed_tokens += step_tokens

        # 1. 步数卡扣检查：超过单任务 Max Steps 强制阻断 ★
        if self.current_step > self.max_steps:
            return GuardCheckResult(
                allowed=False, 
                reason="MAX_STEPS_EXCEEDED", 
                action="GENERATE_PARTIAL_REPORT"
            )

        # 2. Token 算力预算检查：突破配额触发财务卡扣 ★
        if self.consumed_tokens >= self.max_tokens:
            return GuardCheckResult(
                allowed=False, 
                reason="TOKEN_BUDGET_EXHAUSTED", 
                action="CIRCUIT_BREAKER_TERMINATE"
            )

        return GuardCheckResult(allowed=True)
  • 优雅截断而非暴溃：触发配额卡扣时自动导出已完成阶段的部分结果（Partial Summary Report），保障已消耗算力的价值投产。
核心：用多维物理阈值锁定算力上限，杜绝越权刷爆企业 API 账单

流量控频与配额熔断的三大防护支柱

3 Core Pillars of Cost Guard

Cost Pillars
1. 单任务多维硬预算 (Multi-dimensional Hard Budget) Task Budget Cap

绑定 Max Steps ($N \le 12$)、Max Token Cap ($T \le 50,000$) 与最大单次计算美元上限 ($C \le \$2.00$)，多重物理阀门阻断长链耗算。

2. 多租户令牌桶限流 (Multi-tenant Rate Limiter) Token Bucket / Leaky Bucket

引入 Redis 令牌桶算法实施 RPM/TPM 控制；在高并发并发请求触顶时优先排队挂起，避免击穿第三方 SaaS API 或大模型网关。

3. 渐进式预警与优雅降级输出 (Progressive Degradation) Partial Report Output

消耗达 80% 预算时向 Context 注入警告提示“算力即将耗尽，请立即收敛并生成最终总结”，避免因直接中断丢弃中间计算成果。

Architectural Core Thesis / 架构师视角

无上限算力是财务灾难的根源！通过 多维硬预算卡扣 (Max Steps/Tokens) 与令牌桶限流网关 建立严格的资费卡扣与控频隔离墙，是生产级 Agent 商业化落地的硬核前提。
