// 1. [Spring AI 后端] 暴露受控事务与安全沙箱 RPC Bean ★
@Configuration
public class BackendSecSkillConfig {
    @Bean
    @Description("Executes AST-based DB patch with Spring @Transactional rollback")
    public Function<DbPatchRequest, DbPatchResponse> springDbPatcherSkill() {
        return request -> dbService.applyTransactionalPatch(request);
    }
}

# 2. [Claude Code 前端] .claude/skills/ci-refactor/SKILL.md 声明式契约 ★
---
name: ci-refactor
tools: [springDbPatcherSkill, git_stash_tool]
---
# Workflow
1. Local Git: create Stash backup via `git_stash_tool`.
2. Remote Spring AI: call `springDbPatcherSkill` for DB patch.
3. Local Docker: run `pytest`. If failed, auto-trigger local Undo.
  • 优势互补：前端 Claude Code 掌控本地 Git 工作树与终端，后端 Spring AI 管辖物理数据库事务与安全鉴权。
核心：前端声明式指令控制本地工作流，后端强类型组件控制高危写动作

混合 Skill 链四大控制机制

4 Hybrid Control Mechanics

Dual-Framework
1. 前端 CLI 声明式工作流 (Claude Code `SKILL.md`) CLI Local Control

在开发者 IDE / CLI 端维保 Markdown 规则，负责处理 Bash 脚本执行、Git Stash 快照与本地物理文件改动。

2. 后端 JVM 强类型服务 (Spring AI Managed Bean) Spring AI Backend

在 Java 微服务后端托管复杂修改命令，借助 `@Transactional` 物理事务回滚与 `@PreAuthorize` 拦截违规写入。

3. 状态同步与 JSON-RPC 桥接 (State Synchronization) JSON-RPC Bridge

前后端通过轻量级 JSON-RPC 或 REST API 完成状态对齐，实现多语言、跨进程的统一 `tool_call_id` 句柄强锁定。

4. 跨框架双向反撤销 (Cross-Framework Rollback) Unified Rollback

当后端 Spring AI 事务抛错回滚时，瞬间向前端 Claude Code 返回失败信号，同步触发本地 `git checkout .` 物理复原。
