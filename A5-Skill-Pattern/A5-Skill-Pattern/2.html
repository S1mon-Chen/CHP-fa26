开放 Agent Skill 标准形态：SKILL.md 架构解构（YAML Frontmatter + Markdown）

解构 Agent Skills 社区开放标准契约：通过 YAML Frontmatter 声明式元数据 与 Markdown 程序化工作流 的双层物理缝合，构建跨 AI 引擎通用的能力描述标准

标准 SKILL.md 物理结构解构

YAML Frontmatter + Markdown Body

Standard Spec 
---
name: security-vulnerability-auditor
description: Audits source code for OWASP vulnerabilities.
tools: [ast_parser, semgrep_scanner]
user_approval_required: false
---

# Skill Workflows
1. Parse code into AST via `ast_parser`.
2. Run static rules via `semgrep_scanner`.
3. If critical flaw is found, request fix patch.

## Constraints & Examples
- Do NOT modify production DB credentials.
- Example: `auditor --severity=HIGH`
  • 头部 Frontmatter 结构化解析：供宿主引擎做类型推导、权限卡扣与依赖匹配。
  • 主体 Markdown 注入上下文：自然语言 Prompt 作为领域微型指导网关拉引 LLM 推理。
核心：由 Claude Code、Cursor 与 Agent Skills 社区共同支持的开放格式

SKILL.md 契约设计的两大核心优势

Declarative Spec + Procedural Prompt

Design Benefits
1. 声明式元数据 (Declarative Frontmatter) Engine Control Layer

YAML 前置三导线解析工具依赖（`tools`）、触发词描述（`description`）与安全拦截阀门（`user_approval_required`），无需运行全量 Prompt 即可提前预判权限。

2. 程序化指导文本 (Procedural Markdown Body) Context Guidance Layer

Markdown 正文提供领域微型 Prompt（Micro-Prompt），定义一、二、三阶段工作流步骤、边界约束与 Few-Shot 正反例，确保 LLM 决策过程强收敛。

3. 跨引擎互操作性 (Cross-Engine Interoperability) Zero Provider Lock-in

同一份 `SKILL.md` 既能被 Claude Code 原生加载，也能被 Cursor、LangChain 以及 Java 生态的 Spring AI 动态解析，消杀厂商锁定。

Architectural Core Thesis / 架构师视角

SKILL.md 实现了“声明式元数据”与“程序化指导文本”的物理缝合；它不仅是自然语言 Prompt，更是跨 AI Agent 宿主引擎通用的能力能力契约。
