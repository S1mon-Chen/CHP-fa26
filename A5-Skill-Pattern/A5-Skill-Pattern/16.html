缓存与幂等模式 (Cache & Idempotency Pattern)：耗时 Skill 调用的缓存与状态快照

消杀高耗时与高计费调用的算力浪费：基于 SHA-256 确定性幂等键 (Idempotency Key) 匹配与 Observation 状态快照持久化，在源码未改动时秒级命中缓存返回，降本 90% 并保障长链重试的平滑收敛

CachedVulnerabilityScanSkill 缓存实现

Idempotent Snapshot & Fast Cache Engine

Idempotency Pattern 
import hashlib, json

class CachedVulnerabilityScanSkill(BaseSkill):
    def __init__(self, cache_store: RedisCache):
        self.cache = cache_store
        self.skill_version = "v2.1"

    def execute(self, file_path: str, rules: list[str]) -> ScanResult:
        content = read_file(file_path)
        # 1. 计算文件哈希 + Skill版本 + 规则集的物理确定性 Key ★
        raw_key = f"{content}:{self.skill_version}:{sorted(rules)}"
        cache_key = hashlib.sha256(raw_key.encode()).hexdigest()

        # 2. 检查缓存是否命中 (Zero Execution Time) ★
        cached_obs = self.cache.get(cache_key)
        if cached_obs:
            return ScanResult.from_json(cached_obs, is_cached=True)

        # 3. 未命中：触发物理重型 AST / Semgrep 静态扫描
        result = self._expensive_ast_scan(file_path, rules)
        self.cache.set(cache_key, result.to_json(), ttl_seconds=86400)
        return result
  • 计算零等待：重试或多轮推演中遭遇未变动源码时直接返回 Snapshot，响应耗时从 8.5 秒剧降至 2 毫秒。
核心：利用确定性输入 Hash 锁定 Observation 快照，杜绝重复计算与 Token 浪费

缓存与幂等模式的三大核心支柱

3 Core Pillars of Idempotency Pattern

Idempotency Pillars
1. 物理确定性幂等键 (SHA-256 Keying) Deterministic Keying

将源码内容、参数配置、底层扫描规则库 Hash 及 Skill 代码版本联合生成唯一 `Cache-Key`，避免因版本更新读取陈旧快照。

2. 状态快照与观察透传 (Observation Persistence) Observation Snapshot

将复杂的 AST 语法树解析结果或微服务 RPC 返回完整序列化存入 Redis/PostgreSQL，即使多轮推演崩溃重启后亦能瞬间复原。

3. 变动失效与失效粒度 (Cache Invalidation) Granular Invalidation

绑定 Git Diff 变动感知；仅当目标文件内容物理更新或提交新 Commit 时才触发该节点的缓存失效，实现局部精确重算。

Architectural Core Thesis / 架构师视角

高耗时 Skill 不加缓存等于财务与延迟灾难！通过 缓存与幂等模式 (Cache & Idempotency Pattern) 锁定输入 Hash 与 Observation 快照，是确保大型 Agent 系统在高频重试与长依赖链条下维持高响应速度与低成本的黄金法则。
