Skill 物理存储与作用域隔离

Scope Isolation & Storage Paths

Scope Spec
项目级 Skill Team Shared Standard Git Committed 
.claude/skills/<skill-name>/SKILL.md

随仓库代码提交 Git，对团队所有成员强生效。用于定义团队架构规约、Lint 代码规范检查、项目专有 CI 脚本集成。

个人级 Skill Personal Preferences Cross-Project 
~/.claude/skills/<skill-name>/SKILL.md

存储于本地 Home 目录，跨项目通用。用于开发者个人偏好的 Commit 格式化、特定调试助手或个性化 Workflow 工具。

覆盖顺序：Enterprise (组织) > Personal (个人) > Project (项目)

渐进式加载生命周期 (Progressive Disclosure)

3-Tier Progressive Load

Token Saver
1 启动摘要扫描 (Startup Registration) ~100 Tokens/Skill

会话启动时，Agent 控制器仅预加载所有 Skill 的 `name` 与 `description` 到系统 Prompt 中作为路由网关。

2 匹配正文加载 (Context Activation) On Intent Match

当用户 Task 与描述命中时，才向 Context 中拉引读取完整的 `SKILL.md` 正文指令与操作步骤。

3 关联资源深挖 (Sub-rule Navigation) Lazy Loaded

仅在特定步骤需要时，才按需读取附带的脚本、参考样例 (reference.md) 或配套 Bash 脚本。

Architectural Core Thesis / 架构师视角

划分项目级（以 Git 仓库维保）与个人级（跨项目偏好）作用域，兼顾了团队统一治理与个人灵活性；通过三层渐进式加载（Progressive Disclosure），消杀未触发 Skill 对上下文窗口（Context Window）的无谓侵占。

Speaker Notes / 讲师讲稿
🎯 剖析项目级 vs 个人级 Skill 作用域： “向学员深入剖析：在 Claude Code 和 Agent Skills 生态中，Skill 具有明确的作用域（Scope）。存储在项目仓库 `.claude/skills/` 下的 SKILL.md 随 Git 提交，保证团队所有成员与 CI 流程拥有一致的 Agent 操作规范；而 `~/.claude/skills/` 则是开发者个人的私有偏好。”
💡 讲授渐进式加载（Progressive Disclosure）： “提示学员注意右侧的渐进式加载流程：如果安装了 30 个 Skill，如果不加控制，每次对话就会吃掉数万 Tokens。Claude Code 采用三层渐进加载，启动时仅用少量 Token（~100 tokens/skill）读取 `name` 和 `description`；只有当用户请求匹配该 Skill 意图时，才在运行时懒加载 `SKILL.md` 正文，彻底解决 Context Window 溢出问题。”
