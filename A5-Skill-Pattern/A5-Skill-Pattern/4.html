手把手打造生产级 Skill 配置文件：以 refactor-legacy-sql 为例，掌握 精确定向 description 触发表、环境变量边界 与 Few-Shot 示范表达

`refactor-legacy-sql/SKILL.md`

Production SKILL.md Code Example

YAML + MD 
---
name: refactor-legacy-sql
description: Refactors MySQL 8.0 queries to fix index invalidation, DATE() function traps, & full-table scans. Triggers on slow SQL optimizing tasks.
tools: [ast_parser, explain_analyzer]
environment_variables: [MYSQL_VERSION]
user_approval_required: false
---

# Refactor Legacy SQL Workflows
1. Run `explain_analyzer` to check `type=ALL` risks.
2. Scan anti-patterns: `DATE(column)` or implicit type cast.
3. Rewrite into range queries or index-friendly forms.

## Few-Shot Exemplar
- Bad:  `WHERE DATE(created_at) = '2026-08-01'`
- Good: `WHERE created_at >= '2026-08-01 00:00:00' AND created_at < '2026-08-02 00:00:00'`
  • 结构清晰易维护：YAML 定义静态环境规则，Markdown 正文注入领域微型 Prompt。
物理文件：存储于 `.claude/skills/refactor-legacy-sql/SKILL.md`

编写高质量 SKILL.md 的四大核心要点

4 Golden Rules for SKILL.md

Authoring Spec
1. 触发词精准匹配 Precise Trigger Keywords

在 `description` 中写明具体的业务名词（如 `MySQL 8.0`、`index invalidation`、`DATE() trap`），确保意图路由网关高召回。

2. 声明环境变量依赖 Environment Variables Bound

通过 `environment_variables: [MYSQL_VERSION]` 显式拦截环境依赖，若宿主未配置则提前报错，杜绝盲目执行。

3. 步骤递进工作流 Step-by-Step Workflow

正文使用清晰的 `1. 2. 3.` 步骤约束推理路线：从 EXPLAIN 分析 $\to$ 反模式扫描 $\to$ 范围改写，收敛 LLM 决策过程。

4. 内嵌 Few-Shot 示例 Few-Shot Bad/Good Pair

提供明确的 Bad Input 与 Good Output 对比，为模型生成重构代码提供最直观的注意力对齐参照。

下一步：学习大型复杂 Skill 的树状拆解与子规则网络装载

Architectural Core Thesis / 架构师视角

SKILL.md 中的 Markdown 正文就是针对该专业能力定制的领域微型 Prompt（Micro-Prompt）；通过触发词精确化与 Few-Shot 正反例模版，能将工具生成的二次修补成功率提升 90% 以上。
