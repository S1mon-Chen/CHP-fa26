# Workflows
1. Parse target scope (DB layer or Auth layer).
2. If auditing DB: read [DB Rules](./rules/db-rules.md)
3. If auditing Security: read [Security Rules](./rules/security-rules.md)
  • 引用隔离：主 `SKILL.md` 仅作为网关，把数万字专有规则拆入 `rules/*.md`。
物理特性：使用相对 Markdown 链接 `[Title](./rules/file.md)`

子规则网络的三大工程优势

3 Core Pillars of Sub-Rule Network

Sub-Rule Specs
1. 避免 Context Window 爆表 Context Slimming

主控 `SKILL.md` 极度瘦身（通常控制在 300~500 Tokens 内），避免将尚未用到的全量架构规约一次性灌入上下文。

2. 相对路径按需懒加载 Lazy-Loaded Navigation

当 Agent 确定需要审计 DB 模块时，才通过 Markdown 链接导航去抓取 `./rules/db-rules.md`，实现精确注意力聚焦。

3. 领域规则解耦与协作 Modular Cohesion

安全团队维保 `security-rules.md`，DBA 团队维保 `db-rules.md`，实现多团队在大型项目中的 Git 并行协作。

Architectural Core Thesis / 架构师视角

利用高内聚低耦合的软件工程思想，将大型巨型 Skill 拆解为“主控路由 + 子规则网络（Sub-Rule Network）”；通过相对路径实现按需延迟装载，是支撑企业复杂规则库扩展的关键手段。

Speaker Notes / 讲师讲稿
🎯 讲授大型 Skill 的树状拆解哲学： “向学员深入剖析：在企业大型项目里，如果把全量架构审计规则或者安全规约都塞进一个巨型 `SKILL.md`，文件可能会长达上万行。这不仅会直接挤爆 Context Window，还会导致大模型生成时发生‘注意力迷失’。”
💡 强调相对路径按需导航： “提示学员注意：主 SKILL.md 应当只保留最核心的路由判别和工作流。对于具体的子领域规则（如 DB 规范、OWASP 安全规范），分别存放在 `rules/` 目录下。Agent 只有在确定要审查 DB 模块时，才通过 Markdown 链接导航去抓取 `db-rules.md`，实现极致的 Context 瘦身。”
