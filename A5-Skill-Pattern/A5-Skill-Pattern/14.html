降级容错模式 (Fallback Pattern)：API 断路器、模型降级与本地规则兜底

消除单点故障（SPOF）引发系统溃败的物理护城河：建立 API 断路器 (Circuit Breaker) 与 阶梯式降级链 (Fallback Chain)，在首选微服务发生 500、超时或限流时自动降级至 本地工具 (git grep) 或规则兜底，保障 Agent 流程强收敛

FallbackCodeSearchSkill 实现

Resilient Multi-Tier Code Search Engine

Fallback Chain 
class FallbackCodeSearchSkill(BaseSkill):
    def __init__(self):
        self.breaker = CircuitBreaker(fail_max=3, reset_timeout=30)
        self.remote_api = RemoteCodeSearchAPI()  # 远程高精搜检索微服务

    def execute(self, query: str, repo_path: str) -> SearchResult:
        # 1. 尝试主线：远程高精度微服务 API（带断路器与超时）★
        if self.breaker.is_closed():
            try:
                return self.remote_api.search(query, timeout_s=3.0)
            except (TimeoutError, Service500Error):
                self.breaker.record_failure()  # 触熔断阈值开启隔离

        # 2. 一级降级：本地 git grep 物理高速扫描 ★
        try:
            res = subprocess.check_output(["git", "grep", -n, query], cwd=repo_path)
            return SearchResult(status="DEGRADED_GIT_GREP", matches=res)
        except Exception: pass

        # 3. 二级兜底降级：本地 Python 文本正则匹配 ★
        return SearchResult(status="DEGRADED_LOCAL_REGEX", matches=...)
  • 允许局部能力优雅降级：即使远程向量搜索 API 宕机，Agent 依然能通过本地 `git grep` 取得大部分有效结果，确保主工作流不中断。
核心：用阶梯式本地兜底与 API 断路器，保障 Agent 整体任务流高可用

降级容错模式的三大核心支柱

3 Core Pillars of Fallback Pattern

Fallback Pillars
1. API 断路器与超时卡扣 (Circuit Breaker & Timeout) Failure Isolation

在 Skill 内部拦截网络超时与 5xx 错误；当连续失败次数触发阈值时打开断路器（Open State），快速切断故障节点避免长延时阻塞。

2. 阶梯式模型/工具降级 (Staircase Fallback Chain) Tiered Fallback

建立高精 API $\to$ 本地工具 $\to$ 规则/小模型（SLM）的降级阶梯；在云端服务不可用时，利用本地确定性脚本提供替代结果。

3. 结果可敛性与状态标记 (Degraded State Tagging) Strong Convergence

降级执行的结果明确标注 `DEGRADED_*` 状态码，使上游 LLM 或 Controller 在推理时能感知能力缩减，调整下一步决策方向。

Architectural Core Thesis / 架构师视角

零单点故障（Zero SPOF）是企业级 Agent 的硬指标！通过 降级容容模式 (Fallback Pattern) 与断路器机制 允许局部能力优雅降级，是确保 Agent 系统在面对第三方 API 宕机与网络抖动时依然能完成任务的黄金准则。
