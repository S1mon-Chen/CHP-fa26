消杀长链条推演中的注意力稀释与 Context Window 溢出：通过 Log 语义提纯中间件 (Pruning Middleware) 提取关键失败堆栈，配合 首尾双视窗滑动裁剪，将 5000 行冗余日志凝练至 200 Tokens，确保 Agent 上下文维持极高信息密度

LogPruningMiddleware 提纯实现

High-Density Observation Pruner

Context Pruning 
import re

class LogPruningMiddleware:
    def __init__(self, max_token_budget: int = 500):
        self.budget = max_token_budget

    def compress_observation(self, raw_log: str) -> str:
        lines = raw_log.splitlines()
        if len(lines) < 60: return raw_log  # 未超预算直接原样放行

        # 1. 正则匹配核心 FAILURES & Traceback 关键错误段 ★
        failures = re.findall(r"(?:FAILURES|ERROR|Traceback).*?(?=\n\n|\Z)", raw_log, re.S)
        
        # 2. 首尾双视窗保留：保留 Header 15 行 + Tail 25 行 ★
        head = "\n".join(lines[:15])
        tail = "\n".join(lines[-25:])
        core_stack = "\n".join(failures[:2]) if failures else "NO_EXPLICIT_STACK"

        # 3. 5000 行被精准压平为 200 Tokens 核心 Observation
        return f"{head}\n...[Truncated {len(lines)-40} Lines]...\n{core_stack}\n{tail}"
  • Token 消耗剧降 95%：原本占满 12,000 Tokens 的垃圾构建刷屏日志被瞬间提纯，彻底消除“中间迷失”陷阱。
核心：用日志提纯中间件截断冗余打印，仅向 Context 输送高价值堆栈与结果

上下文瘦身模式的三大核心支柱

3 Core Pillars of Context Pruning

Pruning Pillars
1. 动态滑动窗口 (Sliding Window Truncation) Token Budget Limit

为工具的 Observation 设定物理预算上限（如 Max 500 Tokens）。超过门限即触发首尾双视窗物理裁剪，保留任务参数与结尾总结。

2. 异常堆栈提纯 (Stacktrace Extraction) Regex Semantic Filter

通过正则或 AST 检索算法，抓取 `FAILURES`, `ERROR`, `Traceback` 等核心节点，剥离无意义的底层库加载与下载进度条。

3. 观察快照降维 (Observation Compression) Summary Snapshot

将极长的 JSON 或 SQL 查询结果集转换为统计元数据（如 `Count: 42, Sample: [...]`），在不损失模型推理必要信息的同时极大瘦身。
