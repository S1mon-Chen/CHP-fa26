模块四导论：评估驱动开发 (Eval-Driven Development) 在 Skill 工程中的应用

告别主观猜想与盲目修改 Prompt：建立以 定量基准数据集 (Eval Benchmark Dataset)、自动化质量回归门控 (Regression Gate) 与 持续闭环优化 (Continuous Eval Loop) 为核心的评估驱动开发 (EDD) 工程体系

盲目微改导致意图召回暴跌惨案

Prompt Silent Regression Incident

Regression Case
[SKILL.md Baseline] 原始精确定向 Description Accuracy: 96.2%

"Queries MySQL 8.0 user order records by user_id or order_id."

[Blind Prompt Edit] 盲目泛化修改 Description Accuracy: 58.4% ⬇ (-37.8%)

"Helps query various database tables and order details flexibly."

  • 隐蔽退化风险：以为泛化说明能提高表达力，却无意中模糊了意图边界，导致高频误唤醒与上下文爆表。
物理事实：未经量化 Eval 数据测试的技能修补，90% 都会产生隐蔽的生产退化

评估驱动开发 (EDD) 的三大工程支柱

3 Core Pillars of Eval-Driven Skill Engineering

EDD Pillars
1. 定量评估基准集 (Benchmark Dataset) Ground-Truth Test Suite

收集真实生产流量中的 100+ 典型输入、期望 Tool Choice 与必填入参，构建不可篡改的 Ground-Truth 数据集。

2. CI/CD 自动化回归门控 (Automated Regression Gate) PR Quality Gate

每次修改 `SKILL.md` 或分类逻辑提交 PR 时自动跑 Eval，若召回率 F1 或 Pass@1 降幅超过 1.0% 则阻断合并。

3. 多维归因诊断与闭环迭代 (Multi-Dimensional Attribution) Continuous Refinement

针对盲目唤醒、参数漏填与逻辑漂移分类归因，驱动 Prompt 边界修补与大型 Skill 的模块化拆分。

下一步：学习 Skill 评测指标体系构建 (Pass@1, F1, Cost, Latency)

Architectural Core Thesis / 架构师视角

没有量化评估 Harness 支持的 Skill 优化只是盲人摸象！通过 评估驱动开发 (Eval-Driven Development, EDD) 在 CI/CD 中建立硬性回归门控，是确保 Agent 技能池持续演进且绝不发生隐蔽退化的黄金法则。
