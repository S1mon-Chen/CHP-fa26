防腐层架构 (Anti-Corruption Layer, ACL)：隔离不稳定外部 Tool API 的变更震荡

阻断外部第三方 API（Jira、GitHub、Slack、SaaS 微服务）变更对 Agent 推理层的倒灌破坏：引入 DDD 防腐层适配器 (ACL Adapter)，保持 LLM 视角的 SKILL.md 契约绝对稳定，将 API 字段更迭、版本废弃与异常格式物理隔离于适配层内部

JiraApiAntiCorruptionAdapter 实现

ACL Adapter Pattern for Stable Tool Schema

ACL Shield 
class JiraApiAntiCorruptionAdapter:
    def __init__(self, upstream_v3_client: ExternalJiraClient):
        self.upstream = upstream_v3_client

    # 1. 暴露给 LLM 的 SKILL.md 契约保持 100% 绝对固定不变 ★
    def query_issue_canonical(self, issue_id: str) -> CanonicalIssueDTO:
        try:
            # 2. 外部 SaaS 从 REST v2 升级到 v3，字段名从 summary 变更为 fields.title
            raw_v3_resp = self.upstream.get_issue_v3(issue_id)
            
            # 3. 在 ACL 防腐层内部完成数据转化、清洗与归一化 (Data Normalization) ★
            return CanonicalIssueDTO(
                id=raw_v3_resp["key"],
                title=raw_v3_resp.get("fields", {}).get("summary_v3", "UNTITLED"),
                status=self._map_status_enum(raw_v3_resp.get("status_code"))
            )
        except ExternalUpstream5xxError as err:
            # 4. 上游溃败时由 ACL 拦截，转化为 LLM 友好可诊断 Observation ★
            return CanonicalIssueDTO(is_degraded=True, error="UPSTREAM_JIRA_DOWN")
  • 零微调与零 Prompt 重写：第三方 SaaS 升级改动接口时，仅更新 ACL 适配代码，无需修改 Agent 系统 Prompt 或重写 `SKILL.md` 文件。
核心：将不稳定的外部数据流映射为内部强类型的规范模型（Canonical Model）

API 防腐层的三大防护支柱

3 Core Pillars of Anti-Corruption Layer

ACL Pillars
1. 契约稳定性隔离 (Schema Stabilization) Invariant Prompt Spec

锁定大模型感知到的 `SKILL.md` 描述与 Pydantic 入参 Schema；上游 REST/GraphQL API 如何迭代，LLM 的意图识别率绝不受震荡影响。

2. 统一领域规范模型 (Canonical Data Model) Payload Normalization

将外部纷繁复杂的 HTTP 响应包清洗、剥离无用元数据，并映射为结构化标准格式（如 `CanonicalIssueDTO`），控制 Token 长度。

3. 物理故障断路与伪装兜底 (Fault Isolation & Fallback) Graceful Degradation

外部 3rd-party 服务丢出 500 HTML 报错页或 HTTP 429 被限流时，ACL 前置拦截并翻译为 `Observation: Upstream API Unavailable`，防止原生报错抛崩 Agent 主循环。

Architectural Core Thesis / 架构师视角

别让杂乱不稳的外部 API 污染了大模型的大脑！通过构建 DDD 防腐层 (Anti-Corruption Layer, ACL) 吸收第三方 API 变更震荡，是保障生产级 Agent 技能池长期可维保与高抗逆性的铁律。
