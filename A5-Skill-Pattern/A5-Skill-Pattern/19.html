DryRunRollbackSkill 代码实现

Transactional Dry-Run & Undo Engine

Dry-Run & Rollback 
class DryRunRollbackSkill(BaseSkill):
    def execute(self, patch_diff: str, dry_run: bool = True) -> SkillResult:
        # 1. 预演逻辑 (Dry-run): 物理检查补丁冲突与语法树合法性 ★
        if dry_run:
            if not self.git.apply_check(patch_diff):
                return SkillResult(status="DRY_RUN_FAILED", error="Patch conflict")
            return SkillResult(status="DRY_RUN_PASSED", diff_summary=...)

        # 2. 真实物理写入前：捕获 Git / DB 物理状态快照 (Snapshot) ★
        stash_id = self.git.create_snapshot_stash()
        try:
            self.git.apply_patch(patch_diff)
            self.sandbox.run_pytest()  # 在沙箱跑单测验证
            return SkillResult(status="SUCCESS")
        except TestFailureError as err:
            # 3. 产生任何崩溃：原位触发 Undo 撤销回复物理原貌 ★
            self.git.rollback_stash(stash_id)
            return SkillResult(status="ROLLED_BACK", error=str(err))
  • 零无意环境污染：Dry-run 校验不改物理文件；单测抛错自动执行 `git checkout .` 快速复原。
核心：预演看后果，写入存快照，出错原位 Undo，确保写操作 100% 可撤销

预演与回滚模式的三大核心支柱

3 Core Pillars of Dry-Run & Rollback

Rollback Pillars
1. 预演物理模拟 (Pre-flight Simulation) Dry-Run Check

在数据库执行 `EXPLAIN` 或在 Git 执行 `git apply --check`。在无副作用的前提下提前校验语法合法性与修改冲突。

2. 状态快照与原位 Undo (Snapshot & In-place Undo) State Rollback

绑定 Git Stash / 数据库 `BEGIN...ROLLBACK` 物理锁。一旦后续单元测试或规则校验失败，瞬间将物理状态撤销至更改前。

3. 物理可撤销性屏障 (Reversibility Barrier) Write Security Gate

将不可撤销的动作（如删除第三方生产环境 S3 Bucket）隔离在允许范围之外，对所有有副作用的修改赋予确定性物理撤销能力。

Architectural Core Thesis / 架构师视角

允许 Agent 拥有系统写权限的硬前提是物理可撤销性（Reversibility）！通过 预演与回滚模式 (Dry-Run & Rollback Pattern) 锁住修改前快照，是确保大模型在复杂代码库和生产数据库中开展改动时不污染物理环境的终极底线。
