能力越大，破坏力越大

刚才查数据很爽对吧？但如果你的表达有歧义，AI 可能会瞬间清空你的业务表。
在使用 MCP 连接核心数据时，必须学会“上双重锁”。

恐怖故事：一条随意的指令
"这个月退款的订单太多了看着心烦，帮我把退款的数据处理掉吧。"
AI 的理解逻辑：处理掉 = 删除
> DELETE FROM orders WHERE is_refunded = 1;
"老板，已为您永久删除所有退款记录！"
恭喜你，达成“删库跑路”成就！
架构师心法：双重防呆锁

第一把锁 提示词卡扣 (PACT 约束)

每次涉及敏感数据，必须在 Prompt 中加入免死金牌：

<安全约束>
1. 绝对不要对数据库执行 INSERT, UPDATE, DELETE 操作。
2. 本次任务仅限只读查询 (SELECT)。
</安全约束>

第二把锁 MCP 物理隔离 (推荐)

最好的防御是不给它刀。在配置 MCP 时，很多组件支持直接开启 Read-Only (只读) 模式：

"env": {
  "SQLITE_DEFAULT_PATH": "/Users/...",
  "SQLITE_READ_ONLY": "true"
}

永远保持敬畏心

大模型就像一个极其勤奋但不通人情世故的实习生。当你把它接入公司真实业务数据时，先备份、给只读权限、加严格约束，是每位合格的“AI 产品经理”必修的基本功。

Speaker Notes / 讲师备课备注
⚠️ 敲黑板，重点警示： “刚刚体验完查数据的同学，是不是觉得很爽？但请大家看左边的大屏！如果你平时说话随意惯了，跟 AI 说‘这批退款数据处理掉’。AI 不懂人类的职场潜台词，它理解的‘处理掉’就是数据库里的 `DELETE` 命令。这在现实中是极其恐怖的！”
💡 强调双重锁的概念： “所以我们在玩 MCP 连外部数据时，一定要有架构师的防呆思维。第一把锁，是在 Prompt 里死死咬住‘绝不修改’（对应上一单元的 PACT 里的 Constraints）。第二把锁，是物理断绝，在配置环境变量时，给组件传一个只读参数（部分优秀组件支持），直接没收它手里的刀。”
⏭️ 单元收尾： “懂得了连接，又懂得了安全防范。我们在 MCP 这一块就已经算是出师了！下一页，我们将对本单元进行总复盘，并布置一个非常有挑战性的打卡作业。”
