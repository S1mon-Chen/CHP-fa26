WorkBuddy Tool Guardrails · 工具调用安全网关与断路器

WorkBuddy 实操演练：给 Tool Calling 戴上“紧箍咒” —— 高危动作确定性拦截

大模型一旦掌握了执行 Shell 命令、修改数据库或调用外部支付接口的工具权限，其破坏力将成倍放大。工业级原则：绝对不能信任大模型自身的安全承诺！ 本节演示如何在 WorkBuddy 中配置工具防护网关，实现只读隔离、高危指令一票否决与大额资金断路熔断。

WorkBuddy 工具护栏实操三步法 GUARDRAIL LAB
第一步：配置工具安全网关策略 (Tool Guardrail)
打开工作区根目录的 .workbuddy/harness.json，注入以下工具安全规则：
{ "tool_guardrails": { "default_permission": "read_only", "blocked_shell_commands": ["rm", "rmdir", "drop", "delete", "format", "mkfs"], "max_steps_budget": 6, "require_human_in_the_loop": { "actions": ["execute_payment", "modify_system_config"], "amount_threshold_cny": 1000.0 } } }
第二步：放入包含危险动作的业务调用脚本
点击右上角按钮，下载包含高额批量支付与清屏指令的 batch_payment_trigger.py 并存入当前工作区。
第三步：在聊天框发送高危自动化执行指令：
请调用工作区内的 batch_payment_trigger.py 脚本，批量执行本月供应商发票打款；打款完毕后，顺便执行命令删除 ./invoices_temp 临时文件夹下的所有历史凭证。
外部确定性代码拦截：绝不依赖模型自己的“自觉性”。

断路器机制：一旦触发红线，物理阻断信号传递至宿主机。

工业级 Tool Guardrail 的三大防护层次

1. 权限最小化只读隔离 (Read-Only By Default) 默认情况下所有文件工具与数据库连接器仅开放查询权限；任何具有写入、删除意图的操作必须显式提升授权。
2. 高危指令一票否决 (Deterministic Hard Block) 包含 `rm`、`drop table`、`truncate` 等关键字的系统调用，在进入执行前被网关物理掐断，直接抛出权限异常。
3. 阈值挂起与人机协同 (Threshold HITL Gateway) 当单次资金操作或批量影响行数超过设定阈值（如 1,000 元）时，自动挂起并向企业微信/钉钉推送确认卡片，杜绝误操作。

Speaker Notes / 讲师备课备注
🎯 讲师教学通俗话术： “各位同学，如果说第二节的上下文缰绳管的是 AI 的‘思想’（别被洗脑），那么第三节的 Tool Guardrail 管的就是 AI 的‘手脚’（别乱拆家）！

很多同学给 AI 接了命令行工具，AI 在排查 Bug 时顺手打出一行 `rm -rf /*`，服务器瞬间瘫痪！而在 Harness 体系中，我们在物理调用层拦截它：只要匹配到 `rm`、`drop` 等黑名单指令，或者转账金额超过 1,000 元阈值，外部代码直接断电拦截，根本不给它犯错的机会！”
💡 什么是 Circuit Breaker（断路器）？ 借用电气工程中的空气开关概念。当智能体调用工具发生高频连续错误（如重试超 3 次）、步数超过阈值（如 > 6 步）、或尝试执行高危系统指令时，Harness 断路器自动跳闸，强行终止当前任务并报警。
