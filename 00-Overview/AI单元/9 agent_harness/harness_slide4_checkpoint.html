WorkBuddy State Persistence · 长任务事务快照与故障自愈

长流程任务崩溃怎么办？WorkBuddy Checkpoints 快照机制 与断点续跑

企业级任务往往需要连续执行数十个步骤（如批量核验 100 张供应商账单、跨多系统对账）。如果运行到第 48 步时突发网络中断或进程崩溃，传统 Agent 只能推倒重来，造成严重的 Token 浪费与数据不一致。Harness 步骤级状态快照让长任务具备“自动存档”能力，支持秒级断点自愈！

WorkBuddy 状态快照实操三步法 PERSISTENCE LAB
第一步：在 harness.json 中追加持久化配置
打开工作区的 .workbuddy/harness.json，追加 "persistence" 节点：
{ "persistence": { "enable_step_checkpoints": true, "checkpoint_interval_steps": 1, "storage_path": "./.workbuddy/checkpoints", "auto_resume_on_restart": true } }

状态持久化快照 (Checkpoints) 的三大工业级核心价值

1. 零重复算力开销 (Zero Redundant Tokens) 长任务发生中断时，已处理的前置步骤直接从快照反序列化复原，杜绝为已完成项重复向大模型支付费用。
2. 状态强一致性 (Atomic State Guarantee) 每一步落盘绑定事务 ID，避免因中途退出导致部分数据重复入账或账目不平，保证财务级对账严肃性。
3. 免值守高可用 (Unattended Self-Healing) 配合 Scheduled 定时任务或守护进程，服务器重启后守护模块自动执行 `/resume` 重新唤醒，业务零中断。

Speaker Notes / 讲师备课备注
🎯 讲师教学通俗话术： “各位同学，很多人的 Agent 在实验室测试时处理 3 条数据很顺畅，但放到生产环境中批量处理 1,000 条数据时，跑到第 990 条因为网络抖动断开了！如果是裸奔的 Agent，没有存盘，只能全部推倒重来，白白烧掉几万 Token！

而 Harness Checkpoints 就像单机游戏里的‘随时自动存档’功能：每核对完一张发票，就把当前进度写入磁盘。系统哪怕断电重启，敲一行 `/resume`，它看一眼存档文件，直接从第 991 条继续往下走，前面已经核算好的零重复开销，这才是工业级的韧性！”
💡 关于追加配置还是覆盖的提示： 特别向学员强调，WorkBuddy 的 `.workbuddy/harness.json` 是一个统一总控文件。第 2 节的 `context_steering`、第 3 节的 `tool_guardrails` 和这一节的 `persistence` 是并列并存的关系，页面上提供了‘一键复制合并全量配置’按钮，方便学员直接核对。
