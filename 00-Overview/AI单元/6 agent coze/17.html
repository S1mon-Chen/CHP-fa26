Module 4 · 工程避坑与生产调优

生产环境稳定性调优：Prompt 瘦身、精准路由与黄金测试集

系统上线前的最后一公里，是将粗糙的 Demo 打磨成坚不可摧的工业级软件。我们需要对大模型的 Prompt 进行“减脂增肌”，消除带有歧义的自然语言路由，并建立自动化回归测试集，以此来对抗大模型版本迭代带来的概率性波动。

生产级系统调优三大法则

BEST PRACTICES

1 Prompt 瘦身与绝对边界约束

痛点： 提示词写了 3000 字口水话，模型不仅响应慢、费钱，还会把后面的重点忘了（注意力丢失）。
调优： 使用 Markdown 结构化编写（如 # 角色, # 规则, # 约束）。将安全红线写在最末尾的约束中：绝对禁止回答非本职工作内容，违规将受到严厉惩罚。

2 MECE 原则与路由条件精确化

痛点： Router 靠猜测，两个分支的转移条件语义重叠。
调优： 转移条件必须符合 MECE 原则（相互独立，完全穷尽）。在 Coze 中尽可能使用精确匹配逻辑，例如：提取意图实体，只有 intent == "refund" 才走财务，杜绝模糊的自然语言连线描述。

3 沉淀黄金测试集 (Golden Test Cases)

痛点： 自己测了 3 句话觉得没问题就上线，用户一用就翻车。
调优： 收集 100 条最刁钻、最容易混淆的历史高危客诉。每次修改 Prompt 或底层大模型升级后，在 Coze 工作台中一键批量跑回归测试，保证准确率不下跌。
