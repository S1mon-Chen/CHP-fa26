Module 1 · 架构选型与决策边界

架构选型指南：什么时候用工作流？什么时候选多智能体？

没有万能的架构，只有最适合业务的方案。作为企业级 AI 架构师，你必须克制“手里有锤子看什么都是钉子”的冲动。理清业务需求的**确定性**与**发散性**，是决定采用 Workflow (工作流) 还是 Multi-Agent (多智能体) 的唯一标准。

企业 AI 架构选型决策树

DECISION TREE

Q1：任务流转路径是否 100% 固定？

业务是否总是遵循 A -> B -> C 的顺序（例如：每天先爬数据，再翻译，最后发邮件）？

是 ➡️ 首选 Workflow 否 ➡️ 往下看

Q2：是否需要处理极其发散的用户意图？

系统是否面向 C 端用户或复杂的内部问答，用户可能问出完全不相关的问题（如查物流、技术答疑、投诉）？

是 ➡️ 首选 Multi-Agent 否 ➡️ 往下看

Q3：对输出格式是否有苛刻的“防脱轨”要求？

结果是否必须严格按照指定的 JSON 结构或排版输出，哪怕错一个标点都不行（如自动化入库、生成正式合同）？

是 ➡️ 必须用 Workflow 锁死 否 ➡️ 可尝试 Multi-Agent

Speaker Notes / 讲师备课备注
🎯 为什么选型这么难？ “各位同学，这是我在指导很多企业落地 AI 时遇到的最大误区：**大家都觉得 Multi-Agent 听起来更高级，所以什么业务都想用多智能体。**

结果就是，明明只是想洗个数据生成个图表，非要派个智能体去‘自主思考’，结果每次生成的格式都不一样，甚至有时候它还会偷懒跳过某些步骤，导致下游系统直接崩溃。”
💡 黄金法则一句话总结： “当你追求 **100% 确定性和格式稳定** 时，必须用 工作流 (Workflow)，把大模型锁死在一个节点里剥夺它的自主权。
当你面向 **C 端用户无法预测的提问** 时，必须用 多智能体 (Multi-Agent)，用 Router 去灵活分发。这才是真正的架构智慧！”
