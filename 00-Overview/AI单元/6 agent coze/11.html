Module 3 · 多智能体 (Multi-Agent) 编排实战

创建 Router 与意图识别：配置转移条件，让大模型充当“派单员”

在多智能体系统（Multi-Agent）中，Router（主控路由节点） 是大门的守卫。它的核心任务绝不是直接回答用户的问题，而是利用大模型的语义理解能力，对复杂意图进行拆解与分类，并基于您设定的“转移条件（Conditions）”，将任务精准派发给下属的专科 Bot。

Router 节点配置三步法

UI GUIDE

1 设定 Router 专属人设 (Persona)

在 Router 节点的提示词中，明确告诉它：“你是一个分诊员，只负责分类，不要直接回答问题！”

你是电商售后前台。你需要分析用户的意图：
1. 若涉及硬件报错、死机、零部件损坏，归为【硬件故障】。
2. 若涉及开发票、退款、查物流，归为【财务票务】。
请严格分类，不要擅自解答业务问题。

2 配置自然语言转移条件 (Condition)

Coze Router 强大的地方在于，不需要写正则表达式。直接用自然语言描述触发条件，大模型会自动判断匹配。

条件 1：用户询问了机器报错或维修问题 指向 ➡️ 售后技术 Bot
条件 2：用户索要发票或要求退款退单 指向 ➡️ 财务客服 Bot

3 托底策略 (Fallback)

当用户的意图不在上述分类中（如闲聊），配置“否则 (Else)”路径，交给兜底节点处理，或直接回复“抱歉，我不明白”。

Speaker Notes / 讲师备课备注
🎯 重点强调 Router 的“克制”： “教大家一个避坑口诀：**派单员不修车！** 很多人在写 Router 提示词的时候，忍不住把产品的维修手册也写进去了。结果 Router 直接把用户问题回答了，根本没有触发下面的专科 Bot！
