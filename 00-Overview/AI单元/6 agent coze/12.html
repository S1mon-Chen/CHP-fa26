建立 Worker 1 (售后专员)：配置专属人设与挂载订单 API 插件

在多智能体架构中，Worker (执行节点) 才是真正干活的数字员工。我们将为售后专员配置明确的系统提示词（System Prompt），并挂载“订单查询 API”插件，让它拥有实时查单的超能力，而不是瞎编乱造。

Worker 节点配置指南

UI GUIDE

1 设定专属售后人设 (Persona)

在 Worker 的提示词中，明确其工作边界，防止它回答与售后无关的问题（如被套话去写代码）。

你是电商金牌售后专员。你的核心职责是：
1. 接收用户的订单号，调用插件查询最新的物流与发货状态。
2. 处理用户的退换货咨询，语气必须耐心、专业、充满安抚感。
警告：绝不回答任何非售后类的闲聊或技术问题。

2 挂载业务系统插件 (Plugins)

大模型本身没有你的订单数据。在节点的“插件”面板，添加内部开发的 订单 ERP 查询 API。

Order_ERP.check_status(order_id)

3 测试单兵作战能力

在将 Worker 接入主控 Router 之前，先在右侧沙箱单独测试它能否正确理解参数并成功调用插件。

Speaker Notes / 讲师备课备注
🎯 重点强调大模型的工具调用 (Tool Calling)： “在单体智能体里，我们说要克制，就是因为如果你给一个机器人配了 10 把刀，它很容易砍错人。现在我们在多智能体架构下，售后专员只需要一把刀：订单查询插件。

大家要注意，大模型本身是不知道订单状态的。当它收到带有‘8890’的问句时，它的推理逻辑是：暂停回答 -> 生成一段调用 API 的 JSON 发给系统 -> 系统返回结果 -> 大模型再把结果包装成温柔的人话回答客户。这就是所谓的 Tool Calling！”
