Module 3 · 多智能体 (Multi-Agent) 编排实战

实战场景设定：电商大促海量发散客诉的智能分类与专业接待

在上一模块中，我们用 Workflow 解决了“格式固定、逻辑线形”的问题。但客服场景截然不同：用户可能问退款、问发票、问技术故障，甚至混合双打。面对这种极度发散的意图，如果把所有规则塞进一个单体大模型，它必然“精神分裂”。我们需要引入 Multi-Agent (多智能体) 架构。

业务痛点与“专科医院”破局方案

BUSINESS CASE

单体大模型 (Single Bot) 的认知灾难

  • Prompt 溢出：把售后规则、财务报销要求、产品故障排查手册全写进一个 Bot 的人设里，提示词长达上万字，导致严重“注意力丢失”。
  • 工具互斥混乱：既给它挂查订单的插件，又挂知识库，模型经常调错工具。
  • 回复毫无专业度：面对复合问题（如：机器坏了+退款），容易避重就轻。

Coze Multi-Agent 专科医院架构

将系统划分为“导诊台”和“专科医生”。主控负责精准分发，专科负责深挖解决，互不干扰！

剧透：下一节我们将构建的 Coze 多智能体三大核心节点

1. Router (路由节点) 智能体大门的“分诊台”。它不直接回答问题，只负责分析意图，并设定严格的转移条件（Condition），将任务派发给正确的底层 Worker。
2. Worker: 售后技术 Bot 人设：资深维修工程师。外挂能力：产品说明书与故障排查知识库 (RAG)。专注于解决硬件报错、操作指导。
3. Worker: 财务客服 Bot 人设：严谨的财务专员。外挂能力：ERP 订单查询 API 插件。专注于查询付款状态、开具发票与退单审核。
