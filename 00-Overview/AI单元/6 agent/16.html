Pitfalls & Troubleshooting · 常见翻车现场剖析

自动化工作流常见翻车现场：死循环、Token 溢出与 API 鉴权失效

在企业级落地自动化与 AI 智能体时，往往会遇到这三大经典“翻车”场景。提前掌握排查与规避方法，保障系统平稳运行。

1. 节点触发死循环 (Infinite Loop)

现象： Webhook 或定时触发器配置不当，或者写入文件后触发了目录监听，导致管道无限自我调用，瞬间耗尽服务器 CPU 或 API 额度。

💡 规避： 严格设定过滤条件与最大执行次数限制。

2. 大模型 Token 溢出 (Context Overflow)

现象： 接入的客诉或商品数据量过大，未经 Split Out 拆包直接整段塞给 LLM 节点，导致超过模型上下文窗口报错。

💡 规避： 使用拆包或摘要截断，控制单次请求输入规模。

3. API 鉴权过期与凭据失效

现象： 第三方平台 Token 长期不刷新或凭据写死在环境变量中，导致工作流运行几天后突然大面积报错中断。

💡 规避： 采用凭据管理器统一托管，设置自动刷新机制。
