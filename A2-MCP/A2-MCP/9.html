传输层与分层模型

类比 OSI 标准分层模型，理解 MCP 协议在现代 AI 集成架构中的定位与约束

OSI 参考层级 MCP 协议对应实现
应用层 (Application)
MCP 原语模型 Tools / Resources / Prompts 业务逻辑
会话/表示层 (Presentation)
消息层 (Messaging) JSON-RPC 2.0 数据结构化与生命周期协商
传输/网络层 (Transport)
传输层 (Transports) STDIO: 本地进程通信 (首选) HTTP: 远程 SSE (Server-Sent Events)
物理/链路层 (Link/Physical)
底层 OS 进程 / 网络 连接状态维护
⚖️

软件工程核心约束

在 STDIO 模式下，协议数据必须通过 stdout 交换。为防止开发者的调试信息、错误堆栈污染 JSON 数据流，Server 端的错误日志必须严格显式重定向至 stderr。

STDIO_DATA_FLOW_DEBUG 
# 🧑‍💻 正确的数据与日志分离范式

[stdout] {"jsonrpc": "2.0", "id": 1, "result": {...}}
[stderr] ERROR: db_connection_refused - retrying in 2s...
[stdout] {"jsonrpc": "2.0", "method": "notifications/progress"...}

# ❌ 错误示范：协议污染 (将导致 Client 解析崩溃)

[stdout] DEBUG: Attempting to connect to SQLite. {"jsonrpc": "2.0",...}
↑ 这里混杂了文本和 JSON，导致通信链路损坏
