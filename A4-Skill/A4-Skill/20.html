模块二演练：设计一个企业级 Database Query & Patch Skill 描述契约

融汇贯通模块二契约设计：基于 Pydantic 声明 只读查询 (Query) 与 状态修改 (Patch)，整合受影响行数限制、回滚 SQL 备忘与 Dry-Run 预演

Database Skill 双重契约代码

Pydantic DB Query & Patch Contract

Capstone Contract 
from pydantic import BaseModel, Field, field_validator

# 1. 只读查询 Skill 契约 (ReadOnly)
class DatabaseQueryInput(BaseModel):
    sql: str = Field(description="SELECT statement ONLY.")
    max_rows: int = Field(default=100, ge=1, le=1000)

    @field_validator("sql")
    def must_be_select(cls, v: str) -> str:
        if not v.strip().upper().startswith("SELECT"):
            raise ValueError("Query MUST begin with SELECT")
        return v

# 2. 修改更新 Skill 契约 (State-Changing)
class DatabasePatchInput(BaseModel):
    patch_sql: str = Field(description="UPDATE/INSERT statement.")
    expected_rows: int = Field(ge=1, le=50, description="Expected row count")
    rollback_sql: str = Field(description="Mandatory UNDO SQL statement") ★
    dry_run: bool = Field(default=True, description="Pre-run via EXPLAIN")
  • 兼顾灵活性与绝对安全：只读工具自动放行，写工具强加 `rollback_sql` 与受影响行数阈值强约束。
核心：要求模型在发出 Patch SQL 的同时提供撤销 SQL，建立可恢复事务机制

企业级 DB Skill 的四大安全基石

DB Skill Contract Design Pillars

Safety Pillars
1. 严格只读隔离 (@field_validator) SELECT Only Check

在宿主侧物理解析 SQL 语句，确保 `db_query` 工具绝对不包含任何修改命令，避免高危写操作混入只读管道。

2. 受影响行数强限制 (ge=1, le=50) Row Count Guard

要求模型明确声明 `expected_rows`。物理执行时若实际受影响行数超出预期（如忘记加 `WHERE` 条件导致全表更新），立即回滚抛错。

3. 强制回滚 SQL 备忘 (rollback_sql) Undo Command

强迫大模型在提交修改 SQL 时同时推演对应的撤销命令（Undo SQL），存入事务审计日志，保障系统的完全可恢复性。

4. EXPLAIN 预演模式 (dry_run=True) Dry-Run Preflight

默认启用 `dry_run`，先对 SQL 执行 `EXPLAIN` 校验索引使用情况与语法合法性，无异常后再进入 HITL 审批与真实写入。
