Tool Choice & Pass@1 评测引擎代码

Tool Eval Harness Code

Eval Harness 
class ToolEvalHarness:
    def run_benchmark(self, model, test_suite: list[EvalSample]) -> dict:
        tp, fp, fn, exact_param_matches = 0, 0, 0, 0

        for sample in test_suite:
            res = model.predict_tool_choice(sample.query)
            pred_tool = res.tool_name
            pred_args = res.tool_args

            # 1. 评测 Tool Choice 路由正确性 (F1 Score) ★
            if pred_tool == sample.expected_tool:
                tp += 1
                # 2. 评测参数填充精确匹配度 (Pass@1) ★
                if pred_args == sample.expected_args:
                    exact_param_matches += 1
            else:
                if pred_tool: fp += 1
                if sample.expected_tool: fn += 1

        f1 = 2 * tp / (2 * tp + fp + fn + 1e-9)
        pass_at_1 = exact_param_matches / len(test_suite)
        return {"tool_choice_f1": f1, "pass_at_1": pass_at_1}
  • 自动化质量回归门控：在 CI/CD 中拦截由于 System Prompt 修改或模型微调带来的 Tool 路由与参数填错退化。
物理铁律：没有客观 Tool Eval 评测集支持的提示词或工具修改均属于盲人摸象

Skill 评测的三大核心量化指标

3 Core Tool Eval Metrics

Metrics Spec
1. 工具选择召回率 (Tool Choice F1) Selection Precision/Recall

评估模型在面临 50+ 工具时，能否精准命中目标工具，同时惩罚误唤醒（False Positive）与漏唤醒（False Negative）。

2. 入参精确匹配度 (Pass@1 Accuracy) Schema & Argument Exact Match

衡量 1st-turn 生成的 JSON 入参是否无缺漏、满足强类型与枚举约束，且每个 key-value 完全符合期望标注。

3. 物理执行端到端成功率 (E2E Exec Success) Sandbox Convergence Rate

在真实物理隔离沙箱（Docker / e2b）中执行，评估在结合 Self-Correction 重试闭环后，任务在 $N$ 轮内成功收敛的概率。

实践选型：SWE-bench / BFCL (Berkeley Function Calling Leaderboard)

Architectural Core Thesis / 架构师视角

没有量化评测的 Tool 优化只是主观臆测！构建包含 Tool Choice F1 与 Pass@1 参数精确匹配度的自动化 Tool Eval Harness，是确保企业级 Agent 系统在迭代中持续高可用与抗退化的核心工程凭据。
