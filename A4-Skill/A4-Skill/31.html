from enum import Enum

class ToolErrorCategory(str, Enum):
    SCHEMA_ERROR = "SCHEMA_ERROR"      # 入参缺少/类型反序列化失败
    RUNTIME_ERROR = "RUNTIME_ERROR"    # 语法错/Traceback/Timeout ★
    LOGICAL_ERROR = "LOGICAL_ERROR"    # 物理执行成功，但结果集为空/不符

def classify_and_feedback(err_event) -> str:
    if isinstance(err_event, ValidationError):
        return f"Observation: Schema Error - {err_event}. Fix arguments!"
    elif isinstance(err_event, SandboxRuntimeError):
        # 提取干净的失败堆栈回写给 LLM 做修补 ★
        return f"Observation: Runtime Traceback:\n{err_event.pruned_traceback}"
    else:
        return f"Observation: Business Assertion Failed: {err_event.reason}"
  • 崩溃转换为输入信号：宿主捕获三类错误后均不中断退出，而是格式化为 `role: "tool"` 的 Observation。
核心：把 Exception 当作正常 Feedback 喂回，是 Agent 实现自愈的灵魂

工具调用的三层异常剖析

3-Tier Exception Taxonomy

Taxonomy
1. Schema 契约错 (Validation Error) Input Spec Violation

模型遗漏必填字段、数据类型混淆（如字符串传给了 `int`）或未通过 `@field_validator` 前置校验，在宿主入口被拦截。

2. 物理运行时错 (Runtime Exception) Traceback & Crash

代码包含语法错误（`SyntaxError`）、导包缺失（`ModuleNotFoundError`）、死循环超时（`TimeoutError`）或被沙箱强杀。

3. 业务逻辑错 (Business Assertion) Assertion Failure

工具物理运行成功，但数据库影响行数为 0、查询结果集为空，或单测断言失败（`AssertionError`），需要重构逻辑策略。

Architectural Core Thesis / 架构师视角

异常不是程序崩塌退栈的终点，而是驱动大模型调整决策的最强反馈输入（Error As Feedback）；建立三层异常分类与自愈重试机制，是构建高吞吐 Agent 控制流的硬核前提。
