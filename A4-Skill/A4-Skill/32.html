class SelfHealingLoopController:
    def dispatch_with_feedback(self, tool_call, messages):
        try:
            # 1. 在沙箱中执行带有物理副作用的工具
            result = sandbox.execute(tool_call)
            return {"role": "tool", "tool_call_id": tool_call.id, "content": result}
            
        except Exception as err:
            # 2. 捕获崩溃异常绝不中断退出，提取干净的 Traceback ★
            pruned_tb = self.extract_clean_traceback(err)
            
            # 3. 将报错包装为标准的 Observation 消息反馈给大模型 ★
            feedback_msg = (
                f"Observation: Execution Failed with Exception:\n"
                f"
```python\n{pruned_tb}\n```\n"
                "Please analyze the traceback, fix your code or parameters, and retry."
            )
            return {"role": "tool", "tool_call_id": tool_call.id, "content": feedback_msg}

“Error As Feedback”的三大工程支柱

Feedback Philosophy Pillars

Resilience
1. 阻断进程退栈 (Halt Exception Crash) Zero Process Exit

传统程序遇到异常会直接抛出 Traceback 并退出进程；在 Agent 架构中，宿主必须拦截所有沙箱异常，转化为有状态的对话消息。

2. 结构化错误堆栈表达 (Structured Traceback) Clean Context Feedback

剥离冗长的宿主内部调用栈，仅保留沙箱代码行号、报错类型（如 `TypeError`, `KeyError`）及关键错误提示，便于大模型一眼识别。

3. 闭环纠错驱使 (Autonomous Correction) Self-Correction Trigger

大模型读取错误 Observation 后，在接下来的 Completion 中会自动调整入参或重构代码逻辑，实现从失败到成功的自动演进。

实践参考：Claude Dev / Cursor 在单测失败后自动修改代码的底层原理

Architectural Core Thesis / 架构师视角

异常不是程序运行的终点，而是最宝贵的指导信号！将 Runtime Traceback 优雅转化为 Observation 反写回 Context，是赋予大模型自主纠错与鲁棒自愈能力的核心哲学。

🎯 剖析 Error As Feedback 的核心思维转换： “向学员深入剖析：在传统后端软件开发中，抛出 `Exception` 代表程序执行失败，通常需要中断并打印堆栈日志。但在 Agent 架构中，大模型写出的代码或传参难免一次出错。如果我们直接让程序 `raise` 崩溃，Agent 就失去了自主进化的机会。正确的哲学是——把报错当成普通数据（Observation）喂回给大模型，让它自己去看错在哪并重新修改。”
💡 强调提取干净的 Traceback： “提示学员：在把异常转译为 Observation 时，注意不要把宿主框架里长达几十行的无用调用栈全部传给模型。只提取最核心的报错行和行号（Pruned Traceback），能极大地节省 Token 并让大模型快速聚焦于逻辑 Bug。”
