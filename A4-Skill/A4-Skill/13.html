消杀工具歧义的三大架构法则

Disambiguation Architectural Principles

Design Rules
1. 强制系统前缀 (Domain Prefix) [Domain]_[Entity]_[Action]

所有 Skill 函数名必须按 `系统_实体_动作` 结构化约束（如 `github_pr_merge`），彻底将不同系统的同名实体分隔离。

2. 互斥否定排除 (Negative Boundary) Do NOT Use If...

在近义工具的 description 中增加负向互斥提示（如在 `get_user_profile` 里注明：`Do NOT use for batch queries; use batch_get_users`）。

3. 动作粒度收敛 (Verb Standard) Standard Verbs

在团队内规范统一的动词集合（如只使用 `get`, `query`, `create`, `update`, `delete`），避免滥用 `handle`, `process`, `do` 等模糊词。

Architectural Core Thesis / 架构师视角

在大规模 Skill 注入场景中，工具名就是注意力概率分发的索引路由（Routing Index）；通过规范的领域命名空间（Domain Prefix）与互斥边界，才能保障多工具 Agent 在复杂的上下文交互里做到零错唤醒。
