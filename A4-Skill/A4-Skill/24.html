AST Command Security Interceptor

Shell Interceptor 
import bashlex

def verify_shell_command(cmd: str) -> bool:
    # 1. 利用 bashlex 进行 AST 词法拆解，防分号/管道混淆绕过 ★
    trees = bashlex.parse(cmd)
    
    # 2. 禁用高危指令与提权句柄 (Blacklist Tokens)
    forbidden = {"sudo", "su", "chmod", "chown", "mkfs"}
    for node in bashlex.split(cmd):
        if node.lower() in forbidden:
            raise SecurityError(f"Forbidden command '{node}' detected!")
            
    # 3. 环境变量脱敏隔离：剔除敏感 AK/SK ★
    clean_env = {
        k: v for k, v in os.environ.items()
        if not k.startswith(("AWS_", "DB_", "SECRET_"))
    }
    return run_in_sandbox(cmd, env=clean_env)
  • 防形变与管道绕过：不依赖脆弱的纯文本正则匹配，使用 AST 语法树彻底消杀 `; sudo` 或重定向混淆。
物理铁律：绝不允许 LLM 终端工具拥有 root 提权或直接读取包含私有密钥的宿主环境变量

Shell 终端防护的三大工程壁垒

Shell Security Pillars

Hardening Pillars
1. AST 语法树词法审计 (AST Auditing) No Bypass String Tricks

通过 `bashlex` 解析指令结构，拦截重定向注入、Base64 解码执行（`base64 -d | sh`）与连字符提权绕过。

2. 环境变量隔离与脱敏 (Env Sanitization) No Secret Leakage

终端沙箱启动时彻底清洗 `AWS_SECRET_ACCESS_KEY`、`DATABASE_URL` 等环境变量，防止提示注入通过 `env` 命令窃取密钥。

3. 严格指令白名单与出站熔断 (Command Whitelist) Egress & Command Gates

默认禁止外网 curl/wget 出站外退数据；白名单仅允许 `git`, `pytest`, `ls`, `grep`, `cat` 等安全开发指令。

最佳实践：严格限制可执行命令字典，配以物理网络出站断路器

Architectural Core Thesis / 架构师视角

终端 Shell 是大模型改变物理世界的最强“双刃剑”；通过 AST 语法树防绕过、环境变量脱敏与出站网络白名单，在沙箱外层建立硬件级防火墙，是允许 Agent 触碰终端命令的硬前提。
