第一代：文本解析与 ReAct 正则

Unstructured Text & Regex Capture

// 经典崩塌场景：未转义字符引发 json.loads() 崩溃
Assistant Response:
<action>{"func": "git_commit", "msg": "fix: "quote" issue"}</action>
// Regex Match SUCCESS, but json.loads() throws JSONDecodeError! ❌
  • 极易受格式污染：代码块反引号、引号未转义或文本客套话会导致正则提取失效或反序列化崩溃。
  • 高解析崩溃率（~15%-30%）：依赖 Prompt 里的自然语言约定，大模型随时可能漏写双引号或少写括号。
痛点：应用层需要编写海量复杂的补救正则与错误重试控制流。

第二代：API 原生约束采样

Logit Masking & Grammar-Based Decoding

// 物理层概率掩码：设定非法 Token 概率为 -Inf
GBNF Grammar Rule: root ::= "{" "tool_calls" ":" "[" ... "]" "}"
Logit Masking: Non-JSON Tokens Logit $\to -\infty$
// Result: 0.00% Syntax Error! 物理保证 100% 合法 JSON ★
  • 文法树掩码（Grammar Masking）：在 Sampling 阶段屏蔽不符合 JSON BNF 范式的非法 Token。
  • 结构化 Payload 注入：模型原生产出 `tool_calls` 载荷与 `finish_reason: "tool_calls"` 标志。
突破：将格式合法性保障从 Prompt 约定下沉为采样层的物理约束。

Architectural Core Thesis / 架构师视角

原生 Function Calling 不再依赖模型“听话地输出 JSON”，而是将函数 Schema 提炼为 BNF 文法掩码，在 Sampling 物理层实现 100% 格式防崩溃，这是构建高吞吐 AI Agent 的关键演进。

🎯 剖析第一代与第二代的技术鸿沟： “向学员深入剖析：第一代文本提取（如 Early ReAct）本质上是在 prompt 里写规则：‘请输出 XML 或 JSON’，然后应用层用 `re.search()` 去匹配。一旦用户或模型输出里包含了未转义的引号或多余括号，`json.loads()` 就会崩溃。”
💡 解释 Logit Masking 原理： “第二代 Native Function Calling（如 OpenAI / llama.cpp GBNF Grammar）是在 Transformer 的 **Softmax 采样层** 上施加算法。如果在生成 JSON 时当前应该输出双引号 `"`，算法会把所有非双引号 Token 的概率全部抹为 $-\infty$，从而在物理上消灭了语法错误。”
