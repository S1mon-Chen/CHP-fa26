class SelfCorrectionAgentController:
    def run_with_self_healing(self, user_query, max_retries: int = 3):
        messages = [{"role": "user", "content": user_query}]
        
        for turn in range(max_retries):
            response = llm.chat_completion(messages)
            if not response.tool_calls:
                return response.content  # 推理完成并收敛输出

            tool_call = response.tool_calls[0]
            messages.append(response.as_message())  # 记录 Assistant 1st-turn
            
            # 1. 物理沙箱执行 & 捕获 Exception 转换为 Observation ★
            obs = self.sandbox_runner.execute(tool_call)
            messages.append({"role": "tool", "tool_call_id": tool_call.id, "content": obs})
            
            if "Exception" in obs:
                # 2. 2nd-turn 自动带上报错 Traceback 进行 self-correction 重试 ★
                continue
                
            return self.run_with_self_healing(user_query, max_retries - 1)
            
        raise MaxRetriesExceededError("Self-correction loop failed to converge.")
  • 多 Turn 自然演进：1st-turn 报错自动追加写回上下文，LLM 读取 Traceback 后在 2nd-turn 自动修补入参。
核心：必须设定硬性最大重试次数（`max_retries=3`），防止模型盲目死循环

Self-Correction 闭环控制的三大工程支柱

Self-Correction Control Pillars

Closed Loop
1. 多 Turn 状态对齐与提示强化 (2nd-Turn Re-prompt) Context-Driven Reflection

将前一轮失败的 `tool_call`、`tool_call_id` 与对应清爽的 Traceback Observation 顺序追加入 `messages`，迫使 LLM 展开上下文自我反思。

2. 收敛性约束与最大重试次数 (Max Retries Bound) Convergence Circuit Breaker

硬性限制单个子任务的最大自愈重试次数（通常取 3 次）；若连续重复相同报错或达上限，主动熔断并触发降级兜底逻辑。

3. 动作指纹去重与死锁检测 (Action Deduplication) Action Fingerprint Hash

记录 `sha256(tool_name + arguments)` 指纹。若发现 LLM 在 2nd-turn 吐出了与 1st-turn 完全一致的入参，前置拦截并强加反思提示。

最佳实践：结合单测 Pytest 输出，实现无人值守的代码自动修补（Auto-Fixing）

Architectural Core Thesis / 架构师视角

智能的本质是容错与纠错！通过 多 Turn 状态对齐、错误 Traceback 注入与 Max Retries 收敛约束，构建 Self-Correction 闭环控制流，是将概率大模型升级为高可用自治 Agent 的关键工程里程碑。

💡 强调 Max Retries 与 Action 指纹去重： “提醒学员注意防范死循环：如果大模型在 2nd-turn 中依然吐出了与 1st-turn 完全一模一样的入参，或者重试超过 3 次依然未能解决报错，控制器必须触发断路器熔断，避免无限循环吞噬 Token 成本。”
