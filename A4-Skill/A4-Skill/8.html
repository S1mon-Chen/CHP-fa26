解构单 Turn 并发意图派发：如何通过 tool_calls 数组批处理 与 异步并发宿主执行，将 Agent 多文件检索的 RTT 网络延迟压低 3 倍

Batch Payload
// Model Response (Turn 1 Completion)
"message": {
"role": "assistant",
"tool_calls": [
{"id": "call_a1", "function": {"name": "read_file", "args": "{\"path\":\"a.py\"}"}},
{"id": "call_b2", "function": {"name": "read_file", "args": "{\"path\":\"b.py\"}"}},
{"id": "call_c3", "function": {"name": "read_file", "args": "{\"path\":\"c.py\"}"}}
]
}
  • 并发意图一次性喷吐：大模型在单次采样里分析出需要查阅 3 个相关源码文件，并在同一个 `tool_calls` 数组中挂载。
  • 独立 ID 句柄：分别分配 `call_a1`, `call_b2`, `call_c3` 唯一句柄，宿主环境可以基于 asyncio 瞬间并发发起 3 个 I/O 请求。
机制：宿主必须追加 3 条 `role: "tool"` 消息，并完全匹配对应的 `tool_call_id`

RTT 拓扑对比与端到端耗时

E2E Latency Reduction

3x Acceleration
串行循环模式 (Sequential Tool Loop) 3 Turns (3x RTT)

Turn 1 查 `a.py` $\to$ 等待 API 回传 $\to$ Turn 2 查 `b.py` $\to$ 等待回传 $\to$ Turn 3 查 `c.py`；网络往返耗时严重拉长，用户等待感剧烈。

并行调用模式 (Parallel Tool Calls) 1 Turn (1x RTT) ★

Turn 1 一次性吐出 `a.py`, `b.py`, `c.py` $\to$ Python `asyncio.gather()` 并行读取 $\to$ 追加 3 条结果消息并发起下一次 Completion。端到端耗时降低 60%-70%！

实测收益：大幅提升 Agent 首字响应时间 (TTFT) 与复杂任务完成吞吐

Architectural Core Thesis / 架构师视角

并行工具调用（Parallel Tool Calls）不仅是 API 表达层面的微调，更是重构 Agent 交互流拓扑（Interaction Topology）的关键手段；宿主环境利用异步 I/O 并发承接，是解决高延迟 Agent 系统瓶颈的必备设计。

Speaker Notes / 讲师讲稿
🎯 引导学员思考并发调用的性能收益： “向学员深入剖析：在构建复杂的 Coding Agent 时，排查一个 Bug 经常需要读取多个关照文件。如果每次只能查一个文件，每次 API 往返需要 2 秒，3 个文件就是 6 秒；而开启 Parallel Tool Calls 后，模型一次性吐出 3 个 `tool_calls`，宿主用 `asyncio.gather()` 1 秒内就能全量并发查完。”
💡 强调消息对齐细节： “提醒学员：当模型一次返回 N 个 `tool_calls` 时，宿主程序必须异步执行完这 N 个工具，并**向消息队列里依次追加 N 条 `role: 'tool'` 消息**，每条消息的 `tool_call_id` 必须与请求载荷里的 `id` 绝对对齐，否则下一 Turn 发给大模型时会触发 API 校验失败。”
