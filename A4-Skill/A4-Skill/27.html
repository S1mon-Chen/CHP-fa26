异步超时断路器与强杀引擎

Async Timeout & Kill Engine

Timeout Gate 
import asyncio

async def execute_tool_with_timeout(tool_call, timeout_s: float = 30.0) -> str:
    try:
        # 1. 异步拉起子进程，主事件循环保持非阻塞挂起 ★
        proc = await asyncio.create_subprocess_exec(
            *tool_call.cmd,
            stdout=asyncio.subprocess.PIPE,
            stderr=asyncio.subprocess.PIPE
        )
        
        # 2. 包裹 asyncio.wait_for 施加硬性超时阀门 ★
        stdout, stderr = await asyncio.wait_for(
            proc.communicate(), timeout=timeout_s
        )
        return stdout.decode()
        
    except asyncio.TimeoutError:
        # 3. 超时强杀隔离子进程 (SIGKILL) 并回写 Observation ★
        try:
            proc.kill()
            await proc.wait()
        except ProcessLookupError:
            pass
            
        return f"Observation: Execution timed out after {timeout_s}s and was killed."
  • 非阻塞自愈闭环：将 TimeoutError 直接转译为 Observation 反写给 LLM，触发模型重构高效算法。
物理铁律：绝不允许任何未设置超时边界的同步阻塞函数（Sync Blocking Call）触碰 Agent 主循环

超时控制与异步挂起的三大工程支柱

Timeout Engineering Pillars

Availability
1. 物理线程解锁与非阻塞挂起 (Async Suspend) Event Loop Unlocking

在耗时编译、大型 pytest 或 API 请求期间，将任务挂起交由底层事件循环（`asyncio` / Tokio），释放 CPU 算力承接其他并发请求。

2. 物理死锁与僵尸进程强杀 (SIGKILL Cleanup) Forced Tear-down

一旦达到超时阈值，必须向隔离子进程或 Docker 容器发送物理 `SIGKILL` 信号并做 `wait()` 回收，防止炸弹死循环成为后台僵尸进程。

3. 长任务异步句柄与唤醒 (Async Disconnecting) Long-Running Callback

对于耗时几十分钟的高重任务，返回 `task_id` 句柄切断同步 HTTP 连接，待物理任务完成后通过 Webhook 唤醒 Agent 恢复推理。

最佳实践：高频轻量工具设 5s，代码执行设 30s，超长任务改走异步任务队列

Architectural Core Thesis / 架构师视角

死锁是 Agent 生产系统的毒药！构建 非阻塞异步挂起与 SIGKILL 物理超时强杀机制，是保障大模型控制流在面对死循环代码和网络卡顿时依然能够保持高可用的关键护城河。
