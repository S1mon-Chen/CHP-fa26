Docker 沙箱执行引擎核心代码

Docker Sandbox Engine Code

Capstone Engine 
import docker, asyncio

class DockerSandboxEngine:
    def __init__(self, image: str = "python:3.11-slim"):
        self.client = docker.from_env()
        self.image = image

    async def run_code(self, code: str, timeout_s: float = 10.0) -> dict:
        # 1. 物理安全约束：切断出站网络、禁写根文件系统、限制资源 ★
        container = self.client.containers.create(
            image=self.image,
            command=["python", "-c", code],
            network_mode="none",         # 切断网络，防止数据外退
            mem_limit="256m",            # 256MB RAM 内存强上限
            read_only=True,              # 根文件系统只读
            user="nobody"                # 禁用 root 提权 ★
        )
        try:
            container.start()
            # 2. 包裹 asyncio.wait_for 实现非阻塞物理超时处理 ★
            loop = asyncio.get_running_loop()
            await asyncio.wait_for(
                loop.run_in_executor(None, container.wait),
                timeout=timeout_s
            )
            logs = container.logs(stdout=True, stderr=True).decode()
            return {"stdout": logs, "status": "SUCCESS"}
        except asyncio.TimeoutError:
            # 3. 超时物理强杀并清除死锁容器 ★
            container.kill()
            return {"error": f"Timed out after {timeout_s}s"}
        finally:
            container.remove(force=True)  # 临态生命周期清理
  • 开箱即用高可用：完美融合了网络防泄漏、低权限运行、配额限制与 `container.kill()` 强杀回收。

Docker 沙箱工程的四大防御柱石

Sandbox Defense Pillars

Cap Security
1. 物理出站断路 (network_mode="none") Network Lockdown

在容器底层强制封锁网卡出站流量，即使代码被提示注入试图通过 `curl` 外退密钥或建立反向 Shell，也会因网络中断而彻底失效。

2. 严苛配额与只读防破坏 (Read-Only & Quotas) Resource Limits

挂载 `read_only=True` 阻断恶意的物理文件抹除，配合 `mem_limit="256m"` 物理隔离死循环炸弹对宿主机内存资源的侵占。

3. 异步超时强杀 (container.kill()) Deadlock Mitigation

主事件循环通过 `asyncio.wait_for` 监控耗时；一旦超时瞬间发送物理强杀指令（SIGKILL），并安全回收僵尸容器资源。

4. non-root 低特权隔离 (user="nobody") Privilege Boundary

强制容器内代码以 Linux 极低权限用户（nobody）身份运行，规避任何潜在的 Docker 容器提权与内核逃逸漏洞。
