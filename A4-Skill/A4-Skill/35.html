Tool 领域的 5 大经典陷阱

5 Classic Anti-Pattern Traps

Pitfall Catalog
1. Over-Tooling Trap 工具过载陷阱

盲目给模型注入 100+ 个微 API，造成 Context 爆表与“Lost in the Middle”注意力严重稀释。

2. Vague Parameter Trap 模糊参数陷阱

参数命名为 `data: str`，缺少示例与枚举约束，导致模型随机乱传不合规的 JSON 字符串。

3. No-Timeout Danger 无超时死锁陷阱

未包裹 `asyncio.wait_for` 与 `SIGKILL` 强杀，模型生成的死循环代码直接死锁 Agent 主流程。

4. Side-Effect Blindness 副作用盲区陷阱

忽视写操作对物理环境的破坏，缺少 `dry_run` 预演、事务 Undo 快照与 HITL 人工审批卡扣。

5. Unsanitized Feedback 裸日志污染陷阱

将几万行构建控制台日志原封不动丢回 Context，瞬间撑爆窗口并诱发无限报错重试。

Architectural Core Thesis / 架构师视角

避免 Tool 领域的 5 大反模式陷阱不是代码审美要求，而是构建生产级 Agent 的绝对物理安全防线；通过动态加载、强契约校验、物理超时强杀与 HITL 卡扣，彻底封堵死锁与越权缺陷。
