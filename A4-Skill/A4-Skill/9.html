第 4 课：AI 原子能力与工具调用

隐式思考模型 (Reasoning Models) 与 Tool Call 的无缝解耦机制

解构新一代 Reasoning 模型（如 OpenAI o3-mini / DeepSeek-R1 / Claude 3.7 Sonnet）的二段式 Payload 表达：思维链推演 (Reasoning Tokens) 与 确定性工具派发 (Tool Calls) 的职责分离

二段式 API Response Payload

Two-Phase Reasoning Response Stream

o3 / DeepSeek-R1
// Phase 1: Internal Reasoning Stream (No Side Effects)
"reasoning_content": "Need to query orders. Schema requires user_id integer, status='PAID'. Optimal SQL uses composite index...",
// Phase 2: Action Dispatch (Deterministic Tool Call)
"message": {
"role": "assistant",
"tool_calls": [{
"id": "call_sql_99",
"type": "function",
"function": {"name": "execute_sql", "arguments": "{\"sql\":\"SELECT * FROM orders WHERE user_id=1024 AND status='PAID'\"}"}
}]
}
  • 思考期 (Thinking Phase)：模型在思维链中充分推演算法复杂度、正则与 SQL 范式，不触发物理执行。
  • 决策派发期 (Action Phase)：推演完成后，将最成熟的逻辑精准收敛为结构化 `tool_calls`。
物理事实：思考 Tokens 为推理算力服务，`tool_calls` 负责触发宿主物理环境

逻辑规划与物理落地的解耦法则

Planning vs Execution Isolation

Decoupled Architecture
1. 思考不具有副作用 零外部 I/O 风险

`reasoning_content`（或 `` 块）仅发生在模型前向计算的概率空间里，不触发任何数据库修改或 API 调用，避免试错代码对外部环境造成污染。

2. 思考推演锁定工具入参 消杀“尝试性误召回”

普通模型容易直接吐出不成熟的函数入参；Reasoning 模型在思维链中完成了自我断言与参数校验后，生成的 `tool_calls` 一击即中率大幅提升。

工程收益：极大地降低了 Agent 因试错工具调用产生的网络开销与失败重试

Architectural Core Thesis / 架构师视角

思考链负责在隐式高维概率空间推演最佳策略，Tool Call 负责在低维物理环境执行确定性动作；将思考推演与工具派发在协议层面彻底解耦，是构建高可靠 Reasoning Agent 系统的前提。
