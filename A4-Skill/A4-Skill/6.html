GBNF 文法树与状态机推进

Grammar-Based State Machine

Grammar Engine
// GBNF (GGML BNF) Grammar Spec
root ::= "{" ws "\"name\":" name-str "," ws "\"args\":" object "}"
name-str ::= "\"git_commit\"" | "\"query_db\""
// 状态机即时预测 (Current State: Expecting Opening `{`)
Valid Next Tokens = ["{", "{\n"]
Invalid Tokens = All other 128,000+ vocabulary tokens!
  • 文法树驱动 (State Transition)：每生成一个 Token，文法引擎向前推进一步，明确锁定下一位置合法的 Token 集合。
  • 彻底脱离 Prompt 祈祷：不依赖模型“听话地输出 JSON”，而是由引擎在解码循环（Decoding Loop）中进行硬控制。
原则：文法树将无界的 Token 概率空间强制降维为离散状态图

Softmax 采样层的物理概率掩码

Logit Bias = $-\infty$ Injection

Sampling Layer
// Softmax Formula with Grammar Mask $M_i$
$P(t_i) = \frac{\exp(z_i + M_i)}{\sum_j \exp(z_j + M_j)}, \quad M_i = \begin{cases} 0 & t_i \in \text{Valid} \\ -\infty & t_i \notin \text{Valid} \end{cases}$
// 掩码前后的采样概率对比：
Token "{": $z = 2.1 \implies P = \text{1.0000}$ (Masked)
Token "Sure": $z = 8.5 \implies P = e^{8.5 - \infty} = \text{0.0000}$ (Blocked)
  • 物理级拦截：即使模型原始倾向于输出 `"Sure, here is the JSON"`，掩码算法会将 `"Sure"` 的 Logit 抹为 $-\infty$。
  • 语法报错率降为 0.00%：从底层消除了括号不匹配、未转义引号、缺少逗号等反序列化噩梦。
工业实现：OpenAI Structured Outputs / vLLM Outlines / llama.cpp GBNF

Architectural Core Thesis / 架构师视角

格式正确性不属于模型的“推理范式”，不应消耗宝贵的语义 Token 算力；通过 Logit Masking 在物理采样层解决格式校验，是将 LLM 转化为无故障工程微服务（Type-Safe Microservice）的关键一步。

🎯 深入剖析 Logit Masking 的物理逻辑： “向学员深入剖析：在 Transformer 计算的最后一步，网络会输出一个维度为 Vocabulary Size（如 128,000）的向量，这就是 Logit。正常情况下经过 Softmax 得到概率。如果引入了 GBNF 语法掩码，推理框架会先检查当前状态下哪些 Token 是符合 JSON 范式的。对于不符合的 Token，将其 Logit 直接设为 $-\infty$。”
💡 强调与传统 ReAct 正则捕获的断代区别： “传统 ReAct 靠应用层去匹配 `re.search()`，遇到未转义的引号就直接死掉；而 Constrained Decoding 是在 **采样层** 物理抹除了生成非法 JSON 的概率。这就是 OpenAI Structured Outputs、vLLM Outlines 和 llama.cpp 能实现零语法报错的原因。”
