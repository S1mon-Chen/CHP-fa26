从 Python Function 到 Tool Schema 的元编程修饰器 (Decorator Pattern 实战代码)

零侵入声明式工具注册：通过 Python 元编程修饰器 (@tool) 结合反射 (`inspect`) 与 Pydantic `create_model`，将原生函数一键打包为标准的 Tool Registry 实体

@tool 装饰器实现引擎

Python Metaprogramming Decorator

@tool Pattern 
import inspect
from functools import wraps
from pydantic import create_model

# 全局工具注册表 (Tool Registry)
TOOL_REGISTRY = {}

def tool(description: str = None):
    def decorator(func):
        # 1. 利用 inspect 提取签名参数与 Docstring
        sig = inspect.signature(func)
        fields = {
            name: (p.annotation, ... if p.default == p.empty else p.default)
            for name, p in sig.parameters.items()
        }
        
        # 2. 动态构建 Pydantic 模型并导出 JSON Schema ★
        model = create_model(f"{func.__name__}_Args", **fields)
        schema = model.model_json_schema()
        
        # 3. 压入注册表
        TOOL_REGISTRY[func.__name__] = {
            "description": description or func.__doc__,
            "parameters": schema,
            "func": func
        }
        return func
    return decorator
  • 零重复开发开销：只需要在普通 Python 函数上方打上 `@tool(...)` 标签，函数自动升级为包含强类型 Schema 与执行句柄的 Skill。
核心：利用 Python 反射机制将静态函数自动化转译为 AI 协议要求的契约字典

修饰器注册模式的三大工程红利

Decorator Engineering Benefits

Meta Architecture
1. 声明式解耦 (Declarative Decoupling) Zero Boilerplate

开发者无需了解 OpenAI 的 `tools[].function.parameters` JSON 结构规范，只需用熟悉的 Python 语法编写普通业务函数即可完成接入。

2. 自动类型推导 (`create_model`) Dynamic Model Generation

借助 `pydantic.create_model` 在运行时根据 `inspect.signature` 动态创建临时 BaseModel，实现类型推导与 Schema 导出的完全自动化。

3. 统一注册表管控 (Registry Control) Centralized Dispatch

所有装饰函数自动汇入 `TOOL_REGISTRY` 字典。控制器通过名称一键抓取全量工具 Schema 发送给 LLM，并在回传时直接分发到 `func` 句柄执行。

应用选型：LangChain `@tool` / FastMCP `@mcp.tool()` / LlamaIndex `FunctionTool.from_defaults`

Architectural Core Thesis / 架构师视角

利用 Python 元编程修饰器（Decorator Pattern） 将原生函数签名自动提炼为工具契约，是构建框架级 Skill Registry 的核心基础设施；它将开发者从繁琐的 JSON Schema 拼装中彻底解放出来。
