Memcached 架构与 Slab 内存分配 (Memcached & Slab Allocation)

Key-Value Storage, Slab Allocation Mechanics, Chunk Pre-allocation & CAS Race Condition Control

1. Slab Allocation 预分配机制（避免内存碎片）

No Fragmentation

传统 OS malloc/free 频繁分配变长内存会导致严重的内存碎片与频繁 GC 卡顿。Memcached 采用 **Slab Allocation** 预分配机制，按固定尺寸切分内存：

Slab Class 分组（增长因子 Growth Factor，默认 1.25） Page Size = 1 MB
Slab Class 1 (Chunk Size: 88 Bytes)
Chunk 88B Chunk 88B ...
Slab Class 2 (Chunk Size: 112 Bytes)
Chunk 112B Chunk 112B ...
Slab Class 3 (Chunk Size: 144 Bytes)
Chunk 144B ...
精准尺寸匹配分配 (Best-Fit Chunk Routing)

例如向 Memcached 存入一个 **100 Bytes** 的数据 Item 时，系统自动遍历 Slab Class，选择最接近且大于 100B 的 **Slab Class 2 (112 Bytes Chunk)** 进行存放，极大消除了外部内存碎片。

本质：牺牲少量内部碎片（Slab 内部空间闲置），换取绝对的零外部碎片与物理高效

2. 核心命令集与 CAS 并发控制

Command Set & CAS
set / add / replace 无条件覆盖 / 仅不存在时存 / 仅存在时存
append / prepend 在现有 Item 末尾/头部追加数据
get / delete 读取数据项 / 删除指定的缓存键
incr / decr 对 64位整数执行原子加减递增
CAS (Check-And-Set / Compare-And-Swap) 原子更新

解决多客户端并发更新缓存时的竞态条件 (Race Condition)：

1. Client A: gets key ──► 返回 Value 与 64位唯一的 **CAS token**
2. Client A: cas key val token ──► 仅当 CAS token 未变时写入成功！

核心架构启示 (Memcached Memory Philosophy)

Memcached 是纯粹的 Key-Value 内存缓存标杆。其通过 **Slab Class** 预分配机制彻底解决了内存碎片与操作系统垃圾回收卡顿问题，并通过 **CAS (Check-And-Set)** 指令原生支持无锁化的原子并发更新。
