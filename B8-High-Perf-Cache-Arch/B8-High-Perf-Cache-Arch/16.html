Redis 内存管理与 8 大淘汰策略 (Memory Eviction Policies)

`maxmemory` Threshold, 8 Eviction Policies, Approximate LRU Sampling & LFU Counter Decay

1. `maxmemory-policy` 8 大内存淘汰策略全景分类

8 Policies

当 Redis 内存使用量突破 maxmemory 限制时，将根据配置的 maxmemory-policy 触发主动淘汰：

分类 策略名称 (Policy) 物理淘汰行为
No Eviction noeviction (默认) 不淘汰数据。写操作直接返回 OOM 错误，只读命令正常。
Volatile Keys
(仅设 TTL 键)		 volatile-lru 从设置了 TTL 过期时间的 Key 中，剔除最久未使用的 Key。
volatile-lfu 从设置了 TTL 过期时间的 Key 中，剔除访问频率最低的 Key。
volatile-ttl 优先剔除剩余生存时间 TTL 最短的 Key。
volatile-random 从设置了 TTL 过期时间的 Key 中随机剔除。
All Keys
(所有键)		 allkeys-lru (推荐) 从所有 Key 中，剔除最久未使用的 Key（常规缓存首选）。
allkeys-lfu 从所有 Key 中，剔除访问频率最低的 Key（防突发流量污染）。
allkeys-random 从所有 Key 中随机挑选进行剔除。
建议：纯缓存场景首选 `allkeys-lru` 或 `allkeys-lfu`，混合场景选 `volatile-lru`

2. 近似 LRU 采样算法与 LFU 访问计数衰减机制

LRU vs LFU
1. 近似 LRU 采样算法 (`maxmemory-samples 5`) Sampling LRU

真正的 LRU 算法需要维护一个贯穿所有 Key 的巨型双向链表，内存开销巨大。Redis 采用**随机采样近似 LRU**：随机抽取 $N$ 个 Key（默认 5 个），剔除其中最久未使用的 Key。采样数设为 10 时，效果近乎等同于真正 LRU！

2. LFU (Least Frequently Used) 频率与衰减 (Redis 4.0+) Counter & Decay

解决 LRU “冷门 Key 突发单次访问被误升为热点”的问题。将对象头 24-bit 字段拆分为： • **16-bit 访问时间戳 (LDT)** • **8-bit 概率访问计数器 (LOG_FACTOR)** 很久未访问的 Key 其计数器会自动**随时间衰减 (Decay)**，精准剔除真正的低频冷数据。

LRU Mode: [ 24-bit 绝对物理访问时间戳 ]
LFU Mode: [ 16-bit LDT 减半时间 ][ 8-bit 访问对数计数器 ]

核心架构启发 (Eviction Policy Insight)

Redis 的内存淘汰设计体现了极致的空间优化哲学：通过**随机采样近似 LRU** 避免了全局链表的指针内存损耗，通过 **8-bit 对数计数器 + 衰减时间** 实现了极小内存代价下的精确 LFU 淘汰，保证了高并发下内存使用的极致稳定。
