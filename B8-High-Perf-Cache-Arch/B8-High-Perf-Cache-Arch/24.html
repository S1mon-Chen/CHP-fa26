缓存穿透治理与布隆过滤器防护 (Cache Penetration & Bloom Filter)

Non-existent Key Attacks, Null Value Caching (`SET EX`), Bloom Filter BitMap & Mathematical Error Rate

1. 缓存穿透 (Cache Penetration) 定义与空值缓存

Penetration Def
缓存穿透产生原因 (Non-Existent Key Attack) Bypass Cache

查询一个在 **Redis 缓存** 和 **底层数据库 (DB)** 中物理上均不存在的数据（例如黑客使用伪造的 `id = -1` 进行恶意并发攻击）。每次请求绕过缓存直击数据库，导致 DB 瞬间高压瘫痪。

防御方案 1：缓存空值 (Cache Null Values) Short TTL

当数据库查为空时，依然向 Redis 写入一个空值或特异标记（如 `SET key "" EX 60`），并设定较短的生存时间（如 60 秒），阻断短时间内的重复攻击。

// 缓存空值拦截处理流
String val = redis.get(key);
if (val != null) { return val.equals("") ? null : parse(val); }
String dbVal = db.query(key);
if (dbVal == null) { redis.set(key, "", 60, SECONDS); return null; }
局限：若黑客随机更换不同非法 Key，空值缓存会导致 Redis 内存大量占用

2. 防御方案 2：布隆过滤器 (Bloom Filter) 高效前置校验

Bloom Filter
布隆过滤器结构与判定定理 (BitMap & Hash) Bit Array + k Hashes

由一个巨大的 $m$ 位二进制数组（BitMap）和 $k$ 个独立哈希函数组成。数据写入时，通过 $k$ 个 Hash 函数计算 $k$ 个 Bit 位置并置为 $1$。

• 判定不存在 $\implies$ 物理上绝对不存在！(100% 准确，直接拦截)
• 判定存在 $\implies$ 物理上可能存在 (有极小误判率 $p$)
最佳哈希函数个数与误判率公式 (Optimal Hash Count & Error Rate)
$$k = \frac{m}{n} \ln 2, \quad p \approx \left(1 - e^{-kn/m}\right)^k$$

其中 $m$ 为 BitMap 长度，$n$ 为插入元素总数，$p$ 为允许的假阳性误判率 (False Positive Rate)。

// RedisBloom 模块命令或 Guava BloomFilter 实战
BF.RESERVE user_filter 0.01 1000000 # 误判率 1%，预期 100 万数据
BF.EXISTS user_filter "user:-1" # 拦截！返回 0 直接拒绝穿透 DB
开启下一个核心：Slide 25 · 缓存击穿与互斥锁 (SETNX) / 逻辑过期重构

核心架构启发 (Cache Penetration Defense Insight)

防范缓存穿透展现了严密的拦截分层思想：简单的静态 Key 攻击使用**空值缓存 (`SET EX`)** 快速阻断；而面对海量随机变动的不存在 Key 攻击，则前置**布隆过滤器 (Bloom Filter)** 依靠 $100\%$ 的“不存在确定性”构建坚不可摧的内存保线。
