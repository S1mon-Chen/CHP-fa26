Part 02 · Redis 内部内核与核心数据结构

Redis 数据结构 1：String 与 SDS 物理内核 (Simple Dynamic String)

C String Limitations vs. SDS Header (`sdshdr8`), $O(1)$ Length, Binary Safety & Buffer Allocation

1. C 语言原生字符串缺陷与 SDS 结构体

SDS C-Struct

C 语言原生字符串以 '\0' 标记结尾，获取长度需遍历数组 ($O(N)$)，且数据中不能包含 '\0'。Redis 自研了 **SDS (Simple Dynamic String)** 结构：

// Redis 内部 SDS 报头结构体 (sdshdr8 样例)
struct __attribute__ ((__packed__)) sdshdr8 {
uint8_t len; // 1. 已使用字节长度 (O(1) 获取长度)
uint8_t alloc; // 2. 预分配总字节长度 (不含 header 和 '\0')
unsigned char flags; // 3. SDS 类型标志 (sdshdr5/8/16/32/64)
char buf[]; // 4. 柔性字节数组 (二进制安全字节流)
};
内存紧凑优化 (`__attribute__ ((__packed__))`) Zero Alignment Padding

结构体禁止编译器字节对齐填充，直接通过 buf - 1 快速定位 flags 字段，节省内存并提高 CPU 缓存命中率。

本质：将定长字符数组升级为自带长度元数据的动态字节缓冲区

2. SDS 的三大物理设计优势 (Core Advantages)

SDS Superiority
1. 常数复杂度 $O(1)$ 获取字符串长度 $O(1)$ Time

C 字符串执行 `strlen` 必须从头遍历到结尾 ($O(N)$)。SDS 直接读取结构体头部的 len 字段，时间复杂度恒为 **$O(1)$**。

2. 真正的二进制安全 (Binary Safe) Raw Byte Stream

不以 '\0' 字符判定文本截断，而是依赖 `len` 判定长度。可以安全地存储图片、压缩字节流、Protobuf 或序列化 JSON 对象。

3. 空间预分配与惰性释放 (Prevent Buffer Overflow) Lazy Allocation

字符串拼接修改时，自动检查并分配额外的冗余空间（$< 1\text{MB}$ 时扩容为 2 倍），大幅减少内存重分配 (`realloc`) 系统调用，杜绝缓冲区溢出。

核心数据结构启发 (SDS Design Insight)

Redis 的 SDS 结构体现了极致的 C 语言性能优化思维：通过在字符数组前增加包含 **`len` 与 `alloc`** 的 Header 报头，用极小的空间开销（几字节），换取了字符串 $O(1)$ 长度获取、二进制安全与防止缓冲区溢出的三大物理能力。
