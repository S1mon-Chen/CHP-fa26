AI 时代缓存演进：Redis Stack 向量索引与 Prompt 语义缓存 (AI Semantic Cache)

LLM API Cost & Latency Bottleneck, Text Embeddings, HNSW Vector Index & Cosine Distance Thresholding

1. 大模型 API 调用的痛点与语义缓存 (Semantic Cache) 原理

5ms vs 3000ms
大模型 (LLM API) 的物理痛点与传统 KV 缓存失效 0% Hit Rate

• **高延迟与昂贵费用**：GPT-4 / Claude API 单次响应耗时数秒（1000~5000ms），按 Token 计费极其昂贵。
• **传统 KV 缓存失效**：用户输入的 Prompt 语言极其灵活（如 *"如何重置密码？"* 与 *"怎么修改密码？"*），传统精确 Key 匹配命中率为 **0%**！

// AI 语义缓存过滤管线 (Semantic Cache Pipeline)
1. 用户输入 Prompt: "How to reset password?"
2. 向量化: EmbeddingModel.encode(prompt) ──► [0.12, -0.45, ...]
3. Redis Stack 检索: FT.SEARCH idx "*=>[KNN 1 @vector $vec]"
4. 判定: d_cosine <= 0.05 ──► 秒级返回缓存 (5ms, 0 Token Cost!)
特点：将相似语意表达映射为高维向量，从“精确匹配”升维至“语义近邻匹配”

2. Redis Stack HNSW 向量索引与余弦距离阈值判定

HNSW & Cosine
向量余弦距离判定公式 (Cosine Distance Threshold)
$$d_{\text{cosine}}(\mathbf{u}, \mathbf{v}) = 1 - \frac{\mathbf{u} \cdot \mathbf{v}}{\|\mathbf{u}\| \|\mathbf{v}\|} \le \delta \quad (\delta \approx 0.05)$$

当余弦距离低于阈值 $\delta$ 时，证明两句 Prompt 在语义上高度重合，可直接复用旧回答。

// Redis Stack (RediSearch) 创建 HNSW 向量索引命令
FT.CREATE prompt_idx ON HASH PREFIX 1 prompt: SCHEMA
prompt_vector VECTOR HNSW 6 TYPE FLOAT32 DIM 1536 DISTANCE_METRIC COSINE
语义缓存三大工程收益 Cost & Latency Reduction
  • • **响应延时绝降**：从 LLM API 的 3000ms 剧降至 Redis 内存向量搜索的 **5ms**。
  • • **API 费用削减 90%+**：针对高频重复客服/FAQ 问题，彻底免去 LLM Token 计费。
  • • **支持多语言泛化**：同一语义的英文与中文 Prompt（如 *"How to use"* 与 *"怎么使用"*) 可直接命中。
