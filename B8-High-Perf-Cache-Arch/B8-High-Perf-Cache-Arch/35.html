Spring Data Redis 代码实战：DAO 层手动编程缓存 (`PersonDaoImpl`)

Programmatic Cache Query Pipeline, JSON Serialization, Defensive TTL Jitter & Null Value Protection

1. 编程式缓存管线与防御性代码设计

Pipeline Steps

相较于注解（如 `@Cacheable`），手动编程式缓存赋予了开发者对**防穿透空值设置**、**防雪崩随机 TTL 抖动**以及**自定义序列化**的绝对掌控权：

1 先查 Redis 缓存 (Cache-First) Fast Path

使用 redisTemplate.opsForValue().get(key) 快速获取 JSON 字符串。命中则直接调用 FastJSON / Jackson 反序列化为对象并返回。

2 防穿透校验与 DB 退避查空 Anti-Penetration

若取出的字符串为物理标记空值 ""，说明之前已被防穿透判定，直接返回 `null`；若未命中再查 RDBMS 数据库。查空时写入空值标记并设短 TTL（60s）。

3 写缓存 + 随机 TTL 抖动 (防雪崩) Random Jitter

查库成功后，为基础 TTL（如 30 分钟）加上 1~300 秒的离散随机时间（`1800 + random.nextInt(300)`），避免大量 Key 同秒失效。

特点：手动编程式控制防穿透、防雪崩，比注解方式更具掌控力

2. 生产级 `PersonDaoImpl.java` 手动缓存实现代码

PersonDaoImpl.java
// PersonDaoImpl.java 手动缓存与防穿透/防雪崩代码
@Repository
public class PersonDaoImpl implements PersonDao {
@Autowired private PersonRepository personRepo;
@Autowired private StringRedisTemplate redisTemplate;
private static final String KEY_PREFIX = "person:";
@Override
public Person findOne(Integer id) {
String key = KEY_PREFIX + id;
// 1. 查 Redis 缓存
String json = redisTemplate.opsForValue().get(key);
if (StringUtils.hasText(json)) {
return JSON.parseObject(json, Person.class);
}
// 2. 防穿透检查：处理空字符串标记
if (json != null) return null;
// 3. Cache Miss：查询底层 RDBMS 数据库
Person person = personRepo.findById(id).orElse(null);
if (person == null) {
// 防穿透：写入空标记，设置 60 秒短过期
redisTemplate.opsForValue().set(key, "", 60, TimeUnit.SECONDS);
return null;
}
// 4. 写缓存：加入 30min + 5min 随机抖动 (防雪崩)
long ttl = 1800 + new Random().nextInt(300);
redisTemplate.opsForValue().set(key, JSON.toJSONString(person), ttl, TimeUnit.SECONDS);
return person;
}
// 5. 更新与删除：先写 DB，再擦除 Cache (Cache-Aside 模式)
public Person update(Person p) {
Person saved = personRepo.save(p);
redisTemplate.delete(KEY_PREFIX + p.getId());
return saved;
}
}

核心架构启发 (Programmatic Caching Insight)

声明式注解（如 `@Cacheable`）适合常规简单查询，而 **手动编程式缓存** 是应对高并发复杂场景的“核武器”。在 DAO/Service 层手写缓存控制，可以精确嵌入**防穿透空标记设置**与**防雪崩随机 TTL 抖动**，实现极其稳健的生产级缓存访问控制。
