Spring Cache 声明式缓存抽象与 `@EnableCaching` 机制

Spring Cache Abstraction, Unified `CacheManager` SPI, Spring AOP Aspect & Zero Code Invasion

1. Spring Cache 解耦哲学与 AOP 切面代理体系

Cache SPI

Spring Cache 并不直接实现具体的缓存存储，而是提供了一套高度抽象的 **SPI 接口 (Service Provider Interface)**，通过 Spring AOP 动态代理将业务代码与具体缓存实现完全解耦：

// Spring Cache 声明式切面拦截管线
1. 启动类标注: @EnableCaching // 激活 CacheAspectSupport
2. 业务方法标注: @Cacheable("users") // 声明缓存切点
3. AOP 代理拦截: CacheInterceptor.invoke() // 拦截目标方法
4. 路由 CacheManager: CacheManager.getCache("users") ──► Redis / Caffeine
核心接口双雄 (Cache Core SPI) Cache & CacheManager
  • • **`CacheManager`**：缓存管理器接口，负责管理与生命周期控制多个命名的 `Cache` 容器。
  • • **`Cache`**：底层缓存操作接口，统一封装了 `get(key)`, `put(key, val)`, `evict(key)` 等原子读写。
特点：修改底层缓存（如 Caffeine 升级 Redis）只需替换 Bean，业务代码零改动

2. 常见 `CacheManager` 实现类与 Maven 依赖集成

Cache Providers
实现类 (CacheManager) 存储介质类型 典型适用场景
RedisCacheManager Redis 集中式内存集群 分布式微服务集群（生产首选）
CaffeineCacheManager JVM 进程内本地内存 单体高并发、纳秒级本地 L1 缓存
CompositeCacheManager 组合多级缓存链 Caffeine (L1) + Redis (L2) 级联
ConcurrentMapCacheManager JVM ConcurrentHashMap 快速单元测试 / 本地 Demo

核心架构启发 (Spring Cache Abstraction Insight)

Spring Cache 展现了极其高超的设计模式运用：通过 **AOP 切面拦截** 屏蔽了繁琐的缓存判定代码，通过 **统一 `CacheManager` SPI 接口** 抹平了底层 Caffeine 与 Redis 的技术差异，使得项目能够以极低成本进行缓存技术的架构升级。
