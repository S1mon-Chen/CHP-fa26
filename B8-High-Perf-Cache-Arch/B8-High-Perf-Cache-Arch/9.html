Redis 架构概述与单线程/多线程 I/O 模型 (Threading Model Evolution)

Non-blocking Multiplexing, Single-Threaded Execution Core & Redis 6.0+ Multi-Threaded I/O Offloading

1. 经典 Redis 单线程内核何以达到 10W+ QPS？

Single-Thread Core
纯内存操作 (Pure Memory Access) Zero Disk I/O

所有数据物理驻留在内存中，没有随机磁盘 Seek 寻道损耗。内存读写耗时通常在 50~100 ns。

非阻塞多路复用 I/O (epoll / kqueue) Reactor Event Loop

基于 Reactor 事件驱动模型，单个内核线程配合 epoll 监听数万 Socket，无线程阻塞挂起。

无锁化与无上下文切换 (No Lock Contention) Zero Context Switch

避免了操作系统多线程频繁上下文切换及线程死锁风险，无需加互斥锁即可天然保证命令执行的**原子性**。

本质：Redis 性能瓶颈不在 CPU 计算，而在网络 Socket 传输带宽

2. Redis 6.0+ 多线程 I/O 架构演进（只读写网络，不改命令内核）

Redis 6.0+ Multi-I/O
Redis 6.0+ 多线程 I/O 读写与主线程命令执行分工管线 Reactor + I/O Worker Threads
阶段 1: 多线程 Socket 读取与 RESP 协议解析 Parallel Socket Reading

主线程收到 Socket 可读事件，把 Socket 分配给 **I/O Threads**。多线程并发读取网络数据包并解析 RESP 命令协议。

★ 阶段 2: 主线程单线程顺序执行命令 (Single-Thread Execution) Main Thread Only!

**命令的实际内存读写与数据修改依然完全由主线程单线程顺序完成**！彻底维持了 Redis 零锁竞争、命令执行原子的核心哲学。

阶段 3: 多线程响应写回 (Parallel Response Writing) Parallel Socket Writing

主线程执行完命令，把写回任务分发给 **I/O Threads**，多线程并发把 Response 字节流刷新写回各个 Socket 网卡。

Redis 6.0+ 多线程开启配置方法 (`redis.conf`) io-threads 4
io-threads 4 # 设置 I/O 线程数 (建议 <= CPU 逻辑核心数)
io-threads-do-reads yes # 默认仅开启写多线程，设为 yes 可开启读多线程
开启下一个核心：Slide 10 · SDS (Simple Dynamic String) 动态字符串物理结构

核心架构启发 (Redis Threading Model Insight)

Redis 的线程模型演化展示了极其高超的系统折中艺术：**用多线程解决网络 Socket I/O 数据包收发的带宽瓶颈，同时维持命令执行内核的绝对单线程**，既释放了多核 CPU 处理网络报文的能力，又完美规避了并发锁竞争。
