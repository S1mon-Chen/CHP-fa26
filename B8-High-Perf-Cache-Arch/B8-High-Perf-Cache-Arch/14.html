Dual Encoding (ziplist/listpack vs. skiplist + dict), $O(\log N)$ Range Scan & Random Level Promotion

1. ZSet 对象的底层双重结构与跳表选型哲学

zset Struct

Redis 中的 Sorted Set (ZSet) 在元素较少时用 **ziplist/listpack**（成员与分值交替紧凑存储）；大量数据时使用 **`zset` 结构体**（同时包含 **`skiplist`** 与 **`dict`**）：

// Redis zset 物理结构体定义
typedef struct zset {
dict *dict; // 1. 哈希表: member -> score ($O(1)$ 查询得分)
zskiplist *zsl; // 2. 跳表: 按 score 排序 ($O(\log N)$ 范围扫描)
} zset;
为何选择跳表 (Skiplist) 而非红黑树 (Red-Black Tree)？ Range Query & Simplicity
  • • **极速范围扫描**：`ZRANGEBYSCORE` 范围查询时，跳表只需在最底层双向链表横向移动指针；红黑树需要中序遍历，复杂度极高。
  • • **实现简单与无锁调整**：跳表无需红黑树复杂的平衡旋转（Rebalance），高并发或内存调整更容易实现。
  • • **内存开销更小**：跳表节点平均层高仅 $1.33$，比红黑树更加节省指针开销。
双剑合璧：dict 搞定 $O(1)$ 查找，skiplist 搞定 $O(\log N)$ 范围排序

2. 跳表 (Skiplist) 物理层级图解与概率随机晋升

Level Promotion
// zskiplist 物理多层跨步链表布局 (以查找 Score=30 为例)
Level 3: [Head] ───────────────────────────► [Node 30] ──────────► NULL
Level 2: [Head] ──────────► [Node 10] ──────► [Node 30] ──────────► NULL
Level 1: [Head] ──► [Node 5] ──► [Node 10] ──► [Node 30] ──► [Node 50] ──► NULL
最底层 (Level 1) 带有后退指针 (backward)，形成支持倒序遍历的双向链表！

从顶层跨步查找，每次跳过多个节点。若下一个节点 Score $> 30$，降层往下走，下降到 Level 1 定位元素。

随机层高晋升算法 (`zslRandomLevel`) $p = 1/4$, Max = 32/64

新节点插入时，通过抛硬币式的概率算法决定层高：每增加一层概率为 **$25\%$ ($1/4$)**。 使得平均层高为： $$\text{Average Height} = \frac{1}{1-p} = \frac{1}{1 - 0.25} = 1.33$$ 在概率上达到了完美的平衡树高度，且无需昂贵的物理重平衡操作！

核心数据结构启发 (Skiplist Design Insight)

Redis 的 **`skiplist`** 展示了数据结构设计的灵动与优雅：用极简的概率掷骰子算法代替了红黑树极其繁琐的平衡旋转，用 **`skiplist` + `dict` 组合** 同时达成了范围扫描与 $O(1)$ 单点精确查找，是 Redis 内存性能神话的关键柱石。
