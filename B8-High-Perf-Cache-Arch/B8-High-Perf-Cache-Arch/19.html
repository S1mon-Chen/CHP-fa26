Append-Only File (`appendonly.aof`), Flush Strategies, `bgrewriteaof` & Hybrid Persistence (`aof-use-rdb-preamble`)

1. AOF 追加日志与 3 大刷盘策略 (`appendfsync`)

appendonly.aof

AOF (Append-Only File) 以文本协议格式记录 Redis 执行的**每一条写命令**。通过配置 appendfsync 策略平衡安全与性能：

刷盘策略 (Policy) 物理行为 安全性与性能评估
always 每条写命令均强行调用 fsync() 刷盘。 绝对安全（极低丢数据风险），但磁盘 I/O 慢爆。
everysec (推荐) 每秒由后台子线程调用 fsync() 异步刷盘。 黄金平衡！兼顾高吞吐，最坏只丢失 1 秒数据。
no 仅写 OS Buffer，由操作系统决定刷盘时机 (通常 30s)。 写入极快，但宕机时数据丢失量不可控。
AOF 重写瘦身机制 (`bgrewriteaof`) File Compaction

长期运行后，AOF 文件会急剧膨胀（如连续 100 次 `INCR counter`）。bgrewriteaof 创建子进程，**直接读取当前内存数据集生成等价的最简写命令**（合并为 1 条 `SET counter 100`），瘦身效果极其显著。

提示：AOF 重写并不读取旧 AOF 文件，而是直接扫描当前物理内存重构指令

2. Redis 5.0+ 混合持久化 (Hybrid Persistence - 生产默认)

aof-use-rdb-preamble

传统 RDB 恢复快但丢数据多，传统 AOF 丢数据少但重启加载极其漫长。Redis 4.0 引入、**5.0 默认开启**的**混合持久化**融合了二者长处：

// 混合持久化文件物理布局 (`appendonly.aof`)
[ 文件头部 Header: RDB 二进制格式内存快照 ] 极速恢复 (Flash Boot)
[ 文件尾部 Tail: AOF 文本格式增量命令追加日志 ] 零数据丢失 (Zero Loss)

重写时，将当前内存数据以 RDB 形式写入 AOF 文件头部；重写期间收到的新写命令，以 AOF 追加日志的形式拼接到文件尾部。

混合持久化开启配置 (`redis.conf`) aof-use-rdb-preamble yes
appendonly yes # 开启 AOF 持久化
aof-use-rdb-preamble yes # 开启混合持久化 (Redis 5.0+ 默认开启)
开启下一个核心：Slide 20 · PSYNC 2.0 主从复制与增量同步机制

核心持久化启发 (Hybrid Persistence Insight)

**混合持久化 (Hybrid Persistence)** 是 Redis 持久化演进的集大成者：它用 **RDB 头部** 解除了传统 AOF 重启耗时数十分钟的尴尬，用 **AOF 尾部** 规避了 RDB 两次快照间数据丢失的短板，是现代高可用生产环境的标准必备选择。
