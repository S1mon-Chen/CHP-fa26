`RedisTemplate` vs. `StringRedisTemplate` 与 Jackson 序列化配置

JDK Serialization Binary Prefix (`\xac\xed\x00\x05`), `StringRedisSerializer`, Jackson JSON Auto-Typing & Custom `RedisConfig`

1. 两种客户端模板对比与 JDK 默认序列化乱码痛点

Serializer Pitfall
对比维度 StringRedisTemplate (推荐) RedisTemplate (默认配置)
Key 序列化器 `StringRedisSerializer` (UTF-8) `JdkSerializationRedisSerializer`
Value 序列化器 `StringRedisSerializer` (明文 String) `JdkSerializationRedisSerializer` (二进制)
Redis CLI 可读性 100% 清晰明文可读，支持常规检索 带着 `\xac\xed\x00\x05` 二进制前缀乱码
跨语言互通性 支持 Python/Go/Node.js 共享解析 仅限 Java 虚拟机解包（严重耦合）
JDK 默认序列化乱码物理现象 Binary Mess
127.0.0.1:6379> KEYS *
1) "\xac\xed\x00\x05t\x00\x07user:1001" # 严重浪费内存且打乱搜索！
解决方案：自定义 RedisTemplate Bean 强制替换为 String + Jackson 序列化

2. 生产级 `RedisConfig.java` 序列化定制配置代码

Jackson Custom Config
// RedisConfig.java 自定义序列化 Bean 配置
@Configuration
public class RedisConfig {
@Bean
public RedisTemplate<String, Object> redisTemplate(RedisConnectionFactory factory) {
RedisTemplate<String, Object> template = new RedisTemplate<>();
template.setConnectionFactory(factory);
// 1. Key 序列化：使用 UTF-8 字符串
StringRedisSerializer stringSerializer = new StringRedisSerializer();
template.setKeySerializer(stringSerializer);
template.setHashKeySerializer(stringSerializer);
// 2. Value 序列化：使用 GenericJackson2JsonRedisSerializer
GenericJackson2JsonRedisSerializer jsonSerializer = new GenericJackson2JsonRedisSerializer();
template.setValueSerializer(jsonSerializer);
template.setHashValueSerializer(jsonSerializer);
template.afterPropertiesSet();
return template;
}
}
GenericJackson2JsonRedisSerializer 的类型机制 `@class` Property

它会在 JSON 结构体中自动附加 "@class": "com.example.Person" 属性，反序列化时能精准自动还原为 Java 具体 DTO 对象，免去强转步骤。

开启下一个核心：Slide 35 · `PersonDaoImpl` 手动缓存与防穿透代码实战

核心架构启发 (Serialization Insight)

序列化是连接 JVM 堆内存与 Redis 物理内存的唯一桥梁。彻底弃用默认的 JDK 二进制序列化，转用 **`StringRedisSerializer`（Key）** 和 **`GenericJackson2JsonRedisSerializer`（Value）**，不仅让 Redis CLI 中的数据清晰可读，还彻底避免了跨语言反序列化的物理崩溃陷阱。
