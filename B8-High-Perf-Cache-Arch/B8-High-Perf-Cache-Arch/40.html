1. 课后核心架构思考题与高频面试挑战 (Discussion Questions)

Deep Questions

Q1 Cache-Aside 模式下的双写与失效策略物理分析

在 Cache-Aside 模式中，为什么“先更新数据库，再删除缓存”比“先更新数据库，再更新缓存”或“先删除缓存，再更新数据库”更能大幅降低数据不一致发生的概率？请结合并发读写时序与物理 I/O 耗时差异说明物理原因。

Q2 Redis 6.0+ 多线程 I/O 与单线程命令执行内核分析

Redis 6.0 引入的多线程 I/O 与 Netty / Node.js 的多线程 Reactor 模型在架构设计上有何异同？为什么 Redis 依然严格坚持“内存数据读写与命令执行由主线程单线程完成”？

Q3 RedLock 红锁协议中的 NTP 时钟跳跃 (Clock Drift) 风险

在部署 5 个独立 Master 节点的 RedLock 红锁协议中，如果某个 Master 节点突然发生 NTP 时钟向前跳跃 (Clock Drift) 或操作系统停顿（如 GC 卡顿），会如何破坏红锁的互斥性防护？红锁有效时间的数学公式是怎样定义的？

提示：结合本讲 Slide 9, 27 与 29 的物理原理解答以上思考题

1. Q1 考察 Cache-Aside 为什么先更新 DB 再删 Cache 最安全：写 DB 包含磁盘 I/O 耗时远大于读 DB，时序颠倒写回脏缓存的物理概率趋近于零。
2. Q2 考察 Redis 多线程 I/O 与单线程命令执行：多线程只负责网络 Socket 报文读取与响应写回，而命令执行严格由主线程单线程完成，以维持零锁竞争。
3. Q3 考察 RedLock 与 NTP 时钟跳跃：如果某 Master 时钟向前跳跃，导致已加的锁提前失效，其他线程就能在该 Master 上重新加锁并达成过半数，破坏了红锁的互斥性！”
