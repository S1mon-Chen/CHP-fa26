Redis 数据结构 4：Set 对象物理内核 (intset 与 hashtable 升级机制)

Dual Encoding (`OBJ_ENCODING_INTSET` vs `OBJ_ENCODING_HT`), Sorted Integer Memory Layout & Dynamic Bit-width Upgrading

1. Set 底层双重编码转换与 intset 物理结构

intset Struct

Redis 中的 Set 对象在所有元素均为整数且数量较小时，使用极省内存的 **`intset` (整数集合)** 连续物理内存；出现非整数或数量超标时升轨为 **`dict`**：

// Redis intset 物理结构体定义
typedef struct intset {
uint32_t encoding; // 1. 编码方式 (INT16 / INT32 / INT64)
uint32_t length; // 2. 包含的元素个数
int8_t contents[]; // 3. 按升序排列的连续整数数组
} intset;
// intset 连续物理内存阵列 (例如 INT16 编码, length = 4)
[encoding: INT16][length: 4][ -1024 ][ 5 ][ 42 ][ 999 ]

数组元素**严格升序排列且绝不重复**。通过二分查找 (Binary Search) 在连续内存中快速定位元素，时间复杂度 $O(\log N)$。

优点：零指针开销，物理紧凑，CPU L1/L2 Cache 命中率极高

2. Intset 自动升级机制与 Dict 升轨条件

Upgrading & Dict
1. 编码自动升级机制 (`intsetUpgrade`) 16 $\to$ 32 $\to$ 64 bit

当插入一个超出当前编码范围的大整数（如在 INT16 集合中插入 65535），intset 触发升级：重新分配内存，将现有元素的位宽扩大为 INT32 并按原顺序从后往前重新搬迁放置。**升级不可逆（不支持降级）**。

2. Dict 哈希表升轨阈值配置 (`redis.conf`) set-max-intset-entries 512
  • • **元素数量限制**：当 Set 包含的整数个数超过 set-max-intset-entries (默认 512) 时，自动转换为 `dict`。
  • • **非整数阻断**：只要插入任意一个非整数字符串（如 `"hello"`），立刻直接升轨为 `dict`。
// 升轨为 dict 时的 Set 结构
Set 升轨为 dict 时，哈希表中的每个 **Key 保存元素值**，而对应的 **Value 统一定为 NULL**。使得 `SISMEMBER` 查找直接达成 $O(1)$。

核心数据结构启发 (Set Architecture Insight)

Redis 的 **`intset`** 是内存极致压缩的教科书范例：通过按需升轨位宽（$16\text{-bit} \to 32\text{-bit} \to 64\text{-bit}$），在保证数字有序二分查找 $O(\log N)$ 效率的同时，用最小的内存容纳小整数集合；只有遇到字符串或海量数据时才借力 `dict` 达成 $O(1)$ 哈希性能。
