Spring Cache 核心注解：`@Cacheable`, `@CachePut` 与 `@CacheEvict`

Method Interception Lifecycle, SpEL Key Generator, Condition & Unless Filtering, Complex `@Caching`

1. 声明式缓存三大核心注解功能与生命周期

Spring Annotations
`@Cacheable` (只读/拦截查询) Query Optimization

先检查指定 Cache 容器中是否存在 Key：若 **Hit (命中)** 直接返回缓存对象，**不执行方法体**；若 **Miss (未命中)** 则执行方法，并自动将返回值存入 Cache。

`@CachePut` (写/强制更新) Update Flush

**必定强制执行方法体**（通常用于数据库更新 UPDATE 操作），方法执行完毕后，自动将最新的返回值覆盖刷入 Cache 容器。

`@CacheEvict` (擦除/清理缓存) Delete Purge

用于数据库 DELETE 操作。根据 Key 从 Cache 中清除条目。
• allEntries = true：清空整个命名 Cache 空间的所有项。
• beforeInvocation = true：在方法执行前提前清空，防止方法异常导致脏缓存留存。

`@Caching` 组合注解： 支持在一方法上聚合多个 `@Cacheable`, `@CachePut` 或 `@CacheEvict` 复杂组合法则。
核心原则：查询用 @Cacheable，更新用 @CachePut，删除用 @CacheEvict

2. SpEL 表达式生成 Key 与 Service 层完整代码实战

SpEL & Service
SpEL (Spring Expression Language) 常用 Key 规则 Dynamic Key
#id / #p0 入参名为 id 的变量或第 0 个参数
#user.id 读取入参 DTO 对象内部属性
condition 执行前过滤 (如 `#id > 0`)
unless 执行后过滤 (如 `#result == null`)
// PersonServiceImpl.java 声明式缓存实战
@Service
public class PersonServiceImpl implements PersonService {
// 1. 查询：Miss 时自动写缓存，排除 null 返回值
@Cacheable(value = "persons", key = "#id", unless = "#result == null")
public Person findById(Integer id) { return personRepo.findById(id).orElse(null); }
// 2. 更新：每次都执行数据库更新，并更新缓存
@CachePut(value = "persons", key = "#person.id")
public Person update(Person person) { return personRepo.save(person); }
// 3. 删除：删除 DB 并将 Redis 中该 Key 擦除
@CacheEvict(value = "persons", key = "#id")
public void delete(Integer id) { personRepo.deleteById(id); }
}

核心架构启发 (Declarative Cache Insight)

Spring Cache 注解彻底将业务逻辑从繁琐的“防穿透、查询、写入、序列化”样板代码中解放出来。结合 **SpEL 动态 Key 表达式** 与 **`unless = "#result == null"`** 过滤条件，可以用零侵入的方式构筑安全、高效的缓存访问控制层。

Speaker Notes / 讲师讲稿
🎯 引导学员透视三大缓存注解的区别： “向学员做解构说明：很多人搞混 `@Cacheable` 和 `@CachePut`。记住：`@Cacheable` 包含**拦截机制**，如果 Cache 里有就根本不会去调底层数据库；而 `@CachePut` **必定强制调用数据库更新方法**，然后把结果刷新回 Cache；`@CacheEvict` 则是在删除记录时同步清空 Cache。”
💡 强调 SpEL 表达式与 `unless` 防空值缓存： “请学员特别关注右侧代码中的 `unless = "#result == null"`：如果在数据库里没查到该用户返回了 null，加了 `unless` 就不把 null 写进缓存，防止将数据库查空的对象乱刷进 Redis。下一个 Slide 33 将讲解 **Spring Boot 整合 Redis (`RedisTemplate` 序列化与配置)**。”
