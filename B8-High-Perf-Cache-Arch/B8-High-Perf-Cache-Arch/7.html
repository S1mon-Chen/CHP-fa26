Memcached vs. Redis 核心维度全景选型矩阵

Feature Matrix
对比维度 (Dimension) Memcached Redis
1. 数据结构支持 仅纯 String (Key-Value)

无原生复杂类型，复杂对象需客户端自定义序列化/反序列化。

 丰富数据结构库 (Data Structure Server)

String, Hash, List, Set, ZSet, Stream, Bitmap, GEO, Vector
2. 持久化支持 不支持持久化

纯内存存储，服务重启或断电后缓存数据全数丢失。

 完善持久化 (RDB / AOF / 混合)

RDB 内存快照 (COW) + AOF 追加日志 + Redis 5.0+ 混合持久化。
3. 线程与 I/O 模型 原生多线程 (Slab + Lock)

基于多线程与细粒度锁，能高效跑满多核 CPU。

 单线程内核 + 多线程 I/O (Redis 6.0+)

命令执行绝对单线程无锁，网络 Socket 读写多线程并发加速。
4. 内存管理与利用率 Slab 预分配 (无外部碎片)

小数据空间利用率极高，绝无 OS GC 卡顿。

 复杂结构带 Header 开销

用 ziplist/listpack、intset 等紧凑编码优化小数据内存。
5. 高可用与集群 无原生 Cluster（依赖客户端）

节点间互不通信，依赖客户端一致性 Hash 算法分片。

 原生 Sentinel 哨兵 + Cluster 集群

主从复制 + Sentinel 自动故障转移 + Cluster 16384 哈希槽切片。
6. 高级扩展功能 无 (仅纯粹 KV 存取) 极其丰富的高级生态

Lua 脚本原子操作、Pub/Sub 发布订阅、事务、Redisson 分布式锁、AI 向量缓存。

核心架构选型启示 (Selection Philosophy)

如果只需要**极小简单 String 数据的超高频纯内存缓存**，Memcached 依然是极其轻量高效的选择；但在现代化微服务与高并发服务端架构中，凭借丰富数据结构、高可用 Cluster、持久化与分布式锁支持，**Redis 已成为绝对的行业事实标准**。

🎯 引导学员透视 Memcached 与 Redis 的本质区别： “向学员做解构说明：Memcached 是一个极其纯粹的 Key-Value 内存对象缓存；而 Redis 的定位则是 Data Structure Server（数据结构服务器）。在实际选型中，Redis 提供了 RDB/AOF 持久化、哨兵高可用与 Cluster 切片集群，已经全面主导了现代化分布式服务端架构。”
💡 强调 Redis 6.0+ 多线程 I/O 与单线程命令执行： “请学员重点关注线程模型对比：很多人以为 Redis 是完全单线程的。要向学员澄清：Redis 的命令执行和内存操作始终保持单线程顺序执行（无锁化）；但在 Redis 6.0+ 中引入了多线程来加速网络 Socket 数据包的读取与解析！下一个 Slide 8 将探讨基于 Caffeine 与 Redis 的多级缓存架构。”
