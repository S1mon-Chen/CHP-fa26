Redis 高级数据类型：Bitmap, HyperLogLog, GEO 与 Stream

Bit-array Compact Sign-ins, Probabilistic Cardinality (12 KB), GeoHash Spatial Index & Stream Message Bus

1. 极致内存压缩类型：Bitmap 与 HyperLogLog

12 MB & 12 KB
Bitmap (位图 - 位运算) SETBIT / BITCOUNT

基于 SDS 动态字符串实现的二进制位阵列。支持按 Bit 位进行 `SETBIT`, `GETBIT`, `BITCOUNT`, `BITOP`（与/或/异或）。

场景： 1 亿用户每日签到打卡，仅需 $100,000,000 \text{ bits} / 8 \approx 12 \text{ MB}$ 内存！
HyperLogLog (概率型基数统计) PFADD / PFCOUNT

基于 LogLog 概率算法估计集合的独立元素个数。标准误算率仅为 **$0.81\%$**。

场景： 统计海量千万级 UV 独立访客，单个 Key **固定仅占用 12 KB** 物理内存！
特点：用极简的数学算法与位运算，解决传统 HashSet 海量内存爆满痛点

2. 空间索引与消息总线：GEO 与 Stream

GeoHash & Stream
GEO (地理位置空间检索) GEOADD / GEOSEARCH

基于 **GeoHash** 算法将二维经纬度坐标（Longitude, Latitude）编码转换为 52 位长整数分值，存入 **ZSet** 中实现范围邻近搜索。

场景： 查找附近 3 公里内的外卖骑手与共享单车 (`GEOSEARCH radius 3 km`)。
Stream (持久化多消费者消息队列 - Redis 5.0+) XADD / XREADGROUP / XACK

借鉴 Kafka 设计理念的多消费者组持久化消息队列。支持**消息持久化追加**、**消费者组 (Consumer Group)**、**消息确认 (`XACK`)** 与挂起未确认消息列表 (PEL) 追溯。

核心数据结构启发 (Advanced Data Types Insight)

Redis 的高级数据类型展示了极其深刻的系统工程智慧：**用 GeoHash 借力 ZSet 解决地理检索**，**用概率统计 LogLog (12 KB) 解决海量 UV 爆炸问题**，**用 Stream 打造原生的消息队列**，将 Redis 从单纯的 KV 缓存升化为全能的内存服务底座。
