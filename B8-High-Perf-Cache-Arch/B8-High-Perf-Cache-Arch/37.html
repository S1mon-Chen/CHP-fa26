Spring Boot Redis 消息发送与监听代码实战

`convertAndSend()`, MessageListenerAdapter, ChannelTopic & End-to-End Pub/Sub Execution

1. 消息接收组件与容器装配代码 (`Receiver.java`)

Subscriber Code
// 1. 业务监听器 POJO 组件
@Component
public class CacheInvalidateReceiver {
private static final Logger log = LoggerFactory.getLogger(CacheInvalidateReceiver.class);
@Autowired private Cache caffeineCache; // 本地 Caffeine 引用
// 接收到 Pub/Sub 广播事件后执行的清理方法
public void receiveMessage(String message) {
log.info("收到 Pub/Sub 广播消息，擦除本地 L1 缓存 Key: {}", message);
caffeineCache.invalidate(message); // 清除本地 JVM 缓存
}
}
// 2. Spring 容器注入监听点绑定
// (RedisPubSubConfig.java 内部 Bean 定义)
@Bean
RedisMessageListenerContainer container(RedisConnectionFactory factory, MessageListenerAdapter adapter) {
RedisMessageListenerContainer container = new RedisMessageListenerContainer();
container.setConnectionFactory(factory);
container.addMessageListener(adapter, new ChannelTopic("cache:invalidate"));
return container;
}
特点：完全解耦，`MessageListenerAdapter` 自动将字节消息转为 Java 方法调用

2. 消息发布 Controller 与端到端广播链路

Publisher Controller
// MsgController.java 消息推送端点
@RestController
@RequestMapping("/api/msg")
public class MsgController {
@Autowired private StringRedisTemplate redisTemplate;
// 暴露 HTTP REST API 触发消息广播
@PostMapping("/publish")
public String publishInvalidateEvent(@RequestParam String cacheKey) {
// 发布到频道 "cache:invalidate"
redisTemplate.convertAndSend("cache:invalidate", cacheKey);
return "Broadcasting invalidate event for key: " + cacheKey;
}
}
端到端广播执行四步管线 (Pub/Sub Lifecycle) End-to-End Pipeline
1. HTTP POST 请求发起 $\to$ `MsgController.publishInvalidateEvent("user:1001")`
2. Redis Template 物理调用 $\to$ `convertAndSend("cache:invalidate", "user:1001")`
3. Redis Server 物理广播 $\to$ 发送至所有订阅了 `"cache:invalidate"` 的 JVM 节点
4. Thread Exec 异步线程响应 $\to$ 触发 `caffeineCache.invalidate("user:1001")`
开启下一个核心：Slide 38 · Spring Boot + Caffeine + Redis 双级缓存综合整合实战

核心架构启发 (Pub/Sub Messaging Insight)

借助 **`StringRedisTemplate.convertAndSend()`** 与 **`RedisMessageListenerContainer`**，只需几行代码即可在分布式集群中构建高性能内存消息管道。在多节点部署时，该模式能以纳秒级延迟同步清空所有节点的 L1 本地缓存，完美解决数据一致性隐患。
