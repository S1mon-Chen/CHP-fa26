LLM-as-a-Judge 架构：编写可确定性评分的 Reviewer Evaluator Prompt

用强对齐模型打造无偏见的代码质量裁判：构建基于 LLM-as-a-Judge 裁判评估架构，编写包含 三维 Scoring Rubric (正确性、OWASP 安全性、架构规范) 与 硬性 JSON Schema 裁决输出 (`APPROVED` / `REJECTED`) 的 Evaluator Prompt 模板

1. LLM 裁判架构设计原则与 Scoring Rubric

LLM-as-a-Judge Design & Scoring Rubric Specs

Judge Specs
3D Rubric
三维物理评分细则 (Scoring Rubric)： 结合 Correctness (功能逻辑修正 1-5)、Security (OWASP Top 10 漏洞 1-5) 与 Style (PEP8/Clean Code 1-5) 进行综合量化。
Anti-Bias
锚定物理证据与扣分理由 (Anti-Bias)： 要求裁判必须基于输入的 Issue 描述、Patch 代码与单测报错日志出具引用行号，消杀盲目打高分偏置。
JSON Gate
强类型 JSON 结果导出 (`verdict`)： 强制输出标准 JSON 格式，明确标记 `verdict: "APPROVED"` 或 `"REJECTED"`，以便直接接入 CI/CD 卡扣。
物理本质：把前沿对齐大模型转化为标准化、程序化可判决的代码审查中间件
