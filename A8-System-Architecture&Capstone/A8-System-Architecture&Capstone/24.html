1. HumanEval 与 SWE-bench 评估基准对比与工程设计

HumanEval vs. SWE-bench & SWE-bench Lite Specs

Benchmark Specs
HumanEval
HumanEval（离散单函数补全）： 关注 Docstring 到函数的纯生成能力；但无法衡量跨文件依赖、真实 GitHub 漏洞修复与项目复杂重构。
SWE-bench
SWE-bench / Lite（真实仓库修复基准）： 基于开源 GitHub Issue 与真实代码库，要求 Agent 自主搜索、修改 Patch 并跑通项目原本的完整单元测试。
F2P & P2P
Fail-to-Pass 与 Pass-to-Pass 物理断言： 校验生成的 Patch 必须让原本失败的测试集变绿（F2P），同时确保原本通过的测试集不受任何退化破坏（P2P）。
物理本质：把非确定性的代码生成转化为可自动化验证、可无偏估计的工业级运行断言

# 生产级 SWE-bench 风格 Agent 自动化评估 Harness
from e2b_code_interpreter import Sandbox
import math

def evaluate_swe_bench_task(repo_dir: str, patch_code: str, test_spec: dict) -> dict:
with Sandbox() as sbx:
# 1. 挂载真实仓库基线与 Patch 补丁
sbx.files.write(f"{repo_dir}/patch.diff", patch_code)
sbx.commands.run(f"cd {repo_dir} && git apply patch.diff")
# 2. 校验 F2P (原本失败现需成功) 与 P2P (原先成功不破坏) 测试集
f2p_res = sbx.commands.run(f"cd {repo_dir} && pytest {test_spec['f2p_tests']}")
p2p_res = sbx.commands.run(f"cd {repo_dir} && pytest {test_spec['p2p_tests']}")
passed = (f2p_res.exit_code == 0) and (p2p_res.exit_code == 0)
return {"task_id": test_spec["task_id"], "passed": passed}

def calculate_pass_at_k(n: int, c: int, k: int) -> float:
# 3. 组合数算无偏 Pass@k 概率 (避免采样盲目求均值偏置)
if
n - c < k: return 1.0
return 1.0 - (math.comb(n - c, k) / math.comb(n, k))
  • 真实回归测试：通过 F2P 与 P2P 双向断言，防止 Agent 修复了 Bug A 却搞砸了 5 个已有功能。
  • 组合数无偏估计：使用数学公式精确推算 $Pass@1$ 与 $Pass@5$，为 CI/CD 提供确定性得分。
物理本质：建立在真实软件仓库测试集基础上的无偏估计评估套件
