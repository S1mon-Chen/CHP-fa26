把大模型生成的补丁精准且安全地应用到物理代码库：手写 Unified Diff 解析与应用引擎，从模型输出中提取 `` 节点，对 Hunks 块做模糊匹配应用，并在写盘前利用 AST 静态语法断言 拦截坏代码

1. Unified Diff 补丁解析与写前 AST 校验规约

Unified Diff Hunks & AST Pre-Apply Validation

Diff Specs
Hunk Parsing
Hunks 补丁块精准拆解： 解析 `@@ -l,s +l,s @@` 块头，识别增加行 (`+`) 与删除行 (`-`)，支持偏移容错模糊行匹配。
AST Pre-check
内存写前 AST 语法预检 (Syntax Assert)： 补丁在内存中合成完毕后，先调用 `ast.parse()` 进行语法检查，若产生 `SyntaxError` 直接抛错拒绝写盘。
Atomic Patch
多文件原子事务应用 (Atomic Transaction)： 多文件补丁采用全成功或全回滚（All-or-Nothing）策略，任一文件语法不通或 Hunk 冲突即原位取消。
物理本质：用标准 Unix Patch 逻辑替代大模型盲目输出全文件覆写导致的乱丢代码事故

def apply_unified_diff_with_ast_check(repo_dir: str, llm_response: str) -> bool:
# 1. 正则精准提取 标签内部的 Patch 文本
match = re.search(r"<unified_diff>(.*?)</unified_diff>", llm_response, re.DOTALL)
if not

diff_text = match.group(1).strip()

# 2. 内存预试组装补丁，并执行 AST 语法前置断言预检
