1. Devin / Claude Code 风格 Prompt 设计四要素

System Prompt Structural Engineering Principles

Prompt Specs
<role>
角色与物理环境声明： 定义全自治 Senior Software Engineer 身份及其具备的沙箱操作权限与目标。
<constraints>
物理安全红线（System Constraints）： 强行限定只能通过 Unified Diff 修改代码、只读根目录限制与网络访问锁。
<workflow>
递进式工作流规约： 约束从 Issue 分析 $\to$ AST 影响定位 $\to$ Patch 生成 $\to$ 沙箱单测 $\to$ 成果输出的推演链条。
<contracts>
强类型 XML 输出契约： 要求必须将思维链放在 `` 中，物理 Patch 放在 `` 中，确保解析器 100% 确定性提取。
物理本质：用结构化 XML 标签为大模型的非确定性推演建立不可违背的“宪法级契约”

2. Devin / Claude Code 风格 System Prompt 模板

Production System Prompt Template with XML Tags

Prompt Template
<system_prompt>
<role>
You are Devin, an autonomous Senior Coding Agent in a sandboxed repo.
</role>

<system_constraints>
1. All code modifications MUST be emitted as valid <unified_diff> format.
2. MUST execute unit tests via `run_pytest` before declaring success.
3. If test fails, read <traceback>, regenerate diff, and retry. Max retries: 3.
4. DO NOT modify files outside repository root.
</system_constraints>

<workflow>
Step 1: Parse issue & locate symbols via <ast_skeleton>.
Step 2: Formulate fix plan inside <thought> tags.
Step 3: Emit patch inside <unified_diff> tags.
Step 4: Execute sandbox unit tests & verify Pass@1.
</workflow>
</system_prompt>
  • 消除闲聊污染：模型被迫将所有思维链与代码重构产物收敛在规范的 XML 节点中。
  • 原生编码自愈（Self-Correction Loop）：在 Prompt 中直接编码了“测试失败 $\to$ 抓 Traceback $\to$ 重修”的自动兜底。
物理本质：把 Devin 与 Claude Code 的工业实践提炼为标准化 XML System Prompt
