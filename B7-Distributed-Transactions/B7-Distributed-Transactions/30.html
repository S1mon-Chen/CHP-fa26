Apache Seata 架构：TC、TM 与 RM 三大核心组件 (Seata Architecture)

Transaction Coordinator (TC), Transaction Manager (TM), Resource Manager (RM) & Global XID Lifecycle

Apache Seata 三大核心组件角色交互与全局 XID 驱动拓扑 (Seata Core Architecture Topology) Industrial Standard Distributed Transaction Solution (High Performance & Low Invasiveness)
TM (Transaction Manager) Initiator
• 角色定位：全局事务发起者（微服务入口）
• 核心动作：调用 TC 开启全局事务 (`begin`)
• 终态裁决：发起全局提交 (`commit`) 或全局回滚 (`rollback`)
1. Begin(XID) 4. End(XID)
TC (Transaction Coordinator) Server Cluster
• 角色定位：独立部署的中央事务协调器集群
• 全局视角：分配全局 XID，维护全局与分支事务状态
★ 驱动两阶段：向各地 RM 下发分支 Commit 或 Rollback
2. Reg Branch 3. Report
RM (Resource Manager) Branch Worker
• 角色定位：各分支微服务中的资源管理者
• 注册与汇报：向 TC 注册分支事务并汇报 local 执行结果
• 驱动二阶段：响应 TC 命令执行分支提交或反向 Undo 清理

1. 全局 XID 穿透传播与分支事务生命周期 (XID Lifecycle)

XID Propagation
步骤 1：TM 向 TC 开启全局事务，获取唯一 XID

注解 @GlobalTransactional 被切面拦截，TM 拦截器向 TC 申请全局唯一的 XID 标识符。

步骤 2：微服务 RPC 链路将 XID 隐式穿透透传

Seata 自动拦截 Feign / Dubbo / RestTemplate 调用，在 RPC Header 中透传 TX_XID，将下游 RM 绑定入同一个全局事务。

步骤 3：下游 RM 向 TC 注册分支，汇报本地执行状态

下游 RM 识别到 XID 后，向 TC 注册分支事务，执行本地 DB SQL 并提交本地事务，同时向 TC 汇报 SUCCESS。

本质：借用 RPC Header 隐式透传 XID，实现跨物理微服务的分布式管线绑定

2. Seata 提供的四大分布式事务模式概览 (Seata 4 Modes)

4 Transaction Modes
★ AT 模式 (无侵入/零代码修改/主推)

基于关系型数据库 SQL 镜像解析，自动生成 Undo Log。本地事务在一阶段直接提交，二阶段异步清理日志。

TCC 模式 (应用层预留)

显式手写 Try / Confirm / Cancel 三个接口，适合非关系型数据库（如 Redis、NoSQL）或极高并发资金扣减。

Saga 模式 (状态机长事务) & XA 模式 (强一致)

Saga 适合跨第三方系统的长流程编排；XA 模式适合金融级对底层数据库强一致有硬性要求的场景。

Part 05 开篇核心哲学 (Seata Architecture Insight)

Apache Seata 是工业界事实上的分布式事务标准中间件。它通过巧妙解耦 **TC (协调器)、TM (事务发起者) 与 RM (资源管理者)** 三大角色，用全局 XID 贯穿微服务调用链，为企业级分布式事务治理提供了强有力的底座支持。
