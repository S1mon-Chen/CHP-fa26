1. AT 模式写隔离机制 (Write Isolation Protocol)

Write Isolation
全局锁的物理定义与生命周期

全局锁（Global Lock）由 TC 中央内存统一维护。它在 **一阶段本地 DB 事务提交前** 向 TC 申请注册；在 **二阶段全局 Commit 或 Rollback 完成后** 由 TC 异步注销释放。

防脏写重试与回滚控制 (Retry & Rollback)

如果并发事务无法抢到全局锁，它会在配置的时间内（默认 lockRetryInterval = 10ms，lockRetryTimes = 30）重试。超时后本地事务被强行回滚，同时释放已持有的本地 DB 锁，彻底杜绝死锁。

本质：用内存极轻量的 TC 全局锁，替换跨网络持有底层 DB 排他行锁

2. AT 模式读隔离与 `@GlobalLock` 强一致读

Read Isolation
默认读隔离级别：Read Uncommitted (读未提交)

由于一阶段本地 DB 事务已经提交，修改在二阶段提交前对外部直接 SQL 已经可见。因此 AT 模式默认的读隔离级别是读未提交。

实现强一致读 (Read Committed)：`SELECT ... FOR UPDATE` & `@GlobalLock`

若普通查询方法需要读到绝对一致的数据（确保当前行没有正在被其他全局事务修改或准备回滚）：
• 方法 A：在代理数据源下执行 SELECT ... FOR UPDATE，Seata 会自动校验全局锁。
• 方法 B：非全局事务方法上标注注解 @GlobalLock，跳过分支注册，仅校验全局锁状态！

开启下一个核心：Slide 34 · Seata TCC 模式原理与 Try/Confirm/Cancel 手动控制

核心架构启发 (Global Lock Philosophy)

Seata AT 模式之所以能兼顾高吞吐与写安全，关键就在于用内存极轻量的 **TC 全局锁** 替代了底层数据库锁。通过全局锁进行并发控制，既保证了一阶段提交归还连接池，又彻底堵住了脏写风险。
