Part 04 · 微服务最终一致性模式：TCC、Saga 与消息事务

全链路电商分布式事务架构模式选型 (End-to-End E-Commerce Transaction Selection)

Hybrid Architecture: Combining Seata AT, TCC, Saga & Transactional MQ in a Unified Order Placement Flow

典型电商下单全链路混合分布式事务架构拓扑 (Hybrid E-Commerce Order Architecture) Context-Aware Pattern Allocation per Sub-Service Boundary
1. 扣减库存 (Stock) Seata AT
• 子服务：`Stock-Service`
• 特点：高并发、强实时更新要求
★ 选型：Seata AT 模式（低代码侵入，SQL 镜像自动回滚）
2. 扣减余额 (Account) TCC Mode
• 子服务：`Account-Service`
• 特点：金融级敏感资金交易
★ 选型：TCC 模式（`frozen_balance` 预留资金防超扣）
3. 赠送积分 (Member) Transactional MQ
• 子服务：`Member-Service`
• 特点：非实时关键路径，容忍延迟
★ 选型：MQ 事务消息（异步解耦，秒级最终一致）
4. 仓储发货 (Logistics) Saga Mode
• 子服务：第三方 ERP / WMS 仓储系统
• 特点：跨机构 API，无法改动代码
★ 选型：Saga 模式（状态机正向指令与逆向撤销）

1. 订单主入口混合事务编排 (`OrderServiceImpl`)

Hybrid Master
// 主下单入口使用 @GlobalTransactional + MQ 混合驱动
@Service
public class OrderServiceImpl {
@GlobalTransactional(name = "create-order", rollbackFor = Exception.class)
public void submitOrder(OrderRequest req) {
// ① 扣库存 (Seata AT 模式)
stockFeignClient.deduct(req.getSkuId(), req.getCount());
// ② 扣余额 (TCC 模式 - Try 阶段)
accountTccAction.prepare(req.getUserId(), req.getAmount());
// ③ 发送积分赠送事务消息 (RocketMQ)
rocketMQTemplate.sendMessageInTransaction("points-topic", msg);
}
}
本质：按子系统敏感度、响应延迟与系统边界进行针对性差异选型

2. 企业级分布式事务四大选型准则 (Decision Criteria)

Selection Rules
准则 1：非核心主干路径，优先采用 MQ 事务消息

对延迟不敏感的旁路逻辑（发积分、送优惠券、日志审计），**一律使用异步消息**，彻底切断物理调用链。

准则 2：核心自研 RDBMS 服务，首选 Seata AT 模式

对于自身维护的关系型数据库，**Seata AT 模式提供零代码侵入**，性价比最高。

准则 3：资金与超卖敏感业务，采用 TCC 预留资源

涉及现金划转或高并发抢购，采用 **TCC 显式冻结资源**，防止高并发脏写与超卖事故。

Part 04 总结 (Microservice Transaction Governance Insight)

真实的微服务架构**绝不存在“一种模式打天下”的万能方案**。优秀的服务端架构师应当像排兵布阵一样：在主干链路上用 **TCC/AT** 保障实时数据安全，在旁路上用 **MQ 事务消息** 实现高性能异步解耦，在外部接口上用 **Saga** 完成退避补偿。
