Part 05 · 企业级分布式事务框架：Apache Seata 深度实战

Seata Saga 模式：基于 JSON 状态机的可视化长事务编排 (Seata Saga Mode)

JSON State Machine Engine, `ServiceTask`, `CompensateState`, Forward Recovery vs. Backward Compensation

Seata Saga 状态机引擎调度与故障恢复路线 (Seata Saga State Engine Workflow) Event-Driven Asynchronous Long Living Transaction (LLT) Engine
步骤 1：JSON 状态机画图与建模 JSON Designer
• 使用 Seata Visual Designer 拖拽或手写 JSON 状态机
• 绑定每个 ServiceTask 的正向 API 与 CompensateState 补偿 API
• 支持条件分支判断与并发并行分支节点
步骤 2：引擎驱动正向节点 ($T_1 \to T_2 \to T_3$) Forward Execution
• Seata 状态机引擎 (statemanager) 异步驱动节点
• 每个节点执行本地 DB 事务并立刻提交，释放底盘锁
• 自动保存节点入参出参状态至 Seata 存储库
步骤 3：异常判定与恢复策略触发 Recovery Mode
• 向前恢复 (Forward Recovery)：重试正向节点直至成功
• 向后恢复 (Backward Recovery)：触发逆向补偿链 ($C_2 \to C_1$)
• 确保跨服务的长活事务（LLT）最终数据对齐

1. Seata Saga 状态机 JSON 描述文件范例 (`order_saga.json`)

JSON Schema
// Seata Saga 状态机节点映射定义
{
"Name": "CreateOrderSaga", "StartAt": "ReduceStock",
"States": {
"ReduceStock": {
"Type": "ServiceTask",
"ServiceName": "stockService", "ServiceMethod": "reduceStock",
"CompensateState": "CompensateStock", "Next": "ReduceBalance"
},
"CompensateStock": {
"Type": "ServiceTask",
"ServiceName": "stockService", "ServiceMethod": "addStock"
}, ...
}
}
本质：将分布式复杂控制解耦为纯文本 JSON 状态图，实现业务可视化监控

2. 相比 AT 与 TCC 模式，何时必须选型 Seata Saga？

When to use Saga
1. 业务包含极长的长活事务 (Long Living Transactions)

例如“订机票 $\to$ 订酒店 $\to$ 租车 $\to$ 支付”长流程，中间可能耗时数秒甚至数小时，使用锁会卡死系统。**Saga 正向提交释放锁，性能极高**。

2. 改造遗留旧系统 (Legacy Systems) 或第三方外包 API

调用的下游是遗留系统或外部第三方机构 API，**无法修改其代码增加 TCC 接口或添加 `undo_log` 表**，只能提供“提交 API”与“撤销 API”。

3. 复杂分支逻辑与并行执行需求

需要根据正向节点的返回结果进行 Choice 条件分支跳转，或同时并发并行调用多个独立子服务。

开启下一个核心：Slide 36 · Seata XA 模式：整合原生 DB 规范的强一致分布式事务

核心架构启发 (Seata Saga Engine Insight)

Seata Saga 模式将分布式的复杂控制逻辑从微服务业务代码中解耦出来。通过 JSON 状态机，开发者可以**像画流程图一样编排分布式长事务**，不仅提供了高吞吐的事件驱动性能，更赋予了跨遗留系统的完美兼容性。
