Spring 事务隔离级别与底层数据库映射 (Isolation Level Mapping)

Spring Isolation Enum, JDBC Connection Setting, DB Default Mappings & Concurrency Anomalies Prevention

Spring 隔离级别枚举与底层数据库映射矩阵 (Isolation Level Mapping Matrix) JDBC Connection Isolation & Concurrency Anomalies
Spring 隔离级别枚举 (`Isolation`) 底层数据库设置与映射 (JDBC Level) 解决的并发异常 (Prevented) 典型数据库默认配置 (DB Defaults)
DEFAULT (默认) 遵循底层 Connection 默认隔离级别 取决于底层数据库配置 MySQL = RR; Oracle/Postgres/SQL Server = RC
READ_UNCOMMITTED TRANSACTION_READ_UNCOMMITTED 仅防脏写（允许脏读、不可重复读、幻读） 极少生产使用（极度不安全）
READ_COMMITTED TRANSACTION_READ_COMMITTED 防止脏读 (Dirty Read) Oracle, PostgreSQL, SQL Server 默认
REPEATABLE_READ TRANSACTION_REPEATABLE_READ 防止脏读 + 不可重复读 (Non-Repeatable Read) MySQL InnoDB 默认（MVCC+Next-Key 防幻读）
SERIALIZABLE TRANSACTION_SERIALIZABLE 防止脏读 + 不可重复读 + 幻读 (Phantom) 最高安全级别（串行读写锁，高并发吞吐低）

1. Spring 声明式配置与底层 JDBC 接口设置

Spring vs JDBC
// 1. Spring 声明式隔离级别标注
@Transactional(isolation = Isolation.READ_COMMITTED)
public void queryFinancialReport() {
accountDao.getReport();
}
// 2. Spring 底层通过 JDBC API 映射设置数据库 Connection
Connection con = dataSource.getConnection();
con.setTransactionIsolation(Connection.TRANSACTION_READ_COMMITTED);
本质：Spring `@Transactional` 隔离属性最终下发为 JDBC `Connection` 设置

2. 主流数据库默认隔离级别与并发权衡

DB Defaults
MySQL InnoDB（默认 REPEATABLE_READ）

配合 **MVCC 快照读** 与 **Next-Key Lock（临键锁）当前读**，在 RR 级别下已经解决了绝大多数幻读问题，兼顾高并发与一致性。

Oracle / PostgreSQL / SQL Server（默认 READ_COMMITTED）

行业绝大多数数据库默认选型 **RC 级别**，避免过重的区间间隙锁，依靠 MVCC 实现读写解耦，大幅提升多线程并发吞吐。

开启下一个核心：Slide 10 · 长事务并发离线锁：乐观离线锁 vs. 悲观离线锁 (PoEAA)

核心架构启发 (Isolation Level Insight)

理解 Spring 事务隔离级别的核心是意识到 **“Spring 本身不提供隔离实现，而是通过 JDBC API 将配置透传给底层数据库 `Connection`”**。在生产选型中，若使用 MySQL InnoDB，默认 DEFAULT (REPEATABLE_READ) 已能提供极佳的隔离保护；若在 Oracle 或 PostgreSQL 下，通常配合 READ_COMMITTED。

Speaker Notes / 讲师讲稿
🎯 引导学员理解 Spring 隔离级别透传本质： “向学员做解构说明：很多同学误以为 Spring 框架内部自己实现了一套数据库锁或 MVCC。实际上，Spring 的 `@Transactional(isolation = ...)` 只是将参数通过 JDBC API 映射下发给数据库连接：`connection.setTransactionIsolation(...)`。隔离性是由底层数据库引擎保障的。”
💡 强调不同数据库默认隔离级别的区别： “请提醒学员特别注意：MySQL InnoDB 默认的隔离级别是 `REPEATABLE_READ`，并且它通过 MVCC 快照读和 Next-Key Lock 当前读，解决掉了绝大部分幻读；而 Oracle、PostgreSQL、SQL Server 的默认隔离级别是 `READ_COMMITTED`。”
