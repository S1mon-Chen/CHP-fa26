Seata AT 模式原理：无侵入两阶段提交与 Undo Log 机制 (Seata AT Mode)

Automatic SQL Parsing, Before/After Image Logging, `undo_log` Table DDL & Two-Phase Execution

Seata AT 模式两阶段自动镜像生成与回滚流程 (AT Mode Execution Pipeline) Zero Code Invasion: Automatic Before/After Image Generation
一阶段：业务 SQL 执行与镜像落盘 (Phase 1) Phase 1
① 解析 SQL：Seata 代理数据源拦截并解析业务 SQL 语义。
② 查前镜像 (Before Image)：查询待更新记录行快照。
③ 执行业务 SQL：执行更新逻辑（如 `balance = balance - 100`）。
④ 查后镜像 (After Image)：查询更新后的记录行快照。
⑤ 写入 Undo Log & 提交：镜像写入本地 `undo_log` 表，申请全局锁并提交本地 DB 事务。
二阶段：全局提交或脏写校验回滚 (Phase 2) Phase 2
全局 Commit (全成功)

TC 下发 Commit，异步并行清理 `undo_log` 表记录与全局锁，速度极快！

全局 Rollback (任一失败)

读取 Undo Log 的 Before Image，进行脏写校验（Current == After Image）；校验通过后重置为 Before Image 完成回滚。

1. Seata 专属撤销日志表 DDL 结构 (`undo_log`)

Undo Table DDL
// 每个业务分支数据库必须建此 undo_log 表
CREATE TABLE undo_log (
id BIGINT AUTO_INCREMENT PRIMARY KEY,
branch_id BIGINT NOT NULL,
xid VARCHAR(128) NOT NULL,
rollback_info LONGBLOB NOT NULL, -- JSON 前/后镜像快照
log_status INT NOT NULL,
log_created DATETIME NOT NULL,
log_modified DATETIME NOT NULL,
UNIQUE KEY ux_undo_log (xid, branch_id)
);
镜像序列化 (Image Payload)

rollback_info 中以 Jackson/Kryo 序列化形式储存了更新前数据记录（Before Image）与更新后数据记录（After Image）的全部字段值。

本质：用本地事务原子写镜像表，替代物理 XA 锁对连接池的死锁挂起

2. 脏写校验算法与反向补偿还原 (Dirty Write Check)

Rollback Algorithm
校验通过：Current Data == After Image

说明一阶段提交后，没有任何外部非法修改（非 Seata 管理的 SQL）改动过该行。使用 **Before Image 执行反向更新**，完成无缝还原。

校验失败：Current Data != After Image (脏写发生)

说明一阶段后该行数据被外部直接 SQL 越过 Seata 强行改动！Seata 无法直接用 Before Image 覆盖，会**抛出脏写异常报警并转人工干预**。

开启下一个核心：Slide 32 · Seata 全局锁 (Global Lock) 机制与隔离级别保障

核心架构启发 (Seata AT Mode Insight)

Seata AT 模式之所以能够成为工业界的主流选型，原因在于其**零代码修改的“无侵入性”**与**一阶段直接提交本地 DB 事务释放锁**的物理吞吐优势。它巧妙利用 SQL 前/后镜像表，将复杂的两阶段提交收拢至数据源代理层。
