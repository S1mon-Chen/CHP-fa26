Seata AT 模式回滚链路与脏写校验机制 (AT Mode Rollback Pipeline)

Phase 1 Execution, Undo Log Replay, Dirty Write Detection (`Current == After Image`) & Human Escalation

Seata AT 模式二阶段反向补偿与脏写防御演进流程 (AT Rollback Pipeline) Reversing SQL Execution with Before Image Snapshot
步骤 1：解析撤销日志 Fetch Undo
• TC 下发全局回滚指令与分支 XID
• RM 读取本地 undo_log 记录
• 反序列化反解析出 Before / After Image
步骤 2：查库校验脏写 Dirty Check
• 开启本地 DB 临时事务
• SELECT ... FOR UPDATE 查当前行
• 比对 Current Data 与 After Image
步骤 3：数据匹配判定 Validation
• 通过：Current == After Image
• 失败：Current != After Image
• 未通过说明一阶段提交后发生越权脏写
步骤 4：反向补偿还原 Restore
• 用 Before Image 生成反向还原 SQL
• 提交本地还原事务，删除 undo_log
• 向 TC 汇报分支回滚成功

1. 二阶段反向补偿 SQL 自动生成与物理提交细节

SQL Generation
一阶段正向修改示例

UPDATE account SET balance = balance - 20 WHERE id = 1;

镜像数据快照 (In `undo_log` JSON Payload)

Before Image: { id: 1, balance: 100 }
After Image: { id: 1, balance: 80 }

二阶段自动生成的反向更新 SQL

UPDATE account SET balance = 100 WHERE id = 1 AND balance = 80;

本质：反向 SQL 附加 `WHERE balance = 80` 条件做 CAS 级别的原子防护

2. 脏写发生时的升轨防御与人工干预 (Dirty Write Escalation)

Escalation Flow
脏写产生原因 (Root Cause)

在一阶段本地 DB 事务提交后、二阶段回滚前，有**非 Seata 管理的底层 SQL** 直接越过代理数据源强行修改了这行数据（如 DBA 手动执行了 UPDATE 脚本）。

升轨处置机制 (Escalation Protocol)

Seata **拒绝直接盲目覆写 Before Image**（否则会覆盖非 Seata 的有效修改）。RM 抛出不可重试异常 BranchRollbackFailed_Unretriable，在控制台弹出严重告警并**通知管理员进行人工对账修复**。

开启下一个核心：Slide 33 · Seata AT 模式全局锁 (Global Lock) 机制与隔离级别保障

核心架构启发 (AT Rollback Mechanics Insight)

Seata AT 模式的二阶段回滚不是盲目的覆写，而是**带有并发 CAS 校验的智能补偿**。通过比对 `Current Data == After Image`，Seata 能够精准识别越权物理脏写并及时告警升轨，确保分布式环境下的数据安全。
