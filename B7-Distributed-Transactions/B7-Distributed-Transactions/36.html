Part 05 · 企业级分布式事务框架：Apache Seata 深度实战

Seata XA 模式：整合原生 DB 规范的强一致分布式事务 (Seata XA Mode)

`DataSourceProxyXA`, Native Database XA Protocol, Strong Consistency & Phase 1/Phase 2 Execution

Seata XA 模式两阶段原生数据库指令管线 (Seata XA Protocol Pipeline) Database-Native XA Driver Integration via DataSourceProxyXA
一阶段：业务 SQL 执行与 XA PREPARE (Phase 1) XA PREPARE
① **注册分支**：`DataSourceProxyXA` 拦截 JDBC 连接，向 TC 注册分支。
② **开启 XA 事务**：代理驱动向底层数据库下发 XA START 'xid'。
③ **执行业务 SQL**：执行 SQL（如 `UPDATE`），锁定物理行资源。
④ **预提交**：下发 XA END 'xid' 并执行 XA PREPARE 'xid'。
⑤ **汇报状态**：向 TC 汇报 `Prepared` 成功（物理数据库排他锁持续保持！）。
二阶段：全局裁决与 XA COMMIT / ROLLBACK (Phase 2) XA COMMIT
全局 Commit (全成功)

TC 向各 RM 下发指令，RM 向数据库执行 XA COMMIT 'xid'，完成物理提交并释放 DB 排他行锁。

全局 Rollback (任一失败)

TC 下发回滚，RM 执行 XA ROLLBACK 'xid'，由数据库底层 Undo 日志直接物理撤销并释放行锁。

1. Seata XA 数据源代理配置 (`DataSourceProxyXA`)

Spring Config
// 1. 在 Spring 中开启 DataSourceProxyXA
@Configuration
public class DataSourceConfig {
@Bean
public DataSource dataSource(DruidDataSource druidDataSource) {
// 使用 DataSourceProxyXA 包装物理数据源
return new DataSourceProxyXA(druidDataSource);
}
}
核心优势 (Zero Undo Log Table)

业务分支数据库**完全不需要建 `undo_log` 表**！Seata 依托底层 MySQL/Oracle/PostgreSQL 驱动原生的 XA 规范，由数据库内核直接保障数据原子性。

本质：无代码侵入，纯依靠底层关系型数据库引擎提供物理强一致保证

2. Seata XA 模式 vs. Seata AT 模式硬核对比

XA vs AT
对比维度 Seata XA 模式 Seata AT 模式
数据一致性 物理强一致性 (Strong) 柔性最终一致性 (BASE)
物理锁持有时长 长 (从 1 阶段挂起到 2 阶段) 短 (1 阶段直接提交本地 DB)
脏写防御手段 数据库底层原生 XA 锁挂起 TC 内存全局锁 + `undo_log` CAS 校验
数据库要求 必须支持 XA 驱动 (MySQL/Oracle) 普通关系型 DB 并建 `undo_log` 表

核心架构启发 (Seata XA Mode Insight)

Seata XA 模式将复杂的两阶段管线完全委托给数据库内核。对于**金融核心等对数据准确性有严格硬性要求，且希望零代码侵入、零表结构修改**的场景，Seata XA 模式提供了最优雅的强一致性安全保障。
