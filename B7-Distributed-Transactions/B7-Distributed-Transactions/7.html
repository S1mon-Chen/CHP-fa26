Spring 事务回滚规则与 Exception 踩坑指南 (Rollback Rules)

Default Rollback Policy, `RuntimeException` vs `Checked Exception`, `rollbackFor = Exception.class` & Try-Catch Traps

Spring 异常捕获与回滚决策树 (Spring Exception Rollback Decision Spectrum) Default Policy: Rollback on RuntimeException & Error ONLY
Unchecked Exception Auto Rollback
• RuntimeException及其子类
如 NullPointerException, ArithmeticException (10/0)

✓ Spring 拦截器捕获后自动触发 setRollbackOnly() 物理回滚。

Checked Exception NO Rollback!
• Checked Exception (受检异常)
如 IOException, SQLException, Exception

❌ 默认策略下 Spring 判定为业务预预期异常，不触发回滚而直接物理提交！

Production Standard rollbackFor
• 生产防线显式配置
@Transactional(rollbackFor = Exception.class)

★ 覆盖所有 Exception 子类，彻底防止数据静默损坏。

1. 受检异常 Checked Exception 物理踩坑与修正

Checked Exception
// ❌ 踩坑示范：IOException 是 Checked Exception，默认不回滚！
@Transactional
public void processOrder() throws IOException {
orderDao.insert(order); // 写库成功
throw new IOException("Network Timeout"); // 抛出受检异常
} // 结果：Spring 不回滚，导致数据库脏写入！
// ✅ 生产标准方案：显示指定 rollbackFor = Exception.class
@Transactional(rollbackFor = Exception.class)
public void processOrderCorrect() throws Exception {
orderDao.insert(order);
throw new Exception("Custom Error");
} // 结果：正确触发事务全局回滚！
法则：无思考地使用裸 `@Transactional` 是绝大多数生产数据不一致的源头

2. try-catch 吞掉异常陷阱与手动触发回滚

Try-Catch Trap
内部 try-catch 吞掉异常后果

若方法内部用 try-catch 捕获了异常且未将其向上重新抛出，AOP 切面代理无法感知到异常，事务会正常提交！

// 方案：如必须在内层 try-catch，需手动标记 setRollbackOnly()
@Transactional
public void updateWithCatch() {
try {
accountDao.update();
} catch (Exception e) {
TransactionAspectSupport.currentTransactionStatus().setRollbackOnly();
}
}
开启下一个核心：Slide 8 · 生产环境八大 `@Transactional` 事务失效陷阱

核心架构启发 (Rollback Policy Insight)

理解 Spring 回滚规则的核心是记住 **“AOP 拦截器是通过捕获未被吞掉的异常来决定 `commit` 还是 `rollback`”** 的。要防止 Checked Exception 静默提交破坏数据，必须显式加上 rollbackFor = Exception.class；而要在 `try-catch` 中吞掉异常又想回滚，必须调用 setRollbackOnly()。

🎯 引导学员透视 Spring 默认回滚规则陷阱： “向学员做解构说明：许多同学以为标注了 `@Transactional`，方法抛出任何异常都会自动回滚。这是一个非常危险的误区！Spring 默认只对 `RuntimeException`（非受检异常）和 `Error` 回滚。对于受检异常（如 `IOException`），Spring 会直接提交事务！”
💡 强调 `rollbackFor` 与 `try-catch` 解决方案： “请学员特别关注生产标准：1. 一律加上 `rollbackFor = Exception.class` 显式覆盖受检异常；2. 若在业务方法内部捕获了异常（try-catch），切记调用 `TransactionAspectSupport.currentTransactionStatus().setRollbackOnly()` 手动置回滚标记。”
