幂等不变式法则
$$f(f(X)) = f(X)$$

重复调用 1 次与执行 $N$ 次对系统底层状态产生的物理结果完全一致。

1. 去重表 DDL 约束与状态机更新物理实现

SQL Level Protection
// 防重表 DDL 结构 (local_dedup_log)
CREATE TABLE local_dedup_log (
biz_uniq_id VARCHAR(128) PRIMARY KEY, -- 业务全局唯一 ID (如 ORDER_1001)
create_time DATETIME NOT NULL
);
// 状态机条件更新 SQL (有限状态自动机跃迁)
UPDATE order_info
SET status = 'PAID', update_time = NOW()
WHERE order_id = 'ORD_1001' AND status = 'UNPAID';
// 若返回影响行数 (Rows Affected) == 0，说明已处理过，自动拦截返回成功！
本质：借用关系型数据库单机主键唯一性约束与原子更新保障幂等

2. Redis 令牌与分布式并发防锁 (Redis Token & Lock)

Distributed Protection
// 消费端通用防重幂等处理框架
public void processMessage(OrderPaidEvent event) {
// ① 先查持久化 Token 标记，若已处理则直抛幂等成功
if (redis.hasKey("PROCESSED:" + event.getOrderId())) return;
// ② 抢占短时分布式并发锁 (SETNX key token EX 300)
boolean locked = redis.setIfAbsent("LOCK:" + event.getOrderId(), token, 300);
if (!locked) throw new ConcurrentProcessingException();
// ③ 执行业务扣减 + 写入完成标记
try { ... redis.set("PROCESSED:" + event.getOrderId(), "1"); }
finally { redis.delete("LOCK:" + event.getOrderId()); }
}
高并发性能提示

使用 Redis 短时并发锁过滤高频重复并发，配合 DB 主键唯一性做兜底，兼顾了微服务毫秒级吞吐量与 100% 数据精确性！
