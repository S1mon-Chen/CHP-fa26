MQ 事务消息机制与最大努力通知模式 (Transactional Messages & Notification)

Apache RocketMQ Two-Phase Half Messages, Transaction Checkback Listener & Best-Effort Notification

Apache RocketMQ 事务消息两阶段与反向回查管线 (Transaction Message Pipeline) Half Message + Local Transaction + Checkback Protocol
步骤 1：发送 Half 消息 Half Msg
• Producer 发送 Half Message 至 Broker
• 消息暂存在系统的内部 Half Topic 中
• 对 Consumer 暂不可见，防未提交读
步骤 2：执行本地 DB 事务 Local TX
• Broker 返回 ACK 后，Producer 开始执行本地 DB 事务
• UPDATE order SET status = 'PAID';
• 本地事务成功记 COMMIT，失败记 ROLLBACK
步骤 3：提交/回滚二阶段 2nd Phase
• 收到 COMMIT 指令：Broker 还原原 Topic，消息对 Downstream Consumer 可见
• 收到 ROLLBACK 指令：Broker 直接物理丢弃 Half 消息
步骤 4：Broker 反向回查 Checkback
• 若步骤 3 二阶段 ACK 丢失或网络超时
• Broker 主动发起 checkLocalTransaction() 回查
★ 彻底攻克网络丢包带来的悬挂硬伤

1. RocketMQ 事务监听器代码结构 (`RocketMQTransactionListener`)

TransactionListener
// 生产级事务消息监听器规范
@RocketMQTransactionListener
public class OrderTxListener implements RocketMQLocalTransactionListener {
// ① 执行本地 DB 事务
public RocketMQLocalTransactionState executeLocalTransaction(Message msg, Object arg) {
boolean success = orderService.payOrder(msg.getPayload());
return success ? COMMIT : ROLLBACK;
}
// ② Broker 反向事务回查入口
public RocketMQLocalTransactionState checkLocalTransaction(Message msg) {
boolean isPaid = orderService.checkPaidStatus(msg.getHeaders().get("ORDER_ID"));
return isPaid ? COMMIT : ROLLBACK;
}
}
本质：将消息中间件转化为带有“事务反向检查能力”的协调器

2. 最大努力通知模式与对账兜底 (Best-Effort Notification)

Best-Effort
适用场景 (Target Scenarios)

适用于**跨企业、跨机构的 B2B 外部系统回调通知**（如支付宝/微信支付异步回调通知商户服务端）。

指数退避重试阶梯 (Exponential Backoff Retries)

如果接收方未返回 `success`，通知系统将按递增时间间隔重复发起通知：
$$\text{Retry Intervals}: 15s \to 1m \to 5m \to 30m \to 1h \to 12h$$

对账与主动查询兜底 (Reconciliation & Query API)

若多次重试全数失败，通知服务停止发送。接收方可以通过**主动调用提供方提供的对账查询 API**，或依靠夜间对账 Job 兜底修复单边账。

核心架构启发 (Transactional MQ Insight)

RocketMQ 事务消息通过巧妙的 **“Half Message（预备消息）+ 反向事务回查”** 机制，解耦了本地事务与消息发送。它不仅能保证 100% 的消息可靠投递，更避免了本地消息表轮询扫描数据库的物理开销。
