TCC 异常治理：防空回滚、防悬挂与幂等性 (TCC Anomaly Governance)

Empty Rollback, Hanging (Late Try Arrival), Idempotency Protection & TCC Fence Log Table (`tcc_fence_log`)

TCC 分布式网络的三大极端陷阱 (Three Physical Anomalies in TCC) Network Packet Losses, Timeouts & Out-of-Order Delivery
1. 空回滚 (Empty Rollback) Try Lost
• 诱因：Try 请求丢包或超时，主主协调器发起全局 Cancel。
• 陷阱：Try 根本未执行，Cancel 却收到了。如果 Cancel 直接执行解冻，会产生错误状态！
★ 解法：Cancel 先查 Try 记录，若未执行则直接返回成功。
2. 悬挂 (Hanging) Late Try
• 诱因：Try 请求因网络拥堵严重迟到，Cancel 已先行到达并执行空回滚。
• 陷阱：迟到的 Try 随后到达并成功预留资源，导致此资源永远无法被 Confirm/Cancel 释放！
★ 解法：Try 执行前校验是否已被 Cancel，若是则强行拒绝！
3. 幂等性 (Idempotency) Duplicate RPC
• 诱因：由于网络 ACK 丢失，TC 协调器重复重试发送 Confirm 或 Cancel。
• 陷阱：重复扣减余额或重复解冻资金造成数据损坏。
★ 解法：记录分支事务执行状态，重复请求直接幂等响应成功。

1. 统一防线：TCC 屏障控制表结构设计 (`tcc_fence_log`)

Atomic Fence
// 防空回滚、防悬挂与幂等性通用屏障表
CREATE TABLE tcc_fence_log (
xid VARCHAR(128) NOT NULL, -- 全局事务 ID
branch_id BIGINT NOT NULL, -- 分支事务 ID
action_mode INT NOT NULL, -- 1: Try, 2: Confirm, 3: Cancel
status INT NOT NULL, -- 1: TRIED, 2: COMMITTED, 3: ROLLEDBACK
PRIMARY KEY (xid, branch_id) -- 主键唯一性约束
);
物理约束保护机制

利用数据库主键唯一性约束（xid + branch_id），将状态校验与更新合并为原子性本地 DB 操作，彻底解决并发交错下的三大陷阱！

本质：利用 DB 唯一主键把跨网络时序颠倒转化为本地事务冲突

2. TCC 防线三大逻辑执行算法 (Fence Control Flow)

Fence Algorithm
Try 执行流程 (防悬挂)

在同一个 DB 本地事务中：先尝试插入记录 status = TRIED。若发现主键已存在且状态为 ROLLEDBACK（说明 Cancel 已经先到了），说明发生悬挂，直接回滚并拒绝 Try 执行！

Cancel 执行流程 (防空回滚 + 幂等)

尝试插入记录 status = ROLLEDBACK：
• 若主键插入成功：说明 Try 还没执行（空回滚），跳过业务解冻，直接返回成功！同时占据主键，阻止后续 Try (防悬挂)！
• 若主键冲突且记录已为 ROLLEDBACK：说明为重复 Cancel，幂等返回成功。
