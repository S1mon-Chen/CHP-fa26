Part 04 · 微服务最终一致性模式：TCC、Saga 与消息事务

微服务柔性事务模式矩阵 (Soft Transaction Patterns Matrix)

Comparison Matrix: TCC, Saga, Local Message Table & Transactional MQ Messaging

微服务四大柔性事务架构技术概览 (4 Microservice Soft Transaction Patterns) Application-Level Decoupling vs. Database-Level Lock Relief
1. TCC 模式 Application 2PC

应用层两阶段预留：手写 Try (冻结资源)、Confirm (实扣) 与 Cancel (解冻)。

2. Saga 模式 Compensation

长事务链路：依次执行正向本地事务 $T_i$；若中途失败，逆向触发补偿事务 $C_i$ 还原状态。

3. 本地消息表 DB + Job

借助单机 DB 本地事务，将业务更新与写消息记录原子绑定，后台定时 Task 轮询投递。

4. MQ 事务消息 RocketMQ Half

利用 MQ 预备消息 (Half Message) 与反向回查机制，实现服务间的高并发异步最终一致性。

1. 四大柔性事务技术选型矩阵对比 (Soft Transaction Decision Matrix)

Patterns Comparison
柔性事务模式 业务侵入性 一致性时效 性能 / 吞吐量 典型应用场景
TCC 模式 极高 (手写 3 方法) 较快 (二阶段异步) 极高 (无 DB 长锁) 核心支付、资金扣减、高并发库存
Saga 模式 中等 (提供补偿接口) 最终一致 (链式执行) 高 (本地事务即提交) 长流程订机票+酒店、跨服务审批
本地消息表 低 (写本地消息表) 最终一致 (依赖定时 Job) 中等 (受到 Job 轮询限制) 支付成功发积分、异步发短信
MQ 事务消息 低 (依赖中间件) 最终一致 (秒级投递) 高 (异步解耦) 高并发异步解耦、跨系统通知
核心启发：用“业务层预留与逆向补偿”替代数据库级别的物理行锁

2. 柔性事务选型演进法则 (Selection Philosophy)

Architecture Rules
法则 1：优先考虑消息事务 / 本地消息表

对于非核心主干流程（如下单后的发积分、发短信、通知物流），一律采用 MQ 事务消息进行异步解耦，不阻塞核心下单主线程。

法则 2：核心高并发扣减选用 TCC 模式

对于资金账户、秒杀库存等极度敏感且并发极高的数据，采用 TCC 预留机制，将死锁和冲突提前在 Try 阶段消化。

法则 3：长流程与第三方系统选用 Saga 模式

涉及到第三方接口（如订机票+订酒店+租车），无法改动对方代码实现 TCC，通过 Saga 状态机实现逆向调用撤销。

Part 04 核心开篇哲学 (BASE Soft Transaction Insight)

柔性事务的灵魂在于“解耦数据库底层锁，将一致性保障提升至应用层与业务逻辑层”。理解四大模式的折中（侵入性 vs 时效性 vs 吞吐量），是构建高性能微服务架构的基本功。
