7 大事务传播行为矩阵与选择光谱 (Propagation Spectrum Matrix)

Spring `Propagation` Enum: `REQUIRED`, `REQUIRES_NEW`, `SUPPORTS`, `NOT_SUPPORTED`, `MANDATORY`, `NEVER` & `NESTED`

Spring 7 大传播行为全方位矩阵对比 (Spring Transaction Propagation Matrix) Savepoint vs. Suspended Connection vs. Joint Connection
传播行为枚举 (Propagation) 当前存在事务 $TX_1$ 当前不存在事务 典型生产应用场景 (Scenarios)
REQUIRED (默认) 加入当前 $TX_1$（共享物理 Connection） 开启独立新事务 $TX_1$ 绝大多数写业务（如创建订单、扣减库存）。
REQUIRES_NEW 挂起 $TX_1$，开辟独立新事务 $TX_2$ 开启独立新事务 $TX_1$ 独立审计日志、扣减操作独立流水日志。
NESTED 创建 DB Savepoint 嵌套局部回滚 开启独立新事务 $TX_1$ 子步骤失败仅回滚 Savepoint，不破坏外层事务。
SUPPORTS 加入当前 $TX_1$ 以非事务方式普通执行 只读查询方法（有事务复用，无事务亦可）。
NOT_SUPPORTED 挂起当前 $TX_1$，以非事务方式执行 以非事务方式普通执行 耗时网络 RPC 调用、文件大批量导出（避免占锁）。
MANDATORY 加入当前 $TX_1$ 抛出 IllegalTrxStateException 异常 必须由上层控制事务的底层核算/清算子组件。
NEVER 抛出 IllegalTrxStateException 异常 以非事务方式普通执行 绝对禁止在事务中运行的非线程安全批处理。

1. 三大核心写传播模式：REQUIRED vs. REQUIRES_NEW vs. NESTED

Core Writes
REQUIRED（合并共退）

内层与外层绑定在同一物理 Connection 上，内层异常抛出即便被外层捕获，全局仍会强制回滚。

REQUIRES_NEW（物理独立 Connection）

内层开辟新 Connection，内层 commit 后外层再抛出异常，内层改动不受任何影响。

NESTED（JDBC Savepoint 嵌套）

共享物理 Connection，但通过 JDBC Savepoint 实现局部回滚。内层回滚仅退回到 Savepoint，外层提交时才统一物理提交。

法则：要保证部分成功请选 REQUIRES_NEW 或 NESTED，全成全败选 REQUIRED

2. 辅助挂起与校验模式：NOT_SUPPORTED / MANDATORY / NEVER

Guard & Suspend
NOT_SUPPORTED（挂起事务释放连接）

在方法执行期间暂时挂起外层事务，确保内部耗时 RPC/文件导出操作**不长时间占用数据库连接池资源**。

MANDATORY 与 NEVER（严格边界防线）

• MANDATORY 强制要求必须上层有事务，用于防止底层计算方法被误独立单独调用。
• NEVER 强制要求绝对无事务，防范在锁等待中运行非线程安全批量任务。

开启下一个核心：Slide 7 · Spring 事务回滚规则与 Checked Exception 踩坑指南

核心架构启发 (Propagation Selection Insight)

事务传播行为的本质是**方法嵌套调用时对“物理数据库连接与 Savepoint”的调度管控**。REQUIRED 共享同一连接共退退，REQUIRES_NEW 拿新连接物理隔绝，NESTED 借助 Savepoint 实现单连接局部可逆。
