1. Java EE JTA 与 CMT 历史回顾 (History Review)

Java EE Heritage
Java Transaction API (JTA)

定义了独立于具体持久化实现的标准事务接口。应用通过 JNDI 查找 java:comp/UserTransaction 或依赖注入获取句柄，显式编排事务界限。

Container-Managed Transactions (CMT)

在 EJB 企业级组件中，由 EJB 容器拦截方法调用，根据部署描述符 (XML / 注解) 自动声明事务边界。但是其紧耦合于昂贵的 Java EE 应用服务器 (如 WebLogic, WebSphere)。

痛点：传统 JTA/CMT 侵入性强、测试繁琐，且强绑定于 Java EE 容器环境

2. Spring `PlatformTransactionManager` 核心接口定义

Unified SPI

Spring 将底层各种持久化技术的事务操作完全解耦，统一抽象为极简的 SPI 接口：

// Spring 核心事务 SPI 接口定义
public interface PlatformTransactionManager extends TransactionManager {
TransactionStatus getTransaction(TransactionDefinition definition)
throws TransactionException;
void commit(TransactionStatus status) throws TransactionException;
void rollback(TransactionStatus status) throws TransactionException;
}
开启下一个核心：Slide 4 · Spring `@Transactional` 切面原理与 AOP 动态代理机制

核心架构启发 (SPI Abstraction Insight)

Spring 框架通过 PlatformTransactionManager 实现了**业务服务代码与底层持久化事务 API 的彻底解耦**。无论底层是单库 JDBC、JPA/Hibernate 还是跨库 JTA/XA 分布式事务，上层业务只需使用统一的 @Transactional 注解即可无缝切换！
