1. InnoDB 三大行级/区间锁模式

Lock Modes
行锁 (Record Lock)

仅锁住**具体的单条索引记录**本身（如锁住 `id = 20` 这一行）。

间隙锁 (Gap Lock)

锁住索引记录之间的**开区间 $(X_i, X_{i+1})$**，不包含记录本身。主旨是阻止其他事务在该间隙执行 `INSERT`。

临键锁 (Next-Key Lock)

**Record Lock + Gap Lock 的结合体**，锁住**左开右闭区间 $(X_i, X_{i+1}]$**。InnoDB 在 RR 隔离级别下的默认当前读算法。

法则：Next-Key Lock 通过同时锁定已有行与间隙，物理消除了当前读下的幻读

2. 锁退化规则与 SQL 场景分析 (Degradation Rules)

Optimization Rules
规则 A：唯一索引等值查询 (Unique Index Point Query)

若记录存在，Next-Key Lock **退化为 Record Lock**（只需锁该行即可，无幻读风险）；若记录不存在，退化为 **Gap Lock**。

规则 B：非唯一索引等值查询 (Non-Unique Index)

向右扫描到第一个不满足条件的记录时，该记录上的 Next-Key Lock **退化为纯 Gap Lock**。

规则 C：范围查询 (Range Query)

对命中索引的范围逐个施加 Next-Key Lock，一直锁定至边界。

核心物理哲学 (Gap & Next-Key Lock Insight)

间隙锁是 InnoDB 为解决“当前读下无法锁定尚未诞生的记录”而创造的杀手锏。通过锁住索引开闭区间 $(X_i, X_{i+1}]$，将尝试在区间内插入新行的并发事务强行挂起，从而在 Repeatable Read (RR) 级别下实现了极致的数据一致性。
