1. 四大隔离级别物理运行语义 (Levels Mechanics)

Standard Definitions
1. Read Uncommitted (读未提交)

不加读锁也不建立 MVCC 视图，直接读取最新的物理数据页，可能读到其他事务尚未提交的临态“脏数据”。

2. Read Committed (读已提交)

对每条 SQL 查询独立生成一次 MVCC ReadView，只能看到已被提交的修改。杜绝了脏读，但同一事务内多次读取可能返回不同数据。

3. Repeatable Read (可重复读)

仅在事务第一条 `SELECT` 时生成一次 ReadView 并贯穿事务始终，保证多次读取相同行结果绝对一致。

4. Serializable (可串行化)

放弃轻量级快照读，对读取和修改全量隐式加 S/X 读写锁（如 2PL 协议与间隙锁），强制让并行事务串行化排队。

法则：隔离级别越高，并发读写冲突越少，但吞吐量与并行度也随之越低

2. MySQL InnoDB 物理引擎的特殊工程优化

InnoDB Engine Note
InnoDB 在 RR 级别下消除幻读的物理组合拳 MVCC + Next-Key Lock

ANSI SQL 标准中 Repeatable Read 允许幻读发生。但 MySQL InnoDB 引擎通过组合拳在 **RR 级别下物理消除了绝大部分幻读**：

  • • **普通快照读 (Snapshot Read)**：依赖 MVCC 的 ReadView 隔离，新插入行对当前 ReadView 不可见。
  • • **当前读 (Current Read)**：对 `SELECT ... FOR UPDATE` 加 **Next-Key Lock (行锁 + 间隙锁)**，强行排他锁定整个物理间隙，阻止其他事务插入新行。
主流商业数据库默认隔离级别 Defaults
  • • **MySQL InnoDB**：默认 **Repeatable Read (RR)**。
  • • **Oracle / PostgreSQL / SQL Server**：默认 **Read Committed (RC)**。

核心物理哲学 (Isolation Level Engineering Insight)

隔离级别是**隔离安全性与物理并发吞吐量之间的调音阶**。数据库引擎通过把锁（2PL）和版本快照（MVCC）按不同粒度进行组合，为上层业务提供了从 RU 到 Serializable 的可调平衡点。
