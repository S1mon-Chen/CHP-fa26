1. 为何需要检查点？与全量静态检查点 (Full Checkpoint)

RTO & Truncation
1. 无检查点的致命痛点 (Why Checkpoint?)

若没有检查点，数据库发生崩溃重启时，必须从开天辟地的第一条 Redo 日志开始扫描重放！**故障恢复时间 (RTO) 将长达数小时甚至数天**，且磁盘将因积压海量历史日志而爆满。

2. 早期全量静态检查点 (Full / Static Checkpoint)

**机制**：强行暂停所有用户事务（Stop-The-World），将 Buffer Pool 中所有脏页彻底刷回磁盘，然后向日志写入一条 `` 标记。
**缺点**：严重阻塞并发写 SQL，造成频繁的物理卡顿（Stall），无法用于高并发生产环境。

法则：检查点限制了崩溃恢复重放日志的边界，彻底解决了 RTO 爆炸问题

2. 现代商业数据库标配：模糊检查点 (Fuzzy Checkpoint)

Fuzzy Checkpoint

现代关系型数据库（MySQL InnoDB、Oracle、PostgreSQL）全数选型**模糊检查点（Fuzzy Checkpoint）**：

异步平滑刷脏，绝不暂停用户事务

后台独立线程 (`page_cleaner`) 持续平滑地将数据脏页写入磁盘，用户 SQL 正常并发执行，完全无需 Stop-The-World。

记录 `CHECKPOINT_BEGIN` 与 `CHECKPOINT_END`

检查点写入时，仅记录当前的**脏页表 (Dirty Page Table, DPT)** 与**活跃事务表 (Active Transaction Table, ATT)**。

精确计算 Redo 重放起点 $\min(\text{RecLSN})$

找到 DPT 脏页表中**最早未刷新脏页对应的 RecLSN**，重启时直接从 $\text{Redo Start LSN} = \min(\text{RecLSN})$ 开始正向扫描重放，绝不遗漏任何未落盘改动。

开启下一个核心：Slide 38 · ARIES 崩溃恢复算法精要与三大数据结构 (LSN, DPT, ATT)

核心物理哲学 (Fuzzy Checkpoint Insight)

模糊检查点是数据库工程设计折中理念的极致体现。它**用记录脏页表中最小 RecLSN 的轻量动作，替代了高昂的全量数据脏页同步**，成功将恢复重放时间限制在一个极小的安全物理窗口内。
