1. 可串行化调度的形式化定义 (Formal Definition)

Gold Standard

一个并发调度 $S$，如果在任何合法的初始数据库状态下执行，**其最终数据库状态与某个串行调度 $S_{\text{serial}}$ 的执行结果完全相同**，则称 $S$ 为**可串行化调度（Serializable Schedule）**。

正确性范式的核心物理价值 Concurrency Core
  • **保持绝对一致性**：串行调度天然满足一致性与隔离性，因此可串行化调度也必定能将数据库平滑推演到合法一致状态。
  • **兼顾物理高吞吐**：在保持串行调度数据正确性的前提下，放开多核 CPU 与磁盘 I/O 的交叉重叠执行（Interleaving）。
法则：可串行性是衡量并发控制算法（锁/MVCC）正确性的黄金铁律

2. 终态检验之困与冲突可串行化工程折中

Verification Soluton

理论上的“终态可串行化”在实际工程中存在致命难题：**无法直接通过比对终态来验证调度**，因为必须穷举所有初始数据库状态和应用层未知的计算逻辑（计算复杂度属于 NP-Hard）。

工程解法：冲突可串行化 (Conflict Serializability) Sufficient Condition

数据库引擎放弃复杂的终态穷举，转而寻找可串行化的充分条件——**冲突可串行化**：只要调度中不冲突的操作可以通过连续对调（Swap）转换为某个串行调度，即可证明该并发执行绝对安全。

开启下一个核心：Slide 12 · 冲突可串行化与非冲突操作对调推导

核心理论启发 (Serializability Paradigm Insight)

可串行化理论是数据库并发控制的核心灵魂：**应用层编写代码时只需假设事务是串行排队执行的，而数据库底盘通过理论证明等价性，放开并发物理交错**。
