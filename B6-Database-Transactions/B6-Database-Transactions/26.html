1. InnoDB 行记录三大隐藏系统列 (Hidden System Columns)

Hidden Fields

InnoDB 在聚簇索引的每一行物理记录中，除了用户定义的字段外，都会隐式自动添加 2~3 个系统级隐藏列：

DB_TRX_ID (6 Bytes)

最近一次对该行进行 `INSERT` 或 `UPDATE` 的**事务 ID**。若是 `DELETE`，也会在内部当作 `UPDATE` 将删除标记位置位，并更新 `DB_TRX_ID`。

DB_ROLL_PTR (7 Bytes)

**回滚指针**。指向写在 Undo Segment 中该行上一个历史版本的镜像地址（Before-Image），以此串联起版本链。

DB_ROW_ID (6 Bytes)

隐藏自增主键。如果数据表既没有显式主键，也没有非空唯一索引，InnoDB 会自动生成此列作为聚簇索引键。

法则：DB_TRX_ID 与 DB_ROLL_PTR 是 MVCC 实现版本推演的物理基石

2. Undo 版本链的动态构建与物理回溯 (Version Chain)

Chain Mechanics

当不同的事务先后修改同一行记录时，Undo 版本链按以下物理步骤动态增长：

步骤 A：写入 Undo Log (Before-Image)

写事务在修改数据页前，先把当前页中的旧版本镜像完整拷贝写进 Undo Log 页面。

步骤 B：更新数据页与回滚指针

修改 Buffer Pool 中最新行记录，更新 `DB_TRX_ID` 为当前事务 ID，并将 `DB_ROLL_PTR` 指向刚才生成的 Undo Log 记录地址。

步骤 C：版本链物理形态

头节点（最新行）在聚簇索引页中，历史节点在 Undo 段中。回溯方向为**从最新版本一路向前指向最旧版本**。

开启下一个核心：Slide 27 · ReadView 结构与一致性快照可见性算法

核心物理哲学 (Undo Version Chain Insight)

Undo Log 不仅服务于事务 `ROLLBACK` 原子性撤销，更通过 `DB_ROLL_PTR` 将分散的历史镜像串联成**单向版本链**。这使得读事务能够沿着版本链向过去追溯，精准还原出属于自己的历史快照镜像。
