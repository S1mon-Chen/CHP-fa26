什么是数据库事务？ (What is a Database Transaction?)

Logical Unit of Work (LUW), Demarcation Syntax (`BEGIN` / `COMMIT` / `ROLLBACK`) & Abstraction Value

1. 事务的工程定义与逻辑边界 (Demarcation) LUW Concept

逻辑操作单元 (Logical Unit of Work)

数据库事务（Transaction）是数据库管理系统（DBMS）执行过程中的一个**不可分割的逻辑工作单元**，由一条或多条 SQL 语句组合而成。事务中的所有操作作为一个整体向系统提交，**要么全部执行生效，要么全部被拒绝并撤销**。

// 典型的银行转账事务逻辑边界 (`SQL Demarcation`)
START TRANSACTION; // 或 BEGIN / BEGIN TRANSACTION; 显式开启事务
UPDATE account SET balance = balance - 100.00 WHERE user_id = 'Alice';
UPDATE account SET balance = balance + 100.00 WHERE user_id = 'Bob';
COMMIT; // 提交事务：使所有变更永久生效
// 或发生异常时执行: ROLLBACK; (或 ABORT;) 撤销所有未提交修改
边界核心：`START TRANSACTION` 设定起点，`COMMIT` 或 `ROLLBACK` 确定终点
2. 为何数据库引擎必须提供“事务”机制？ Why Transactions

应对系统崩溃与硬件故障 (Handling System Failures) Fault Tolerance

物理世界充满不确定性：服务器突发断电、数据库进程崩溃（Crash）、磁盘故障、网络抖动或死锁。事务机制能够确保在任何极端故障重启后，数据库**绝不会残留“半完成”的中间脏数据**。

简化高并发编程抽象 (Simplifying Concurrency) Abstraction Layer

当数千个客户端同时并发读写同一张表时，事务机制为每个业务线程提供了**“独占式访问数据库”的假象**。应用开发人员无需手写繁琐复杂的底层并发互斥与死锁恢复代码。

守护数据状态合法平滑转移 (Valid State Transitions) State Invariants

强制要求数据库状态只能从一个合法一致的旧状态转移到另一个合法一致的新状态，不违背任何物理约束与业务不变式法则。

开启下一个核心：Slide 4 · ACID 四大特性全景剖析与物理实现支撑

核心哲学启发 (Transaction Abstraction Insight)

事务是数据库管理系统向上层应用提供的**最优雅、最强大的抽象屏障之一**。它将物理硬件断电故障、并发读写竞争与脏数据回滚等极度复杂的底盘细节完美屏蔽在数据库引擎内部。
