并发异常 3：幻读与断言缺失 (Phantom Read & Predicate Violation)

Phantom Read, Predicate Queries, Row-Lock Inadequacy & Next-Key Lock Gap Defense

并发读写冲突图解：幻读 ($T_1$ 范围谓词读，与并发 $T_2$ 插入冲突) Hazard: Non-existent Gap Insertion & Phantom Rows
异常 A：幻读 (Phantom Read 序列) Predicate Query Risk
// $T_1$ 读取谓词条件 $age > 20$（返回 10 条记录）；$T_2$ 插入 $age=25$ 并提交
Sequence: $r_1(age>20 \Rightarrow 10 \text{ rows}) \to w_2(\text{INSERT } age=25) \to \mathbf{c_2} \to \mathbf{r_1(age>20 \Rightarrow 11 \text{ rows!)}}$
* 灾难性后果：$T_1$ 再次按原谓词查询，看到了凭空出现的“幽灵/幻影记录”（得到 11 条），破坏了基于原范围的逻辑断言。
• **核心矛盾**：普通行锁 (Record Lock) 只能锁住**已经存在的物理行**，无法阻止在**尚不存在的物理间隙 (Gap)** 插入新记录。
物理概念区分：不可重复读 vs. 幻读 Row Lock vs. Gap Lock
不可重复读 (Non-Repeatable Read)

作用于**已有具体数据行**（针对 `UPDATE` / `DELETE`），行排他锁 (Record Lock) 即可防范。

幻读 (Phantom Read)

作用于**范围间隙/集合记录增减**（针对 `INSERT`），必须依赖**间隙锁 (Gap Lock)** 或 **Next-Key Lock**。

• **解法**：在当前读 (Current Read) 下，使用 **Next-Key Lock** 锁住索引范围及开区间间隙。

1. 幻读形成机制与断言缺失 (Predicate Violation)

Gap Failure

当事务基于某个**谓词条件 (Predicate Condition)** 执行范围查询并进行后续决策时，幻读会破坏应用层的逻辑断言（Predicate Invariant）：

谓词断言失效场景 (Example Scenario)

事务 $T_1$ 检查 `SELECT COUNT(*) FROM user WHERE name = 'Alice'` 返回 0（推断账户名可用），正准备插入 `'Alice'` 账户。此时并发事务 $T_2$ 抢先插入 `'Alice'` 并提交。随后 $T_1$ 插入时直接触发唯一主键冲突异常，产生逻辑悖论！

行锁失效物理根源 (Row-Lock Inadequacy)

对数据库而言，新记录 `'Alice'` 在 $T_1$ 查询时物理上尚不存在，因此 $T_1$ 无法对其施加任何行锁。这就要求封锁协议必须超越物理行，锁定**潜在插入的索引间隙**。

法则：普通行锁无法封锁尚未存在的物理行，必须引入间隙锁定协议

2. 幻读消除的双重解法：MVCC 与 Next-Key Lock

MVCC & Gap Lock

现代数据库引擎通过区分“快照读”与“当前读”，在性能与安全性之间实现了精准防护：

解法 A：快照读下的 MVCC 屏蔽 (Snapshot Read in RR)

对于普通 `SELECT` 语句，依赖 **ReadView** 历史快照。即便 $T_2$ 插入了新行并提交，其事务 ID 晚于 $T_1$ 的 ReadView 规则，新行在快照读下自动被过滤，不会产生幻读。

解法 B：当前读下的 Next-Key Lock (Current Read in RR)

对于 `SELECT ... FOR UPDATE` 或 `UPDATE/DELETE`，执行**当前读**。InnoDB 隐式使用 **Next-Key Lock (行锁 + 间隙锁)**，锁住索引记录及其前后的开闭区间 $(X_i, X_{i+1}]$，阻塞其他事务的 `INSERT`。

解法 C：Serializable 隔离级别的谓词锁 (Predicate Locking)

对查询条件本身加谓词锁或表锁，全面排斥任何满足条件的并发写与插入。

核心物理哲学 (Phantom Read & Gap Lock Insight)

幻读的本质是**谓词集合范围在事务执行期间发生了变化**。由于行锁无法对不存在的数据行加锁，InnoDB 引擎开创性地使用 **Next-Key Lock (行锁 + 间隙锁)**，成功在 Repeatable Read (RR) 隔离级别下物理杜绝了当前读下的幻读问题。
