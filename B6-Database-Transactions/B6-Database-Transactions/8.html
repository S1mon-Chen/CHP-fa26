1. 数据库引擎层约束 (Schema & Database Constraints)

Engine Protection

数据库引擎通过语法解析器与执行器强行校验与维护物理 Schema 约束。一旦发现任何 SQL 违反规则，**直接抛出 Exception 并触发 Undo 自动回滚**：

  • **主键/唯一索引 (Unique Index)**：杜绝重复插入相同的唯一键（如身份证号或交易流水号）。
  • **外键约束 (Foreign Key)**：确保子表记录关联的父表主键真实存在（参照完整性）。
  • **`CHECK` 谓词约束**：强行限定数据列范围，例如：CONSTRAINT balance_non_negative CHECK (balance >= 0)。
法则：引擎级约束是由数据库系统自动防御的第一道强一致性防线

2. 应用层不变式与 ACID 物理哲学映射

AID Supports C

并非所有业务规则都能写成 SQL `CHECK` 约束。更复杂的复式记账法或商品库存扣减守恒，必须依赖**应用层逻辑 + 数据库 ACID 底座**共同守护。

为什么说一致性 $C = f(A, I, D)$？ Physical Formula
  • • **失去原子性 ($A$)**：扣了 Alice 钱但 Bob 没收到就系统崩溃 $\implies$ 破坏转账总额守恒！
  • • **失去隔离性 ($I$)**：并发线程读到脏数据并重复扣款 $\implies$ 导致账户余额破产透支！
  • • **失去持久性 ($D$)**：提交成功后断电丢失记录 $\implies$ 出现“钱扣了账查不到”的不一致状态！
法则：Consistency 是目的，Atomicity、Isolation 与 Durability 是手段
