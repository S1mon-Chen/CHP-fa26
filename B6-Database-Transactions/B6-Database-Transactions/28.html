ReadView 生成策略：RC 与 RR 差异 (ReadView Creation: RC vs. RR)

Statement-level ReadView (RC) vs. Transaction-level ReadView (RR) & Execution Timeline Comparison

并发事务执行时序对比：RC 动态生成 ReadView vs. RR 首次生成并复用 ReadView Core MVCC Difference: ReadView Generation Timing
Read Committed (RC - 读已提交) Statement-Level ReadView
• **T1 执行第一个 SELECT** $\implies$ 生成 ReadView 1 $\implies$ 读到 age = 20
• **T2 修改并提交** $\implies$ UPDATE age = 25; COMMIT;
• **T1 执行第二个 SELECT** $\implies$ 重新生成新 ReadView 2 $\implies$ 读到最新提交的 age = 25！
• **后果**：同一事务内两次查询看到了不同的结果（允许不可重复读）。
Repeatable Read (RR - 可重复读) Transaction-Level ReadView
• **T1 执行第一个 SELECT** $\implies$ 首次生成 ReadView 1 $\implies$ 读到 age = 20
• **T2 修改并提交** $\implies$ UPDATE age = 25; COMMIT;
• **T1 执行第二个 SELECT** $\implies$ 直接复用 ReadView 1 $\implies$ 沿 Undo 链找回历史快照，依然读到 age = 20！
• **效果**：同一事务内多次查询看到的快照完全一致（彻底消除不可重复读）。

1. 读已提交 (RC) 隔离级别：语句级快照

Statement Snapshot

在 Read Committed (RC) 隔离级别下，MVCC 遵循**“按需及时刷新的语句级快照”**原则：

每次 SELECT 均重算 `m_ids`

只要执行一条 `SELECT` SQL 语句，MVCC 就会重新拍摄一张物理快照，更新当前的活跃事务列表 `m_ids`。

数据可见性动态演进

如果在两次 `SELECT` 之间，并发写事务 $T_2$ 完成了提交，那么在第二个 `SELECT` 生成新 ReadView 时，$T_2$ 已经不在 `m_ids` 活跃列表中了，因此 $T_2$ 的修改对第二个 `SELECT` 变成**可见**。

特点：能够及时看到其他事务最新已提交的物理改动，但无法保持事务内读一致

2. 可重复读 (RR) 隔离级别：事务级快照

Transaction Snapshot

在 Repeatable Read (RR) 隔离级别下，MVCC 遵循**“一快照到底的事务级历史视窗”**原则：

仅在首次 SELECT 生成一次 ReadView

事务启动后，**只有在执行第一条快照读 `SELECT` 语句时，才捕获全局 ReadView**。随后无论执行多少次 `SELECT`，都强行复用这个最初的 ReadView。

屏蔽事务执行期间的所有并发修改

即便并发写事务 $T_2$ 在中途提交，由于最初的 ReadView 里将 $T_2$ 记为了活跃事务或未来事务，后续查询依然会在 Undo 链上向过去回溯，还原最初时刻的静态快照。

开启下一个核心：Slide 29 · MVCC + Next-Key Lock 组合拳消除当前读下的幻读

核心物理哲学 (ReadView Strategy Insight)

RC 与 RR 在 MVCC 层的物理区别**仅仅在于 ReadView 生成的时机与生命周期**：RC 是“语句级动态快照”（每条 SQL 拍一次），RR 是“事务级静态快照”（首次 SQL 拍一次并全程复用）。

🎯 引导学员透视 RC 与 RR 的生成时机本质： “向学员做解构说明：很多人觉得 MVCC 在 RC 和 RR 下很复杂，其实本质非常简单——就是 ReadView 的生成时机不同！在 RC 级别下，每一条 `SELECT` 执行前都会拍摄一张新 ReadView；而在 RR 级别下，仅在第一次 `SELECT` 时拍一张 ReadView，后续整个事务期间都重复使用这张旧照片。”
💡 剖析不可重复读在 RR 下被消除的原因： “请学员关注右侧卡片：既然 RR 级别下全过程复用第一张 ReadView，那么即使其他并发事务 $T_2$ 在中途修改了数据并提交，由于 $T_2$ 在最初那张 ReadView 里要么被归为活跃事务、要么被归为未来事务，因此按照 Slide 27 讲的可见性算法，$T_2$ 的改动对 $T_1$ 永远不可见！这就是 RR 级别消除不可重复读的物理原理。”
