1. 物理日志与逻辑日志物理特性权衡

Physical vs Logical
纯物理日志 (Physical Logging)

记录数据页具体字节级别的变更。**优点**：完全幂等，只要直接覆写对应 Offset 即可重放；**缺点**：B-Tree 节点分裂或页面整理时，一条改动会产生数 KB 的字节日志（体积爆炸）。

纯逻辑日志 (Logical Logging - 如 MySQL Binlog)

记录高层 SQL 语句或抽象变更逻辑。**优点**：占用磁盘极小；**缺点**：不满足幂等性（重复重放 `age = age + 1` 会产生数据累加错误），且重放需依赖复杂的索引与锁结构，无法用于物理页级别的崩溃恢复。

法则：纯物理日志太重，纯逻辑日志无法支持底层物理页崩重放

2. 工业界金标准：生理逻辑日志 (Physiological Log)

Industrial Standard

商业数据库（MySQL InnoDB MTR Redo Log、Oracle、PostgreSQL）全数选择**生理逻辑日志（Physical-to-a-Page, Logical-within-a-Page）**：

物理到页，页内逻辑 (Physiological Formula)

• **物理定位**：日志头指定目标 16KB 物理数据页号 (`Page ID`)。
• **逻辑更新**：在指定的物理数据页内部，按逻辑记录格式执行更新操作（如“将 Slot 3 记录的 Column 2 修改为 'Bob'”）。

完美兼顾幂等性与极小体积

结合数据页头部的 `PageLSN`，重放时只需判断 **$\text{Log LSN} > \text{PageLSN}$** 才应用日志。既保证了物理重放的绝对幂等性，又极大地压缩了日志体积。

开启下一个核心：Slide 34 · Undo Log 物理结构与事务逆向回滚

核心物理哲学 (Physiological Logging Insight)

生理逻辑日志是数据库设计史上折中思想（Trade-off）的典范。它**用 Page ID 锁定了物理作用边界**，避免了跨页重放并发冲突，同时**在页内使用逻辑描述极大地精简了写盘体积**，实现了极高吞吐的重放恢复。
