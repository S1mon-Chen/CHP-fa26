1. ReadView 快照结构 4 大核心字段

4 Key Fields

当事务执行快照读时，内存中会瞬间捕获并生成一个 `ReadView` 结构，包含以下四大核心成员：

m_ids

生成 ReadView 瞬间，当前数据库中**所有活跃且未提交的事务 ID 列表**。

min_trx_id

`m_ids` 列表中最小的事务 ID（即当前活跃事务中的最小编号）。

max_trx_id

系统准备分配给**下一个新事务的 ID**（即当前已分配最大 `TRX_ID + 1`，非 `m_ids` 的最大值）。

creator_trx_id

创建该 ReadView 的当前事务自身的 `TRX_ID`。

法则：ReadView 是快照读判定历史版本是否“合法可见”的衡量刻度尺

2. Undo 版本链遍历与可见性判定算法

Traversal Rules

当事务沿 Undo 版本链从头节点（最新行）向后遍历时，针对每个版本的 `DB_TRX_ID` 依序校验：

// 可见性算法判定步骤 (bool is_visible(trx_id))
规则 1: 自身改动特例
if (trx_id == creator_trx_id) return true; // 始终能看见自己修改的数据
规则 2: 早期已提交版本
if (trx_id < min_trx_id) return true; // ReadView 生成前已提交
规则 3: 未期未来事务
if (trx_id ≥ max_trx_id) return false; // ReadView 生成后才开启
规则 4: 活跃列表判定
if (trx_id in m_ids) return false; // 活跃未提交
else return true; // ReadView 生成前已完成提交

核心物理哲学 (ReadView Visibility Insight)

ReadView 算法的本质是**给物理时间轴上重叠交错的并发事务划定一条属于自己的“历史记忆割裂线”**。通过对比 `DB_TRX_ID` 与 `ReadView` 成员，读事务可以沿着 Undo 链准确追溯到那个物理上合法且一致的快照版本。
