1. 共享锁 ($S$) 与排他锁 ($X$) 核心语义

Basic Locks
共享锁 (Shared Lock / $S$ 锁 / 读锁)

允许事务读取某数据项。多个事务可以同时对同一记录加 $S$ 锁（读读并发），但不允许任何事务加 $X$ 锁。

排他锁 (Exclusive Lock / $X$ 锁 / 写锁)

允许事务更新或删除某数据项。加有 $X$ 锁的记录禁止其他任何事务施加 $S$ 锁或 $X$ 锁（独占排他）。

锁升级与死锁风险

若两个事务同时持有一行的 $S$ 锁并尝试升级为 $X$ 锁，双方将无限等待对方释放 $S$ 锁，直接触发死锁！

法则：读读不互斥，读写与写写绝对互斥

2. 多粒度封锁与意向锁 ($IS$ / $IX$) 必要性

Intent Locks
为何引入意向锁？(Why Intent Locks?) $O(1)$ Table Lock Check

当事务要对全表加表级 $X$ 锁时，必须确认表中**没有任何一行被加了行级 $X$ 或 $S$ 锁**。如果逐行扫描判断，开销为 $O(N)$（极慢）。引入表级**意向锁 ($IS/IX$)** 标志后，检查开销瞬间降为 $O(1)$！

意向共享锁 (Intent Shared / $IS$)

事务准备在表的某些数据行上加 $S$ 锁，加行锁前必须先获取表级 $IS$ 锁。

意向排他锁 (Intent Exclusive / $IX$)

事务准备在表的某些数据行上加 $X$ 锁，加行锁前必须先获取表级 $IX$ 锁。

开启下一个核心：Slide 21 · 封锁粒度与表锁、行锁 (Lock Granularity)

核心物理哲学 (Lock Hierarchy Insight)

意向锁 ($IS/IX$) 是表级锁，它的存在**绝不是为了锁住数据，而是为了表达“内部某行已被锁定”的意向**。通过表级意向标志，避免了表级锁申请时 $O(N)$ 遍历底层行锁的昂贵开销。
