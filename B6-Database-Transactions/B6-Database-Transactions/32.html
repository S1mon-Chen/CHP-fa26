预写日志金律 WAL (The Write-Ahead Logging Protocol)

WAL Golden Rule: Log Flush Must Precede Page Flush, Sequential Log I/O vs. Random Data Page I/O

WAL 协议物理落盘顺序管线 (Write-Ahead Logging Execution Pipeline) Inviolable Constraint: $\text{Log Flush} \prec \text{Data Page Flush}$
1. 内存修改 RAM

修改 Buffer Pool 数据页，同时向 Log Buffer 追加生成 Redo / Undo 日志。

2. 优先刷日志 (WAL) Mandatory fsync

★ 金律限制：在数据脏页允许落盘前，日志必须已强行刷入物理磁盘！

3. 提交确认 COMMIT OK

由于日志已安全落盘，向客户端快速返回事务提交成功（微秒级响应）。

4. 延迟刷脏页 Async Page Write

数据脏页随后由后台线程异步写回物理表空间文件（`.ibd`），解耦实时写开销。

1. WAL 预写日志金律形式化定义 (Formal WAL Definition)

Inviolable Rule

预写日志（Write-Ahead Logging, WAL）是关系型数据库保证故障可恢复性（Atomicity & Durability）的最核心物理准则：

核心法则：日志刷盘严格先于数据脏页刷盘

对任何内存脏页的修改，在将该脏页刷新写入磁盘数据文件之前，**记录该修改的日志条目必须先一步强行写进磁盘非易失性存储** (`fsync`)。

违背 WAL 的物理灾难 (Why Inviolable?)

若允许脏页在无日志的情况下先写入磁盘，中途一旦突发崩溃，物理磁盘上已存有修改后的数据，但系统中没有任何 Undo 日志记录旧值。该改动将**永久无法被撤销 (Abort/Rollback)**，直接破毁原子性！

定理：没有带日志护航的数据脏页，绝对不允许擅自写入物理磁盘

2. WAL 带来高并发极致吞吐的物理原理 (Performance Mechanics)

I/O Optimization

许多人直觉认为 WAL 多写了一份日志文件，但它反而在物理上实现了上百倍的性能飞跃：

1. 离散随机 I/O $\to$ 顺序追加 I/O (Sequential Write)

数据页刷盘需要更新离散在磁盘各处的 B-Tree 节点（随机写，开销 10ms+）；而 WAL 日志刷盘是向日志文件末尾**连续顺序追加写 (Sequential Write)**，开销微秒级，磁盘磁头与 NVMe 吞吐达到极致。

2. 解耦物理响应延迟 (Decoupling Write Latency)

事务提交只需等待极小的日志顺序写完毕即可响应。昂贵的大块数据页异步留给 Buffer Pool 后台慢慢平滑写盘。

3. 支持极高 Buffer Pool 内存利用率 (NO-FORCE / STEAL)

配合 Slide 31 的 NO-FORCE / STEAL 策略，彻底解除内存与磁盘的锁死捆绑。

开启下一个核心：Slide 33 · 日志物理/逻辑分类（Physical, Logical & Physiological Log）

核心物理哲学 (WAL Insight)

WAL 是数据库工程史上最伟大的发明之一。利用**“日志先于数据落盘”**的物理约束，数据库不仅锁死了原子性与持久性底线，更成功将令人绝望的磁盘数据页离散随机写，巧秒降维转化为极速的日志顺序追加写。
