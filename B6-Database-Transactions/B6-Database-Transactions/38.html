ARIES 算法精要：三大数据结构 (Core Data Structures)

Algorithms for Recovery and Isolation Exploiting Semantics, LSN Scaling, Dirty Page Table (DPT) & Active Transaction Table (ATT)

ARIES 崩溃恢复三位一体核心数据结构拓扑图 (ARIES In-Memory State Mapping) Redo Replay Boundary: $\text{Redo Start LSN} = \min(\text{RecLSN in DPT})$
1. LSN 日志序列刻度 PageLSN & FlushedLSN
• LSN: 单调递增 64 位写日志字节 Offset
• PageLSN: 数据页头部最后修改的 LSN
• FlushedLSN: 日志已同步刷盘的最大 LSN
2. 脏页表 (DPT) Dirty Page Table
• **功能**：记录 Buffer Pool 内所有物理脏页
• **核心字段**：[ PageID | RecLSN ]
★ RecLSN 为最早把该页变脏的 LSN
3. 活跃事务表 (ATT) Active Trx Table
• **功能**：记录崩溃瞬间未完成的所有活跃事务
• **核心字段**：[ TRX_ID | Status | LastLSN ]
★ LastLSN 为该事务最新的日志入口

1. LSN 体系与数据页绝对幂等重放准则

LSN Spectrum

ARIES 算法通过将刻度编码嵌入物理页与日志文件，消除了重复重放带来的数据不一致风险：

PageLSN 物理页写入

对 Buffer Pool 16KB 数据页进行底层修改时，必须**强行把本次修改对应的 Redo Log LSN 写入该数据页头的 `PageLSN` 字段**。

崩溃重放条件：判断 $\text{Log LSN} > \text{PageLSN}$

正向重放 Redo 日志时，先对比当前物理页上的 `PageLSN`：
• 若 $\text{Log LSN} \le \text{PageLSN}$：说明该修改在崩溃前**已成功刷入磁盘**，跳过该日志；
• 若 $\text{Log LSN} > \text{PageLSN}$：说明磁盘页**缺失该修改**，必须重放应用日志！

法则：PageLSN 实现了重放历史的绝对幂等性 $f(f(\text{State})) = f(\text{State})$

2. 脏页表 (DPT) 与活跃事务表 (ATT) 边界推算

DPT & ATT
脏页表 RecLSN：精确锁定 Redo 重放起点

当数据页从“干净页”首次变为“脏页”时，记录当时的 `RecLSN`。DPT 中所有脏页的 **$\min(\text{RecLSN})$ 确定了 Redo 正向扫描的物理起始位置**，绝不遗漏任何未落盘脏数据。

活跃事务表 LastLSN：精确锁定 Undo 撤销入口

崩溃瞬间尚未提交的“失败事务 (Losers)”全数留在 ATT 中。利用每个事务的 `LastLSN`，沿着 `PrevLSN` 链表向回追溯，高效执行单向 Undo 逆向撤销。

开启下一个核心：Slide 39 · ARIES 崩溃恢复三阶段流程（分析 $\to$ 重放历史 $\to$ Undo）

核心物理哲学 (ARIES Data Structures Insight)

ARIES 算法的伟大之处在于**用极轻量的内存数据结构构建了恢复边界**。通过 LSN 刻度锁定物理页状态、通过脏页表 RecLSN 确定 Redo 重放起点、通过活跃事务表 LastLSN 链接 Undo 回滚入口，数据库从算法层面实现了毫秒级精准极速恢复。
