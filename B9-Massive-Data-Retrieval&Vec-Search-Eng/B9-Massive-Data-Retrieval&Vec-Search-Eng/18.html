Near Real-Time Architecture, Translog Durability, 1s Refresh vs. 30m Lucene Commit Flush

1. 近实时 (NRT) 物理写路径与数据流 (Data Pipeline)

NRT Flow
// 写请求落地物理数据流
写请求 (Write Request) In-Memory & Translog Append

文档同时写入内存中的 **Index Buffer** 和追加写入磁盘的 **Translog 日志**。

1 秒刷新 (1s Refresh Pipeline) Index Buffer $\to$ OS PageCache

每秒自动触发 **Refresh**：将 Index Buffer 文档转写为新 Lucene Segment 写入 **OS PageCache**。进入 PageCache 后，文档**立刻变为可检索 (Near Real-Time)!**

30 分钟落盘 (30m / 512MB Flush) PageCache $\to$ Physical Disk

触发 **Flush**：执行 Lucene commit()，强行将 PageCache 中的所有 Segment `fsync` 刷入物理磁盘，清理旧 Translog。

关键解耦：不用等待昂贵的物理磁盘 `fsync`，利用 OS PageCache 换取 1 秒内搜索

2. NRT 核心三部曲与高吞吐调优 (Refresh vs Flush)

3 Core Stages
Refresh (刷新 - 1s 默认) `index.refresh_interval`

清空 Index Buffer 并生成可读的新 Lucene Segment 存入内存 PageCache。此时文档解封可搜，但尚未写入物理磁盘。在大批量 Bulk 写入时可调大为 `30s` 或 `-1` 提升 QPS！

Translog (事务顺序追加日志) WAL Durability

预防 OS PageCache 未落盘时节点突发断电。写 Buffer 的同时追加写 Translog。默认每请求或每 5 秒 `fsync` 落盘，确保节点重启时能够按日志重放还原内存数据。

Flush (落盘 - 30分钟 / Translog 满 512MB) Lucene Commit

真正的物理落盘流程！强行将 OS PageCache 中的 Segment `fsync` 到底层存储物理介质，写 Commit Point，并清空旧的 Translog 日志。

核心架构启发 (NRT Architecture Insight)

Elasticsearch 著名的**近实时 (NRT)** 架构展现了极为精妙的平衡术：利用 **Refresh (1s)** 将文档刷入 **OS PageCache** 让数据秒级可搜；利用 **Translog 顺序追加日志** 防范断电丢数据；最后利用 **Flush (30m)** 执行昂贵的物理磁盘 `fsync`。这种解耦彻底放大了高并发写与检索的整体吞吐量。
