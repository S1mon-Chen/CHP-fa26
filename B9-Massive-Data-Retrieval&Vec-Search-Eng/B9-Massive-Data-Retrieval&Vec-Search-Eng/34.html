大规模写入调优与 Bulk 吞吐提升 (Large-Scale Indexing & Bulk Tuning)

5 High-Throughput Ingestion Tuning Levers: Bulk Payload, Translog Async, Refresh Suppression & Zero Replicas

1. 提升大规模数据导入写入 QPS 的 5 大物理杠杆 (5 Ingestion Levers)

10x QPS Boost
1 批量 Bulk API 替代单条写入 (Batch Payload 5MB~15MB) Batching

避免单文档逐条 POST 带来的巨额 HTTP 握手与客户端线程阻塞开销，控制单次 Bulk 请求 Payload 大小在 5MB–15MB（约 5000–10000 条）。

2 调大或暂停 Refresh (`"refresh_interval": "60s"` 或 `"-1"`) Suppress Refresh

默认 1s 的 Refresh 会频繁产生碎片化的 Lucene 小 Segments 并引发频繁合并。大导入期间设为 `-1`（全量导入后再触发 `_refresh`），可将 QPS 翻倍！

3 Translog 异步刷盘 (`"durability": "async"`) Async Translog

将默认每请求 `fsync` 调整为每 5 秒异步刷盘，牺牲极微小断电落盘概率，彻底消除磁盘随机 I/O 阻塞。

4 临时零副本 (`replicas: 0`)

导入期设 `"number_of_replicas": 0`，免去跨节点副本网络同步，全量导入完成后再切回 1。

5 留足 50% OS PageCache

JVM 堆内存上限设定为 $\le 32\text{GB}$（不超 50% RAM），留出 50% 给 Lucene 段文件缓存。

效果：5 大杠杆协同叠加，可将海量数据导入写入 QPS 提升 1000% 以上

2. 生产环境大导入 Index Settings 调优 DSL

PUT /_settings
// 阶段 1: 导入前切换为高吞吐写配置
PUT /big_data_index/_settings
{
"index": {
"refresh_interval": "-1", // 暂停 Refresh
"number_of_replicas": 0, // 暂停副本同步
"translog": {
"durability": "async", // 异步 Translog 刷盘
"sync_interval": "10s"
}
}
}
// 阶段 2: 全量导入完毕后恢复正常读取设置
PUT /big_data_index/_settings
{
"index": {
"refresh_interval": "1s",
"number_of_replicas": 1
}
}
导入完毕后的收尾标准动作 Post-Load Routine

全量 Bulk 完成后，执行 POST /big_data_index/_forcemerge?max_num_segments=1 将大量 Lucene Segment 强制合并为 1 个最终段文件，并重新将副本数设置为 1，激活高可用状态。

核心架构启发 (Bulk Tuning Insight)

大规模写入调优的核心本质是**“资源暂时向写入吞吐让步”**：通过暂停 1 秒 1 次的 Refresh 和关掉 Replica 节点网络分发，将磁盘与网络带宽全部让给主分片顺序写入，待全量数据写入完成后再通过一次性 ForceMerge 与副本补发回归正常高可用状态。
