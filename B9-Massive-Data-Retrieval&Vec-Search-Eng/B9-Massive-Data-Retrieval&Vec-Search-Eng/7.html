Part 01 · 全文检索原理与 Apache Lucene 物理内核

段的不变性与合并 (Segment Immutability & Segment Merge)

Lock-Free Search, Logical Deletion (.liv BitSet) & Tiered Segment Merge Mechanics

1. Segment 物理不可变原则 (Immutability Principle)

Immutable Segments

Lucene 中的 Segment 一旦创建并写入磁盘，**绝对物理不可变 (Immutable)**！这一核心原则赋予了系统极致的并发检索性能：

① 零锁竞争 (Lock-Free Search) Zero Lock Contention

读写彻底解耦！并发检索无需施加任何读写排他锁，多个查询线程可并发无锁压榨 CPU 多核性能。

② OS PageCache 极度友好 Cached Forever

索引文件一旦加载到操作系统 PageCache 后长期有效，不会因为数据写入而导致缓存频繁失效或脏页重刷新。

// 面对 Segment 不变性，新增/修改/删除如何处理？
• 删除 (Delete)：不修改原 Segment，而是在 .liv (Live BitSet) 中将 DocID 标记为 0 (已删除)，检索时过滤。
• 更新 (Update)：先在旧 Segment 中标记逻辑删除，再将新版本的文档追加写入全新的 Segment 中。
代价：旧数据逻辑删除会遗留无效空间，需依靠后台段合并 (Segment Merge) 回收

2. 后台段合并机制 (Segment Merge)

TieredMergePolicy
// IndexWriter 自动触发段合并过程
Segment 1 (包含 3 个未删除, 2 个已删除)
Segment 2 (包含 4 个未删除, 1 个已删除)
Segment 3 (包含 5 个未删除, 0 个已删除)
↓ TieredMergePolicy (后台异步合并)
Segment 4 (合并后大段：物理剔除 3 个已删除文档，仅存 12 个有效文档!)
物理磁盘空间真正回收 Purge Deleted Docs

在段合并过程中，逻辑删除标记为 `0` 的文档将被真正物理剔除，解决物理空间膨胀。

保持检索性能与控制句柄数 FD Count Reduction

避免小 Segment 过多导致检索时遍历文件数过大、控制操作系统 Open File Descriptors 句柄开销。

核心架构启发 (Segment Immutability & Merge Insight)

Lucene 的 **Segment 不变性** 展现了现代存储引擎“无锁并发”的设计之美；而 **段合并 (Segment Merge)** 则通过牺牲一部分后台磁盘写 I/O，换取了检索时小段数量的压缩与逻辑删除文档的物理空间回收。
