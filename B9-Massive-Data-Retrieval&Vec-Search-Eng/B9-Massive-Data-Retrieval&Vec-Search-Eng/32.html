Part 03 · 向量检索与 AI 时代 Vector DB

检索增强生成 (RAG) 系统架构全景 (RAG System Architecture)

Offline Chunking & Dual-Indexing Pipeline, Online Hybrid Recall, Rerank & LLM Context Ingestion

1. 端到端 RAG 线上与线下双管线拓扑 (End-to-End RAG Pipelines)

RAG Topology
// 1. 离线/实时数据写入与双重索引管线 (Ingestion Pipeline)
企业文档/数据库 $\to$ 文档解析与语义切块 (Chunking) $\to$ Embedding 向量化 $\to$ 存入 Vector DB

文本切块为 512 Tokens（带 50-token 覆盖），调用 Embedding 模型转化为高维向量，同时构建 **BM25 倒排索引** 与 **HNSW 向量图索引**。

// 2. 在线 RAG 检索与大模型生成管线 (Online RAG Pipeline)
User Prompt ──► 双路混合检索 (BM25 + HNSW) Top 50-100 Candidates
└──► RRF 倒数排名融合 ──► Cross-Encoder 重排 (Reranker) Top 3-5 Chunks
└──► 组装 Prompt Context ──► 大语言模型 (LLM) ──► 事实对齐回答 Grounded Output
关键解耦：通过检索外部私有知识库作为 Prompt 上下文，彻底解决 LLM 幻读与时效性问题

2. RAG 系统的三大核心工程优势 (RAG Advantages)

RAG Pillars
① 根治大模型“幻觉” (Eliminating Hallucinations) Grounding

强制要求 LLM 根据检索出的真实 Chunk 进行归因回答，回答附带引用来源（Citation），大幅提升回答的可信度与准确率。

② 企业私有知识隔离与安全防护 (Data Security) Access Control

无需把企业敏感文档盲目提交给公有云模型微调；在 Vector DB 中配合 ACL 权限过滤，确保敏感文档“无权者无法检索”。

③ 实时知识更新与超低维护成本 (Low Cost) Zero Fine-Tuning

知识更新只需在 Vector DB 中增删 Chunk 记录，数秒内即刻生效；免去了数十万美元的高昂 LLM 微调 (Fine-Tuning) 成本。

开启 Part 04：Slide 33 · 海量检索治理与生产实战（Mapping 优化、Bulk 调优与 ILM 冷热架构）

核心系统架构启发 (RAG Architecture Insight)

RAG (检索增强生成) 成功实现了“检索技术”与“生成能力”的物理分工：**让 Vector DB / ES 负责精确无误的记忆存储与高质量召回，让大语言模型 (LLM) 负责高超的语言理解与推理总结**。这是现代 GenAI 落地企业级应用的最关键支柱。
