集群 Topology 与节点角色 (Cluster Topology & Node Roles)

Master-Eligible, Data Node, Ingest Node, Coordinating Role & `elasticsearch.yml` Configurations

1. ES 集群三大核心物理节点角色 (Node Roles)

Node Roles
Master-Eligible Node (候选主节点) Metadata Manager

参与选主 (Election) 并维护全局集群状态 (Cluster State)。负责**索引创建/删除**、分片 (Shard) 分配与路由表更新。生产环境建议独立部署，禁用数据存储以防垃圾回收卡死。

Data Node (数据节点) High I/O & CPU

保存物理 Shard 数据。执行具体的**文档 CRUD 读写**、倒排索引检索与复杂的 Buckets/Metrics 聚合。消耗大量 CPU、内存与磁盘 NVMe SSD。

Ingest / Coordinating Node (预处理与协调节点) Request Broker

**Coordinating** 角色接收客户端 REST 请求，根据路由计算分发给对应 Data Node，并汇总 (Reduce) 多 Shard 结果返回；**Ingest** 负责执行 Pipeline 预处理（文本提取/正则/Grok 解析）。

提示：任何节点默认都可以充当 Coordinating 协调节点，但独立 Coordinating 节点能有效缓解 Data 节点压力

2. `elasticsearch.yml` 角色配置与生产分离法则

YAML Config
// 1. 开发/测试环境：单节点全功能角色
node.roles: [ master, data, ingest ]
// 2. 生产环境推荐：专用角色隔离配置
# 专用 Master 节点 (不存数据，低配即可)
node.roles: [ master ]
# 专用 Data 节点 (高 CPU + 高内存 + NVMe SSD)
node.roles: [ data_content, data_hot ]
# 专用 Coordinating 协调入口节点 (高内存，不存数据)
node.roles: [ remote_cluster_client ]
生产环境角色分离三黄金法则 Best Practices
  • • **专用 Master (>=3 奇数个)**：防止脑裂 (Split-Brain)，绝对不处理读写与 Aggs，确保集群控制面稳定。
  • • **Data 节点内存保护**：堆内存设置为不超过 32GB (避免指针膨胀)，预留 50% OS PageCache 给 Lucene。
  • • **Coordinating 独立挡盘**：应对海量并发客户端连接，承担结果 Reduce 拼装开销。

核心架构启发 (Node Role Separation Insight)

Elasticsearch 集群的稳定高可用来自于**物理节点角色的职责分离 (Separation of Concerns)**。让专用的 **Master 节点** 专心做元数据决策，**Data 节点** 专心做磁盘 Lucene 检索，**Coordinating 节点** 专心做网络流量分发与结果 MapReduce 汇总，才能打造百万 QPS 级稳健架构。
