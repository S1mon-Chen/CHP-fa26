Part 01 · 全文检索原理与 Apache Lucene 物理内核

Lucene 核心数据模型 (Lucene Data Model & Core Abstractions)

Physical Hierarchy: Index $\to$ Document $\to$ Field $\to$ Term Tuple

1. Lucene 数据模型物理包含关系 (Model Container)

Physical Hierarchy

Apache Lucene 对全文检索建立了极其严密的层级抽象（从宏观索引容器到最小检索单元 Term）：

// Index (逻辑索引：包含多个 Segment 段)
├── Document 1001 (检索与存储的物理基本单位)
Field "id" StringField("1001") [Verbatim]
Field "title" TextField("Lucene in Action") [Analyzed]
Field "price" DoublePoint(39.99) [1D B-Tree]
Field "vector" KnnFloatVectorField([0.12, -0.45, ...])
├── Document 1002 ...
特点：无 Schema 强约束（非 Schema-less，但不同 Document 的 Field 可动态变化）

2. 四大核心抽象对象与物理职责 (4 Core Abstractions)

Core Abstractions
1 Index (索引) Logical Container

包含一系列 Document 的逻辑容器。物理上由一个或多个不可变的**段 (Segment)** 组合而成。

2 Document (文档) Unit of Retrieval

检索与结果返回的物理基本单位（相当于数据库中的一行）。包含一组命名的 Field。

3 Field (字段) Key-Value & Type

字段名、数据类型与字段值的集合。支持文本 (`TextField`)、精准词 (`StringField`)、数值点 (`LongPoint`)、DocValues 以及高维向量 (`KnnFloatVectorField`)。

4 Term (词项) Atomic Search Unit

倒排索引中的最小检索单元，物理表达为 (FieldName, BytesValue) 二元组。即使字节流相同，不同 Field 里的词项物理上亦完全隔离。

开启下一个核心：Slide 5 · Analysis 分词管线 (Tokenizer & TokenFilter 拆解)

核心架构启发 (Lucene Data Abstraction Insight)

Lucene 的层级模型将复杂非结构化数据解构为 **Index $\to$ Document $\to$ Field $\to$ Term**。注意 **Term 是二元组 `(FieldName, BytesValue)`**：搜索 title:lucene 与 content:lucene 命中的是倒排索引中两个物理上独立的 Term！
