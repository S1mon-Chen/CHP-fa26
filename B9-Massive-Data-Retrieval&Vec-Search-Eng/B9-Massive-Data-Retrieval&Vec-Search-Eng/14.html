Concept Matrix

2. 物理底盘：1 个 ES Shard = 1 个完整 Lucene 实例

Shard Physics
为什么 ES 彻底废弃了 `Type`？ Sparse Field Bug

在同一个 Lucene Index 中，不同 Type 的同名字段（如 `user.name` 和 `tweet.name`）物理上共享同一个 Lucene Field 数据结构，容易引发稀疏数据 (Sparse Field) 存储浪费与倒排冲突。因此 ES 7+ 废弃 Type，全面推行 1 Index 对应 1 业务表。

核心物理架构启发 (Physical Lucene Engine Insight)

透视 ES 的物理底盘至关重要：**Elasticsearch 并不直接写文件，而是将写请求分发给底层的每一个 Shard——而每一个 Shard 就是一个完全自治的 Apache Lucene 引擎实例**。ES 的本质是建立在海量单机 Lucene 实例上的分布式网关与集群协调框架。
