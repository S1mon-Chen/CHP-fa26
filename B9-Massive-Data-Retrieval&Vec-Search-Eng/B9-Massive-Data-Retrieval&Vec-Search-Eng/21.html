Elasticsearch 聚合分析：Buckets 与 Metrics (Aggregations)

Distributed Analytics Engine, Bucket Grouping (Terms, Date Histogram) & Metric Calculations (Stats, Cardinality)

1. ES 聚合两大维度：Buckets (分桶) 与 Metrics (指标)

Buckets vs Metrics
Bucket Aggregations (分桶聚合 $\approx$ SQL `GROUP BY`) Document Sets

根据特定条件将文档划分到不同的“桶 (Bucket)”中，每个桶包含满足该条件的数据集合。

  • • Terms Agg：按字段具体值分桶（如按 `category.keyword` 分类）。
  • • Date Histogram：按时间粒度（按天、按小时）自动切分时间直方图。
  • • Range / IP Range：按数值区间（如价格 50-100）或 IP 段分桶。
Metrics Aggregations (指标聚合 $\approx$ SQL `SUM/AVG`) Calculations

针对文档桶内的数值字段计算具体的统计指标值。

  • • Stats / Extended Stats：一次性计算 `min`, `max`, `avg`, `sum`, `count` 及方差。
  • • Cardinality：微秒级基数估算（基于 **HyperLogLog** 算法高并发计算 UV）。
  • • Percentiles：百分位数分布（如 API 响应延迟的 p50, p95, p99 统计）。
底盘支撑：聚合分析完全依托 DocValues (.dvd) 高性能列式存储进行物理运算

2. 嵌套聚合 DSL 实战 (Nested Aggregations DSL)

POST /sales/_search
// 经典按分类分桶 + 计算各桶平均价格 DSL
{
// size: 0 表示仅返回聚合结果，不返回明文档
"size": 0,
"aggs": {
// 1. 顶层 Bucket 聚合：按 category 分桶
"by_category": {
"terms": { "field": "category.keyword" },
"aggs": {
// 2. 子 Metric 聚合：计算当前分类桶内的平均价格
"avg_price": {
"avg": { "field": "price" }
}
}
}
}
}
聚合性能调优关口 `size: 0` & DocValues

针对只需大盘图表分析的场景，设置 "size": 0 能彻底跳过 StoredFields (.fdt) 的 Fetch 阶段，仅读取内存映射的 DocValues (.dvd)，将响应时间压缩到毫秒级！

核心架构启发 (Aggregations Insight)

Elasticsearch 不仅是搜索引擎，更是极强大的分布式海量数据分析引擎。通过 **Buckets (分桶) 与 Metrics (指标) 的任意多层嵌套**，结合底层 **DocValues 列式存储**，无需离线 Hadoop 批处理即可对数十亿条日志实现秒级 OLAP 大盘统计。

Speaker Notes / 讲师讲稿
🎯 引导学员理解 Buckets 与 Metrics 的嵌套关系： “向学员做解构说明：ES 的聚合分析非常强大。分为两大类：
1. **Buckets (分桶)**：类似于 SQL 的 `GROUP BY`，把文档划分成不同的集合（比如按分类 `category` 分桶，或按时间 `date_histogram` 分桶）；
2. **Metrics (指标)**：类似于 SQL 的 `AVG/SUM/COUNT`，在分好的桶内部计算数值指标。
桶与指标可以进行任意深度的嵌套！比如‘按商品分类分桶 $\to$ 桶内按品牌再分桶 $\to$ 计算每个品牌的平均价格’。”
💡 剖析 `"size": 0` 的性能优化关口： “请学员注意右侧 DSL 代码：当做统计大盘分析时，务必设置 `"size": 0`。这样 ES 就不会去读取磁盘上的原始文档 (.fdt)，而是直接读取内存映射的列式存储 DocValues (.dvd)，极大提升响应速度！下一个 Slide 22 将讲解 **ES 8.x 现代强类型 Java API Client 实战**。”
