结构化指令核心概念

什么是结构化指令工程？

从 “随意自然语言描述” 到 “规范化工业级指令契约” 的维度升级

01

角色域 (System Role)

设定 LLM 的认知视角、专业领域与责任边界。激活特定领域的参数先验集。

// 示例 / Code Reviewer
Role: Senior Java Architect
Scope: Security & Performance
锁定领域知识上下文
02

目标指令 (Instruction)

明确、无歧义的原子级任务说明。使用动词开头的分步骤推理指导，消除语义模糊性。

// 示例 / Step-by-Step Task
1. Analyze SQL execution plan
2. Identify full table scan
确立清晰计算流程
03

确定性边界 (Constraints)

负向约束与输出结构契约。明确指示“禁止做什么”与“必须满足的强类型 Schema”。

// 示例 / Defensive Rules
- NO markdown text
- Return valid JSON only
阻断熵增与格式崩溃

Architectural Takeaway / 架构小结

结构化提示词本质上是降低大模型输出熵（Entropy）的控制工程。缺少任意一个要素（角色、目标或约束），系统的输出方差都会急剧上升。

Speaker Notes / 讲师讲稿
🎯 概念升维： “向学生强调，提示词工程不是随心所欲地跟聊天机器人说话，而是像定义接口 API 一样，定义 Role（上下文先验）、Instruction（逻辑步骤）和 Constraints（约束边界）。”
💡 案例对比： “如果不加 Role，模型可能给出泛泛的自然语言解释；如果缺少 Constraint，模型可能会附带大量的礼貌客套话，破坏 downstream parser 的 JSON 解析。”
