模块二：结构化上下文与确定性输出

确定性 JSON 输出：从 Prompt 约束到 JSON Schema / Pydantic

剖析结构化输出的三代技术演进：从 自然语言弱提示 到 JSON Schema 注入，最终走向 语法约束采样 (Constrained Decoding) 与 Pydantic 强类型契约

Level 1: 提示词约定

自然语言弱提示约定

在 Prompt 末尾硬编码：“请只返回纯 JSON 格式，不要包含任何 Markdown 三重反引号或解释性文字”。

// 高概率失败输出
"好的，这是为您分析的结果：
```json
{"status": "ok"}
```"
  • 解析崩溃率 > 30%，产生 Markdown 包裹或客套话
  • 缺失字段类型校验与必填断言
绝不可用于生产环境 可控度: 40%
Level 2: Schema 拼接注入

Few-Shot + Standard JSON Schema

将系统的 JSON Schema 定义或标准 Few-Shot 范例直接拼接入 Prompt 上下文，指导模型推演。

<output_schema>
{"type": "object", "properties": {...}}
</output_schema>
<example>{"status": "SUCCESS"}</example>
  • 显著降低格式错误率，提供范例参考
  • 占用大量 Context Token；高并发下仍偶发乱序
适用于无原生 Tool Call 模型 可控度: 85%
Level 3: 语法约束采样

Pydantic + Grammar-Based Decoding

在 Logit 采样阶段使用文法树（GBNF / JSON Grammar）进行物理卡死，非法 Token 概率直接降为 0。

class CodeReviewResult(BaseModel):
passed: bool
issues: List[IssueItem]
client.beta.chat.completions.parse(...)
  • 100% 语法确定性：绝对物理零格式解析报错
  • 代码原生结合：自动反序列化为强类型 DTO
工业级 Agent 标准采纳方案 可控度: 100%
Production Pydantic + Constrained JSON Integration Pattern 100% Type-Safe API
from pydantic import BaseModel, Field
from typing import List, Literal

class CodeIssue(BaseModel):
file_path: str
severity: Literal["CRITICAL", "WARNING", "INFO"]
suggestion: str = Field(description="具体的修复建议")
class CodeReviewReport(BaseModel):
summary: str
issues: List[CodeIssue]

# 关键：通过 Structured Outputs API 或 Instructor 进行约束采样
response = client.beta.chat.completions.parse(
model="gpt-4o", response_format=CodeReviewReport
)

Architectural Shift / 架构师原则

在生产级 AI 系统中，永远不要相信模型“会自律地返回纯 JSON”。必须通过底层 Logit Masking（约束采样）或 Pydantic + Instructor 构建零幻觉数据反序列化管道。
