Zero-Shot vs Few-Shot 在代码场景的边界

明确范式选择的临界点：从 标准 Open Source API 调用的 Zero-Shot 敏捷生成，到 企业私有 SDK、自研 DSL 与编码风格契约 的 Few-Shot 精确对齐

Zero-Shot Direct Prompting Standard Knowledge

适用边界：标准公共库与经典算法

依赖大模型 Pre-training 阶段吸纳的海量开源代码先验，无需在 Prompt 中放置示范例即可一次性精准生成。

// Prompt: "用 Python stdlib 实现 LRU Cache"
from collections import OrderedDict
class LRUCache(OrderedDict): ...
  • 最佳场景：Python/Java 标准库、LeetCode 经典算法、RFC 协议
  • 失能死穴：企业内部包（如 `com.internal.rpc.*`）、私有配置规范
Token 消耗最低，响应延迟最优 幻觉率: 高(私有域)
Few-Shot In-Context Learning Domain Alignment

适用边界：私有 SDK、DSL 转换与团队规范

在 Prompt 中注入 2~3 个 `` Input-Output 参照对，对齐特定命名法则、异常处理约定与转译逻辑。

<example_1>
In: SQL Select -> Out: Custom QueryBuilder DTO
</example_1>
<target_input>SELECT name FROM users</target_input>
  • 最佳场景：自研框架注入、DSL 生成、代码风格 100% 对齐
  • 架构收益：无需微调（Fine-Tuning），以零成本实现格式强拟合
占用额外部份 Context Token 格式拟合度: >95%
01

Relevance (语义相关性)

借助 RAG 向量检索，从知识库中动态选择与当前 Task 最相似的示例（Semantic Similarity），避免无关范例占用 Context。

02

Diversity (范例多样性)

示例需覆盖边界状态（如空数组、网络超时异常），教会 LLM 在生成业务代码时自动补全边界判空防护。

03

Negative Examples (对比反例)

引入 <bad_example> 说明“禁止编写的垃圾代码”，实现对比引导（Contrastive Prompting）。

Architectural Decision Rule / 决策黄金准则

通用算法用 Zero-Shot 省 Token；团队私有框架、自研 DSL 转译与规范约束，必须使用 动态 RAGFew-Shot 范例对齐。

🎯 引导学员理解“为什么 Few-Shot 可以替代模型微调”： “向学员强调：在企业代码场景中，去专门微调一个基座模型成本极高且容易产生过拟合（Overfitting）。而利用 Few-Shot In-Context Learning，配合基于向量数据库的动态示例检索（Dynamic Few-Shot RAG），可以在零微调成本的前提下，让大模型 100% 遵守企业内部私有 SDK 和架构规范。”
💡 强调反例教学（Negative Examples）： “告诉学员：不要只给模型提供正确代码范例！在 Prompt 中显式加入 ``（如未关连接的数据库查询），并标注‘绝对禁止此类写法’，效果往往比单独正面强调好倍以上。”
