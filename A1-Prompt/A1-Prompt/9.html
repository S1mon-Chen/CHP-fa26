结构化提示格式规范：Markdown、XML 与 YAML 的对比

剖析不同格式在 上下文隔断、语法歧义度 与 抗提示注入能力 上的工程表现

Markdown Format

自然语言与 Markdown 代码块

使用 ````` 包裹代码与 `#` 标题划分区块。适用于通用交互与文档生成。

# Instruction
Review this code:
```python
def add(a, b): return a+b
```
  • 预训练权重天然亲和，无额外学习成本
  • 嵌套黑洞：代码内若含 ``` 易早熟闭合崩溃
适用场景：单文件代码片段 / Markdown 文档生成
Anthropic Standard

XML 显式标签语法 (XML Tags)

使用带有闭合标记的定制标签（如 ``、``），精准定义逻辑区块与文件边界。

<instruction>
Analyze code for bugs
</instruction>
<code path="main.py">
def run(): pass
</code>
  • 零语法二义性：精确闭合边界，完美支持树形嵌套
  • 强抗注入：轻松隔断代码注释中的恶意指令
推荐场景：多文件 Codebase / Code Agent / 复杂 System Prompt
YAML / JSON Format

YAML 配置与 Key-Value 序列化

使用标准配置字典表达复杂元数据。极适合系统参数、微服务配置与无代码规则列表管理。

task: Refactor
rules:
- "Max cyclomatic complexity: 5"
target_file: "service.py"
  • 编程语言原生解析方便（如 `yaml.safe_load`）
  • 多行长代码缩进处理繁琐，换行符易转义失真
适用场景：系统元数据注入 / API 规则声明

Architectural Recommendation / 架构规范指南

在代码 Agent 系统中，首选 XML 标签作为上下文隔离容器。XML 能有效隔离包含三重反引号（```）的源码文件，彻底解决 Markdown 代码块混淆与二义性问题。

🎯 讲授核心痛点（Markdown 破坏）： “向学员展示：当我们在 Prompt 中使用 Markdown 三重反引号装载一个包含 Markdown 文档编辑器的 `.md` 或 `.py` 代码文件时，源码中的反引号会导致外层反引号提前闭合，破坏整个上下文。这是 Markdown 的物理缺陷。”
