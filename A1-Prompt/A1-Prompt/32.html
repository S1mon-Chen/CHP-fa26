模块四：工具与物理状态交互 / Module 4: Runtime Fault Tolerance

ReAct 的常见失效模式与恢复机制

剖析 Agent 运行时的 4 大经典崩塌陷阱：解构 死循环 (Infinite Action Loop)、语法/Schema 解析崩溃、Observation 上下文爆表 与 环境状态不对齐，并建立自愈型架构控制流

1. 动作死循环 (Infinite Action Loop) Repeated Action

LLM 陷入固定概率陷阱，重复调用完全相同参数的工具（例如反复执行 ls -la），导致 Agent 耗尽 Token 预算而无法向目标推进。

2. 语法/Schema 解析崩溃 (Syntax/Schema Failure) Parse Error

吐出的 JSON 缺少双引号、包含未转义的多行字符串或遗漏必填参数字段。若 Controller 抛出异常直接中断主进程，Agent 任务便提前夭折。

3. Observation 日志过长 (Context Window Overflow) Context Bloat

工具（如 npm install 或全量 Maven Build）抛出数万行原始日志，瞬间挤爆上下文窗口，导致之前积累的 System Instructions 与中间推理全盘丢弃。

4. 环境物理状态不对齐 (State Desync / Zombie Process) Zombie State

前一次 Action 在沙箱中占用了端口或残留了后台锁（如未关闭的子进程），后续 Step 误以为环境清洁，持续报端口冲突引发无法解释的连锁故障。

Self-Healing Agent Controller Architecture Runtime Safeguards
[Fix 1] Hash Deduplication Guard
Controller 维护 `seen_actions` 哈希集合。若相同参数连踩 2 次，自动插入系统警告： "Warning: You performed this EXACT action twice with same output. Change your strategy!"
[Fix 2] Syntax Error Feedback Reprompt
JSON 解析失败时不 Crash，而是包装为特殊 Observation 回写： `Observation: ValidationError in param 'filepath': field required. Please fix JSON.`
[Fix 3] AST / Tail Log Pruning
日志若超过 2000 Tokens，使用正则提取 `ERROR` / `FAILED` 关键行 + 尾部 50 行，其余用 `/* ... [14,200 lines truncated] ... */` 替换。
[Fix 4] Container Snapshot & Cleandown
关键 Step 后自动触发清理脚本（如 pkill -f node 与 git checkout .），隔离物理有状态干扰。
从“一错就崩”提升至“容错自愈” Robustness +95% ★
01

`Hash(Action)` 去重熔断

在 Controller 中维护历史 Action 指纹，检测到无意义重复操作时强行向 LLM 注入方向纠偏指令。

02

错误堆栈即 Feedback

将工具执行失败、解析失败的 Traceback 转化为 `Observation` 喂回模型，让 LLM 在下一 Turn 自我修补。

03

智能日志截断 (Log Pruning)

严禁海量 Shell 日志直接灌入上下文，必须保留堆栈报错上下文与控制末尾，防止 Context 溢出。

Architectural Self-Healing Rule / 运行时自愈法则

生产级 Agent 控制器的灵魂在于“把异常当作正常 Feedback 处理，而非直接崩溃中断”；结合硬计数熔断、语法反写与沙箱状态重置，才能打造坚不可摧的 Agent 运行时。

🎯 剖析 ReAct 生产级防崩要点： “向学员强调：Demo 级别的 ReAct 只要跑通一次 happy path 就行，但工业级的 Agent 框架 90% 的代码量都在写**容错与自愈**。必须假设工具会报语法错误、Shell 输出会有几万行、甚至模型会在同一个动作上死循环。”
💡 强调‘Error As Feedback’哲学： “告诉学员：当代码发生 JSON 解析失败时，千万不要在 Controller 里 `raise Exception` 直接停掉程序！正确的做法是捕获报错信息，把它装进一个 `Observation: [Error Traceback]` 投递给大模型，模型在下一个 Turn 往往就能自己把缺少引号或必填项补全。”
