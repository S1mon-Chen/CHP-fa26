LLM 底层计算机制与特性

LLM 文本生成底层原理：自回归与注意力机制简析

理解 Token 概率预测模型如何推演代码，以及为何 “前文的微小偏差” 会导致 “灾难性代码漂移 (Error Cascading)”

原理 01

自回归生成 (Autoregression)

LLM 本质是一个逐 Token 的条件概率预测器，依据历史所有 Token 推算下一位置的概率分布：

// Token 条件概率公式

P(wt | w1, w2, ..., wt-1)

单向推演：无原生“事后重写”机制。
代码逐行生成，后文强依赖前文语法。
原理 02

自注意力权值 (Self-Attention)

计算当前生成 Token 与上下文已有 Token 之间的关联度（$QK^T$ 点积注意力）：

// Scaled Dot-Product Attention

Attention(Q,K,V) = softmax(QKT / √dk)V

上下文关联：建立变量声明与调用的映射。
注意力衰减：长距离导致关键接口被忽略。
架构风险

错误级联效应 (Error Cascading)

当 prompt 或生成早期产生了一个微小错误（如错别字或虚构方法名），模型将该错误加入 Context 后：

1. 初始提示模糊 / 误导
↓ 自回归把错误作为已知条件
2. 产生幻觉 API / 错误类型定义
↓ 强行自我圆谎 (Self-Consistency Failure)
3. 灾难性代码崩塌 / 彻底无法编译

这就是为什么需要在输入端做强类型与 XML 隔断的本质原因！

Architectural Insight / 架构师洞察

LLM 缺乏编译器的“前瞻词法分析”与“回溯修改”能力。因此，指令工程的核心任务是**在初始上下文（Step 0）建立绝对清晰的约束**，截断错误级联链条。
