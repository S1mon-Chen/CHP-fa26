1. 巨型 Prompt 吞噬 (Mega-Prompt Monster) Token Bloat

把 50 条业务规则、全量架构文档与大量无关代码静态塞入单个 Prompt，引发注意力中间迷失 (Lost-in-the-Middle) 与响应延迟飙升。

2. 形容词替代定量断言 (Adjective Anti-Pattern) Ambiguity

使用“高质量”、“优雅”、“高性能”等主观词汇。应替换为硬性量化指标（如“圈复杂度 $< 5$”、“只允许 $O(n)$ 时间复杂度”）。

3. 假设输入 100% 有效 (Blind Trust Input) No Pre-Condition

未设置前置条件断言，当用户提交缺失上下文的代码片段时，模型被迫凭空“脑补”假设，导致产生虚构 API 与严重幻觉。

4. 隐式提权与未授权沙箱 (Unrestricted Shell) Security Void

直接暴露包含删库、网络外联权限的终端沙箱，且缺失 Human-in-the-Loop 人工审核卡扣，面临间接提示注入删库风险。

01

静态规则剪枝 (Scope Triggers)

使用路径匹配 (Glob Matching) 仅在编辑 API 层时装载接口校验规则，绝不全量加载不相干规则。

02

结构化输出强约束

废弃基于文本的“请返回 JSON”提示，改用 API 原生 Pydantic / GBNF 语法树掩码 (Logit Masking)。

03

错误即 Feedback (Self-Healing)

将模型语法解析失败与单元测试 Traceback 包装为 Observation 喂回，驱动 Agent 自动收敛。

Architectural Anti-Pattern Rule / 避坑工程法则

提示词不是聊天表白，而是控制非确定性计算单元（V-CPU）的严格软件工程契约；杜绝主观描述、引入动态剪枝与沙箱硬约束，才能构建不退化的企业级 AI 应用。

Speaker Notes / 讲师讲稿
🎯 剖析反模式（Anti-Patterns）的教学价值： “向学员强调：很多初学者看了前面的最佳实践后，依然会在日常开发中写出反模式。最常见的就是用‘简洁’、‘高性能’等模糊形容词去指导大模型，或者把所有规范扔在一个几千行的 Mega-Prompt 里，结果导致注意力中间迷失 (Lost in the Middle)。”
💡 总结重构解法： “告诉学员：把形容词重构为定量指标（如‘圈复杂度 $< 5$’），把 Mega-Prompt 拆解为动态 Scoped Rules（如 `.cursor/rules/*.mdc`），并用 Pydantic 强类型契约卡死 JSON 输出，这才是解决生产环境 AI 编程不确定性的关键法则。”
