控制权倒置 (Control Loop Inversion) Core Pattern

大语言模型本身无状态且无法直接调用 OS API。Controller 作为宿主进程充当状态机：拦截 Action 指令、在沙箱中运行工具、将 Observation 打包再投递给 LLM。

超时熔断与挂起防护 (Timeout Guard) Safety Lock

沙箱工具执行必须设置严苛超时限制（如 Bash 限制 30 秒）。防止诸如阻塞式 `npm start` 或等待键盘输入的指令将 Controller 线程彻底死锁。

上下文缓冲区增量追加 (Context Sync) Memory Sync

工具调用的原始输出（Observation）需经过结构化清洗后追加至消息数组。Controller 维护长对话历史，防止在多轮交互中丟失任务目标。

01

强隔离物理沙箱

Tool Executor 必须运行于隔离容器（Docker/Firecracker）或零信任微进程中，切断删库与越权网络风险。

02

状态机硬计数熔断

Controller 必须对 `Max Iterations` 进行硬编码计数（如最多 15 步），单任务超时强行向用户抛出异常。

03

原生 Function Calling 升级

将早期基于正则解析 Action 的文本模式，升级为 API 原生的 Function Calling Schema 契约调用。

Architectural Sequence Rule / 系统时序法则

ReAct 系统的灵魂是“调度器 (Controller) 掌控绝对状态机主导权，LLM 仅作为无状态逻辑决策节点”；通过严密的工具超时隔离与状态回调，保障 Agent 系统在面对复杂物理环境时的坚固性。

🎯 剖析 ReAct 系统时序的核心： “向学员强调：很多初学者以为 ReAct 是大模型自己‘直接调了 API’。实际上，大模型只负责输出结构化的字符串（如 Function Call JSON），真正的网络请求或 Shell 命令是由外层的 **Controller 调度器** 捕获并送到沙箱执行的。这叫控制权倒置（Control Loop Inversion）。”
💡 强调超时与安全卡扣： “向学员提醒：在写 Controller 状态机时，千万不要对沙箱执行做无限等待！必须设置 Timeout 和最大循环步数，这是生产级 Agent 避免耗尽 API 预算与服务器 CPU 的命门。”
