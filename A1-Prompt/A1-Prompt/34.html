Enterprise Multi-Tier Rule Inheritance Architecture Rule Cascade Engine
Tier 1: Global Enterprise Security Gate (公司级红线) Highest Priority ★
严禁硬编码 AK/SK、凭证密钥；禁止引入许可证不合规开源库 (GPL/AGPL)；硬性隔离敏感 PII 数据。
Tier 2: Repository Rule Spec (`.cursorrules` / `CLAUDE.md`) Repo Scope
锁定特定的前端/后端框架约束（如 Next.js App Router、Tailwind CSS、Spring Boot 3.0 DTO 命名与 Lombok 规则）。
Tier 3: Dynamic Module AST Scope (`.cursor/rules/*.mdc`) Dynamic Match
匹配模式 glob: "src/api/**/*.ts" 时，仅在改动 API 接口层时装载 OpenAPI & Zod 检验规则。
继承链: Enterprise Security $\to$ Repo ADR $\to$ Scoped File Match 防冲突覆写机制
按需装载与剪枝 (Scoped Injection) Token Saving

拒绝把 2000 行全量规范静态写在单个 `.cursorrules` 中！采用按需匹配（Glob / File Matching），修改前端 CSS 时绝不灌入后端数据库迁移规则。

强否定约束与对比示例 (Bad vs Good) Contract Quality

消除“代码要写得好”等泛泛而谈的废话。规则必须包含否定指令（如“严禁使用 any 类型”）与对立范例（<bad_example> vs <good_example>）。

XML 结构化隔离 (Tag Architecture) Tag Isolation

将规则划分在 ``、``、`` XML 标签内，便于 Agent 解析器将规则压入最高级别的 System Instruction 提示面板。

01

代码规范 ADR 文件化

将团队的架构决策记录 (ADR) 直接转化为规则配置文件，实现新员工与 AI 助手同步对齐编码标准。

02

防范规则过载 (Rule Bloat)

控制单个规则文件不超过 100~150 行，避免无关规则占用过多 Context 挤占真正的代码上下文空间。

03

Git 仓库强版本管控

规则文件（如 `.cursorrules` 或 `CLAUDE.md`）必须提交至 Git 仓库，确保全团队协同与 CI 自动化判定标准绝对一致。

Architectural Rule Engine Principle / 规则引擎法则

企业级 AI 编程的灵魂是“规则分层继承 + 动态 AST 作用域匹配”；把团队架构标准编码为规则契约，才能保障 AI 辅助生成代码 100% 契合企业生产规范。

🎯 剖析 .cursorrules 与 CLAUDE.md 的工程演进： “向学员强调：很多团队开始使用 Cursor 或 Cline 时，把所有规范硬挤在一个 `.cursorrules` 文件里，导致文件越来越大、包含几千行规则。结果 AI 在修改简单的 CSS 时，注意力却被几千行不相干的 SQL 优化规则严重干扰，既浪费 Token 又降低准确率。”
