剖析 Madaan et al. (2023) 与 Shinn et al. (2023) Reflexion 范式：引入 生成 (Generate) $\to$ 评估 (Feedback) $\to$ 修正 (Refine) 闭环，配合 沙箱单测/静态分析反馈 克服模型内在“盲目自自信”

def compute_discount(user, cart): ... # 忽略了 user.level 为 None 的边界

纯内部自纠（Intrinsic Correction）的陷阱 Warning

简单提问“请检查你刚才写的代码是否有错”效果极差（确认偏误 Confirmation Bias）。没有外部客观信号时，模型倾向于坚信自己第一版代码是正确的。

环境驱动自纠 (Extrinsic Feedback) Best Practice

必须引入物理环境反馈（Docker 编译输出、Pytest 单元测试失败堆栈、SonarQube 静态检查报错）。把绝对事实输入给 Refiner 才能触发高质量纠错。

反射记忆 (Reflexion Memory Buffer) Reflexion

将前几轮“尝试失败原因与反思总结”显式追加至上下文缓冲区（Episodic Memory），防止模型在多轮迭代中陷入同一个 Bug 的死循环。

01

严格最大迭代保护 (Max Iterations = 3~5)

必须设置硬性终止计数阈值，防止模型在无法解决的问题上无限重试耗尽 Token。

02

提示词差异化解耦

Generator（注重代码生成）、Evaluator（严苛审核规则）、Refiner（精准改写）建议使用不同的 Prompt 角色。

03

闭环反馈结构化化

将编译器与沙箱报错提取为简洁的 JSON 反馈协议，避免原始海量日志挤爆上下文。

Architectural Reflection Rule / 自我反思法则

自我反思（Self-Refinement）的威力取决于外部客观反馈信号（Environment Signals）的质量；结合单元测试沙箱报错喂给 Refiner，是自动化解决复合 Bug 的关键。

🎯 剖析自我反思（Self-Refinement）误区： “向学员强调：学术界（如 Huang et al. 2023）已经证明，如果没有外部环境反馈（Environment Feedback），仅仅让大模型‘自问自答检查是否有错’，模型的准确率几乎没有任何提升甚至会下降，因为模型存在确认偏误（Confirmation Bias）。”
💡 强调 Reflexion 的核心突破： “Reflexion（Shinn et al.）之所以有效，关键在于引入了 **单测执行反馈** 和 **反射记忆缓冲区（Reflexion Memory Buffer）**。它将错误的单元测试堆栈作为硬约束输入，让模型针对具体 Traceback 写总结反思，从而避免重复犯错。”
