思考步骤标准化 (Thought Taxonomy) Rule 1

在范例的 `` 中必须固定步骤名称（如 `Step 1 [分析]`, `Step 2 [模式选型]`, `Step 3 [边界校验]`），强制 LLM 模仿相同的结构化思考路径。

边界条件主动注入 (Edge Cases Injection) Rule 2

范例中不仅示范正常逻辑，还要在 Thought 中专门示范“如何判断 null 指针与空数组”，教会 LLM 在新任务中自动触发边界防护。

与企业架构风格 100% 对齐 Rule 3

将团队特定的 Lombok 注解、Slf4j 日志记录、自定义 Result<T> 包装类直接内嵌在 Few-Shot 示例输出中，实现编码规范零偏差。

01

思考与代码分离

范例中必须将思维推演装入单独标签，避免思考过程污染最终代码解析。

02

数量原则 (2-3 个足矣)

代码场景下 2~3 个精品 Few-Shot CoT 范例即能达到 95%+ 的格式拟合度，过多会浪费 Context。

03

动态 RAG 注入

结合向量数据库，按当前 Task 的语义动态检索最相似的 Few-Shot CoT 范例组合。

Architectural Design Rule / 架构工程规则

高质量的 Few-Shot CoT 示例是把人类架构师的思考模型（Mental Model）形式化编码并注入 AI 上下文的最佳桥梁。
