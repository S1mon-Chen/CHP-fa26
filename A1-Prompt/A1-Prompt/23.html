克服 CoT 无“悔棋”能力的死穴 Core Value

传统 CoT 一旦在第一步做出了错误的技术选型（如选错数据结构），后续全部自回归过程只能“自圆其说”。ToT 引入回溯（Backtracking）机制，允许发现低分节点后退回父节点重择路线。

外部评估器 (Evaluator Harness) 结合 Heuristics

节点的评分不仅仅依赖 LLM 自评，还可无缝结合外部静态分析器（SonarQube）、AST 复杂度检测、甚至直接放入 Docker 沙箱尝试编译打分。

o1 / o3 / Reasoning 模型的前身思想 Evolution

当今 OpenAI o1/o3 与 DeepSeek-R1 等底层 Reasoning 模型，本质上就是将 ToT 的树状搜索与启发式奖励打分（PRM/ORM）通过强化学习内化到了模型采样层。

01

状态节点显式表示

必须将中间状态（State）抽象为明确的数据结构（如方案元数据 + 代码草稿），便于 Python 调度器序列化并进行树拓扑管理。

02

早期快速剪枝 (Pruning)

设置严苛的 Heuristic 阈值，评分 $< 0.4$ 的分支立即熔断淘汰，防止爆炸式展开导致 Token 成本失控。

03

适合非线性决策任务

最推荐用于大型系统架构选型、复杂重构方案评估以及 LeetCode 困难题/算法竞赛题求解。

Architectural Search Rule / 空间探索法则

Tree-of-Thoughts (ToT) 是将大模型从“单路径一吐到底”升维至“状态树空间搜索”的关键范式；通过在图节点间引入评价与剪枝，能实现高难度技术决策的全局最优解。
