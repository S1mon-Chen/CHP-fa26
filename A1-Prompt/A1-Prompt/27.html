ReAct Interleaved Execution Engine Trace Yao et al. 2022
[Task Query]: "排查 `auth_service.py` 登录失败抛出 KeyError 的根因并修复"
Thought 1:
"我需要首先找到 `auth_service.py` 文件中关于密钥解包的位置"
Action 1:
file_search(pattern="auth_service.py")
Observation 1:
Found: `./src/services/auth_service.py` (Line 42: `payload['user_id']`)
Thought 2:
"源码直接从 JWT payload 拿 `user_id`，但最新 OAuth2 规范返回的是 `sub`。让我跑单测确认"
Action 2:
execute_pytest(test_path="tests/test_auth.py")
Observation 2 (Error Grounding):
FAILED: `KeyError: 'user_id'` in `payload.get('sub')` scenario.
Thought 3 & Final Action: 自动发起修补 Fixed & Pass ★
Replaced `payload['user_id']` with `payload.get('user_id') or payload.get('sub')`. Tests passed!
交织闭环: Thought $\to$ Action $\to$ Observation $\to$ Thought Grounding 现实锚定
推理与动作的协同协同 (Synergy) Core Value

Thought 负责规划方向并维护长期目标上下文，Action 将意图转化为系统调用，Observation 则从物理世界拉取绝对事实，防止 Thought 无根脑补。

实时消杀幻觉 (Error Grounding) Fact Checking

在单纯思维链中，错误的中间猜测会自我强化；而在 ReAct 循环中，Bash 命令或 Pytest 的失败堆栈 (Observation) 会立刻刺破推理幻觉，强制触发修补。

状态可观测与追踪 (Traceability) Observability

显式输出的 `Thought` 为开发者与可观测性平台（如 LangSmith / OpenTelemetry）提供了清淅的 Agent 心理轨迹，极易进行单步 Debug 与 Audit。

01

强结构化解析契约

要求 LLM 使用固定的 XML 标签（如 ``, ``）或原生的 Function Calling 格式，确保解析器可靠提取工具入参。

02

最大步骤限制 (Max Steps = 10~15)

必须设置硬性终止计数器与死循环熔断器，防止 Agent 在重复的无效 Action/Observation 中耗尽 API 预算。

03

过渡至 Skill & Tool Schema

ReAct 范式中的 Action 触发，正是模块四核心技术——Function Calling 与 Skill Schema 暴定义的基础。

Architectural ReAct Rule / 闭环决策法则

ReAct 范式是构建自主 AI Agent 的第一基石：通过将“内部大脑推理 (Thought)”与“外部物理工具执行 (Action & Observation)”同步交织，彻底破解模型的封闭黑盒与盲目猜测。
