边缘化推理路径概率分布公式

传统贪婪采样（Greedy Decoding $T=0$）取极值 $\arg\max$，容易陷入局部最优陷阱。Self-Consistency 通过对中间思考过程 $r$ 边缘化（Marginalization），求解最佳输出 $y$：

// Self-Consistency 数学推导目标
y* = argmax_y ∑_{r} P(y, r | x)
// x: 提示词输入, r: 第 i 条推理链, y: 最终生成的代码
方式 1: 纯文本 Token 多数投票 (Majority Voting) 对多个路径生成的最终 AST / 代码结果做标准化 Token 比较与聚类表决。
方式 2: 代码专属 Unit Test Harness 过滤 (Recommended) 将多路代码放入 Docker 沙箱跑 Pytest/JUnit，直接淘汰未通过测试的代码路径。
最适合高确定性代码生成场景 工程开销: N倍 Token

温度调优 (T=0.5~0.8)

若使用 $T=0$ 则多路生成完全一致；必须设置适度 Temperature 以激发出算法解法的多样性。

算力开销折中 (N=3~5)

生成 $N$ 条链会导致 Token 成本呈 $N$ 倍上升。工程实践中 $N=3$ 到 $N=5$ 即能达到性价比临界点。

与 ReAct / Code Agent 叠加

在生成重构与核心算法补丁时，多路并行推理后用静态分析器（SonarQube/Checkstyle）二次裁决。

Architectural Design Rule / 架构师采样准则

自洽性采样 (Self-Consistency) 是用推理预算（Test-Time Compute）换取代码概率鲁棒性的经典范式；结合沙箱单元测试 Harness 校验，可直接将算法生成 Pass@1 提升至 90%+。

Speaker Notes / 讲师讲稿
🎯 讲授 Self-Consistency 的核心灵感： “向学员强调：单个 CoT 路径可能会因为开头的 Token 采样偏差而‘一条路走到黑’。Self-Consistency 的核心直觉是：**对于一个复杂的算法或重构任务，正确的思维路径往往拥有更高的共识性，而错误的路径千奇百怪**。”
💡 强调代码场景的独特优势（Unit Test Harness）： “提示学员：在自然语言问答中，Self-Consistency 依赖 LLM 做文本语义聚类投票；但在代码工程中，我们拥有绝佳的客观评测器——单元测试（Unit Test）。生成 $N$ 个解法后放入沙箱跑 Pytest，能 100% 裁决出哪个才是正确答案。”
