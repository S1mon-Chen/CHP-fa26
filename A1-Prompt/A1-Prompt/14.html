模块二：结构化上下文与确定性输出

上下文窗口管理：剪枝、压缩与滑动窗口策略

应对超大规模 Codebase 上下文爆表：从 AST 语法树抽象剪枝 到 分层语义摘要压缩，以及 KV-Cache 友好的滑动窗口控制

策略 1: AST 语法树剪枝

骨架提取与函数体抹平

利用 Treesitter 等解析器提炼源码 AST，保留类名、接口、字段及函数签名，将非目标函数体直接剥离替换为占位符。

// AST Pruned Skeleton
class OrderService {
public Order getById(Long id) { /* ... */ }
public void process(Order o) { /* TARGET CODE */ }
}
  • 保留百分之百类型与拓扑依赖信息
  • Token 体积大幅压缩 70% ~ 85%
最推荐的 Codebase 瘦身法 压缩率: ~80%
策略 2: 分层语义压缩

多粒度代码摘要 (Summarization)

非核心模块离线生成自然语言与元数据摘要（Symbol Docstrings + Dependency Graphs），按需替换原始源码。

<module_summary name="auth">
Exports: JWTVerifier, RoleGuard
Behavior: Validates Authorization Header
</module_summary>
  • 跨文件长链推理的首选过渡模式
  • 存在摘要失真风险，需搭配精确检索
适于多层级架构总览 压缩率: ~90%
策略 3: 滑动窗口与 Cache 复用

固定 Header/Tail + 动态 Buffer

固定 Prefix（System Prompt + 关键 Rule）与 Postfix（Current Query），中间交互历史通过队列淘汰并保持 Prefix KV-Cache 复用。

[STATIC] System Prompt & Core Rules
[SLIDING] Turn 4 & Turn 5 Dialogues
[STATIC] User Current Refactor Task
  • 大幅降低 TTFT（首包延迟）与 API 成本
  • 无缝支持 Agent 多轮迭代重构循环
高并发工程必备优化 延迟降低: ~60%

Context Management Principle / 架构师原则

长上下文窗口不等于无脑灌入源码。精细化的 AST 骨架剪枝 + 静态 Prefix 锁定是保证 LLM 推理延迟低、精度高且 Token 成本可控的核心工程壁垒。
