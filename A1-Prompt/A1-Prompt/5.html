上下文污染与幻觉成因

分析多轮交互中的 “历史错误毒化” 现象与最大似然预测下的 “合理编造” 机制

现象一

上下文污染 (Context Contamination)

在多轮对话中，先前轮次产生的错误代码或幻觉 API 被存入历史，成为后续自回归推理的“已知正确条件”，导致错误被不断放大放大。

R1 模型输出错误方法名 getUserIdVal()
↓ 历史被写入 Context 缓冲区
R2 后续生成全部沿用错误 API，死锁陷入幻觉链条
解法： 及时清空无效 Session，引入 Reset 机制与 Context Pruning（上下文剪枝）。
现象二

幻觉成因 (Hallucination Mechanics)

LLM 的本质是概率分布采样（Smooth Probability Smooth Distribution），模型在缺少确切先验时，会选择“语义最通顺但事实不存在”的 Token 补全。

// 采样控制：Temperature 与 Top-P
Temperature = 0.0 确定性最高 (适合代码生成)
Temperature = 0.8 随机性强 (极易虚构 API)
解法： 将 Code Generating 设置为 $T=0$，并辅以外部工具验证（Compiler/LSP/ReAct）。

Architectural Insight / 防御策略

永远不要将多轮对话当做“无限记忆”。工业级 Agent 必须具备 上下文清洗（Context Sanitization） 与 状态重置（State Reset） 机制，防止错误状态毒化全局。
