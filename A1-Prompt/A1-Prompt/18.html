Chain-of-Thought (CoT) 核心原理：思维链的认知科学与数学解释

剖析 Wei et al. (2022) 经典工作：将 LLM 从 System 1（直觉直出） 升维为 System 2（步进推理），通过在上下文缓冲区展开 Token 序列实现计算深度扩展

认知科学视角：双系统理论 (Dual-Process) Kahneman Model
System 1: 快思考 (Direct Generation) 无中间 Token 缓存

依赖参数权重的直觉反应。在面对复杂递归、并发锁或动态规划时，单次前向传播算力不足，极易产生模式匹配幻觉。

System 2: 慢思考 (Chain-of-Thought) 思考 Token 显式化

强制模型将隐式状态转化为可见的逻辑链步骤。利用上下文（KV-Cache）作为**可读写临时工作内存（Working Memory）**。

// System 1 直出死穴:
Input: "写一个 O(n) 的三数之和算法" -> Output: [给出带有双重循环的错误代码]
// System 2 CoT 拆解:
Thought: 先排序 -> 双指针固定左端 -> 判断和与 0 关系 -> 去重 -> 输出代码
从直觉概率估计升级为步骤化思考 错误率降幅: >60%
数学与算力机制：Test-Time Compute 扩展 Compute Unrolling

前向传播深度与 Token 数量的乘积效应

Transformer 针对单个 Token 的前向计算深度（层数 $L$ 与参数量 $P$）是固定的 $O(1)$。复杂逻辑无法在单个 Token 的计算图中解决。

// 推理阶段总算力公式 (Test-Time Compute)
Total FLOPs = N_thinking_tokens × FLOPs_per_token
// CoT 的本质：用自回归时间步（N）补足固定网络深度（L）的计算上限
  • 中间变量驻留：前置步骤计算结果以 Token 形式保留在注意力矩阵中
  • 隔离错误级联：每一步独立推理，降低单步条件概率推导难度
扩展时间轴计算深度 (Test-time Scaling) o1 / o3 原理基石

中间状态显式驻留

在编写复杂重构时，CoT 会在前面先输出指针变动与条件判空清单，后续代码生成直接以这些输出作为硬约束。

降低单步熵增

把“从需求描述一步到 200 行代码”的巨大概率漂移空间，切割为“需求 $\to$ 算法逻辑 $\to$ 边缘用例 $\to$ 最终代码”的极低熵转换。

注意力机制高能对齐

生成代码阶段的 Self-Attention 权重不再飘忽不定，而是以紧邻的前置 CoT Token 为锚点，实现 99%+ 的语法正确性。

Architectural Essence / 架构师本质洞察

思维链（CoT）不是一种玄学提示词技巧，而是通过在 Token 缓冲区展开计算路径，显式增加推理算力（Test-Time Compute）的标准软件工程机制。

Speaker Notes / 讲师讲稿
🎯 引导学员透视 CoT 的物理本质： “向学员强调：不要把 CoT 看成简单的提示词技巧。从 Transformer 结构来看，多层前向网络在生成单一 Token 时的计算 FLOPs 是有限的。当面对复杂的逻辑分析，直接输出最终答案（System 1）会导致模型把有限的算力浪费在概率猜测上。而输出中间 Thinking Steps，就是把复杂的计算过程分摊到了多个 Token 的自回归生成中（Test-Time Compute）。”
💡 联系最新模型架构（OpenAI o1/o3, DeepSeek-R1）： “提示学员：当今诸如 o1 或 DeepSeek-R1 这类 Reasoning 模型，其核心原理就是将 CoT 的思维链生成做到了模型的底层强化学习微调中，让模型在隐式/显式缓冲区中主动进行思维链搜索。”
