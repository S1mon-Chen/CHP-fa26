模块四：工具与物理状态交互 / Module 4: Protocol Evolution

ReAct 与当下 Function Calling (Tool Call) 的技术映射

解构 Agent 交互协议演进：从早期 基于文本正则提取的 ReAct Prompt 到现代 API 原生 Function Calling Protocol 的底层四大映射与性能飞跃

Text-based ReAct Prompt vs. Native API Function Calling Mapping Protocol Evolution
1. 工具声明 (Tool Definition Schema) Schema Layer
Classic ReAct Prompt: System Prompt 嵌入 XML/Markdown 文本（如 ``）说明函数签名。
Native Function Calling: API 顶层参数 `tools: [{type: "function", function: JSONSchema}]` 结构化注入。
2. 动作触发 (Action Trigger) Sampling Layer
Classic ReAct Prompt: 文本输出 `{"name": "...", "params": {...}}`，依靠正则/AST抓取。
Native Function Calling: 模型输出 `finish_reason: "tool_calls"`, 携带结构化 `tool_calls: [...]` 数组。
3. 物理结果回写 (Observation Protocol) Message Role
Classic ReAct Prompt: Controller 拼接字符串 `result...` 反写回 Prompt 尾部。
Native Function Calling: 追加专属消息对象 `{role: "tool", tool_call_id: "call_abc123", content: "..."}`。
从“文本猜规则”演进为“API 原生二进制级契约” 本质思想 100% 继承
语法解析零碰撞 (Zero Syntax Errors) Logit Masking

API 层在 Sampling 采样阶段施加 GBNF 语法树掩码（Grammar-based Decoding），强行将 JSON 格式不合规的 Token 概率降至零，物理消灭语法解析异常。

原生多工具并行调用 (Parallel Tool Calls) Parallelism

原生 Function Calling 允许 LLM 在单个 Response Turn 中吐出多个 `tool_calls`（例如同时并发读取 3 个源文件），极大降低 Agent 循环网络 RTT 延迟。

隐式思考与 Tool Call 无缝解耦 Reasoning API

在新一代 Reasoning 模型（如 OpenAI o1/o3、DeepSeek-R1、Claude 3.7 Sonnet）中，内部思维链 (`thinking`) 与外显的 Function Calling 完美分离，兼顾深度思考与精确调用。

Pydantic 自动导出 API Schema

无需手写 JSON Schema，直接使用 Pydantic Model 导出 `model_json_schema()` 填入 Function Calling API 参数。

02

`tool_call_id` 状态精确追踪

回传 Observation 时必须带上匹配的 `tool_call_id`，Controller 据此在长对话上下文里完成精准状态对齐。

03

开源小模型降级平滑适配

对于不支持原生 Function Calling 的轻量开元小模型（如 Qwen-1.5B），可降级平滑使用文本 Prompt ReAct 模版。

Architectural Protocol Rule / 协议下沉法则

Function Calling 并非否定 ReAct 范式，而是将 ReAct 的“思考-行动-观察”闭环下沉为模型与 API 层的底层原生契约；掌握两者的技术映射，才能在不同模型间灵活构建坚固的 Agent 工具系统。

🎯 剖析 ReAct 与 Function Calling 的演进本质： “向学员强调：不要把 ReAct 范式和 Function Calling 割裂开来看。ReAct 是学术界和早期工程界提出的**思考框架（Mental Model）**；而 Function Calling 是厂商（OpenAI、Anthropic、DeepSeek）把这个思考框架**下沉为 API 原生协议与 Logit 采样掩码**。两者的核心本质完全一致。”
💡 强调并发工具调用与 `tool_call_id`： “提示学员：原生 Function Calling API 带来的最大优势之一是**并行工具调用 (Parallel Tool Calls)**。模型可以一次性返回调用多个工具的请求，极大减少网络往返耗时；同时，`tool_call_id` 保证了异步回传结果时不会在上下文数组里错位。”
