AI Coding Tool Context & Prompt Construction Paradigms IDE Architecture
1. GitHub Copilot: FIM (Fill-In-the-Middle) & Local Neighbor Attention Completion < 100ms
<PRE> Prefix Code ... <SUF> Suffix Code ... <MID> [Predicted Infill Code]
利用 IDE 打开的受关照 Tab 页（Neighbor Tabs）加权组装 Prefix/Suffix，极度追求推理延迟与光标精准推演。
2. Cursor: Repo-wide RAG + AST Merkle Tree + `.cursorrules` Context Engine
Injects Project System Rules + Multi-file AST Skeleton + Active Diff Spec
结合全项目向量索引与文件依赖关系，将 `.cursorrules` 作为强制 System Prompt 指令压入，支持全局多文件 Agent 重构。
3. Cline (Claude Dev): Full System Tools + ReAct Loop + HITL Gate Autonomous Agent ★
Tools: execute_command(), write_to_file(), read_file(), ask_followup()
完全暴露 Bash 与终端权限，结合显式工具调用与人类确认卡扣（Human-in-the-loop Gate），支持独立跑单测与修复。
从“光标单行补全”演进为“全局系统级自主 Agent” Prompt 复杂度升维 100x

项目定制规则 (.cursorrules Injection) Cursor Feature

将仓库根目录下的 `.cursorrules` 文件解析并强制作为最高优先级 System Instructions，锁定特定框架（如 Tailwind/Next.js App Router）规范。

HITL 终端命令安全卡扣 (Cline Pattern) Cline Safety

在运行 Bash 命令（如 `npm run test` 或 `rm -rf`）时，Agent 强制挂起并向开发者展示可视化 Approval 弹窗，防止终端提权误操作。

01

相邻 Tab 缓存切片 (Neighbor Tabs)

Copilot 等工具会优先装载同项目下最近打开的 3~5 个文件，充当微型本地上下文（Working Memory）。

02

AST 剪枝 + Diff 图匹配

Cursor 不把全量代码灌入 Prompt，而是通过 Tree-sitter 提取 AST 接口骨架，只对 Git Diff 区域放大上下文。

03

Terminal 执行即 Observation

Cline 等工具把终端跑单测抛出的 stderr 直接装入 `Observation` 标签，驱动 Agent 在内部完成闭环 Self-Correction。

Architectural Tool Prompting Rule / 工具架构演进法则

现代 AI 编程辅助工具的竞争本质是“上下文工程（Context Engineering）与系统提权沙箱（HITL Control Loop）的竞争”；掌握这三大 Prompt 架构，才能构建出真正理解复杂企业级 Codebase 的智能 Copilot。

Speaker Notes / 讲师讲稿
🎯 讲授主流 AI 编程工具的 3 阶段演进： “向学员剖析：AI 编程工具经历了三个时代：第一代以 GitHub Copilot 为代表，主打 **FIM (Fill-In-the-Middle)** 快速单行代码补全；第二代以 Cursor 为代表，引入全项目向量索引、AST 剪枝与项目规则文件 (`.cursorrules`)；第三代以 Cline (Claude Dev) / Roo Code 为代表，赋予 Agent 终端与文件读写系统权限，进入完全自主的 ReAct Agent 闭环。”
💡 强调安全卡扣与 HITL (Human-in-the-Loop)： “提示学员：当工具具备直接改写文件系统和运行终端 Shell 命令时，必须在 Prompt 和 IDE 交互层设计 **Human-in-the-Loop 授权卡扣**，防止模型在不经意间执行 `rm -rf` 或修改安全配置。”
